### TypeScript 風の構文を選ぶ理由

アトミックなロジックには計算、条件、データ変換が必要です。関数、オブジェクト、型注釈、式は TypeScript 利用者に馴染みのある表現です。この表層構文を使うことで、人と AI の学習・読解・生成の負担を下げ、業務規則と入出力契約に集中できるようにすることを目指します。

一方で ZX は文法と意味論を制限します。明示的な数値幅、検査可能な所有権、制御された機能の境界により、コンパイラは静的解析と Zig の生成を行えます。馴染みのある表記と制約された実行意味論を組み合わせ、単位ごとの検証と最適化の基盤にします。

TypeScript 風であることは完全互換を意味しません。ZX は TypeScript コンパイラや JavaScript ランタイムに依存せず、任意の TypeScript コードや npm パッケージをそのまま利用できるとは限りません。性能の可能性は表面の構文ではなく、静的意味論とコンパイル経路から生まれます。

### 明示的な入出力

ZX は TypeScript に似ていますが、JavaScript ではありません。入出力型を宣言し、関数をデフォルトエクスポートします。次の最小例は入力の金額をそのまま返します。

```typescript
export type Input = {
  amount: u64;
};

export type Output = {
  amount: u64;
};

export default function (in: Input): Output {
  return { amount: in.amount };
}
```

### 計算の範囲を絞る

現在のコンパイラは、スカラー、オブジェクト、列挙型、省略可能な値、リスト、タプル、ローカル束縛、分岐、ファイルのインポートをサポートします。コレクション操作には、外部の値をキャプチャしない `map`、`filter`、`reduce` があります。

任意のクロージャ、汎用ループ、JavaScript の暗黙変換、ランタイム機能のインポートが使えるとは限りません。数値型には明確な意味があり、JavaScript の数値の振る舞いには依存できません。

### 所有権を明確にする

深いコピーが必要なら `clone` を使います。Store へのアクセスは宣言済みのハンドルを通じて提供され、読み取りと書き込みの権限は独立しています。寿命、永続化、コミットはホストコードの責務です。

インストール済みツールチェーンのフォーマッタと診断を使ってください。正確な契約は[コンパイラのリファレンス](https://github.com/MatrixAges/zxc/blob/master/packages/compiler/README.md)で確認できます。

### 共有する契約は型専用ファイルに置く

二つの実行ファイルでデータの形を共有する場合は、別の型専用 `.zx` ファイルからエクスポートします。実行関数のインポートと共有型のインポートを分けることで、計算内部の入力型が意図せず共有 API になることを防げます。

### 必要なすべての経路で値を返す

`void` 以外の出力では、すべての可能な経路で値を返す必要があります。無効な業務条件をガードで処理し、その後に明確な結果を返す形が適しています。`return_path` 診断は、宣言した出力と制御フローが一致していないことを示します。

### 独立して推論できる単位を書く

ZX の単位は価格計算、適格性判断、データ変換など、一つの計算に明確な入出力契約を設けます。RX がそれらを組み合わせます。ここでのアトミック性は責務の境界を示し、トランザクション保証でも、式ごとのファイル分割の要求でもありません。

明示的な型、所有権、副作用の境界は局所検証とオペレーター単位の最適化を可能にする条件です。現在の経路は ZX → 型付き IR → Zig です。インライン化、特殊化、抽象化コストの除去は、バックエンド、生成コード、測定で確認します。形式証明と FPGA 対応には今後のツールチェーン開発が必要で、単位が小さいだけでは実現しません。

### match 式

match 式には二つの形式があります。`match { ... }` は完全な真偽条件で結果を選び、`match value { ... }` は対象の値で結果を選びます。`=>` の右側が結果、`_` が既定分岐です。

```typescript
const shipping = match {
  discounted >= in.free_shipping_minimum => 0,
  _ => in.shipping_fee
};

const label = match status {
  "paid" => "ready",
  "pending" => "waiting",
  _ => "blocked"
};
```

条件は記述順に確認し、選ばれた結果だけを評価します。値モードの対象は一度だけ評価し、void 以外のスカラーまたは列挙型に限定します。末尾に唯一の `_` 分岐が必要で、末尾カンマを許可します。結果の型は一致する必要があります。論理積には `&&` を使います。範囲、構造分解、連鎖比較には対応しません。
