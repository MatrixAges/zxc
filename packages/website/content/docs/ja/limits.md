### 現在のリポジトリで実装済み

- ZX の解析、型と所有権の検査、IR の検証、Zig の生成。
- 複数ファイルのインポートと非循環性の検査。
- RX タグ定義、ファイルパスによるモジュール登録、依存循環の検出。
- コンパイラ境界での Store アクセス契約。コミット動作はホストが提供する。

### 本番用ランタイムではない

コンパイラには完全な RX XML ローダーや本番用スケジューリングランタイムは含まれていません。データベース対応も未実装です。Store のバージョン検査、ロック、永続化、複数オブジェクトのアトミックな公開はホストの責務です。

Gateway や Store の宣言を、HTTP サーバーの稼働や永続データベースの存在の証拠として扱わないでください。

### バージョンの境界

リポジトリのパッケージバージョンは **0.0.1**、ZX 言語契約は **0.1.0**、IR は実験的な **バージョン 2** です。IR は Zig のインメモリ API であり、安定したシリアライズ交換形式ではありません。

この文書は現在のソースのスナップショットであり、互換性を保証するものではありません。設計文書にある機能を使う前に、使用中のリビジョンとホスト契約を確認してください。

### 設計目標と今後の取り組み

- **AI とグラフの連携**：依存解析と非循環検査は実装済みです。コンテキスト選択、追跡、影響解析のため関係を AI に直接公開することは今後の方向であり、安定した検索・出力プロトコルは約束していません。
- **モデル品質とトークン効率**：非 SOTA モデルも SOTA モデルと同じ品質基準を満たせるよう、認知負荷と必要情報量を減らすことが目標です。ここで示せる比較評価の結論はありません。
- **ゼロコスト抽象化**：アトミックなロジック、静的契約、Zig のコンパイル機能が最適化の基盤です。すべての抽象化コストが除去されたわけではなく、一部のコレクション操作は割り当てを行います。
- **LLVM とアセンブリ**：現在の zxc バックエンドは Zig を生成します。Zig の LLVM バックエンドを使えば対象最適化と機械語生成を利用できますが、zxc 独自の直接 LLVM バックエンドやアセンブリコマンドを意味しません。
- **形式証明と FPGA**：長期的な研究方向です。前者には形式意味論、仕様、証明ツール、後者には合成可能な計算部分集合、ハードウェア制約、専用の合成バックエンドが必要です。LLVM 対応だけで実現する機能ではありません。
