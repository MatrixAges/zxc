生成された Zig は、ランタイムサポートとメモリの寿命を提供するホストで動きます。使用中の Zig とコンパイラのリビジョンに合う正確な手順は、リポジトリの動作するサンプルから始めるのが確実です。

### 参考実装をビルドする

```sh
zig build
zig build zx-example
```

このサンプルは ZX をコンパイルし、生成した Zig を実行します。適用する際は、リポジトリのビルド設定と[サンプルディレクトリ](https://github.com/MatrixAges/zxc/tree/master/packages/compiler/examples)をあわせて確認してください。

### 生成モジュールを接続する

1. 入口の `.zx` ファイルとそのインポートをコンパイルする。
2. 生成 Zig モジュールをホストのビルドへ追加する。
3. そのモジュールからコンパイラの `zx_runtime` を参照できるようにする。
4. 実行と結果の利用を覆う寿命の arena を作る。
5. 外部入力を生成された `Input` の形へデコードする。
6. 生成された `execute` 入口を呼び、結果または失敗を処理する。

純粋な生成モジュールは arena と入力を使います。状態ケイパビリティを指定してコンパイルしたモジュールは、さらに実行コンテキストを受け取ります。これらのシグネチャは生成結果の一部です。正確な型は、そのリビジョンの出力を確認してください。

### 結果の寿命を守る

リストや文字列は実行 arena に依存する場合があります。メモリを解放する前に、結果を利用、シリアライズ、または明示的にコピーしてください。arena の破棄後に参照を保持してはいけません。

### ホスト機能を登録する

Store ハンドルや外部インポートには、コンテキストを受け取るコンパイラ API を使います。登録はプログラムの権限境界の一部です。実行時に互換性のある実装を提供する責任はホストにあります。

状態を使うロジックは、同時リクエストへ公開する前にバージョン検査と原子的なコミットを定めます。外部関数についても、同じ境界で失敗時の扱いと所有権を定義してください。

### 経路全体を検証する

コンパイルはソースが検査を通過したことを、生成 Zig のビルドはそのホストビルドとの互換性を示します。代表的な入力での実行は、その入力に対する動作を検証します。どれか一つだけで、RX ワークフローの実行ランタイムが存在するとは証明できません。

続いて[検証と引き渡し](/docs/validate-and-deliver)を読んでください。
