アプリケーションを届けるために必要な、最小の境界を選びます。ZX の計算、RX の合成、ホストランタイムは、それぞれ異なる問題を解決します。

### 出発点を選ぶ

| 目的                                     | 出発点                        | 必要なもの                               |
| ---------------------------------------- | ----------------------------- | ---------------------------------------- |
| 業務上の計算を検査してコンパイルする     | `.zx` ファイル                | コンパイラと明示的な入出力型             |
| コンパイルしたロジックを実行する         | 生成された Zig                | `zx_runtime`、arena、Zig ホスト          |
| 複数段階のワークフローを記述する         | 通常の `.rx` モジュール       | 現在の RX バリデータとは別の実行ホスト   |
| ルートや共有状態を宣言する               | Gateway または Store ファイル | 通信と状態管理のホスト実装               |
| エージェントでアプリケーションを生成する | エージェントガイド            | ツールチェーン、ランタイム、受け入れ基準 |

### 計算から始める

最初に動くものが必要なら、リポジトリの ZX サンプルをビルドして実行します。コンパイラと Zig 統合をまとめて確認できます。[はじめに](/docs/getting-started)に沿って進め、その後でサンプルの計算を自分の型付き入出力に置き換えてください。

### 実際の境界で合成を導入する

どの単位がどの単位を呼ぶかを RX で表し、算術や変換は ZX に置きます。ワークフロー宣言は、実行ホストがなくても構造のレビューに役立ちます。ただし、宣言だけで実行可能なサービスになるわけではありません。

### ホストとの契約を定める

通信や状態を扱う前に、通信経路、認証、入力のデコード、メモリの寿命、状態アクセス、コミットの意味を誰が提供するか明確にします。現在のコンパイラはサーバーやデータベースを提供しません。

ZX の実行については [Zig ホストとの統合](/docs/host-integration)、RX の構造については[モジュールの合成](/docs/compose-modules)へ進んでください。
