モジュールはパスで識別されます。ファイルの配置を業務上の責務に合わせることで、別名の登録表を見なくてもインポートを理解できます。

### RX のサービスパス

`Call.service` と `Import.from` は、インポートする側のモジュールを基準に解決されます。`.rx` を省略すると正規化時に補われるため、`./load` と `load.rx` は同じ階層の同じモジュールを指します。

| 形式                                              | RX の動作                                      |
| ------------------------------------------------- | ---------------------------------------------- |
| `users/load`                                      | 呼び出し元ディレクトリ配下のモジュール         |
| `../shared/load`                                  | プロジェクト内の親ディレクトリにあるモジュール |
| `/users/load`                                     | 絶対パスのため拒否                             |
| プロジェクトルートを越えるパス                    | 拒否                                           |
| バックスラッシュ、コロン、末尾のスラッシュ        | 拒否                                           |
| `app.rx`、Gateway、Store ファイルをサービスにする | 拒否                                           |

`app.rx` は予約されたファイル名です。入れ子のディレクトリでも通常のモジュール名には使えません。パスの正規化は字句的な処理であり、ファイルシステムのシンボリックリンクは解決しません。

### 依存関係を宣言する

```xml
<Module>
  <Import from="shared/validate" />

  <Call service="orders/create" in={$in} out="ctx.order" />

  <Return value={ctx.order} />
</Module>
```

`Import` はグラフの辺を宣言します。対象を実行せず、`as` による別名も持ちません。サービス呼び出しはそれ自体で辺を宣言するため、有効化のために同じインポートを追加する必要はありません。

### ZX のインポート

ZX では `.zx` 拡張子と、`./`、`../`、`@/` のいずれかを明示します。相対パスはインポート元ファイルが起点です。CLI は `@/` を現在の作業ディレクトリから解決します。

```typescript
import calculateQuote from './calculate_quote.zx'
import type { Money } from './types.zx'
```

デフォルト関数は実行可能な ZX ファイルから、共有型と列挙型は型専用ファイルからインポートします。型専用ファイルは少なくとも一つの型または列挙型をエクスポートし、デフォルト関数を持ちません。実行モジュールの `Input` エクスポートを、共有型モジュールの代わりに使わないでください。

### 両方のグラフを非循環に保つ

コンパイラは未使用のインポートも含めて依存関係を検査します。決して実行されない分岐であっても、循環依存は許されません。共有処理を下位モジュールへ移し、親が所有する値は入力で渡します。

続いて[依存関係の設計](/docs/keep-dependencies-acyclic)を読んでください。
