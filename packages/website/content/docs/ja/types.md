ZX は Zig を生成する前に具体的な型を決定します。JavaScript の単一数値型や暗黙変換の規則は使いません。

### 馴染みのある型名

| ソースの型 | 既定の ZX 型        |
| ---------- | ------------------- |
| `number`   | `f64`               |
| `boolean`  | `bool`              |
| `string`   | 不変の UTF-8 文字列 |
| `void`     | 出力値なし          |
| `Array<T>` | `T[]`               |

`number` は IEEE 754 倍精度浮動小数点で、安全な整数範囲は ±(2^53 − 1) です。それより大きな正確な整数には明示的な整数型を使い、金額は適切な場合に最小通貨単位の整数で表します。これらの名前は既存の型を再利用し、値を自動初期化しません。`bigint`、`symbol`、`any`、`unknown`、動的な `object`、独立した `undefined`、`null`、`never` 型には対応しません。値の不在には `T?` と `null` を使います。リテラル推論は変わらず、JavaScript の暗黙変換も導入しません。

### スカラーを選ぶ

| 型                        | 値                             |
| ------------------------- | ------------------------------ |
| `bool`                    | `true` または `false`          |
| `u8`、`u16`、`u32`、`u64` | 指定したビット幅の符号なし整数 |
| `i32`、`i64`              | 符号付き整数                   |
| `f32`、`f64`              | 浮動小数点値                   |
| `string`                  | 文字列データ                   |
| `void`                    | 値なし                         |

境界で使うビット幅は意図して選びます。既存の整数変数は暗黙に拡幅されず、浮動小数点にも暗黙変換されません。リテラルは文脈から型を受け取れます。文脈による型指定がない場合、正の整数は `u64`、負の整数は `i64`、小数点や指数表記を持つリテラルは `f64` になります。

### データの形を定める

```typescript
export type Input = {
  amount: u64
  label: string?
  adjustments: u64[]
}

export type Output = {
  amount: u64
  label: string
}

export default function (in: Input): Output {
  return { amount: in.amount, label: in.label ?? 'untitled' }
}
```

`T?` は省略可能な値です。オブジェクトのプロパティには `name?: T` も使えます。`T[]` はリスト、`[T, U]` はタプルです。オブジェクト、名前付き型、列挙型により、実行前に境界のデータ形状を検査できます。

### 算術の前提を確認する

整数除算はゼロ方向に切り捨て、余りの符号は被除数に従います。無効な算術は実行時の失敗になります。JavaScript のような型変換や、自動的な値の回復は行いません。失敗し得る演算の前に業務上の前提を確認してください。

`&&`、`||`、`??`、条件式は短絡評価します。文字列の等値比較はバイト単位です。リストやオブジェクトに構造的な深い等値比較があるとは考えないでください。

### 命名を予測しやすくする

値には `snake_case`、インポート関数には `camelCase`、型には `PascalCase` を使います。デフォルトの実行関数は無名で、入力パラメータの名前は `in` です。

続いて[コレクションと所有権](/docs/collections-and-ownership)を読んでください。
