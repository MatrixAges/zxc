状態は、コンパイラとホストの間にある明示的な境界です。Store 宣言はデータを記述し、読み取り、変更、コミットの方法は実行ホストが実装します。

### 三つの層を分ける

| 層                        | 責務                                                   |
| ------------------------- | ------------------------------------------------------ |
| RX Store 宣言             | オブジェクトとフィールドを記述する                     |
| ZX コンパイルコンテキスト | ハンドルと許可されたアクセスを登録する                 |
| 実行ホスト                | 値、寿命、並行性、永続化、コミットの振る舞いを提供する |

現在のリポジトリは、RX Store ファイルを ZX 実行コンテキストへ自動接続しません。名前が一致するだけで、利用可能なケイパビリティができるとは限りません。

### 能力を意図して提供する

ホスト統合は `compileWithContext` またはプロジェクトのコンパイルコンテキストを通じて Store 能力を登録します。読み取りと書き込みの権限は独立しています。生成される状態付きの入口は、arena と入力に加えてホストコンテキストを受け取ります。

コマンドラインコンパイラは、Store XML からアプリケーション固有のハンドルを推測できません。ハンドルを必要とするコンパイルには統合 API を使います。

### 状態を書く前にコミットの意味を決める

各操作について、一貫したスナップショットを構成する値、検査するバージョン、競合する更新が先に成功した場合の動作を決めます。ロック、バージョン、永続化、複数オブジェクトの原子的な公開はホストの責務です。

コンパイラの検査はトランザクション管理ではありません。二つのオブジェクトを更新するとき、ホストが別々に書き込めば、部分的な状態が見えてしまうことがあります。

### 純粋な計算を分ける

状態を必要としない計算には、型付きの入出力を優先します。必要なスナップショットを純粋な ZX 関数へ渡し、その結果はホストのコミット方針に従って適用します。直接の能力アクセスが必要な箇所にだけ Store アクセスを導入してください。

構造上の用語は [Gateway と Store の宣言](/docs/gateway-and-store)、実装の境界は[対応範囲](/docs/capabilities)を参照してください。
