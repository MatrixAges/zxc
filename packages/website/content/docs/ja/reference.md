### RX の構成要素

| 構成要素                    | 責務                                |
| --------------------------- | ----------------------------------- |
| `Module`                    | 通常のワークフローファイルのルート  |
| `Call`                      | RX サービスまたは ZX 関数の呼び出し |
| `Task`                      | 関連する処理のまとまりへの命名      |
| `Parallel`                  | 独立したタスクや呼び出しの合成      |
| `Switch`, `Case`, `Default` | 分岐の選択                          |
| `Return`                    | フローの結果の返却                  |
| `Emit`                      | 外部へ出す業務イベントの記述        |
| `Import`                    | 任意の合成依存関係の宣言            |

`Task` は別の `Task` を直接含められません。`Case` と `Default` は `Switch` の内部に置きます。

### ファイルの役割

| ファイル       | 用途                                   |
| -------------- | -------------------------------------- |
| `*.rx`         | 通常のモジュールのオーケストレーション |
| `*.zx`         | 型付きビジネス計算                     |
| `*.gateway.rx` | Gateway、Group、Route の宣言           |
| `*.store.rx`   | Store、Object、Field の宣言            |

Gateway と Store の名前は業務上の境界を表します。通常のモジュールのファイルパスによる識別を置き換えるものではありません。Store のエイリアスはデータの名前空間であり、モジュールの別名ではありません。

### コンパイラのコマンド

```sh
zxc input.zx --out output.zig
zxc fmt input.zx --check
```

ローカルでビルドした `zxc` が `PATH` にない場合は、その実際のパスを指定します。CLI は `@/` インポートを現在の作業ディレクトリから解決します。通常の相対インポートは、インポート元ファイルを基準に解決します。
