### RX の用語

| 構造                        | 責務                                   |
| --------------------------- | -------------------------------------- |
| `Module`                    | 通常のワークフローファイルのルート     |
| `Call`                      | RX サービスまたは ZX 関数を呼ぶ        |
| `Task`                      | 関連する処理のグループに名前を付ける   |
| `Parallel`                  | 独立したタスクや呼び出しを組み合わせる |
| `Switch`、`Case`、`Default` | 分岐を選ぶ                             |
| `Return`                    | ワークフローの結果を返す               |
| `Emit`                      | 外へ送る業務イベントを記述する         |
| `Import`                    | 任意の合成依存関係を宣言する           |

`Task` の直下に別の `Task` は置けません。`Case` と `Default` は `Switch` の中に置きます。

### ファイルの役割

| ファイル       | 用途                                  |
| -------------- | ------------------------------------- |
| `*.rx`         | 通常モジュールのオーケストレーション  |
| `*.zx`         | 型付きのビジネス計算                  |
| `*.gateway.rx` | Gateway、グループ、ルートの宣言       |
| `*.store.rx`   | Store、オブジェクト、フィールドの宣言 |

Gateway と Store の名前は業務境界を表します。通常モジュールのファイルパスによる識別を置き換えません。Store の別名はデータの名前空間であり、モジュールの別名ではありません。

### 属性の契約

| タグ                   | 必須属性                                 | 任意属性 / 制限                     |
| ---------------------- | ---------------------------------------- | ----------------------------------- |
| `Module`               | なし                                     | 名前なし。通常の `.rx` のルート     |
| `Call`                 | `in` と、`fn` / `service` のどちらか一つ | `out`。`setter` は `fn` の場合のみ  |
| `Import`               | `from`                                   | 別名なし。依存関係のみ              |
| `Task`                 | `name`                                   | 空不可。直下の `Task` 不可          |
| `Parallel`             | なし                                     | 空不可。子は `Task` / `Call` のみ   |
| `Switch`               | `on`                                     | 子は `Case` / `Default`             |
| `Case`                 | `value`                                  | switch 内で一意。本体は空不可       |
| `Default`              | なし                                     | switch ごとに最大一つ。本体は空不可 |
| `Return`               | `value`                                  | 葉ノード                            |
| `Emit`                 | `event`、`value`                         | 葉ノード                            |
| モジュール内の `Store` | `from`                                   | 任意の `as` 名前空間                |

属性は現在の構造モデルの一部として検証されます。`$in` や `ctx.result` のような式の文字列はホストによる解釈が必要です。RX パッケージは現在、それらを解析したり ZX に照らして型検査したりしません。

### 検証する範囲

構築済み AST を検証し、通常モジュールのパスを登録し、グラフの辺に循環がないか検査します。XML 読み込み、戻り値の自動推論、ZX 結合、イベント購読、ランタイム実行は提供しません。

例は[分岐とタスク](/docs/control-flow)を参照してください。Gateway と Store のルートには、それぞれの[宣言リファレンス](/docs/gateway-and-store)があります。

### コンパイラのコマンド

```sh
zxc input.zx --out output.zig
zxc fmt input.zx --check
```

`zxc` が `PATH` にない場合は、ローカルでビルドしたバイナリへのパスを使います。CLI の `@/` インポートは現在の作業ディレクトリから、通常の相対インポートはインポート元ファイルから解決されます。
