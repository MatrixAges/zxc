생성된 Zig는 런타임 지원과 메모리 수명을 제공하는 호스트 안에서 실행됩니다. 설치된 Zig와 컴파일러 리비전에 맞는 정확한 통합은 저장소의 실행 예제에서 시작하는 것이 좋습니다.

### 참조 통합 빌드

```sh
zig build
zig build zx-example
```

예제는 ZX를 컴파일하고 생성된 Zig를 실행합니다. 적용할 때 [예제 디렉터리](https://github.com/MatrixAges/zxc/tree/master/packages/compiler/examples)와 저장소 빌드 설정을 함께 읽으세요.

### 생성된 모듈 연결

1. 진입 `.zx` 파일과 가져오는 파일들을 컴파일합니다.
2. 생성된 Zig 모듈을 호스트 빌드에 추가합니다.
3. 해당 모듈에서 컴파일러의 `zx_runtime` 모듈을 사용할 수 있게 합니다.
4. 실행과 결과 소비를 모두 포함하는 수명의 아레나를 만듭니다.
5. 외부 입력을 생성된 `Input` 형태로 디코딩합니다.
6. 생성된 `execute` 진입점을 호출하고 결과나 실패를 처리합니다.

순수 모듈은 아레나와 입력을 사용합니다. 상태 기능과 함께 컴파일된 모듈은 실행 문맥도 받습니다. 이 시그니처는 생성 결과에 속하므로 리비전의 정확한 타입은 해당 출력을 확인하세요.

### 결과의 수명 유지

리스트와 문자열은 실행 아레나에 의존할 수 있습니다. 메모리를 해제하기 전에 결과를 소비하거나 직렬화하거나 명시적으로 복사하세요. 아레나가 파괴된 뒤 참조를 보관하지 마세요.

### 호스트 기능 등록

Store 핸들과 외부 가져오기에는 문맥을 받는 컴파일러 API를 사용하세요. 등록은 프로그램의 권한 경계에 속합니다. 호스트는 실행 시 호환되는 구현을 제공할 책임이 있습니다.

상태를 사용하는 로직은 동시 요청에 노출하기 전에 버전 검사와 원자적 커밋 동작을 정의하세요. 외부 함수도 같은 경계에서 실패와 소유권 동작을 정의하세요.

### 전체 경로 검증

컴파일은 소스가 컴파일러 검사를 통과했음을 입증합니다. 생성된 Zig의 빌드는 해당 호스트 빌드와의 호환성을 입증합니다. 대표 입력의 실행은 그 입력에서의 동작을 검증합니다. 어느 단계도 단독으로 RX 워크플로에 실행 런타임이 있음을 입증하지는 않습니다.

[검증과 전달](/docs/validate-and-deliver)로 이어가세요.
