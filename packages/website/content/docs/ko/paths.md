경로는 모듈을 식별합니다. 별칭 레지스트리 없이도 가져오기를 이해할 수 있도록 파일 배치를 비즈니스 책임과 맞추세요.

### RX 서비스 경로

`Call.service`와 `Import.from`은 가져오는 모듈을 기준으로 해석됩니다. 정규화기는 생략된 `.rx` 확장자를 추가하므로 `./load`와 `load.rx`는 같은 형제 모듈을 가리킵니다.

| 형태                                               | RX 동작                               |
| -------------------------------------------------- | ------------------------------------- |
| `users/load`                                       | 호출자 디렉터리 아래의 모듈           |
| `../shared/load`                                   | 프로젝트 범위 내 상위 디렉터리의 모듈 |
| `/users/load`                                      | 절대 경로이므로 거부                  |
| 프로젝트 루트를 벗어나는 경로                      | 거부                                  |
| 역슬래시, 콜론, 끝의 슬래시                        | 거부                                  |
| 서비스로 지정한 `app.rx`, Gateway 파일, Store 파일 | 거부                                  |

`app.rx`는 예약된 파일명입니다. 중첩 디렉터리에서도 일반 모듈 이름으로 사용하지 마세요. 경로 정규화는 문자열 수준에서 이루어지며 파일시스템 심볼릭 링크를 해석하지 않습니다.

### 의존성 선언

```xml
<Module>
  <Import from="shared/validate" />

  <Call service="orders/create" in={$in} out="ctx.order" />

  <Return value={ctx.order} />
</Module>
```

`Import`는 그래프 간선을 선언합니다. 가져온 모듈을 실행하지 않으며 `as` 별칭도 없습니다. 서비스 호출은 자체 간선을 선언하므로 호출을 활성화하려고 중복 가져오기를 추가하지 마세요.

### ZX 가져오기

ZX 파일 가져오기는 `.zx` 확장자를 반드시 생략하고 `./`, `../`, `@/` 중 하나를 사용합니다. 확장자를 명시하면 오류가 발생합니다. 상대 경로의 기준은 가져오는 파일입니다. `@/`는 소속 패키지 또는 프로젝트 루트를 가리키며, 프로젝트 설정이 없으면 CLI 작업 디렉터리를 사용합니다.

```typescript
import calculateQuote from './calculate_quote'
import type { Money } from './types'
```

기본 함수는 실행 가능한 ZX 파일에서 가져옵니다. 공유 타입과 열거형은 타입 전용 파일에서 가져옵니다. 타입 전용 파일은 하나 이상의 타입이나 열거형을 내보내고 기본 함수가 없어야 합니다. 실행 모듈의 `Input` 내보내기를 공유 타입 모듈 대신 사용하지 마세요.

### 두 그래프 모두 순환 없이 유지하기

컴파일러는 사용하지 않는 가져오기를 포함하여 의존성을 검사합니다. 실행되지 않는 분기라도 순환 의존성을 허용하지 않습니다. 공통 작업을 하위 모듈로 옮기고 부모가 소유한 값을 입력으로 전달하세요.

[의존성 설계](/docs/keep-dependencies-acyclic)로 이어가세요.
