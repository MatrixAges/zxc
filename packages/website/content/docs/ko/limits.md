### 현재 저장소에 구현된 기능

- ZX 구문 분석, 타입과 소유권 검사, IR 검증, Zig 생성.
- 다중 파일 가져오기 및 순환 의존성 검사.
- RX 태그 정의, 파일 경로 기반 모듈 등록, 의존성 순환 검사.
- 컴파일러 경계의 Store 접근 계약. 커밋 동작은 호스트가 제공합니다.

### 아직 프로덕션 런타임은 아닙니다

완전한 RX XML 로더와 프로덕션 스케줄링 런타임은 컴파일러에 포함되지 않습니다. 데이터베이스 지원도 구현되지 않았습니다. Store 버전 검사, 잠금, 영속성, 여러 객체의 원자적 공개는 호스트의 책임입니다.

Gateway 또는 Store 선언을 실행 중인 HTTP 서버나 영속 데이터베이스의 증거로 제시하지 마세요.

### 버전 경계

저장소 패키지 버전은 **0.0.1**, ZX 언어 계약은 **0.1.0**, IR은 실험적인 **버전 2**입니다. IR은 Zig 메모리 내 API이며 안정적인 직렬화 교환 형식이 아닙니다.

이 문서는 현재 소스의 스냅샷이며 호환성 약속이 아닙니다. 설계 문서에 나온 기능을 사용하기 전에 설치된 리비전과 호스트 계약을 확인하세요.

### 설계 목표와 향후 작업

- **AI 그래프 협업**: 의존성 분석과 비순환 검사는 구현되어 있습니다. 문맥 선택, 추적, 영향 분석을 위해 관계를 AI에 직접 공개하는 것은 향후 방향이며 안정적인 조회·내보내기 프로토콜은 아직 약속하지 않습니다.
- **모델 품질과 토큰 효율**: 비 SOTA 모델도 SOTA 모델과 같은 코드 품질 기준을 충족하도록 인지 및 문맥 부담을 낮추는 것이 목표입니다. 여기서 제시할 비교 평가 결론은 없습니다.
- **무비용 추상화**: 원자적 로직, 정적 계약, Zig 컴파일은 최적화 기반입니다. 모든 추상화 비용이 제거된 것은 아니며 일부 컬렉션 연산은 여전히 할당합니다.
- **LLVM과 어셈블리**: 현재 zxc 백엔드는 Zig를 생성합니다. Zig의 LLVM 백엔드를 선택하면 대상 최적화와 기계어 생성을 활용할 수 있지만 zxc의 직접 LLVM 백엔드나 전용 어셈블리 명령을 의미하지는 않습니다.
- **형식 증명과 FPGA**: 장기 연구 방향입니다. 전자에는 형식 의미론, 명세, 증명 도구가 필요하고 후자에는 합성 가능한 계산 부분집합, 하드웨어 제약, 전용 합성 백엔드가 필요합니다. LLVM 지원만으로 제공되는 기능이 아닙니다.
