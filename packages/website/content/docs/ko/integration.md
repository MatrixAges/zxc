애플리케이션을 구현할 수 있는 가장 작은 경계를 선택하세요. ZX 계산, RX 구성, 호스트 런타임은 서로 다른 문제를 해결합니다.

### 시작점 선택

| 작업                         | 시작점                  | 필요한 것                          |
| ---------------------------- | ----------------------- | ---------------------------------- |
| 비즈니스 계산 검증 및 컴파일 | `.zx` 파일              | 컴파일러와 명시적인 입력/출력 타입 |
| 컴파일된 로직 실행           | 생성된 Zig              | `zx_runtime`, 아레나, Zig 호스트   |
| 여러 단계의 워크플로 기술    | 일반 `.rx` 모듈         | 현재 RX 검증기 외에 실행 호스트    |
| 라우트 또는 공유 상태 선언   | Gateway 또는 Store 파일 | 전송과 상태를 구현하는 호스트      |
| 에이전트로 애플리케이션 생성 | 에이전트 가이드         | 도구 체인, 런타임, 인수 기준       |

### 계산부터 시작하기

실행 가능한 첫 예제가 필요하다면 저장소의 ZX 예제를 빌드하고 실행하세요. 컴파일러와 Zig 통합을 함께 확인할 수 있습니다. [시작하기](/docs/getting-started)를 따라간 뒤, 예제 계산을 직접 정의한 타입의 입력과 출력으로 바꾸세요.

### 실제 경계에서 구성 추가하기

RX로 어떤 단위가 다른 어떤 단위를 호출하는지 표현하세요. 산술과 변환은 ZX에 둡니다. 워크플로 선언은 실행 호스트가 없어도 구조 검토에 유용하지만, 그 자체가 실행 가능한 서비스는 아닙니다.

### 호스트 계약 확립하기

네트워크나 상태 동작을 추가하기 전에 전송, 인증, 입력 디코딩, 메모리 수명, 상태 접근, 커밋 의미를 누가 제공하는지 정하세요. 현재 컴파일러는 서버나 데이터베이스를 제공하지 않습니다.

실행 가능한 ZX는 [Zig 호스트 통합](/docs/host-integration), RX 구조는 [모듈 구성](/docs/compose-modules)으로 이어가세요.
