첫 진단이 가리키는 소스 위치부터 읽으세요. 가장 먼저 나타난 잘못된 구문을 수정하면 같은 가정에서 비롯된 후속 오류도 사라지는 경우가 많습니다.

### 진단 형식

```text
path:line:column:code:message
```

코드는 실패 범주를 나타냅니다. 문제를 보고할 때 메시지와 소스 위치를 함께 보존하세요. 범주만으로는 대개 충분하지 않습니다.

| 코드                | 먼저 확인할 것                              |
| ------------------- | ------------------------------------------- |
| `lexical`, `syntax` | 토큰, 구분자, 지원 문법                     |
| `unsupported`       | 해당 구문이 ZX에 존재하는지                 |
| `contract`          | 파일 역할, Input/Output, 기본 함수 형태     |
| `name`, `naming`    | 선언, 범위, 명명 규칙                       |
| `type_mismatch`     | 명시적인 스칼라 너비와 구조화된 데이터 형태 |
| `return_path`       | 필요한 모든 경로에서 값을 반환하는지        |
| `spacing`           | 컴파일러 포매터가 기대하는 공백             |
| `ownership`         | 빌린 값 또는 이미 소비한 값                 |
| `module`            | 가져오기 경로, 파일 역할, 순환 의존성       |
| `capability`        | 호스트 등록과 접근 권한                     |

### 가져오기를 해석할 수 없을 때

파일이 존재하고 `.zx` 확장자가 명시되어 있으며 상대 경로가 가져오는 파일을 기준으로 하는지 확인하세요. `@/`는 컴파일러 프로세스의 작업 디렉터리를 확인하세요. 타입 가져오기는 타입 전용 파일을, 함수 가져오기는 실행 파일을 가리켜야 합니다.

### 리스트를 다시 사용할 수 없을 때

바인딩을 처음 소비한 연산을 찾으세요. 그 연산이 반환한 리스트를 이어서 사용하거나 독립적인 소유자가 둘 필요해지는 지점 전에 복제하세요. 소비된 값의 이름을 바꿔도 소유권은 복구되지 않습니다.

### 포맷 검사가 실패할 때

`zxc fmt file.zx`로 포맷된 출력을 확인하고, 파일을 교체하려면 `--write`를 사용하세요. `--check`는 파일이 다르면 종료 상태 1을 반환합니다. 이 포매터는 ZX가 지원하는 공백 규칙을 위한 것이며 범용 TypeScript 포매터가 아닙니다.

### XML은 검증되지만 애플리케이션이 실행되지 않을 때

현재 RX 패키지는 이미 구성된 AST와 모듈 그래프를 검증합니다. XML 파서, 표현식 평가기, 스케줄러, 자동 ZX 바인딩은 포함하지 않습니다. 선언을 실행 중인 서비스로 간주하고 디버깅하기 전에 빠진 계층을 제공할 호스트를 확인하세요.

### 재현 가능한 문제 보고

소스 리비전, Zig 버전, 명령과 작업 디렉터리, 관련된 최소 파일, 전체 진단, 예상 동작을 포함하세요. 생성된 Zig에서 실패했다면 생성 소스와 호스트 통합 경계도 포함하세요.
