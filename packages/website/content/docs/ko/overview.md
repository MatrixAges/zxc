zxc는 **RX로 비즈니스 구조를 표현**하고 **ZX로 원자적 로직을 작성**합니다. 데이터 흐름과 데이터 구성을 명확히 드러내어 비즈니스가 계속 성장해도 이해, 추적, 유지보수가 가능하도록 하는 것이 핵심 목적입니다.

zxc는 비즈니스 구조를 RX에, 원자적 로직을 ZX에 맡깁니다. 데이터의 출처, 거치는 계산, 목적지를 경계와 연결로 명시합니다. 컴파일러가 의존성을 검사하여 비즈니스가 성장해도 구조 제약이 유지되도록 합니다.

### 프랙털 확장

ZX 단위 하나는 경계가 명확한 계산 하나를 맡습니다. RX는 단위들을 비즈니스 모듈로, 모듈들을 더 큰 비즈니스 경계로 조합합니다. 세분화가 필요하면 내부를 다시 나눕니다. 모든 계층에서 단일 책임, 명시적 입출력, 단방향 의존성을 유지하는 것이 zxc의 프랙털 구성입니다.

“원자”는 책임과 계약이 명확한 단위이며 데이터베이스 원자 트랜잭션이나 가능한 가장 작은 조각을 뜻하지 않습니다. “프랙털”은 계층마다 같은 분해·조합 규칙을 적용한다는 뜻이며 순환 의존성이나 재귀 호출이 아닙니다. 연결은 데이터가 거치는 단위를, 입출력 타입은 경계의 데이터 형태를 보여줍니다. 비순환성은 의존성 방향을 제약하지만 모든 비즈니스 결합을 제거하지는 않습니다.

### AI 문맥

내장 의존성 분석은 파일, 호출, 타입 관계를 검사 가능한 사실로 만듭니다. 이 그래프를 AI에 직접 제공하여 관련 단위 탐색, 상류와 하류 추적, 변경 영향 파악, 필요한 문맥 조회를 돕고 모든 변경을 추적 가능하게 하는 것이 목표입니다.

토큰 사용과 인지 부담을 최소화하고, 명시적인 계약과 컴파일러 피드백을 통해 비 SOTA 모델도 SOTA 모델과 같은 코드 품질 기준을 충족하도록 돕고자 합니다.

### 원자 단위 최적화

경계가 명확한 ZX 단위는 계산 연산자처럼 분석하고 최적화할 수 있습니다. zxc의 정적 정보와 Zig의 컴파일 타임 기능은 인라이닝, 특수화, 추상화 비용 제거의 경로를 열어 명확한 비즈니스 표현과 고성능을 함께 추구하게 합니다.

현재 ZX는 Zig로 컴파일됩니다. Zig의 LLVM 백엔드를 선택하면 대상 플랫폼 최적화와 기계어 생성을 활용할 수 있습니다. 무비용 추상화는 생성 코드와 측정으로 확인할 목표이며, 모든 연산에 할당이나 런타임 비용이 없다는 뜻은 아닙니다.

장기적으로는 원자 단위의 형식 명세와 증명, 어셈블리 수준 분석과 생성, FPGA 같은 하드웨어 대상으로의 확장을 지향합니다. 형식 검증에는 전용 증명 도구가, FPGA에는 합성 흐름과 백엔드가 필요합니다. LLVM이 자동으로 제공하거나 zxc가 이미 구현한 기능은 아닙니다.

### 기능 범위

현재 구현과 실행 가능한 경로는 [기능과 한계](/docs/capabilities)를 참고하세요. 설계 목표를 이미 출시된 도구 인터페이스나 측정된 성능 결과로 간주하지 마세요.

### 실행 가능한 결과까지 따라가기

1. 계산, 구성, 호스트 기능 중 필요한 것에 따라 [통합 방식 선택](/docs/choose-integration)을 진행합니다.
2. [컴파일러를 빌드](/docs/getting-started)하고 기존 ZX 예제를 실행합니다.
3. 명시적인 입력과 출력으로 [타입이 있는 로직을 작성](/docs/write-logic)합니다.
4. 애플리케이션에 드러나는 워크플로 경계가 필요하면 [모듈을 구성](/docs/compose-modules)합니다.
5. 실제 호스트가 제공하는 기능을 기준으로 [결과물을 검증](/docs/validate-and-deliver)합니다.
