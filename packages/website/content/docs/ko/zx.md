### TypeScript 유사 구문을 선택한 이유

원자적 로직에는 계산, 조건, 데이터 변환이 필요합니다. 함수, 객체, 타입 표기, 표현식은 TypeScript 사용자에게 익숙합니다. 이 표면 구문을 활용하는 목적은 사람과 AI의 학습·읽기·생성 비용을 낮추고 비즈니스 규칙과 입출력 계약에 집중하도록 돕는 것입니다.

ZX는 문법과 의미론을 제한합니다. 명확한 숫자 너비, 검사 가능한 소유권, 통제된 기능 경계 덕분에 컴파일러가 정적 분석과 Zig 생성을 수행할 수 있습니다. 익숙한 표기와 제약된 실행 의미론을 결합하여 원자 단위 검증과 최적화의 기반을 만듭니다.

TypeScript 유사 구문은 완전한 호환성을 뜻하지 않습니다. ZX는 TypeScript 컴파일러나 JavaScript 런타임에 의존하지 않으며 임의의 TypeScript 코드나 npm 패키지를 사용할 수 있다고 가정하면 안 됩니다. 성능 가능성은 표면 구문이 아니라 정적 의미론과 컴파일 경로에서 나옵니다.

### 명시적인 입력과 출력

ZX는 TypeScript와 비슷한 언어이며 JavaScript는 아닙니다. 입력과 출력 타입을 선언하고 기본 함수를 내보내세요. 다음 최소 계산은 입력 금액을 그대로 반환합니다.

```typescript
export type Input = {
  amount: u64;
};

export type Output = {
  amount: u64;
};

export default function (in: Input): Output {
  return { amount: in.amount };
}
```

### 계산의 범위 제한

현재 컴파일러는 스칼라 값, 객체, 열거형, 선택적 값, 리스트, 튜플, 지역 바인딩, 분기, 파일 가져오기를 지원합니다. 컬렉션 연산에는 외부 값을 캡처하지 않는 `map`, `filter`, `reduce`가 있습니다.

임의의 클로저, 일반 반복문, JavaScript의 암시적 형 변환, 런타임 기능 가져오기를 지원한다고 가정하지 마세요. 숫자 타입의 의미는 명시적이며 JavaScript의 숫자 동작에 의존하면 안 됩니다.

### 소유권 명시하기

깊은 복사가 필요하면 `clone`을 사용하세요. Store 접근은 읽기와 쓰기 권한이 독립적인 선언된 핸들을 통해 제공됩니다. 수명, 영속성, 커밋 동작은 호스트 코드가 관리합니다.

설치된 도구 체인의 포매터와 진단을 사용하세요. 정확한 계약은 [컴파일러 참조](https://github.com/MatrixAges/zxc/blob/master/packages/compiler/README.md)에서 확인하세요.

### 공유 계약은 타입 전용 파일에 두기

실행 파일 두 개가 데이터 형태를 공유한다면 별도의 타입 전용 `.zx` 파일에서 해당 타입을 내보내세요. 실행 함수 가져오기와 공유 타입 가져오기를 구분하면 계산 내부의 입력 형태가 의도치 않게 공유 API가 되는 일을 막을 수 있습니다.

### 필요한 모든 경로에서 반환하기

출력이 void가 아니라면 가능한 모든 경로에서 값을 반환해야 합니다. 잘못된 비즈니스 조건에는 가드를 두고, 가드 뒤에서 결과를 명확히 반환하세요. 컴파일러의 `return_path` 진단은 선언된 출력과 제어 흐름이 맞지 않음을 뜻합니다.

### 독립적으로 추론할 수 있는 단위 작성

ZX 원자는 가격 계산, 자격 판단, 데이터 변환 같은 계산 하나에 명확한 입출력 계약을 부여합니다. RX가 이 단위들을 조합합니다. 여기서 원자성은 책임 경계를 의미하며 트랜잭션 보장이나 표현식마다 파일을 만들라는 요구가 아닙니다.

명확한 타입, 소유권, 부작용 경계는 지역 검증과 연산자 단위 최적화의 조건을 제공합니다. 현재 경로는 ZX → 타입이 있는 IR → Zig입니다. 인라이닝, 특수화, 추상화 비용 제거는 백엔드, 생성 코드, 측정으로 확인해야 합니다. 형식 증명과 FPGA에는 후속 도구 체인 작업이 필요하며 작은 단위만으로 실현되지는 않습니다.

### match 표현식

match 표현식에는 두 형태가 있습니다. `match { ... }`는 완전한 불리언 조건으로 결과를 선택하고 `match value { ... }`는 대상 값으로 선택합니다. `=>` 오른쪽은 결과이며 `_`는 기본 분기입니다.

```typescript
const shipping = match {
  discounted >= in.free_shipping_minimum => 0,
  _ => in.shipping_fee
};

const label = match status {
  "paid" => "ready",
  "pending" => "waiting",
  _ => "blocked"
};
```

조건은 소스 순서대로 확인하며 선택된 결과만 평가합니다. 값 모드의 대상은 한 번만 평가하고 void가 아닌 스칼라 또는 열거형이어야 합니다. 마지막에 유일한 `_` 분기가 필요하며 후행 쉼표를 허용합니다. 결과 타입은 일치해야 합니다. 논리곱에는 `&&`를 사용합니다. 범위, 구조 분해, 연쇄 비교는 지원하지 않습니다.
