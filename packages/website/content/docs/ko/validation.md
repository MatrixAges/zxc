### 애플리케이션 경계 검증

대상 애플리케이션에 문서화된 빌드, 검사, 실행 명령을 사용하세요. 변경된 모든 RX 및 ZX 파일, 전이 의존성, 실제 비즈니스 진입점을 확인하세요.

- 모든 모듈 참조가 실제 파일로 해석됩니다.
- 각 호출 경계에서 입력과 출력이 일치합니다.
- 의존성에 순환이 없습니다.
- 정상, 경계, 실패 동작이 비즈니스 계약과 일치합니다.
- 상태 소유권, 동시성, 재시도 동작이 명시적입니다.

### 증거를 정확히 보고하기

정적 분석, 컴파일, 호스트 실행, 비즈니스 검증을 구분하세요. 컴파일러 빌드 성공은 애플리케이션이 실행되었다는 증거가 아닙니다.

런타임이나 검사기를 사용할 수 없다면 그 한계를 밝히세요. 실행 명령을 만들어내거나 예상 출력을 실제 실행 결과로 대신하지 마세요.

### 간결한 보고서로 인계하기

변경된 동작과 파일별 책임, 실제로 실행한 명령과 결과, 해결되지 않은 요구사항을 적으세요. 실패를 숨기지 말고 통과 결과를 얻기 위해 필수 사례를 제거하지 마세요.

### 주장에 맞는 증거 제시

| 검사                  | 뒷받침하는 것                  | 입증하지 않는 것                 |
| --------------------- | ------------------------------ | -------------------------------- |
| `zxc fmt ... --check` | 소스가 포매터 출력과 일치      | 타입 안전성 또는 실행            |
| ZX 컴파일             | 파싱, 의미 검사, Zig 생성      | 호스트 통합 또는 비즈니스 정확성 |
| 호스트 빌드           | 생성 코드가 해당 빌드에 통합됨 | 모든 런타임 경로의 올바른 동작   |
| 호스트 실행           | 주어진 입력에서 관찰된 동작    | 실행하지 않은 경로의 동작        |
| RX 구조 검증          | 태그와 모듈 그래프 제약        | XML 로딩, 스케줄링, 상태 커밋    |
