### 애플리케이션 경계 검증하기

대상 애플리케이션에 문서화된 빌드, 검사, 실행 명령을 사용하세요. 변경된 모든 RX와 ZX 파일, 전이적 의존성, 실제 비즈니스 진입점을 확인하세요.

- 모든 모듈 참조가 실제 파일로 연결됩니다.
- 각 호출 경계에서 입출력이 일치합니다.
- 순환 의존성이 없습니다.
- 정상, 경계, 실패 시 동작이 비즈니스 계약에 맞습니다.
- 상태 소유권, 동시성, 재시도 동작이 명확합니다.

### 근거를 정확히 보고하기

정적 분석, 컴파일, 호스트 실행, 비즈니스 검증을 구분하세요. 컴파일러 빌드 성공은 애플리케이션이 실행되었다는 증거가 아닙니다.

런타임이나 검사기를 사용할 수 없다면 그 제한을 명시하세요. 실행 명령을 지어내거나 예상 출력을 실제 실행 결과로 대신하지 마세요.

### 간결하게 전달하기

변경한 동작과 파일별 책임, 실제 실행한 명령과 결과, 미해결 요구 사항을 나열하세요. 실패를 드러내고, 통과시키기 위해 필요한 사례를 삭제하지 마세요.
