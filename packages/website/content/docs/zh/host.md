生成的 Zig 运行在提供运行时支持并管理内存生命周期的宿主中。要匹配已安装的 Zig 和编译器修订版本，最好从仓库中可运行的示例开始。

### 构建参考集成

```sh
zig build
zig build zx-example
```

该示例会编译 ZX 并执行生成的 Zig。适配时请结合仓库构建配置阅读[示例目录](https://github.com/MatrixAges/zxc/tree/master/packages/compiler/examples)。

### 接入生成模块

1. 编译入口 `.zx` 文件及其导入。
2. 将生成的 Zig 模块加入宿主构建。
3. 向该模块提供编译器的 `zx_runtime` 模块。
4. 创建生命周期覆盖执行与结果使用过程的 arena。
5. 将外部输入解码为生成的 `Input` 形状。
6. 调用生成的 `execute` 入口，处理结果或失败。

纯计算生成模块接收 arena 和输入；带状态能力编译的模块还会接收执行上下文。这些签名属于生成结果，请查看实际输出，确认所用修订版本的准确类型。

### 保持结果有效

列表和字符串可能依赖执行 arena。释放内存前，先使用、序列化或显式复制结果。arena 销毁后，不要继续保留指向它的引用。

### 注册宿主能力

通过编译器支持上下文的 API 提供 Store 句柄与外部导入。注册项是程序权限边界的一部分，宿主负责在执行时提供兼容实现。

对于有状态逻辑，开放给并发请求前，应先定义版本检查与原子提交行为。对于外部函数，也应在同一边界明确失败与所有权行为。

### 验证完整路径

编译说明源码通过了编译器检查；构建生成的 Zig 说明它与该宿主构建兼容；执行代表性输入则验证这些输入下的行为。任何一个步骤单独完成，都不能证明 RX 工作流已经拥有执行运行时。

继续阅读[验证与交付](/docs/validate-and-deliver)。
