### 当前仓库已实现

- ZX 解析、类型与所有权检查、IR 校验和 Zig 生成。
- 多文件导入及导入无环检查。
- RX 标签定义、按文件路径注册模块和依赖环检测。
- 编译器边界上的 Store 访问契约，提交行为由宿主提供。

### 尚非生产运行时

编译器不包含完整 RX XML 加载器与生产级调度运行时。数据库支持尚未实现。Store 的版本检查、锁、持久化与跨对象原子发布仍由宿主负责。

不要把 Gateway 或 Store 声明当作 HTTP 服务已经运行或持久化数据库已经可用的证据。

### 版本边界

仓库包版本为 **0.0.1**，ZX 语言契约为 **0.1.0**，IR 为实验性的 **版本 2**。IR 是 Zig 内存 API，不是稳定的序列化交换格式。

这些文档反映当前源码，不代表兼容性承诺。使用设计文档中的功能前，应核对所用版本与宿主契约。

### 设计目标与后续路线

- **AI 图谱协作**：已有依赖分析与无环校验；将关系直接暴露给 AI，用于上下文选择、追踪和影响分析，是后续接口方向。当前没有承诺稳定的图谱查询或导出协议。
- **模型质量与 token 效率**：目标是降低心智与上下文负担，让非 SOTA 模型达到与 SOTA 模型相同的代码质量标准；尚无这里可引用的对照评测结论。
- **零成本抽象**：原子逻辑、静态契约和 Zig 编译能力提供优化基础；不是所有抽象都已消除开销，当前部分集合操作仍需分配。
- **LLVM 与汇编**：当前 zxc 后端生成 Zig。采用 Zig 的 LLVM 后端时，可进一步利用目标优化及机器代码生成；这不等同于 zxc 已提供直接 LLVM 后端或独立汇编命令。
- **形式化证明与 FPGA**：属于长期探索。前者需要形式化语义、规格和证明工具，后者需要可综合的计算子集、硬件约束与专用综合后端；LLVM 支持本身不构成这两项能力的交付。
