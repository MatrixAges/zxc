### 编写前先阅读

读取 [llms.txt](/llms.txt) 获取章节索引，或读取 [llms-full.txt](/llms-full.txt) 获取完整文档。每个章节都有原始 Markdown 入口，均不需要客户端 JavaScript。

应用开发约定也可参考仓库中的 [Agent 指南](https://github.com/MatrixAges/zxc/tree/master/packages/skills)。这些是 Markdown 指导文档，不是已经发布的可执行软件包。

### 任务契约

提供业务目标、现有应用文件、预期输入输出、失败处理方式和使用的 zxc 版本。可以从下面的提示词开始：

```text
请使用 zxc 完成本应用。

目标：<业务行为>
现有文件：<应用上下文>
输入与预期输出：<示例>
失败处理：<要求>
工具链与宿主运行时：<可用能力>

先阅读当前 zxc 文档。
分离 RX 编排与 ZX 业务逻辑。
以文件路径作为模块身份，保持依赖无环。
只使用当前环境支持的能力。
报告行为变更、实际验证结果和剩余问题。
```

### 交付契约

提供应用文件、各文件职责、验证结果与未解决的限制。不要把一段可阅读的 XML 示例描述成已经执行的应用。

### 围绕结构缩小上下文

先定位业务所在的 RX 模块，再沿调用和导入关系找到相关 ZX 单元。明确它的输入输出、调用方、状态权限与下游依赖，再提交局部改动。若契约变化，继续检查受影响的使用方；若契约不变，仍需验证新行为是否满足调用方的假设。

依赖图谱对接 AI 的目标，是按关系提供必要上下文，减少全库重读、token 消耗与隐含猜测。当前可读取源文件并使用编译器分析与诊断，尚不能假定有稳定的图谱导出命令或现成 AI 查询接口。非 SOTA 与 SOTA 模型应遵循同一套契约和验收标准；达到同等质量是设计目标，需要通过实际任务评测验证。
