选择足以交付应用的最小边界。ZX 计算、RX 组合与宿主运行时解决的是不同问题。

### 选择起点

| 任务               | 从哪里开始            | 需要什么                        |
| ------------------ | --------------------- | ------------------------------- |
| 校验并编译业务计算 | 一个 `.zx` 文件       | 编译器和明确的输入输出类型      |
| 执行已编译逻辑     | 生成的 Zig            | `zx_runtime`、arena 和 Zig 宿主 |
| 描述多步工作流     | 普通 `.rx` 模块       | 当前 RX 校验器之外的执行宿主    |
| 声明路由或共享状态 | Gateway 或 Store 文件 | 宿主提供的传输与状态实现        |
| 让 Agent 生成应用  | Agent 指南            | 工具链、运行时和验收标准        |

### 从计算开始

要得到第一个可运行示例，可以构建并执行仓库中的 ZX 示例，同时验证编译器与 Zig 集成。按照[快速开始](/docs/getting-started)操作，再用自己的带类型输入输出替换示例计算。

### 在真实边界上引入组合

用 RX 表达哪些单元会调用哪些单元，把算术与数据转换留在 ZX。即使还没有执行宿主，工作流声明也能帮助审阅结构，但声明本身并不是可执行服务。

### 明确宿主契约

引入网络或状态行为前，先明确谁提供传输、身份验证、输入解码、内存生命周期、状态访问和提交语义。当前编译器不提供服务器或数据库。

可执行 ZX 的集成方式见 [Zig 宿主集成](/docs/host-integration)，RX 结构见[组合模块](/docs/compose-modules)。
