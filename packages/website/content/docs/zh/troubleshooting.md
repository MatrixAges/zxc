从报告的源码位置开始阅读第一条诊断。修复最早出现的无效结构，往往也能消除同一错误假设造成的后续诊断。

### 诊断格式

```text
path:line:column:code:message
```

代码表示失败类别。报告问题时，请保留完整消息与源码位置；仅有类别通常不足以定位问题。

| 代码                | 优先检查                              |
| ------------------- | ------------------------------------- |
| `lexical`、`syntax` | 标记、分隔符和受支持的语法            |
| `unsupported`       | ZX 是否支持该结构                     |
| `contract`          | 文件角色、Input/Output 与默认函数形状 |
| `name`、`naming`    | 声明、作用域和命名约定                |
| `type_mismatch`     | 显式标量位宽与结构化数据形状          |
| `return_path`       | 每条必要路径是否都返回值              |
| `spacing`           | 编译器格式化器要求的空白              |
| `ownership`         | 借用值或已经消耗的值                  |
| `module`            | 导入路径、文件角色和依赖环            |
| `capability`        | 宿主注册与访问权限                    |

### 导入无法解析

确认文件存在，显式写出 `.zx` 扩展名，相对路径以导入文件为起点。使用 `@/` 时，检查编译器进程的工作目录。类型导入必须指向纯类型文件，函数导入必须指向可执行文件。

### 列表不能再次使用

找到第一个消耗该绑定的操作，继续使用它返回的列表，或在需要两个独立所有者之前克隆。给已消耗值换个名字，并不能恢复其所有权。

### 格式检查失败

运行 `zxc fmt file.zx` 查看格式化输出，确认需要覆盖文件时再使用 `--write`。文件存在格式差异时，`--check` 以状态码 1 退出。格式化器主要处理 ZX 支持的空白规则，不是通用 TypeScript 格式化器。

### XML 校验通过，应用却无法运行

当前 RX 包校验的是已构造的 AST 及其模块图，不包含 XML 解析器、表达式求值器、调度器或自动 ZX 绑定。在把声明当成运行中的服务进行调试之前，先找到提供这些层次的宿主。

### 报告可复现的问题

提供源码修订版本、Zig 版本、命令与工作目录、最小相关文件、完整诊断和预期行为。生成的 Zig 出错时，还应提供生成源码和宿主集成边界。
