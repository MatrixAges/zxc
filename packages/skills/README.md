# 使用 zxc 开发应用

帮助 AI 根据业务需求编写 RX 流程和 ZX 业务逻辑。使用时提供业务需求、现有应用文件、输入输出示例，以及项目使用的 zxc 版本。

## 阅读顺序

1. [RX 编码约定](rx/编码约定.md)：组织业务文件、调用模块、传递数据。
2. [消除循环依赖](rx/消除循环依赖.md)：处理模块之间需要双向协作的场景。
3. [应用验证与交付](rx/验证与交付.md)：确认业务结果、失败处理和交付范围。

## 基本原则

- RX 描述流程和模块协作，ZX 承载具体业务计算。
- 一个模块承担清晰的业务职责，以文件路径作为唯一身份。
- 父模块编排子模块，子模块不反向调用父模块。
- 模块之间通过明确的输入输出交换数据。
- 禁止循环依赖；需要双向协作时，重新划分职责和调用顺序。
- 只使用所用 zxc 版本公开支持的语法和能力。

## 向 AI 描述任务

可以直接使用下面的任务模板：

```text
请使用 zxc 完成以下应用需求：

业务目标：……
现有应用文件：……
输入与期望输出：……
失败时应如何处理：……

先阅读 RX 编码约定，明确需要新增或修改的业务模块。
如果模块需要双向协作，采用消除循环依赖指南中的方案。
遵循本应用已有的文件组织、测试和运行方式。
交付时说明修改了哪些业务行为、验证结果及未完成事项。
```

## 完成任务时提供什么

提供应用文件、必要的使用示例、实际验证结果及尚未完成的需求。说明模块如何协作，确保使用者能理解从输入到最终输出的业务过程。
