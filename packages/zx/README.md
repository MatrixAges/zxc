# zx

ZX 的独立语言数据契约包，面向编译器、编辑器和后端实现者。不依赖 compiler、lint 或 genz。

## Intent：最终目标

共享源码结构与目标无关的语义 IR，使后端不必重新执行 ZX 名称解析和类型推导。

## Data：公开契约

- `source`：UTF-8 字节范围和行列转换；范围左闭右开，行列从 1 开始，列按字节计数。
- `syntax`：Token、独立注释范围、关键字及二元运算符。
- `ast`：带源码范围的语法树，标识符尚未绑定。
- `ir`：有类型的高层 IR；引用使用 `SymbolId`，表达式使用 `ExprId`，类型使用 `TypeId`。
- `Diagnostic`、`Reporter`：规则编号、范围和静态诊断文本。

当前语言契约版本为 `0.1.0`，IR 版本为 `2`。这是一份实验性 Zig 内存 API，不是稳定的跨语言序列化格式。

## Edges：边界与限制

当前 IR 表达多文件有类型计算：固定数值、对象、枚举、可选值、列表、元组、局部绑定、分支、无捕获回调、消费操作、函数调用和受授权 Store slot。它不携带 Zig 代码片段，不实现数据库或宿主持久化。

对未来完整语言的描述见根目录设计文档；设计文档列出某个特性不代表本版本已经实现。

数据结构不拥有内存。compiler 的 ParseResult/AnalysisResult 管理各自 arena；自行创建 IR 的调用方负责保存全部切片。各 ID 只在当前 Program 中有效，不是跨编译稳定标识。

## Answer：后端接入与成功标准

完整 IR 约定见 [IR 契约](IR契约.md)。第三方通过 compiler 的 `frontend` 模块解析和分析，或按契约构造 IR 后调用 `validateIr`。后端只能消费通过校验的数据；校验不检查任意宿主指针是否可读，不能把未经解码的外部字节直接强转为 Zig struct。

成功标准是同一 IR 中所有值具有确定类型，名称引用可由 SymbolId 定位，而不依赖 Zig 推断。
