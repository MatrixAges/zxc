# ZX 迁移边界

以目标 zxc 版本的公开文档和实际编译结果为准。迁移开始时将版本、工具路径、源库提交和适用平台写进 RULEBOOK。

## API 与数据模型

ZX 输入输出是有明确类型的值。先定义公开数据形状和错误语义，再翻译实现。不得用 JSON 字符串绕过结构类型，也不能通过调用原库完成应当迁移的核心逻辑。

逐项核对整数位宽、溢出、浮点精度/NaN/负零、可空与缺失、枚举身份、字符串编码、列表所有权、别名、对象复制和错误路径。源语言隐含规则应转成明确的迁移决定，不能从同名操作推断等价。

引用公开文档中的能力，先编译代表性片段核实。不能假设支持任意递归、反射、动态对象形状、异常机制或运行时插件。需要新能力时记录缺口和用户选择；不在库迁移任务中悄悄扩展编译器。

## 模块与所有权

按职责形成无环依赖。源语言的互相导入可能需要调整单元边界或提取共享类型；不能删除一条依赖来让图通过。

`std:` 使用目标 zxc 标准模块；`zig:`/`c:` 表达原生集成；无前缀包导入依赖 pkg.yaml。明确区分迁移代码和保留的外部依赖，并保留许可与来源信息。

借用输入和拥有值不同。遇到原地修改、共享别名、逃逸引用或闭包捕获，先核对公开所有权契约，不能通过无条件复制掩盖语义与性能差异。需要返回多个结果时设计明确的结果类型，保持调用方能理解的消费关系。

## 构建与消费

清单使用 pkg.yaml。使用所用版本实际支持的 `zxc build ... --mode lib` 构建；独立消费验证应包含 ZX 调用方，需要 Zig 消费时也包含 Zig 调用方。搬迁后验证产物，不依赖源仓库的绝对路径和偶然缓存。

原生资源、头文件和系统库是部署契约的一部分。包装 Zig/C 入口不等于把算法迁移到 ZX；如果用户选择保留原生依赖，在 API 对照和交付说明中单独标明。

## 行为判定

传输适配器只负责 JSON/进程协议等边界转换，不实现被迁移的算法。对浮点特殊值使用显式位模式或标记协议；不能把 NaN 转为 null。JSON 工具不会容忍非标准数值、重复键或整数精度丢失。

默认按输出、错误输出与退出码判定。文件、网络、状态和时间相关行为需要适配器将可观察结果纳入已有判定协议；超出默认工具覆盖的部分应另附真实证据。性能目标需要独立测量，功能一致不证明性能一致。
