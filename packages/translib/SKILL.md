# lib转换

交付可独立消费的 ZX 库及可复核的行为证据。翻译由 AI 完成，随附脚本确定工作顺序、运行命令和核对证据；它不是通用自动转译器。

## 开始前

确认源库版本、许可、公开 API、目标 zxc 版本和需要保留的行为范围。先读取 [ZX 边界](references/ZX边界.md)，区分直接迁移、需改变 API 的设计和当前无法表达的能力。原生 Zig/C 包装可以作为用户选择的集成方案，但不能计作 ZX 翻译完成。

读取 [流程与证据](references/流程与证据.md)，建立迁移清单、RULEBOOK 和原实现可执行判定。优先复用现有测试输入；没有判定依据时，记录缺口并澄清验收要求，不用自编译成功代替行为验证。

## 执行流程

1. **映射与规则。** 用源语言解析器、编译器或现有依赖工具提取真实依赖；按 API/模块划分迁移单元，输入清单。脚本只验证声明图，不推断任意源语言依赖。把会产生不同合理答案的语义选择写进 RULEBOOK，列出依据和未决项。对 ZX 无法表示的循环重新划分职责，不截断依赖。
2. **试迁移。** 选择能暴露主要语义差异的代表性单元，走完整翻译、审查、构建和行为对照流程。修订规则后重新获取证据，再扩大范围。小库可将全部单元作为试迁移，不引入无收益的多轮协调。
3. **翻译与审查。** 每个单元完成后，由两个独立审查上下文检查公开语义、所有权、边界及依赖。给审查者源码、规则、目标和当前摘要，不给实现者的自评结论。修复确证问题；争议回到规则和源实现证据。代码变化后重新审查，不能把旧审查盖到新摘要上。
4. **集中构建。** 指定唯一构建负责人调用 `build`，按 repair_queue.json 分配修复。修复者提交修改和依据，负责人重新构建。编译失败必须继续显示失败；没有识别到定位信息的错误仍留在全局队列。
5. **最小端到端。** `smoke` 运行已有最小真实消费路径。库需要验证导出、导入和调用，不能只运行 `--help`。
6. **行为对照。** `parity` 对每个已有输入运行原实现和迁移实现。用适配层统一传输格式，保留原语义；特殊浮点、异常、资源及副作用需要显式判定协议。最后运行 `check`，并审阅覆盖范围和人工审查证据。

分工不自动授权启动其他 agent。按当前会话授权组织独立审查；资源不足时保留未审查状态，不让同一上下文冒充两名审查者。允许程序化步骤持续复用已有证据，文件变化后自动失效。

## 程序化入口

Bun 1.3.10+，使用 TypeScript 与内置 API。将本技能路径替换为实际位置：

```sh
bun <skill>/scripts/translib.ts 迁移.json status
bun <skill>/scripts/translib.ts 迁移.json review 单元ID 审查者ID 审查.json
bun <skill>/scripts/translib.ts 迁移.json build
bun <skill>/scripts/translib.ts 迁移.json smoke
bun <skill>/scripts/translib.ts 迁移.json parity
bun <skill>/scripts/translib.ts 迁移.json check
```

`status` 给出拓扑顺序、待产出/待审查单元和当前证据；`check` 只有在全部单元双审查及 build/smoke/parity 均有效时返回 0。具体格式、失败处理和证据边界见 [流程与证据](references/流程与证据.md)。

## 交付

提供 ZX 源码、pkg.yaml、公开 API 对照、规则和迁移差异、实际构建与消费方式、原实现/迁移实现的判定结果及覆盖限制。明确未迁移的 API 和不能证明的行为；不得把一组通过的样例推广成整个库等价。

大规模迁移前按“单元数 × 单元翻译/审查/修复成本”估算预算。参照 [Anthropic 迁移流程](https://github.com/anthropics/code-migration-kit-with-claude-code/tree/cf91c9d5068d9aaf95a36164169f08c3e636c909)的分阶段原则；本技能没有安装上游权限配置或复制其完成判定脚本。
