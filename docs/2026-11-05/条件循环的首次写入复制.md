# 条件循环的首次写入复制

## Intent

循环尚未写入列表时保持原视图，首次真正写入才建立私有容量。继续自举的同时
补齐通用物理许可消费，不恢复此前不安全的全量skip-renew方案。

## Data

f0da0dfb。branch夹具入轮但不写入时仍因提前renew改变指针；已有plain/shared/
exclusive描述符与Source transfer裁剪。ListUpdate的静态in_place分支仍会跳过
实际storage检查，plain复制又不建立header，因此不能直接删除renew。

## Edges

Source证明整循环消费者安全，遍历condition/body全部子节点及Scope绑定值。
首次只接入普通selected_state私有值布局；未知调用、任务、并行、嵌套循环、
其他集合变更保持原eager路径。不是禁止这些语言能力，只是不延迟其准备。
只延迟经Source路径检查确认为私有值布局内selected列表的renewal；其余照旧。

受保护区域显式安装/恢复，不复用只在deep开启的iteration_value。ListUpdate
仍先ownership.clip，再检查真实exclusive；不持有许可时reserve(false)建立
header并复制，结果携带exclusive。共享快照不可写，错误与短路次序保持。
不新增专用运行库、语义桥或测试，不修改指针/容量断言。

## Answer

RX连接整循环证明与路径选择，ZX提供原子遍历和路径判断；Native仅借用IR、
消费选择结果并构造普通Zig AST。现有branch、快照、跨调用和Source自编译共同
验收，缓存改动做新旧/冷热及恢复对照，性能只测实际受影响路径。

```mermaid
flowchart LR
    I[IR与布局事实] --> E[Source整循环消费证明]
    E --> P[Source逐renewal路径选择]
    P --> L[生成受保护循环]
    L --> W[首次写入检查exclusive]
    W --> C[必要时建立私有header]
```

```mermaid
flowchart LR
    B[借用初始视图] --> Q[循环条件与分支]
    Q -->|未写入| B
    Q -->|写入| X[裁剪并检查实际许可]
    X -->|exclusive| M[原地写]
    X -->|plain/shared| A[分配私有header并复制]
    A --> M
```

## 实现与验收

新增iteration/deferred的RX/ZX模块。eligible通过core.child覆盖全部Scope绑定和
对象求值列表，allowed显式白名单；Call、ListOperation、Transform、Iteration、
Task、Capture、Parallel及Store读取均不进入延迟路径。path逐条检查私有值布局
祖先和selected列表叶。未知场景保持原路径，不改变语言的接受范围。

Native适配只借用IR、布局布尔列和原renewal路径，Source返回逐路径选择；Native
收集/消费同一owner和value过滤后的原顺序。Lower受保护区域在fields早返回后
安装，condition/body生成后立即恢复，错误也由defer恢复。ListUpdate保留原
clip、bounds、RHS顺序，检查实际exclusive后才复用；新复制路径建立header并
返回exclusive，而非plain dupe。没有打开普通ABI调用的隐式许可。

初次编译的const列指针不匹配已修为只读Program视图。首轮既有循环的两个无写入
指针失败消除，留下四个原短长计量相等失败；它们与前一项已证实的Arena backing
resize计量问题同形。iterate_buffer现有计数器同样禁止backing resize/remap，
相等/指针/容量预算均未修改。最终iterate-buffer+aggregate-loop 169/169步骤、
66/66当次运行检查通过（aggregate结果按已完成范围复用），涵盖无写入、首次
延迟写入、旧快照及OOM。代码没有回到先前被否定的skip-renew原型。

cached-ownership、loop-call-origins、iterate-calls、immutable-list补验合计
258/258步骤、879/879检查通过。未新增用例，未删除失败模式或降低预算。

## 自我复核与后续

这项能力通过Source证明安全消费者，再由结构化AST生成首次写入复制；没有
依靠文件名、用户用例或固定count判定。新增自有判断在RX/ZX中，Native仅做
表示借用、上下文管理及AST构造；生成路径自身仍是待迁移内容，不宣称完整自举。

证明范围是当前白名单，跨helper/其他集合消费者延迟许可仍需继续完善。原有
fallback和其正确性保留，不把保守资格当最终语言限制。reverse容量、独立Store
semantic lint及完整回归其余未解决项也不能用本轮通过代替。继续按完整职责迁移
全局调度、缓存与代码生成，同时保持不可变性、zero runtime和累计性能门禁。
