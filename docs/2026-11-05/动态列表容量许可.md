# 动态列表容量许可

## Intent

补齐跨helper的私有列表容量传递，保留输入不可变、旧快照与错误路径。先修复
完整的pop缩回职责，再根据证据处理其他未通过的容量路径，继续推进自举。

## Data

当前debd84a0。冻结补验的helper_pop两条路径在8192轮分配约36.5MB，原预算
约1MB。pop只切片并把storage降为shared；header.committed仍257，切片长度
变256，后续reserve不能复用frontier，每轮重新分配512槽。静态flags.retract
要求headered且unique，跨调用只有动态exclusive时未进入缩回路径。

state_value/ownership.clip已按transfer许可裁剪输入；plain/shared都不能作为
新增缩回许可。elements.read对连续对象行先按值绑定，row_value的origin为空，
不把返回元素指向即将复用的数组槽；普通对象元素本来存独立指针。

## Edges

- 只使用裁剪后source_value的真实exclusive，不能仅看headered。
- 保留原静态retract路径；不升级shared/plain，也不跳过入轮renew。
- 非空pop才缩回，空pop保持原值；结果保留已有exclusive，不凭空授予权限。
- 继续由结构化AST/printer生成普通Zig，复用既有zxRetract；不增加运行库。
- 不新增用例，不改容量、身份、输入保存或OOM断言；生成输入冻结后集中验收。
- 其他loop_write/borrowed/two_buffers容量失败及累计CPU差距仍是未完成项。

## Answer

修改pop生成路径，贯通动态缩回条件与结果许可。用既有NativeRef transfers、
不可变集合、聚合循环/快照检查验证；随后验证当前Source生成路径及受影响性能。
每个完成职责提交并推送，不能凭helper_pop单例通过宣称全部容量门禁已完成。

```mermaid
flowchart LR
    P[Source transfer事实] --> C[生成前裁剪]
    C --> D[实际storage]
    D --> E[exclusive且非空]
    E --> R[既有结构化zxRetract]
    R --> O[缩短视图并保留exclusive]
```

```mermaid
flowchart LR
    I[已裁剪列表] --> T[检查非空与许可]
    T -->|允许| H[committed缩至新长度]
    T -->|共享或普通| S[仅返回切片]
    H --> N[后续push复用frontier]
    S --> A[必要时分配复制]
```

## 实现与验证

pop读取qualified source的exclusive；新增缩回仅在该许可且非空时执行，原静态
retract分支保持。缩短视图使用proven继承原许可，不把shared升级。没有改变
入轮renew、其他集合操作或运行时表示。生成指纹v54升v55，避免读取旧生成形态。
连续对象行的按值绑定与空origin路径经只读复核，无指向复用槽的返回元素。

既有NativeRef transfers、immutable-list、aggregate-loop合计127/127步骤、
606/606 Zig检查通过；NativeRef transfers的8次Node执行也全部通过，保留其
独立报告口径。原helper_pop source长8192轮约36.5MB降至6534B，短4轮亦6534B；
library降至6240B，短长相同。长度8193的64轮分别196998B/196704B，均低于
原预算。原值、身份、外部输入、无resize和OOM断言未修改。

补验cached-ownership、product-transfer、value-return合计210/210步骤、
313/313检查通过，覆盖重复别名、保留观察者、产品状态及返回值。没有新增用例。

Source当前116入口生成两代2051文件完全相同，仅排除工具身份.zxc-inputs。
旧新形态文件集合不变，变化103个Zig文件均含retract，另有.zxc-files内容摘要。
这是预期生成形态变化，不要求新旧文本相同；行为由上述既有检查核对。

缓存证据使用/tmp复制的相同Source树，未修改正在验收的正式源码：先用旧v54
工具填充共享缓存，新v55工具1970项全部重生成，与冷生成2051产物完全相同。
随后将既有reads/unchanged的函数体合法改成return false（改变算法语义和依赖
签名，不运行该变体的编译器）；热缓存4项生成、1965复用，冷生成1969项，
两者2050产物完全相同。恢复原文件后0生成、1970复用，与原冷生成2051产物
全部相同。额外文件是CLI适配、类型和元数据，不把function files数当总产物数。

所有构建结束、确认无活动Zig编译后，三组交错当前完整Source冷生成：
CPU before5.07/4.98/5.04s，after5.00/5.00/5.00s，中位5.04→5.00s；
wall1154.69→1148.58ms，MaxRSS660176896→648380416B。CPU样本重叠，RSS
也有重叠，不宣称稳定整体提速或整体分配减少；本路径未见可辨别新增CPU成本。
六次计时分别与各自版本的2051固定点产物完全相同。helper_pop的容量改善则由
原计数器和原预算直接证明，不用RSS代替分配量。

原始证据位于/tmp/zxc-function-levels：dynamic-pop-checks.log、
dynamic-pop-alias-checks.log、dynamic-pop-fixedpoint-comparison.json、
