# 并行发射流程自举

## Intent：最终目标

迁移 RX Parallel 父级完整 AST 构造：共享 allocator、worker 初始化、线程启动、
defer join、内层作用域及结果绑定。保留参数求值、命名、错误和线程汇合语义。

## Data：可用证据

起点 `c1eb7d7a`。worker 类型及同步 allocator 已迁 Source。原父级先构造所有
输入和 worker，再进入 spawn/join 作用域，退出后依次读取结果。现有通用 selected
AST 导入可拆分全局子语句与交还调用者的外层语句；scope 材料化尚需补齐。

## Edges：边界与限制

- Native 保留已有参数表达式 lowering 与 worker 类型服务，按原顺序物化句柄。
- 命名顺序为 shared→每项 type/input/worker→参数/worker 类型→thread；参数
  lowering 自身可能消耗 fresh，不得提前批量生成名称。
- 所有参数 lowering 后才读取 used/names；不提前冻结符号是否使用。
- spawn 使用当前 capture，读取结果仍为无条件 try_value；scope 退出前执行
  所有已注册 join，后续 spawn 失败时也须等待已启动线程。
- 内层语句先导入全局，外层仅材料化交还调用者，不重复入表；不新增用例。

## Answer：交付格式与成功标准

```mermaid
flowchart LR
    Services[按原顺序物化参数与 worker] --> Spawn[Source spawn 与 defer join]
    Spawn --> Workers[Source allocator 与 worker 组装]
    Workers --> Scope[Source 内层作用域]
    Scope --> Results[Source 依次绑定结果]
    Results --> Import[分离导入与材料化]
```

```mermaid
flowchart LR
    Inputs[运行时先求值全部输入] --> Spawn[作用域内依次 spawn]
    Spawn --> Joined[退出作用域执行 defer join]
    Spawn --> Failure[spawn 失败]
    Failure --> Joined
    Joined --> Read[正常路径依次 try 结果]
```

保持前后产物/memo、自编译不动点、直接及库回归和固定累计性能标准后统一提交
推送。明确参数 lowering 与 AST 存储等过渡依赖，不将本阶段称为整体自举完成。

## 实现与阶段证据

`analysis/parallel/emit/build.rx` 连接子语句构造、共享 allocator、worker 初始化、
scope 和结果处理。构造顺序先建立内层语句以保证全局范围连续；运行时顺序仍由
外层语句列表明确表示为初始化→scope(spawn/defer join)→结果读取。

命名规则和 allocator 别名也由 Source 提供。Native 适配器只按原位置调用已有
参数/worker 服务，收集暂存记录，并在 Source 返回后导入 AST。记录和引用数组
使用短期工作区，名称由 Lower allocator 持有；label 使用值返回以避免额外结果
对象持久化。所有 callbacks 完成后才读取最终 used/names 并取得 AST 基址。

scope 的通用语句材料化已补齐。内层前缀使用 selected 导入，外层后缀只材料化，
没有复制到全局表两次。selected 原语会拥有型复制内层文本，安全但有成本；
本阶段不在缺少热点证据时扩展该原语的所有权协议。

引导和正式 P16 ReleaseSmall 构建均 21/21，二进制 SHA-256 相同：
`4d310bfba51de88e5644ea4debc2d2b3ce39b47320797e865663ee8350f4fe26`。
当前源码 main / collections / growth 的 3073 / 65 / 357 文件，旧版对引导版
仅 `.zxc-inputs` 不同，引导对正式版全部一致。三组 memo 分别为
10727/3043/2522/0、67/45/27/27、1126/311/266/0，逐键逐内容一致。

### 受影响生成路径

复用 compile-rx-parallel 的全部二十二个既有场景。正式工具确认
generated_analysis=true；基线副本只把父级发射选择器切回原始 seed，worker、
allocator、其他 Source 模块及工具链相同。每组 44 文件，八组前后逐字节一致，
命名、作用域、spawn/join 和结果的实际生成代码保持一致。

交替八组、排除首组，高精度计量的中位数如下：

| 指标             |     原实现 | Source 实现 |        差值 |
| ---------------- | ---------: | ----------: | ----------: |
| 二十二次调用 CPU | 0.120821 s |  0.120612 s | −0.000209 s |
| 二十二次调用耗时 | 0.107475 s |  0.107524 s | +0.000049 s |
| 最大 RSS         | 12533760 B |  12599296 B |    +65536 B |

CPU 使用高精度子进程资源累计差并包含 time 包装器，耗时包含启动，RSS 为最大
子进程而非进程树。没有同时运行构建；微小差值不证明稳定收益或显著退化。

### 自我复核与剩余边界

父级全部 AST 分支和组装已迁 Source，Native 不再解释 Source 操作码重放旧逻辑。
结果保留无条件 try，spawn 保留 capture，并在任何结果读取前退出 join 作用域。
内层仅入表一次，外层由调用者按既有流程接管。输入实际数据没有为迁移而复制。

Native 仍保存 Lower 状态，按原位置准备参数表达式/worker 服务及使用标记；这些
编译期服务调度与 AST 存储是明确的过渡依赖。线程平台 API 继续使用 std.Thread。
本阶段没有迁移 Task 调度或整个编译器控制流程，最终仍需传递依赖审计及约定的
三代自编译。没有以局部产物一致或当前容差重定义完整自举标准。
