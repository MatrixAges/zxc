# 源码入口重导出缓存

## Intent

纯 ZX 入口经 `export { default }` 转发时，可以写入并复用持久语义缓存。验证覆盖目录入口、多个公开成员、递归及依赖编辑。

## Data

最小复现是只含 `export { default } from "./identity"` 的入口。此前启用缓存时，首次生成报工件提取失败。入口采用目标函数体后，发布流程误把目标函数视为入口刚追加的临时行，截掉函数表末行。若目录同时转发其他函数，被截掉的行也可能属于另一个公开成员。

保留完整函数表后，首次写缓存成功，第二次仍重分析转发模块。缓存工件的签名表包含普通导入和重导出所引用的函数。恢复原先只为普通导入重映射编号，重导出专用签名没有当前函数编号，签名校验因此拒绝该工件。

```mermaid
flowchart LR
    Entry[入口原始声明] --> Publish[RX 决定可见函数表前缀]
    Publish --> Artifact[从有效函数记录提取工件]
    Artifact --> Restore[恢复导入和重导出绑定]
    Restore --> Validate[共用编号映射和签名校验]
    Validate --> Reuse[复用模块]
```

## Edges

- 入口发布使用原始源码是否仅含声明这一事实，判定入口是否拥有可截除的行。递归判定仍读取最终正文的调用列。
- 恢复按普通导入和公开成员两组借用现有列，复用 RX 重绑定及签名校验；Native seed 使用同样的绑定规则。缓存格式无需更新。

## Answer

安装版覆盖单层默认转发、两层目录 `index.zx` 中默认函数先后两种顺序，以及递归默认转发。热启动全部命中，生成与禁用缓存一致；目录转发的目标函数改动后，增量与独立生成一致，改回后恢复原产物。现有持久缓存、导入路径和统一库入口共 24 项通过。

同一函数同时作为普通导入和命名重导出时，两组绑定解析到同一当前签名。157 模块普通导入项目全量命中，前后缓存负载与生成 Zig 一致。三轮有效样本中，热缓存墙钟和 CPU 中位数均为 0.05 秒，空缓存墙钟和 CPU 中位数分别为 0.08 和 0.07 秒。

最终版本使用 Source stage 3 引导三代，每代通过 22 步。三代之间及与上一阶段相比，11,011 份生成文件均逐字节一致。

最终整仓冷构建使用 Zig 0.17.0、ReleaseSmall、12 核、四分区和空本地及全局缓存。Native seed 引导生成安装版，安装版运行 Source。构建通过 70 步。

本阶段比上一阶段墙钟多 0.66 秒，CPU 多 1.00 秒。四个 LLVM 分区对象均与上一阶段字节一致。仅修入口发布的中间版本测得 123.03 秒墙钟和 215.41 秒 CPU，增长主要出现在 LLVM 分区和宿主编译。最终版本与固定基线相比，CPU 累计增加 4.99 秒，超过 3 秒警戒线。采样中的主组生成 CPU 为 7.20 → 7.10 秒，LLVM 分区为 79.28 → 80.12 秒，宿主编译为 35.50 → 36.24 秒。累计差异分散在多个进程，现有采样尚未定位到具体代码。
