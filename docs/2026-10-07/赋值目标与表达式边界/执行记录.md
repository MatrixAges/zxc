### 空白必须按字节判断

锁定 `white-space.js` 中第 7 项标签为 `U+000D`，实际赋值两侧字节是 `0A`；组合项中同一位置也为 `0A`。没有因为标签写 CR 就生成 CR 并声称复制了原文。

五个可执行原空白样本为 TAB、VT、FF、SPACE 及这项 LF。LF 样本仅增加 ZX 包装块需要的 ASCII 缩进，保留 LF 的数量、顺序和赋值两侧位置；其他四项 gap 与原文逐字节相同。另列真正含 `0D` 的 zxc 自有 CR 控制，既不改原标签，也不把新增控制计为另一份上游文件。细节见 `空白字节核对.json`。

## Edges：边界与限制

JS var 改为 ZX 类型化显式 state，这个适配不证明普通可变变量、声明提升或环境记录语义。运行中的每条更新均为真实赋值，括号未移除，列表/字段未用纯表达式代替。

原始未括号字面量在语句分派就 parse/syntax 拒绝；同一数字、布尔、字符串加括号后可解析，随后实际进入 state 目标检查，在 analyze/ownership 拒绝。两层都有测试，但后一层的阶段不同于 JavaScript 早期语法错误。null 在有类型上下文前还有独立限制，未伪造为已到达同一语义校验。

ZX 表达式不接受赋值、计算字段读取不接受对象，ASCII 空白契约明确不接受 NBSP、U+2028、U+2029。这些现有边界不是本轮已验证的生产缺陷；没有向实现会话发送消息。原文若需要这些语义仍未兼容，测试通过仅表示边界被稳定、准确地测量。

没有新增生产运行库、解释器或动态加载层。正式源码只修改测试包目录与构建登记，借助普通静态 Zig 执行。
