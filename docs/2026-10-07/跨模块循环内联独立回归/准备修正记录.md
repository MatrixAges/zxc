# 跨模块循环夹具准备修正记录

## Intent：最终目标

明确区分测试准备错误、结构期待误判与真实生产问题，保留首次执行事实，不能把局部绿色结果替换成完整门禁。

## Data：可用证据

首次 Debug 实际执行 86/86，但总构建失败于三个自有准备问题：switch case 使用独立块，ZX 不支持这种普通块；native 函数使用具名导入，被解释为类型导入；生成比较 helper 使用跨出 Zig root 模块路径的相对导入。原始源码与日志分别保存在准备失败源码.json、准备Debug原始日志.txt和准备输入清单.json。

按成熟实现去掉 case 独立块，使用 native namespace 的 observe 成员，并通过显式构建模块导入既有比较 helper。第二轮 Debug 和 ReleaseSafe 实际各执行 100/100，effects 仍被结构断言拦住。旧断言把任何 function_* 都当作聚合 helper，误将应保留的 native bridge 也计入。修正为根据原 IR 的 external 身份区分 native 和聚合 helper，名称匹配区分数字前缀；不删除任何调用或放宽值、次数、错误、输入及 OOM 断言。

此后完整 122/122 双模式和 2263/2263 相邻回归均通过。原生标量 observe 的精确 token 序列、一次参数求值、失败优先级由真实执行证明，结构区分不是语言值 oracle。生成器改为先保存源码/ABI，再作结构检查，便于未来结构失败直接审阅实际输出。

最后补足同一个已填充缓存在逐点修改失败后重试的真实边界。此前两个 generation tests 已覆盖重复、正文修改、恢复和失败清理；它们没有证明失败后在同一个 cache 上重试。因此追加第三条独立测试，不将两个成功测试误写成该恢复路径已完成。追加前的输入、门禁、产物与生成源码分别另存，后续完整门禁单独登记。

## Edges：边界与限制

以上准备失败和结构误判不是生产编译器缺陷。所有失败进程均确认实际终止后才修订自有输入。没有修改生产实现，没有改写业务期待使失败通过，没有向实现会话发送准备错误。

分析中有关 native 是否 pure 的描述需要结合实际签名：对象参数不属于 native inputLeaf，单标量参数则可属于当前边界。实际效果夹具使用单 u64 参数，并保留 native 实现的真实效果，不把结构 pure 等同无可观察调用。

## Answer：交付与成功标准

本目录保留三个准备阶段的终止码、日志、SHA 与必要源码。正式成功仅以后续完整 Debug/ReleaseSafe、精确 fixture 叶子和提交后输入一致性为准；历史局部通过不冒充全部通过。
