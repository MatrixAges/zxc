# 原生模块入口独立覆盖执行记录

## Intent：最终目标

直接运行正式生成的模块与导出校验，独立覆盖六列结构、声明文本、身份与绑定归属、导出签名和错误集合。新增门禁已经接入测试包根 test，固定期望不依赖 seed 算法。

## Data：可用证据

正式修改为七个文件：根注册、build/native_modules.zig，以及 native/modules 下的 fixture 与四个职责测试。fixture 基于原有真实分析源，初始化先通过完整 validateIr；测试编译时断言 generated_parser=true，直接调用实际 native_modules.validate / validateExport。

新门禁共 118 次检查，原回归共 88 次本轮执行检查。每种模式记录新门禁四个及原门禁十个实际二进制，共 28 个二进制身份。实际编译命令中的四个新测试源码，逐个核对命名集合与冻结源完全一致；生成模块、ABI、选项及原始日志同步保存。缓存摘要为新门禁每种模式 21、原门禁每种模式 20，不算新增执行。

两个正式宿主校验入口自身使用零容量 FixedBufferAllocator。全部正负检查实际返回成功，没有走 catch unreachable 的分配失败路径；此结论仅覆盖本批场景，不把备用生成分支的静态审阅升级为任意输入证明。

## Edges：边界与限制

结构错误与导出签名变体属于单位分类输入。最小空表 Program、普通函数行和某些签名/身份变体不声称构成完整合法 IR。导出调用始终显式检查列宽、索引存在、模块编号有效和成员非空；局部 bool 结果不代替完整类型、调用或原生引用校验。

fixture 只借用现有短源码，遵循当前 ZX 单文件最多 240 行规则，没有新增 ZX 大型文件。正式变更全部为测试及构建接线，无生产算法、专用运行库或动态加载层。NativeType 的递归校验等剩余手写边界仍存在，不因本批通过宣称整个 native 或编译器完全自举。

## Answer：交付与成功标准

交付七个正式测试文件、中文 IDEA 计划和记录、两个失败首轮原文、执行基线及快照、四个通过门禁的实际证据、二进制与生成物、精确发布核验。118 个新检查及原门禁 88 个本轮检查均通过，未确认新的生产缺陷，不向实现会话发送绿色消息。使用英文 Conventional Commit：test(compiler): cover native module validation boundaries。

## 自我批判

首轮错误地把兄弟目录 fixture 当作可直接相对导入文件；Zig 模块根限制导致四个测试文件在两个模式下全部编译失败，未执行任何新增检查。保存原始日志、当时接线与 fixture 及基线，在两个进程都结束后，仅将两处接线改为显式 reference_fixture 模块导入。全部测试名称、固定断言及场景保持原样，再实际复验两种模式。

初版证据收集器从收集时 HEAD 读取 source_commit，遇到共享文档提交推进后导致校验失败。对完整包摘要及提交间 packages 差异实际核对后，明确记录执行开始身份与 collected_source_commit，保持不同含义；没有把后来的 HEAD 当作测试执行源，也没有重新归类失败来制造绿色结果。
