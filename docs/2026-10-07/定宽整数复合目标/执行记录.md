# 定宽整数复合目标实施记录

## Intent：最终目标

验证六种定宽整数的复合算术在普通状态字段、嵌套对象字段和列表元素上的读取、计算、写回和输入所有权。补齐先前浮点状态更新、普通整数表达式以及 i64 宿主列表更新仍未覆盖的组合。六种整数来自当前 `packages/core/src/type_table/model.zig` 的 Scalar 枚举，而非根据测试便利任意挑选。

## Data：可用证据

最终验证基线为 `74529e1501ff571fb5556d9b1b925762c3dfb753`，起始基线为 `6851e4ccf4b644d9ecda9dce8abf214f8295e9e0`。正式变更共49个文件：18份 ZX fixture、18份 JSONL目录、精确整数模型与生成器、编译与进程入口、构建接入、生成一致性检查、目录登记及包说明。内容和基线 SHA 保存在 `输入冻结.json`，全部可复制代码在 `草稿/packages/test/`。

### 原理和实际测试路线

复合更新的目标具有不同所有权行为：普通字段写回状态副本，嵌套字段需要重建父对象，列表元素需要保护借用存储。只测普通表达式，无法证明这些行为一致；只有 i64 列表宿主 fixture，也不足以证明窄整数和 unsigned 写回。

每份 fixture 只指定一种目标，五个操作由实际 Input.operation 选择。循环实际执行一次或两次，五个分支分别使用 `+=`、`-=`、`*=`、`/=`、`%=`，不替换为预计算结果。state.round 使用 u8，输入控制轮次；每次成功更新后再递增 round。

源码产物和编译库消费者均经 IR 校验。库路线先编码、解码，毒化编码原字节，并销毁 provider 分析/库对象，之后才在独立消费者中导入公开 Input/Output 和函数。没有通过保留 provider IR 假充编译库消费。

预期使用 BigInt 精确计算，不调用生成程序或 Zig 生产实现。signed 选取13个边界，unsigned选取9个边界，包含 min/max、邻近值、半范围、零和小整数；64位类型额外加入 2^53+1，i64另加入其负值。每个操作数对执行一轮和两轮；第一轮算术非法的组合另执行零轮次，证明不能预先触发未进入循环的算术。

列表专项还有最后元素、非法索引、空列表，以及零右值与 bounds 的优先级；普通/嵌套字段中的 selected 参数应不影响目标选择。每个命名案例是一条实际独立进程输入，不把内部轮次数算成新增案例。

### 输入和输出观察

成功时逐项比较 scalar、field、rounds 和所有 values/original/mirror 元素。算术失败时保留真实 panic 原因，以86退出；列表边界错误输出原始 IndexOutOfBounds，以正常进程返回，不与 panic 混为一种结果。

所有路径都读取调用方 Input 的 operation、left、right、rounds、selected、values.len，并检查 values.ptr 仍指向原来的借用存储。另比较原存储的全部元素与两端 sentinel。完整 stdout/stderr、退出码和 signal 必须符合预期，不能只搜索错误字符串。

测试全局 storage/request 只存在于原生测试进程中，每个案例启动新进程；没有把全局变量引入 ZX 应用、编译器产物或 Store。

## Edges：边界与限制

实际主机为 macOS x86_64，Zig0.17.0、Node v25.8.1。仅验证 Debug/ReleaseSafe 的安全契约，不对关闭 runtime safety 的优化套用溢出 panic 预期。

边界矩阵是有限语义样本，不是整个整数域穷举。源码包含五种操作且由实际输入选择，不能据此声称 bitwise/shift、混合宽度赋值、所有类型转换、所有 RX/Store 生命周期都已覆盖。定宽整数并非 Test262 Number，未登记为 IEEE Number 等价。

本轮成功的多轮结果与单轮/多轮失败分类证明实际复合写回的结果；精确宿主阶段轨迹仍由此前 i64 native 专项负责，本轮不冒充每种整数类型均具有那一套事件观察。

panic采用进程退出，不据此声称运行了defer或完整释放所有临时内存。普通返回和应用错误通过 arena.deinit 释放进程内分配；本轮没有扩大为所有分配失败扫掠，相关 i64 宿主专项保留已有扫掠。

未增加 zxc 专用运行库、解释器、动态加载或持久化状态目录。最终程序仍为普通静态 Zig 与应用语义所需的标准库行为。
