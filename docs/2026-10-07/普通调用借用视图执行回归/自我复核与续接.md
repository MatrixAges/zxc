# 普通调用借用视图自我复核与续接

## Intent：最终目标

本部分验证普通调用返回的前缀/偏移借用视图与真正的编译库消费，继续全量 Test262 与全部 zxc 特性覆盖。当前 83,052 个 JSON 超过数量目标，但尚有 50,773 份上游原文件未审阅，不能据此宣布总体完成。

## Data：可用证据

现有测试家族的五个实现文件各保持独立职责：fixture 选源码，compile 分析和生成，model 给独立预期，shape 检查生成结构，build 注册执行图。新增四个 ZX fixture 和 views_test 仅增加需要的行为，复用既有 seed 与 execution 的输入、OOM、保留结果及释放检查。十份正式输入及十一份原有改动均由 SHA 绑定。

prefix 的 pop 第零结果返回原数组只读前缀，offset 的 splice removed 返回原数组带偏移的区间；这是现有语言和 genz 实际支持的借用路径。调用方明确在 append 之后再次读取旧视图元素与长度。seed 包含空串、相同内容的不同存储、中文、NUL、emoji，并保留完整字节、记录字段和指针槽。1024/4096 次增长及同 arena 连续调用后仍逐项核验第一次结果。

Debug/ReleaseSafe 完整家族每模式 156 个具名入口，新视图的每模式 28 个入口另有独立目标。实际生成二进制重放用于核对名字和内容，不增加独立覆盖计数。旧 reference/reverse 的四个 bounded 入口仍按其原规则直接返回，本文明确不归因其内存上界断言；新增七项语义/生命周期检查均实际进入执行器。

## Edges：批判与限制

初稿凭名称误写 range API，并错误批量调用单文件 formatter，说明必须先查实际公开方法。已根据 list_operations/IR 契约改为 pop/splice，未把此准备错误归咎生产实现。

升级实际消费者后，旧 shape 的 execute 后缀文本搜索误报 MissingReduce。已查生成物证明循环位于前置辅助函数，并改为检查完整模块；仍要求 execute 和循环存在。结构检查只证明生成物包含这些元素，语义证明来自逐项实际输出和输入保留检查，不能颠倒证据强度。

库路线现在是新消费者导入公开接口，而不是解码后直接执行旧入口。provider、旧 library 和被清零的 bytes 在消费者分析前释放；这证明本次消费链不依赖原提供者临时数据。本部分未测试库在跨进程落盘后载入，不把静态链接机制说成运行时动态加载。

不对借用视图的分配量或吞吐量下结论；最终 allocated/freed 平衡与全部分配失败清理是明确检查。所有新程序共享普通输入逻辑，不识别用例名字或内置结果。没有修改生产编译器或使用者 skills，没有发现应通知实现会话的生产缺陷。

## Answer：续接方式

1. 先读取输入清单与原有修改清单，确认当前工作区基线、十份正式文件及非本任务改动。
2. 执行 `执行门禁.py Debug` 和 `执行门禁.py ReleaseSafe`，随后每模式执行收集执行证据脚本。新增独立目标通过执行门禁第二参数 `test-borrowed-call-views` 执行。
3. 运行核验门禁，核对 20 路生成物、全部具名输出、source/library 区别、跨模式 SHA、真实消费者源码与原有修改保留。
4. 若生产基线推进，保存旧证据并同步隔离工作区，更新输入清单后重新执行。准备阶段两个失败门禁日志保留，只归因测试检查范围，不冒充测试失败或成功。
5. 后续继续原始 Test262 审阅，并为实现会话发布的所有权控制流索引模型补上分支与返回路径测试；只有验证为生产缺陷时才发送问题消息。
