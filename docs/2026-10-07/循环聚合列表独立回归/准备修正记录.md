# 准备修正记录

## IDEA

- Intent：保留真实失败与修正原因，避免将准备错误当作生产缺陷。
- Data：首次、第二次、第三次准备 Debug 原始日志及首次行为 Debug 日志。
- Edges：日志不覆盖、不删除；测试预期不因实现错误而放宽。
- Answer：下列修正均作用于新测试或收集脚本，未修改编译器，未通知实现会话。

1. call 夹具的项目导入误写 `.zx`，正式规则要求省略扩展名，改为 `./read_frame`。
2. nested 夹具尝试通过字段路径检查来收窄 optional；改为先绑定 prior，再检查 null 后读取。保留全部 optional 的值观察。
3. 宿主测试用了旧 Zig 的函数类型 params 反射；读取当前 0.17 的 lang.Type.Fn 后改为 param_types。没有改变 ABI。
4. 初次复制脚本只取 cwd.parent，得到 packages 而非仓库根。确认进程 terminal 后修正 parents[1]，第二次日志表明仍为旧输入；不能把它当新实现结果。
5. 宿主 mode 分支需显式 comptime，才能在不同 Input 类型下排除不适用字段。改为显式编译期分支，不给所有普通夹具添加无关字段。
6. 第一次全行为成功门禁实际执行 70 项，已有 32 项缓存；后续使用全新缓存完整执行，不将缓存结果当本轮实际执行。

7. 复核发现共用资源测试在两个回退 mode 中没有实际执行分支。补充 257 元素、9 步的旧值及输入/资源释放观察；回退仍不施加固定容量预算。由于正式断言变化，两模式使用新缓存再次完整验证。

8. 证据收集的 struct 正则误要求闭合括号前换行，导致单行 tuple 定义吞掉下一定义。改为受控 fixture 中无嵌套花括号的字段范围，同时支持单行与多行。正式形态门禁和运行门禁没有失败，不因此重跑测试。

9. 两个模式可合法具有完全相同 ABI。收集器不再以 ABI 哈希全局唯一为前提，先从唯一 program 内容锁定本模式输出目录，再在同目录核对 ABI 与库文件，避免误归属。

生成程序的数学预期和错误顺序未因此改变。具体最终结果在实施记录与原始日志登记。
