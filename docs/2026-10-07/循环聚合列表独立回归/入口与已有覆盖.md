### 局部栈原文的实际观察

已完整阅读 `docs/2026-10-07/解析状态自举前置/草稿/局部栈/stack.zx`。它的元素类型是 `{ position: u64, count: u64 }`，每步执行：

1. 把 `{position: index, count: total}` 压入 frames。
2. 保存最后一个 Frame 为 previous。
3. 将当前最后一个 Frame.count 加一。
4. 将 previous.count 与修改后 count 加入 total。
5. pop 并保存 remaining/popped，将 popped.count 再加入 total。
6. index 加一，最终只返回 `state.total`。

设一步开始时 total=t，旧元素 count=t，新元素 count=t+1，则一步结束 `total=4t+2`。初始 total=0 时，0/1/2/3 步分别是 0/2/10/42。若 previous 误用可变元素别名，第一步可能得到 3 而非 2，因此该原文已经能区分快照语义。

列表每步 push 后 pop，最大活跃长度为 `初始 frames.length + 1`，不是循环步数。初始 frames 的内容不会被该算法修改。宿主输入不变检查应覆盖所有 Frame 字段，不能只比较外层 slice。

## Edges：边界与限制

### 要检查真实错误路径中的输入

每次调用前用普通 testing allocator 或栈内存构造输入及期望值，放在被注入失败的 Arena 外。调用时先保存 error union，然后逐字段检查宿主输入，最后才展开结果。这样 OOM 和 IndexOutOfBounds 路径也必须满足输入未变。

公开生成类型的聚合表示需按 `program.Input`/导出类型构造，不能凭 ZX 的 object 形状假设 Zig 输入元素一定是裸 struct。输入比较应沿真实公开类型检查元素内容；外层指针、长度、元素身份适用时也保留。仅比较 slice 指针无法发现对象字段被原地修改。

所有成功结果必须在 Arena 仍存活时读取。OOM helper 要覆盖 generated `program.execute`，而不只是 compiler.analyze/emit。defer 释放 Arena，并让 testing allocator 负责泄漏检查；禁止 resize/remap 的既有 helper 可覆盖容量扩展的分配回退。

无故障 allocator 下，非法索引应得到 IndexOutOfBounds。注入失败时，初始聚合列表 materialize 可能在索引检查前返回 OutOfMemory，不能要求每个注入位置都优先报告越界；这些错误返回仍需检查输入和释放。

### 资源要求按算法分别确定

零步：内联聚合列表允许为了初始表示转换分配。不继承 i64[] 夹具的“零步输出指针等于输入”和“零步无复制”要求。

有限最大长度：嵌套 product 与局部栈 push/pop 的列表最大长度固定；比较两个正步数、相同种子长度的 allocated_bytes，能够捕获每步重新复制/分配。零步与第一步可能因容量首次增长不同，不应强行要求相等。

两列表与字段更新：列表长度固定，种子相同且步数增加时，成功运行资源不应线性随步数增长。分别记录 bytes 与分配次数更有辨识力；Arena backing 分配次数本身较粗，单用次数可能漏掉在已有块内的持续分配。当前 FailingAllocator 的 allocated_bytes 也是 backing 统计，配合明显不同步数和源形态检查使用，不能据此声称精确测量每次语义分配。

返回聚合列表：回退可以进行公开表示重建和结果分配，不能附加内联无分配要求。先保证结果、输入不变、OOM 和公开 ABI 正确，具体资源上限需按实际生成源码确定。

局部栈 total 按 4t+2 增长。不得照搬旧夹具的 257/4096 步；建议 0/1/2/3/8/16 步。宿主 oracle 逐步用经过检查的整数运算计算，不用 `4^n` 中间值公式引入溢出。

### 源形态检查应落在可证明的生成结构

建议让新 build helper 将同一份 CLI 输出同时用于 program import 与源文本检查，检查具有语义意义的结构：普通 Zig while；局部聚合值类型；ArrayList 元素是内联值布局；初始元素转换在 while 前；循环内对元素值字段更新，而不是逐步构建公开对象。可先读生成源码确定稳定结构，再实现范围受控的断言。

### 1. nested_product.zx：元素 product 和状态路径同时嵌套

这个夹具中的 nested 指递归 product，不是 nested loop，也不是元素内部嵌套 list。

```zx
export type Frame = { position: u64, payload: { count: u64 } }

export type Input = { frames: Frame[], count: u64 }

export type State = { box: { frames: Frame[] }, index: u64, count: u64, total: u64 }

export type Output = u64

export default function (in: Input): Output {
    const initial: State = { box: { frames: in.frames }, index: 0, count: in.count, total: 0 }

    const state = loop(initial, {
        while: current => current.index < current.count,
        next: current => {
            current.box.frames = current.box.frames.push({ position: current.index, payload: { count: current.index } })[0]

            const previous = current.box.frames[current.box.frames.length - 1]

            current.box.frames[current.box.frames.length - 1].payload.count += 1
            current.total += previous.payload.count + current.box.frames[current.box.frames.length - 1].payload.count

            const [remaining, popped] = current.box.frames.pop()

            current.box.frames = remaining

            if (popped != null) {
                current.total += popped.payload.count
            }

            current.index += 1
        }
    })

    return state.total
}
```

独立 oracle：第 i 步加 `3i+2`，0/1/2/3 步结果 0/2/7/15。测试空种子及含不同 position/count 的非空种子，完整比较输入的嵌套字段。最大长度为种子长度加一，比较 2/64 步资源；生成源码应显示元素 payload 的嵌套值布局。运行前仍需由主代理确认普通 CLI 接受该草稿。

### 2. two_lists.zx：两个状态列表共享同一初始输入

```zx
export type Frame = { position: u64, count: u64 }

export type Input = { frames: Frame[], count: u64 }

export type State = { left: Frame[], right: Frame[], index: u64, count: u64, total: u64 }

export type Output = u64

export default function (in: Input): Output {
    const initial: State = { left: in.frames, right: in.frames, index: 0, count: in.count, total: 0 }

    const state = loop(initial, {
        while: current => current.index < current.count,
        next: current => {
            current.left[0].count += 1
            current.right[0].count += 2
            current.total += current.left[0].count + current.right[0].count
            current.index += 1
        }
    })

    return state.total
}
```

正步数使用非空种子，首元素初始 count=s。独立 oracle 每步分别更新 host left/right 数值，再累加两者；公式可辅助审阅为 `2sn+3n(n+1)/2`。s=5 时 1/2/3 步为 13/29/48。若两状态缓冲共享可变 Frame，此观察会偏离。

宿主 seed 的每个 position/count 都应保持原值，尤其首元素不能被改。空种子仅用于 0 步；越界归第五夹具。比较相同种子 2/64 步，形态上应有两条独立的值缓冲。

### 4. initial_zero.zx：零步仍保留初始值和转换错误边界

```zx
export type Frame = { position: u64, count: u64 }

export type Input = { frames: Frame[], count: u64, seed: u64 }

export type State = { frames: Frame[], index: u64, count: u64, total: u64 }

export type Output = u64

export default function (in: Input): Output {
    const initial: State = { frames: in.frames, index: 0, count: in.count, total: in.seed }

    const state = loop(initial, {
        while: current => current.index < current.count,
        next: current => {
            current.frames[0].count += 1
            current.total += current.frames[0].count
            current.index += 1
        }
    })

    return state.total
}
```

主观察为 count=0、seed=37：空及非空输入都返回 37，不访问 frames[0]，输入不变。非空种子零步也做全分配失败检查，验证初始转换 OOM 清理；允许它分配。空种子零步不得误触发 IndexOutOfBounds。

增加非空种子 count=1、首元素 count=5 的对照，结果为 43，确认不是把所有输入硬编码成 seed。此夹具的目标是零步和初始转换，不要求单独的长步资源基准。

### 5. bounds.zx：聚合元素字段更新的非法索引

```zx
export type Frame = { position: u64, count: u64 }

export type Input = { frames: Frame[], index: u64 }

export type State = { frames: Frame[], index: u64, steps: u64, total: u64 }

}
```

成功对照：两个不同 Frame，索引 0/1 分别返回对应旧 count+1，输入全体保持原值。无故障错误输入：空列表索引 0、非空列表索引恰等于 length、较大索引，均须返回 IndexOutOfBounds，且输入未变。

OOM 正常输入与非法索引输入分开覆盖。非法索引运行在故障注入时允许先 OOM；在捕获结果后先检查输入，再处理错误。这里不新增 effectful RHS，避免把内联 eligibility 改成另一种路径；索引与 RHS 求值顺序已有 iterate/cli_test.ts 的 trace 测试可复用其检查方式，不能声称本草稿单独覆盖了该 trace。

### 6. return_list.zx：完整聚合列表返回触发回退

```zx
export type Frame = { position: u64, count: u64 }

export type Input = { frames: Frame[], count: u64 }

export type State = { frames: Frame[], index: u64, count: u64 }

export type Output = Frame[]

export default function (in: Input): Output {
    const initial: State = { frames: in.frames, index: 0, count: in.count }

    const state = loop(initial, {
        while: current => current.index < current.count,
        next: current => {
            current.frames[0].count += 1
            current.index += 1
        }
    })

    return state.frames
}
```

非空种子 0/1/2/17 步：输出长度和所有 position 保留，只有第一个 count 加 n，其他 count 保留；宿主输入所有元素不变。空种子 0 步返回空列表。读取所有公开结果元素，验证生成程序回退后的表示与寿命；必须编译真实生成 Zig，不能只看 ZX 推断 ABI 正确。

0 步只断言值，不机械要求结果指针身份；若后续生成源码和公开契约确认借用，则可以追加精确身份检查。正步数输出不得通过原地修改宿主 Frame 获得。覆盖 runtime OOM；此夹具不施加前五类的内联资源预算。
