## 第一性差异

ZX string 为不可变 UTF-8 字节切片，length 是字节数；index 按 u64 分析，读取结果是 u8；index >= length 返回 IndexOutOfBounds。一个多字节字符中的每个字节都能读取，单独解码该字节通常会返回 InvalidUtf8。这与 JS 的 UTF-16 code unit、String wrapper、动态属性和 undefined 不同。

26 份原文覆盖 String exotic 非数字键/特殊数值/越界的 14 份、numeric-properties 的 1 份和 String.prototype.at 的 11 份。完整主观察已逐项记录在上游审阅准备/入口与逐项观察.md，本轮主代理再次完整读取并核对，没有只看代理结论或 filename。正式 review 的 reason 每份不同，cases 均为空，避免把普通 ZX 回归挂作整份适配。

具体边界包括：动态 foo 与 String wrapper；NaN/Infinity 的 property key 转换；4294967295 的缺失属性返回；负括号键和 at 相对索引；typeof at、函数 name/length、prototype 和 numeric own-property descriptor；对象 valueOf 的调用次数及八种 ToInteger 输入；null/undefined receiver；孤立高代理 D800；空字符串越界返回 undefined。

hello world 的索引 11 恰等于长度，不能因元数据写 greater than 就误记为更大边界。4294967295 能由 u64 表达，差异是 JS 缺失属性结果，而不是不能表达大整数。returns-code-unit 的完整输入含孤立高代理，不能删掉它后仅保留四个 ASCII 输出。prop-desc 两项 typeof 都属于完整原文。

## 普通 ZX 回归及组织

| 分类                               | 新增用例 | 精确观察                                                                                              |
| ---------------------------------- | -------: | ----------------------------------------------------------------------------------------------------- |
| built_ins/string/index/bytes       |      100 | 62 个逐字节正例、30 个 length/length+1 边界、8 个空串/2^32-1/u64 最大值边界；同时检查 byte 与字节长度 |

类型拒绝涵盖 bool/string/fraction/negative/null 索引，绑定 i64/f64/bool/string/optional/object/list 的索引，byte 当 string、length 当 u8，以及 string.at；at 另核对 field name 的精确 span。合法动态 u64、常量零、u64 算术及 length 各自通过。不是把 parse 错误当预期的类型错误。

独立字节表手写 15 组：ASCII、NUL/换行/DEL、é、中、🌱、组合 e+0301、混合文本、U+0080/U+07FF/U+0800/U+D7FF/U+E000/U+10FFFF。准备时再用 Python UTF-8 codec 核对表自身，不从生产生成器导出预期。byte 正例覆盖表中全部 62 个字节；decoded 去掉重复 hello world，按相同有效完整输入显式验证单字节解码。

字符回归实际读取 in.text[in.index]，再调用公开 encoding.decodeUtf8，得到精确字符文本；没有将数字 49 冒充字符串 1，也没有用模板输出十进制字节。原文 returns-item 的五个值、numeric-properties 的三个值和 relative-index 的 index=0 共九个值观察，对应八个不同 ASCII 输入位置；这些只是普通字符用例，typeof/descriptor/负相对索引没有被省略后登记 adapted。

五份 ZX 函数只处理动态输入，没有 case-id、预设答案表或针对上游文件分支。composed 在函数内实际模板拼接，AND/OR 直接使用普通短路运算符。所有 runtime suite 使用成熟 collections.check，先深复制可写输入，成功和错误后均与原输入深比较；结果在 caller Arena 仍有效时检查，Arena 统一释放并由 testing allocator 检查泄漏。

## 最小注册和执行路径

正式 runtime.zig 只新增 test-string-index 与一条 suite 前缀 dependOn；已有 test-strings 自动包含该家族。suites.json 只追加一个 frontend 与五个 runtime 条目，原有注册逐项不变。五份 ZX + 五份 JSON + 前端 JSON + review JSON + 两份注册，共十四个输入，正式、草稿及两个冻结工作区逐字节相同。

decode 复用 shared_abi=true 的正式标准库绑定；四份普通程序直接内联类型，只导入 std。decode 导入 std、zxc_standard、zxc_abi，标准入口实为正式 encoding.decodeUtf8。没有复制标准库函数或为 tests 创建专用宿主契约。

源码中仍有应用语义所需的普通分配：byte/bytes 对象输出、单字节数组及拼接结果由 caller Arena 持有。静态链接和无专用运行库不等于没有分配，也不证明整个编译器完成自举。

## 并行更新、准备问题和保留

构建期间远端 c949379a 新增普通内联循环列表优化。它不修改本轮输入，但会影响编译器传递生成路径，所以主工作区在核对十一份旧修改哈希后 fast-forward，再在第二个隔离工作区冷缓存复验当前实现。没有要求用户确认，也没有改写已推送历史。

准备时发生 case/review 标识混用、suites 全量序列化格式差异和收集脚本误认为所有程序都有 ABI 的问题，具体范围见准备修正记录.md。原始运行测试没有夹具失败，最终没有伪造缺失 ABI；这些构造/收集假设不属于生产缺陷，未通知实现会话。

只清理本会话两个冻结工作区的已发布九输入，保存差异后更新；历史类型查询两版本的实时脚本均需恢复对应 HEAD/输入，既有历史日志不改。原有十一份 tracked 修改在同步和提交前核对，其他未跟踪资源不清理、不提交。
