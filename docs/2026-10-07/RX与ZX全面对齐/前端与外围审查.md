# 前端与外围职责审查

## Intent：最终目标

审查主审负责的词法、解析、整数、模块标识和命名规则，补齐全面审查覆盖，并识别应由 RX 表达的阶段与额外复制。

## Data：可用证据

基线 d3667ffe。静态核对 12 个生产 RX 入口、ZX 传递依赖、build/generate_parser.zig 的真实生成入口。词法与解析没有 zig: 专用 import。源码清单包含整个生产 src；CLI 的 30 个 ZX 均为例子或测试，CLI/src 没有生产 ZX。网站 checkout.rx 已展示 carts/load→quote→orders/create 的数据流，quote.zx 是单一报价计算。测试 fixture 不按编译器生产模块强行改写。

## Edges：边界与限制

静态职责审查不是全部算法正确性的逐行证明。keyword_transition 的大量关键词转移是文法数据，不以行数认定总控；native/header、parameters、typed 按语法状态推进同一接口解析，暂不为每个 token 拆 RX。小型 push/pop、状态恢复及共享文法函数有真实表示或复用边界，不按短函数数量批量合并。

lexer/scan 与 templates/boundary/scan 包含 UTF-8 门禁、字节扫描、flush/finish 与 EOF 发布。扫描循环必须在 ZX；输入门禁和收尾应在模块层表达。templates/streams/step 的事件路由与 byte feed 同属单次扫描步，保留 ZX。

expressions/prepare/scan.zx:11-15 先 map 投影整个 Token 列，再反转，再扫描，最后反转 Hint 结果。投影加反转的中间 token 列并非输出所必需；应借用原 tokens 逆序索引。结果列可直接按原索引写入，需检查生成代码复用和所有权，不能只凭源码短就称 zero copy。

## Answer：整改顺序与成功标准

1. 先移除确定的跨职责总控：IR/scopes/tasks/contracts/program-pure/native-export，以及 semantic 的 origins/resolve/preflight。
2. 再展开前端词法与派生索引阶段，保持原 diagnostics、EOF、模板流行为和所有权。
3. 删除提示扫描的中间 token 列；只分配语义结果。
4. 整理所有权大执行器的规则族；保留 ZX 工作栈算法。
5. 复核 55 个基线入口和新增子模块，单独列出专用 native 状态及手写编译器宿主，不把本次编排修正宣称成完整自举。

## 自我复核

本轮不能继续以补一个 RX 包装结束整改；同时也不能把所有循环或所有辅助调用都提升 RX。判断依据是独立阶段、独立输入结果和失败边界。结构表内的长度/范围检查是同一表不变量的保护步骤，是否展开需结合复用路径判断；不能破坏 ZX 内集合算法对该谓词的复用。
