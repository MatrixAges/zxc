# 独立循环执行回归实施记录

## IDEA

- Intent：证明直接循环语句保留状态迭代、副作用和错误顺序，并维持非 void 普通调用语句的类型边界。
- Data：冻结生产提交 `4f5cb9cf77ff0886dab60eb24876a310f3b5e24e`；正式测试与草稿、独立工作区十个输入文件逐字节一致；原始日志和实际生成产物带 SHA-256。
- Edges：新增 9 条分析声明、15 条运行声明，共 24 条独立声明。三路径及优化模式属于重复验证；没有新增 JSON catalog ID，也没有审阅新 Test262 原文。
- Answer：规范测试、双优化模式门禁、原始证据及可复核脚本；完成后独立 commit、push。

## 覆盖设计

分析层覆盖 scalar/object 状态、嵌套 scope、分支中的 do、括号包裹的直接循环，以及分析、IR 校验、生成全过程的分配失败。三个负例使用语法合法的导入调用，分别返回标量、对象、循环结果；必须准确返回 type_mismatch，诊断区间覆盖调用表达式。返回循环结果的普通函数调用仍不是直接循环语句。

运行层通过原生宿主保存具体事件值，独立列出预期序列。覆盖前置条件零次与多次、后置条件至少一次与多次、不选中的分支、内外循环状态隔离。七个失败点分别处于初值、首次条件、步骤、最后条件、循环后语句、导入模块中的循环、最后语句；另覆盖嵌套内层失败。分配失败检查允许已发生的原生副作用，只要求事件轨迹为正确前缀，并由测试分配器检查泄漏。

复用既有 native_runtime 三路径编译驱动：original 从真实项目分析生成；linked 对模块提取后反序联结生成；cached 在编码缓冲清零并释放、原始 analysis 和 artifact 释放后重新联结，最后释放 decoded artifact 再生成。循环项目分别调用 validateIr。宿主只作为显式静态 Zig 模块链接，生成源码只导入 std、choice、zxc_abi。

## 失败与修正

首轮同步前误启动了既有基线门禁，终止码 0，仅作 baseline 记录，不计本轮新增声明执行。随后首轮新增门禁终止码 1：动态源码的格式未规范，原生声明错误使用具名 error 定义。已改用 compiler.format 和当前规范的 throws { Stop }，并由 CLI fmt --write 规范实际 ZX 文件。

一次命令误在根目录请求子包门禁，终止码 1（no such step），保留错误工作目录日志。证据保存时也曾使用错误相对目录，修正为绝对路径后才保存成功；不会以包含后续命令成功的 shell 终止码代替失败的 Python 保存动作。

第二轮运行路径已全部通过，但三个负例以语法禁止的裸引用、算术和条件表达式启动，无法到达类型边界；改成合法导入调用。修正后的缓存门禁通过，仅实际运行新增分析 9 条、其余 10 个 Zig 测试步骤 cached。随后使用全新构建缓存取得最终源码的完整实际执行证据。

格式器一度修改 53 个无关已跟踪文件的空行；逐文件比较非空行完全一致后，仅撤回这些格式改动，保留用户原有改动。最终测试源码只涉及十个明确列出的文件。

## 自我批判

宿主轨迹验证的是本组有限输入及指定失败点，不能外推无限循环、并发、任意状态组合或所有 native ABI。后置循环正常轨迹有覆盖，逐阶段原生错误断言来自前置循环，不扩张为独立后置错误穷举结论。分配失败检查也不承诺撤回已完成的原生副作用。

目录审计仍为 80,625 个 JSON 用例、53,597 个上游文件、50,869 个未审阅文件；审计不是执行证明。整体对齐目标继续保持未完成。下一部分检查自举 bulk type merging 与 artifact type extraction 的独立类型边界，不能从本轮少量运行类型推断所有类型均覆盖。主工作区在门禁期间新增 `6575f015` 类型表校验自举提交，本轮冻结的 `4f5cb9cf` 证据不外推到该新提交。

实时证据核验需要复验起点中的冻结工作区 HEAD 及十个测试输入，后续复用该工作区前需保存并记录新状态；历史原始日志和草稿不会因工作区复用而改写。
