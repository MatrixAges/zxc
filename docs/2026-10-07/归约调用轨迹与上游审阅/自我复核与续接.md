# 归约调用轨迹自我复核与续接

## Intent：最终目标

本部分补足 Test262 的三个具体观察断言，继续推进全量上游与 zxc 特性覆盖。83,052 个 JSON 达到数量要求，但不是完成整个目标的证据；尚有 50,773 份上游原文件未审阅。

## Data：可用证据

三份上游原文使用锁定 archive 与索引 SHA，保留原始 harness，普通/严格模式 6 次实际执行通过。63 个 zxc 用例的输入、完整输出和逐项轨迹可从 JSON 查阅；独立的 JavaScript 原生 reduce 收集参考观察，ZX 通过实际 reduce 回调收集被测观察。

Debug/ReleaseSafe 各 63 个具名检查通过，实际二进制重放的名称、生成源码、支持文件和 SHA 均核对。两种模式、重放、增长数组元素和故障控制都不增加独立用例总数。相邻目标实际运行 38 个原有检查；新 63 个显示为缓存，原始日志明确保留此差异。

反向检查发生在生成物的副本中，把 previous 错误绑定为 seed，产生 45 个真实断言失败。此故障只证明轨迹对累加参数错误敏感，不代表 zxc 存在这项缺陷。未发现生产缺陷，因此没有给实现会话发送消息。

## Edges：批判与限制

原 JavaScript 的零/一形式参数、外部可变绑定及 undefined 返回没有在 zxc 原样执行。前两份仅适配被断言的计数和首参数观察，审阅理由明确限定归因；第三份保持 current 返回链并记录完整观察，提供更强的传递断言。不能把这三项称为原 JavaScript 文件直接在 zxc 中通过，也不能据此声称支持额外回调参数或闭包捕获。

主入口私有 type 的初稿违反已存在的入口组织约束；直接改为内联 Output 类型，符合最小修改范围。tsc 的首次路径错误和故障日志解析错误均属于本任务自身工具问题，已修正并记录，没有把它们误报给编译器实现会话。

整数样本均可被 JavaScript Number 精确表示，本文不覆盖大整数、浮点舍入或无初值 reduce。增长样本验证完整顺序与长度，未作分配次数、吞吐量或零装箱承诺。没有修改生产编译器和使用者 skills。

## Answer：续接入口与核验顺序

1. 查看本目录输入清单，核对工作区基线与 7 个正式输入 SHA；原有修改清单用于保护非本部分改动。
2. 在仓库根目录运行 `node packages/test/src/generate_reduce_observers.ts --check` 与测试包本地 `tsc --noEmit`，确认目录生成与类型约束。
3. 运行执行门禁脚本的 Debug 与 ReleaseSafe 模式，随后分别运行收集执行证据脚本，再运行核验门禁脚本。相邻目标通过执行门禁的第二参数 `test-array-callbacks` 运行。
4. 若编译器基线推进，先保存旧证据，正常同步隔离工作区，更新输入清单并重新执行，不用旧基线通过冒充新基线通过。
5. 后续继续用 query_upstream 查询未审阅文件，并阅读全文及全部断言；filter/reduce 的额外参数、动态对象和外部突变不能仅凭目录或描述批量判为已对齐。最新实现会话正在推进所有权控制流索引模型，需要在正式发布后为其补上实际分支/返回路径用例。

最终提交使用 `test(conformance): cover reduce callback observation traces`，实际推送结果以终端和远端引用为准。总目标仍保持 active。
