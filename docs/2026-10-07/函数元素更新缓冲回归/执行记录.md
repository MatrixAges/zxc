# 函数元素更新缓冲执行记录

## Intent：最终目标

补充 c938a523 函数内列表元素更新的运行回归，验证优化仍保持持久值语义，尤其首次借用输入、跨调用旧版本和同一调用的混合缓冲槽。继续推进全特性测试目标，本部分不是 Test262 全量完成声明。

## Data：可用证据

基线为 `7786ec66f09d193230b45e7ffc78df4220188e89`，包含生产实现 c938a523；Zig 为官方 0.17.0，Node 为 25.8.1。隔离工作区与 20 个精确正式路径见 `输入冻结.json`，逐字代码副本在 `草稿/`。

新增入口 `zig build test-function-updates`，已接入 test 包默认 `test`。共有 7 种源程序，各自通过源码和真实编译库消费者执行。编译库先编码、解码，再清零原始字节并销毁 provider 和编码存储，随后分析独立消费者的公开输入输出类型与调用；消费者并非直接重新生成旧 provider。

| 模式      | 验证对象                                             | 最终选中元素                   | seen                           |
| --------- | ---------------------------------------------------- | ------------------------------ | ------------------------------ |
| flat      | 函数内部循环，裸列表返回                             | a + mnδ                        | 0                              |
| branch    | 条件写入与禁用索引                                   | 启用时 a + mnδ，禁用时 a       | 0                              |
| chain     | 同一裸列表经过两次调用                               | a + 2mnδ                       | 0                              |
| captured  | 显式状态保留的旧列表在第二轮后读取                   | a + mnδ                        | max(n−1,0) × (ma + nδm(m−1)/2) |
| duplicate | 两个输出字段共享同一更新结果，下一次调用仍读取旧字段 | a + mnδ                        | n>0 时 ma + nδm(m−1)/2，否则 0 |
| fallback  | 无调用者循环，内部局部复用                           | a + nδ                         | 0                              |
| mixed     | 同一被调函数同时更新两列，一列共享、一列 null 回退   | left 为 a+mnδ，right 为 a+2mnδ | n>0 时 ma+nδm(m−1)，否则 0     |

a 是选中元素的独立初值，m 为外层调用次数，n 为函数内部循环次数，δ 为增量。fallback 的 steps 为 n，其余为 m。其它列表元素逐个比较原值；captured 的 mirror 保留最后一次被调函数的输入，duplicate 的两字段检查共享返回指针，mixed 的 mirror 是右列最终结果。

每个模式包含 18 项语义及错误清理检查、1 项同 arena 多次执行后的输出保留检查。flat、branch、chain、fallback、mixed 额外包含容量检查。因此每个优化模式为 5×20×2 + 2×19×2 = 276 项，Debug 和 ReleaseSafe 合计 552 项。OOM 检查还枚举真实分配失败位置；这些重试不重复计入目录数量。

输入使用可写列表，并在前后加哨兵；成功、索引错误和分配失败之后均深比较完整输入存储。零/一/二/多轮、257 内层循环、负增量、中间/末尾索引、空列表、越界、禁用条件、零增量和拒绝 resize 均有执行检查。

容量检查使用 65,537 个 i64，拒绝 allocator.resize；flat/branch/chain/fallback 为 17 外层、64 内层，mixed 为 2 外层、64 内层。实际分配字节要求小于 8 份列表负载。该预算区分安全复用与每轮复制大列表，但不承诺所有临时对象零分配，也不对需要保留多个旧版本的 captured/duplicate 施加错误上界。

在实际 Debug/ReleaseSafe 的 mixed 生成物中，被调函数调用同时传入 `.lane_0 = null` 和 `.lane_1 = .{ ... }`；两个字段分别走局部容量与调用者共享容量。对应完整生成物、ABI、二进制路径及 SHA、复跑原始输出见 `执行证据.json`。28 个真实测试二进制独立复跑均返回 0，合计再次通过 552 项。额外将 flat 生成物的被调函数加法改为减法，真实重新编译执行返回 1，出现 TestExpectedEqual；反例源码、命令与日志在 `反例/`，证明回归能拒绝错误更新而非只验证构建成功。

## Edges：边界与限制

初版草稿直接捕获 callback 外部 original，编译器按已有语言约束拒绝：ZX callbacks cannot capture outer bindings。最终改为显式循环状态字段 original；此次不是生产缺陷，没有通知实现会话。只读分析建议需要经过真实前端验证，不能直接当成语言契约。

第一个选到的缓存 CLI 仍要求分号，不能用于当前源码格式检查。改用当前缓存 CLI 后，所有 12 份 ZX fixture 的 fmt --check 通过；Zig 使用仓库 `scripts/format.mjs`，检查通过。两个工具选择失误没有转化为生产代码修改。

Test262 没有 zxc 特有的函数缓冲 ABI，因此本部分属于全特性运行回归，不新增 adapted/equivalent 评审，不改变现有 83,490 个目录案例的计数。后续仍需独立覆盖副作用错误顺序及 replacement 携带嵌套列表引用；本部分不借普通纯函数路径宣称完成这些边界。

## 自我批判与继续位置

闭式公式不模拟版本证明算法，能独立检查最终值、旧镜像和累计值；完整输入保护比只检查最终首元素更强。同 arena 输出保留检查防止跨 execute 调用错误共享容量。

生成物中的混合槽仅证明目标路径存在，运行断言和容量检查共同提供行为证据；没有把源码形状检查替代运行验证。拒绝 resize 与 OOM 覆盖是有限输入下的内存行为证据，不意味着所有规模与所有 allocator 行为已证明。

阶段完成只代表这一组纯函数边界已有可持续运行的回归。副作用、嵌套候选引用，以及尚未审阅的上游 Test262 文件仍是后续工作，整个目标保持进行中。
