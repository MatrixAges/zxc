# 整数复合赋值安全边界实施记录

## Intent：最终目标

验证真实 i64 复合更新在算术安全失败时的执行顺序、错误优先级和输入所有权。补齐先前宿主专项只在已定义数值域中执行、零右值仅用于提前失败或跳过路径的缺口。

## Data：可用证据

基线为 `32d54fc2687de79346cbbe8f03b6ab502bdcae5d`。正式改动仅六个测试文件：既有构建文件增加安全专项，新增独立进程入口和四个 TypeScript 文件。完整草稿、内容 SHA、基线 SHA 分别保存于 `草稿/` 和 `输入冻结.json`。

### 从根因确定测试边界

复合赋值包含目标读取、右值求值、算术、写回和后续语句，普通表达式安全测试只能证明算术自身；已有无溢出的更新测试也不能证明失败时的截断。这里让编译器输出真正的 compound 操作，再用同一静态原生 probe 捕获宿主调用。测试独立进程的 panic handler 保留 Zig 实际传入的原因，输出已经记录的事件与原始输入，以状态86退出；不会把进程失败转成应用错误或执行替代更新。

独立预期使用 BigInt 计算每轮结果和 i64 范围。除法向零截断，余数随被除数符号；`minimum / -1` 超出范围，`minimum % -1` 结果为0。完整预期包括返回值、original/mirror、steps/seen、每个 source/container/index/value/after 的参数及当前数值、调用方输入和 sentinel。驱动逐字比较 stdout/stderr、状态码和 signal，不只搜索 panic 文字。

### 场景与执行路线

五种操作均使用9个数值边界的81项笛卡尔积：最小值、最小值+1、-7、-1、0、1、7、最大值-1、最大值。这同时验证正负溢出、符号、零、单位值和有效边界。追加第一轮错误、第二轮错误、零外层/内层循环、非法索引、空列表、非法父容器、重复负数更新与最后元素。

加、减、乘分别添加第二轮实际溢出以及该轮五个宿主阶段的错误注入。source/container/index/value 应在算术前截断；after 尚未到达时不能遮蔽溢出。平面场景不调用 container，它的错误注入是未命中对照。除法额外保留零除数和最小值/1；余数额外保留最小值%-1的有效对照。

每项场景都执行平面、嵌套两类目标以及源码、真实编译库消费者两条路线，共20个二进制、2,044次进程执行/优化模式。库路线沿用现有 provider 销毁、编码字节毒化后的独立消费者分析，不冒充源码重编译。

两种模式合计实际观察到900次预期算术 panic、504次预期应用错误，均逐字匹配独立预期；其余2,684次为成功或跳过对照。没有发现经过验证的 zxc 生产缺陷，未向实现会话发送消息。

Debug 与 ReleaseSafe 共40个新增二进制、4,088次进程检查；既有专项回归42个二进制、1,216项/模式。两种模式合计124个实际二进制、6,520项检查。构建命令均为 `zig build test-function-updates --summary all --verbose`，分别传入 `-Doptimize=Debug`、`-Doptimize=ReleaseSafe` 及当前 Zig archive。

`test-function-update-safety` 可单独运行，且被既有 `test-function-updates` 与包总 test 纳入。原始构建日志、生成源码/ABI/native元数据、实际编译参数、二进制 SHA 和所有独立复跑结果保存于本目录。执行证据收集器同时重新运行新增进程专项与全部既有原生测试。

## Edges：边界与限制

实际主机为 macOS x86_64，Zig 0.17.0、Node v25.8.1；没有据此声称完成跨平台验证。

只验证开启 runtime safety 的 Debug/ReleaseSafe。ReleaseFast/ReleaseSmall 的整数非法行为不具有同样的 panic 契约，安全专项不会对它们套用安全构建预期。原有普通宿主测试继续正常注册。

本部分是 zxc i64 原生安全契约，尚不能证明 i32、unsigned、普通字段目标、浮点数和所有应用生命周期均已覆盖。已有其他类型普通表达式、IEEE state 更新专项各有独立证据，不能代替缺失的 compound 类型覆盖。

没有把这511项参数场景算入既有 JSONL 目录；目录累计仍为101,904项。没有新增 Test262 equivalent/adapted 声明，JS Number 与 i64 溢出契约不同。上游未审阅仍为50,688项，完整对齐目标继续推进。

未改变生产编译器、运行库或原生模块行为，未加入解释器、动态加载、序列化共享状态或 zxc 专用运行设施。所有新观察逻辑只存在于测试入口。

## Answer：交付格式与成功标准

正式测试、可复制草稿、IDEA计划、架构与数据流图、输入冻结、全量实际执行证据以及自我批判保存在本目录。发布要求：两种安全构建全部通过，六个正式文件与冻结 SHA 相符，124个实际二进制及独立复跑证据可核验，静态格式/类型/目录审计通过，根目录原有11项修改不被提交或覆盖。

### 自我批判

只测试退出状态86会误把其他 panic 当作预期，故必须逐字匹配实际原因、先发生的宿主事件和保持不变的调用方输入。只观察第一轮失败会漏掉旧值与写回后的样本，故追加真实第二轮溢出和第二轮宿主错误注入。预期不能使用 JavaScript number，否则 i64边界本身已丢失精度；这里传参、算术和报告均保持 BigInt/十进制字符串。

测试进程 panic 时以 exit 结束，不能据此声称清理了所有临时分配；正常和应用错误路径仍由既有分配失败扫掠验证。panic时检查的是外部输入不可被原地更改与事件截断，不声称异常退出进行了defer清理。

当前 Zig 0.17 使用 debug/safe 优化枚举值，历史 Debug/ReleaseSafe 为兼容常量，不能用 `.Debug` 推断枚举字段。初始构建因此失败，改为标准库 `runtimeSafety()` 判断，再按实际 debug/safe 标签编译测试入口。另修正草稿写入时的字符串换行格式。这些属于测试实现问题，没有作为 zxc 生产缺陷通知实现会话。

### 续作入口

继续覆盖定宽整数的普通字段与嵌套字段复合目标，尤其 unsigned 下溢、窄类型写回及多轮样本；再审阅 remaining compound-assignment 数值与语法原文。将每一种缺失行为映射到真实语言契约，不能靠增加参数数量代替上游逐项审阅。

验证在仅含本轮六个正式测试改动的复用 worktree 中完成；发布时逐项核对输入冻结与根目录基线，原有11项用户修改保持原始 SHA，不将根目录未提交的生产源码修改混入本轮验证或提交。

生成 Zig/ABI 原字节包含额外文件末尾空行，完整暂存 diff 的默认 blank-at-eof 检查因此报警。没有改写证据；正式 packages 文件保持默认严格空白检查，完整证据 diff 仅关闭 blank-at-eof 规则，其余空白规则照常检查。

提交 hook 的 gpu-code-spacer 改变了两个 Zig 文件及配套草稿的空行，提交后 SHA 核验准确捕获该差异。已从独立 worktree 保留实际构建时的原始源码于 `执行输入/`，`输入冻结.json` 分别记录 executed_sha256 与交付 sha256；核验器要求所有非空行逐字相同，并继续验证原始输入与124个实际二进制。没有将格式化后的 SHA 冒充执行前 SHA，也未因仅空行变化重复扩张算术测试。
