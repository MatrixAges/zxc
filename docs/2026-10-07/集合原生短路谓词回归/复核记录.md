# 集合短路谓词自我复核

## Intent：最终目标

核对交付是否实现普通列表 every/some 的真正短路，同时防止测试计数、历史断言和并行开发造成错误结论。

## Data：可用证据

- 生产改动只沿统一 Transform、分析、IR 校验、错误效果、所有权摘要和 Zig 生成路线延伸。输入只求值一次；回调表达式位于 for 的条件中；决定结果使用带 bool 值的标签块 break，实际离开遍历。
- 原生宿主记录实际调用次数和参数顺序；结果与调用次数来自显式样例，不使用一份手写遍历复制生成器算法。直接值用例由 Node 的标准 every/some 计算期望。
- 源码和编译库路线分别执行真实 Zig 测试。库路线在消费前销毁分析及解码临时存储并覆盖旧字节，新消费者通过公开导出调用，不能以原 provider 继续执行代替消费。
- 标量原生回调每次检查 arena 容量为零；输入使用可写缓冲和前后哨兵，整块原值必须保留；同一 arena 连续执行时前一次 bool 结果保持独立。
- 构建缓存可能省略已经通过的测试计数，因此编译器三个真实二进制另行重放，核验 39 + 313 + 20 项。保存二进制 SHA、日志 SHA 和每个测试名称，不从总构建步骤推算测试数量。
- 发布前合入远端两笔生成器提交；合入前证据保留在 `并行合入前/`，最终证据必须对应新的冻结输入和基线提交。

## Edges：边界与限制

“无分配”只指结果容器和本部分标量回调执行。回调或目标表达式主动构造集合时仍可能分配，并保留对应 OutOfMemory；不能推广为任意谓词程序都不会分配。

ZX 仍要求单元素、无捕获、bool 回调。JavaScript 的额外回调参数、稀疏数组、动态类型及 truthiness 不在当前 API 范围。二维越界期望使用 ZX 显式 IndexOutOfBounds 语义，不把 JavaScript 的 undefined 当作等价行为。

三个历史测试文件的修正只证明当前持久列表分析和 IR 合法性；不能单凭这些前端检查证明 Store 跨请求生命周期。Store 权限、禁止深拷贝、Task 线性使用和现有运行时门禁仍各自承担其职责。

矩阵审计的 83,317 项只是当前登记的 JSON 用例总数，不代表本部分执行了整个矩阵。Test262 的 50,768 个未审阅条目保持原状态，本次没有提高任何上游等价性结论。

准备阶段出现的空行诊断来自测试样例；core/genz 没有 test 构建目标，调用 core test 是工具使用错误。26 个所有权失败在旧基线与新实现完全相同，根因是测试仍使用已废弃的普通列表消费契约。它们均不作为新增生产缺陷通知其它会话。

合入后曾在 ReleaseSafe 编译尚未结束时读取正在写入的二进制，产物收集得到 Exec format error。已修正收集器：先验证当前基线的构建门禁实际完成，再读取二进制和重放；该错误不归因于生成代码。

## Answer：交付标准与检查方式

执行 `核验交付.py` 核对 48 个隔离输入与草稿、11 个原有修改、最终基线、实际执行日志和生成物 SHA。同步后增加 `--formal`，精确暂存后增加 `--staged`。只在全部通过后提交；提交钩子运行后再次复核，发现字节变化则重新验证对应改动。

IR 序列化版本为 25，旧编译库必须重建；生成指纹为 v27，保留上游 v26 所含优化。本部分不添加 zxc 专用运行库、解释器或动态加载层。
