# 复合赋值宿主求值顺序实施记录

## Intent：最终目标

把现有普通赋值、加法的宿主调用观察补齐到减、乘、除和余数复合赋值，验证每一类操作真实的目标求值、右值错误截断、更新后样本及输入所有权。继续审阅上游动态属性协议，避免用整数索引替代 ToPropertyKey 后声称兼容。

## Data：可用证据

最终验证基线为 `bf80dc708c3101771f719af5436338068a9dd279`；起始基线为 `b019d274aeb6352596d82a751013b2441223bae8`。本轮 15 个正式文件的最终 SHA、起始内容 SHA 与草稿见 `输入冻结.json`、`草稿/packages/test/`。一名只读分析代理完整读取 44 份 A7 原文，主 agent 另核对原字节、索引 SHA、断言数并执行原文，没有交由代理修改代码或通知实现会话。

### 实际操作与路线

新增 8 份 ZX fixture：四种操作分别提供平面列表元素和嵌套父容器版本。运算必须发生在真正的 state 更新语句中，例如：

```ts
state.values[probe.index(state.selected)] /= probe.value(state.delta)

state.round = probe.after(state.round) + 1
```

新模式与现有普通、加法模式均执行源码和真正编译库消费者两条路线。消费者在 provider 分析/库对象销毁、编码原字节毒化后重新分析，不使用同一份存活 IR 假充库消费。native 模块导入名继续从生成 IR 元数据读取。

宿主事件记录 source、可选 container、index、value、after 的顺序、次数、参数及当前选择位置的数值。新测试独立按各运算的 Zig 整数语义迭代预期，既比较最终数组，也比较每轮 source 的最新样本。原数组和两端 sentinel、original/mirror 引用观察继续保留；错误后的更新、后续语句以及未命中的错误均核对。

七项新宿主测试为：有符号右值、零右值且零轮次、零右值的 ValueFailure、先发生 IndexFailure、先发生 SourceFailure、非法索引先于零算术、空列表先于零算术。它们应用到所有已有和新增 native 模式，不仅覆盖新模式。

### 上游 A7 原文

44 份为 11 种运算符 × 四种原文：

- T1：null 基。prop() 的 DummyError 应先发生；动态键对象时 TypeError 先于 key.toString 与 RHS。
- T2：同样要求，基值为 undefined。
- T3：对象基的 ToPropertyKey/toString 抛 DummyError，RHS 不执行。
- T4：toString 内 guard 阻止重复调用，没有末尾计数或写回值断言；原文显式限制至多一次，不能把描述文字当独立 exactly-once 断言。

共 66 项原显式断言（55 次 assert.throws，11 次 guard）。没有 flags/includes 的额外要求；执行在每个新 realm 中先加载锁定的 sta.js、assert.js，再独立运行原文。严格指令位于测试脚本开头，没有拼在已执行 harness 的末尾。计数包装在同一 realm 中调用原断言函数，保留自定义 DummyError 与内建 TypeError 的构造函数身份检查。

44 份均登记 excluded、cases 为空：这是尚未兼容的真实动态属性要求，不把新增 native 整数索引控制映射成它们已通过。移位/按位六组还存在操作符集合边界。对应 SHA、要求和断言数见 `上游原文清单.json`。

### 两个参考引擎的真实结果

| 引擎         | 原文执行次数 | 通过 | 失败 | 实际断言调用次数 |
| ------------ | -----------: | ---: | ---: | ---------------: |
| Node v25.8.1 |           88 |   66 |   22 |              154 |
| Bun 1.3.10   |           88 |   88 |    0 |              132 |

Node 的失败全部为 T4：第二次属性键转换触发 `Expected true but got false`，尝试调用两次 guard。没有修改原文、重置 guard 或忽略错误。独立直接赋值控制也得到 Node 两次、Bun 一次，说明差异可以脱离 vm/断言计数包装复现。

Bun 在同一份锁定原文和 harness 上通过。两边分别保留证据，不能把 Bun 通过写成 Node 也通过，更不能把 Node 的参考引擎行为通知为 zxc 缺陷。额外观察的末尾 propKeyEvaluated 标志与原显式 guard 分开记录。

## Edges：边界与限制

本轮宿主整数算术位于已定义域。乘法长循环的默认因子为 2，最大51轮仍在 i64 范围；其他模式保持原默认右值 7。有符号右值 -2 保留除法向零截断和余数随被除数符号的观察。

零右值仅在零轮次或更早错误/边界时使用，检验不应进入算术的路径。没有把整数溢出、除零的进程安全失败当可捕获错误；它们的 compound 专项进程失败验证仍需继续推进。独立预期使用 Zig 原生整数操作，不读取生成实现；它的职责是状态与调用轨迹对照，不能代替此前独立 IEEE 数值模型的全部算术证明。

JS 动态 ToPropertyKey、null/undefined 成员基与类型化列表/嵌套索引不是同一机制。本轮两种测试结果并存，不把一个框架的支持范围偷换成另一个框架的全部语义。

未新增生产运行库、解释器、动态装载或持久化状态目录。新预期 helper 只在测试中使用，真实编译产物仍为普通静态 Zig。

### 自我批判

不能继续把所有复合操作的 source 样本算成加法闭式预期，因此改为逐轮独立整数运算；若乘法沿用51轮因子7会触发不属于本轮目标的溢出，改用有效范围的因子2，并保留负数与边界截断控制。

初始假设 Node 可以通过所有原文，被 T4 实际结果否定。完整保留失败并用另一个引擎及独立直接赋值控制核对，而不是修改测试降低要求。Bun 的 vm host 侧属性替换不能可靠统计调用，改为同一 realm 包装原断言后，两个引擎的计数均与真实执行吻合。

本阶段没有发现经过复现的 zxc 生产缺陷，因此没有向实现会话发消息。上游 excluded 增加44代表明确未兼容要求被审阅，并不代表这些功能已经实现。所有特性与 Test262 对齐的总目标仍未完成。
