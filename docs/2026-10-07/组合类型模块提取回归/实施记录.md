## 真实数据和职责

main.zx 导入 noise 的普通函数、types 的 Request/Response 和 zig:host 的声明接口。noise 导出一个不被 main 引用的 Noise enum，合法占据较早的全局类型编号。types 声明 Mode enum、包含 u64 和 Mode 的 Record、Node 引用、tuple/list/optional 及 Request/Response。main 建立一个可能失败的并发 task，随后 await；Node 仅通过同步 identity 传入并返回。

这些源码经 project.analyze 得到实际 AnalysisResult、ModuleRecord 和完整合法 IR。没有手工伪造全局类型表，没有交换类型行来制造差异。提取模块按真实路径查找，不依赖分析遍历下标。Node 的来源 key 为 fixture@1，原生 Zig 导入名为 host，声明 specifier 为 zig:host；三者分别检查。

## 断言边界

主模块 artifact 包含全部九个 tag，保留完整 Scalar 前缀，验证 Mode 在对象、tuple、list、optional 中的同一身份，以及输出与输入的共享字段类型。由于 Noise 被裁剪，Mode 和相关复合类型的全局 ID 与局部 ID 确实不同。Node 不要求编号变化：它可能早于 Noise 导入。

纯类型模块保留声明图、source/native 两个 nominal 来源和 Node 原生描述符，排除主模块的 task/error_set。主模块保留虽未调用但已检查的 noise 函数导入，Noise enum 则不属于主模块闭包。完整原生描述符的类型属于根，不能把它们错误当作未使用类型裁剪。

释放整个 AnalysisResult 后，分别读取主模块和纯类型模块 artifact：字段名、枚举成员、来源路径、原生 identity/namespace、依赖 names、函数 namespace/member/export_name、NativeFailure 名称以及 task 捕获符号均仍可读。按函数绑定的本地 ID 定位签名，按 task 表达式检查实际 call 的引用。

只改真实 nominal 元数据：缺失必要 Node 来源精确返回 MissingNominalOrigin；重复 Node 来源或名称不匹配精确返回 InvalidModule；缺失未保留的 Noise 来源仍成功。每次变异后原完整 IR 仍通过 validateIr，避免把无效类型或宿主 owner 当作来源选择器错误。

三个 OOM 声明分别验证主模块成功、纯类型成功、必要来源缺失的拒绝路径。分析和深快照先在 std.testing.allocator 上完成，只有 artifact.extract 使用失败注入 allocator。成功、OOM 和预期拒绝均比较八列类型和五列 nominal 元数据；字符串字节也深复制，避免快照共享输入字符串而掩盖变异。公开 extract 包含完整 IR 前置校验，因而此扫掠包括它的分配，并非仅覆盖内部拷贝。

## 可复制的调用边界

```zig
var analysis = try f.analyze(std.testing.allocator);

defer analysis.deinit();

const index = try f.moduleIndex(analysis, "/project/main.zx");
var result = try f.artifact.extract(std.testing.allocator, &analysis, index);

defer result.deinit();

const module = result.value;
const ids = try graph.check(module.types, module.function.?.input_type, module.function.?.output_type);

try metadata.nominal(module, ids);
try metadata.native(module, ids.node);
try graph.task(module);
```

## 自我批判和未覆盖范围
