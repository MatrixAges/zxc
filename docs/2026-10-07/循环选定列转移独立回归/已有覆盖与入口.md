## Edges：边界与限制

### 输入、别名与输出生命周期

宿主构造 Frame 和标量 seed 时，把它们放在注入失败的 Arena 外。保存 execute 的 error union 后，检查所有 input 的值、长度、外层 slice 地址、Frame 元素字段及适用的元素身份，再处理成功或错误。这使 OOM、bounds、捕获和恢复都承担输入不变要求。

同列重复输出：非空结果应具有相同 ptr/len 和逐项值，不仅“两个列表值相等”。双列：使用内容不同、长度不同的种子，并另设两个列共享同一输入 slice 的 case；正步更新后分别符合独立 oracle，非空结果的内存区间应独立。两个空 slice 的地址比较没有足够证明力。

同 Arena 后续调用是宿主 harness 维度，直接复用前两夹具，无需另加第七个 ZX 文件。先保存第一结果，再用不同 seed/count 调用第二次，调用后同时重读第一和第二的所有输出，包括 mirror 身份；再安排错误调用和成功恢复，继续读第一结果。

当前 execute 结果没有独立销毁入口。测试应先读取所有仍有效结果，之后只 deinit Arena；比较 backing 分配/释放并检查无泄漏。不得在 Arena 销毁后读取旧结果，也不得对 borrowed seed 或重复列字段手工 free。若上层应用另有 owner 协议，它属于单独契约，不能为本轮虚构。

### OOM 与 after-transfer 错误需要两类证据

复用 allocation_testing 对 generated execute 的正常、零步、双列、错误和 retained call 路径注入失败。在无故障运行，非法输出索引必须是 IndexOutOfBounds；注入失败可以先 OutOfMemory。

Arena 的 backing allocator 看不到每个内部逻辑 allocator.create/free；同一块内的分配不会各自触发 backing fault。最后 Arena.deinit 的分配释放相等也不能单独证明转移后的 errdefer 即时 free。必须结合生成源码，验证每个 owned 临时变量存在 errdefer、第二列转移/投影/结果构造位于第一列成功转移之后、未选列保留 defer。禁止将普通全分配失败遍历报告为“已强制命中每个具体转移后分配点”。

可精确触发的 after-transfer 语义错误是 `state.columns[in.selected]`：scalar projection 允许 index 独立于 loop 状态。结果证明先转移列表路径，再读取投影，所以列长度边界错误发生于 finish 之后；源形态确认顺序后，普通 bounds case 提供直接执行证据。

捕获上下文将失败改成 break 控制流，不等同于 Zig 错误返回，不能依赖普通 errdefer 假装安全。直接 capture loop 验证回退；capture 一个独立 helper 调用则是另一条边界：callee 的普通错误返回可以清理，caller 捕获其错误。两者不能互相替代，也不能仅看出现 `try` 就认定触发 result.eligible 的 capture 门禁。

### 资源和形态要求

带 Frame[] 的状态用于真实触发聚合 local list_plan；只保留 u64[] 的 loop 可能不进入本轮入口。不要删掉聚合帧操作来简化测试。

输出 columns 长度按步数增长，其成功内存当然可以随输出大小增长。只对未选 scratch 和 Frame peak 判断不应有额外逐步保留，预算应与 seed 长度、最终输出列长度和最大帧长度相关，不能要求所有运行 bytes 常数。

前两夹具检查唯一选定路径数等于 toOwnedSlice 的站点数，转移之后更新状态 slice，再读取同一路径的所有输出；临时帧和 scratch 都保留 defer。形态检查限定目标 execute/helper 的有关循环，不固定 fresh 后缀，也不把全文件 allocator.create 视为错误。返回对象本来可能需要正常分配。

source/library route 与真实 CLI route 分别保存自己的形态和 runtime 证据。既有 artifact codec roundtrip 不自动覆盖 CLI package publication，若范围只含 link/codec，文档应准确命名。

## Answer：最多六个普通夹具家族

### 共同基础与普通 ZX 形态

前四个建议沿用已存在的混合返回 stack 原文。若担心指数增长影响资源用例，可采用以下普通线性版本；它仍保留 Frame push、旧元素快照、字段更新、pop、optional，以及内部 scratch。

```zx
export type Frame = { position: u64, count: u64 }

export type Input = { frames: Frame[], columns: u64[], count: u64, selected: u64 }

export type State = { frames: Frame[], columns: u64[], scratch: u64[], index: u64, count: u64, total: u64 }

export type Output = { total: u64, columns: u64[], mirror: u64[] }

export default function (in: Input): Output {
    const initial: State = { frames: in.frames, columns: in.columns, scratch: [], index: 0, count: in.count, total: 0 }

    const state = loop(initial, {
        while: current => current.index < current.count,
        next: current => {
            current.frames = current.frames.push({ position: current.index, count: current.index })[0]

            const previous = current.frames[current.frames.length - 1]

            current.frames[current.frames.length - 1].count += 1
            current.total += previous.count + current.frames[current.frames.length - 1].count

            const [remaining, popped] = current.frames.pop()

            current.frames = remaining

            if (popped != null) {
                current.total += popped.count
            }

            current.columns = current.columns.push(current.total)[0]
            current.scratch = current.scratch.push(current.index)[0]
            current.index += 1
        }
    })

    return { total: state.total, columns: state.columns, mirror: state.columns }
}
```

此草稿未编译。独立宿主 oracle 第 i 步加 `3i+2`，最终 total 的 0/1/2/3 步为 0/2/7/15；新列依次追加 2、7、15……。不得调用生成实现计算自己的 expected。若采用既有指数 stack 原文，改用 `t'=4t+2` oracle 并限制步数，两种预期不能混用。

### 1. repeated_column.zx：同一路径重复出现

使用共同基础，输出保持 `{total, columns, mirror}`。输入列取空、`[91]`、`[91,4,91]`，Frame 种子取空及非空；步数 0/1/2/3/17。成功结果逐项匹配 seed+oracle prefix，并检查非空 columns.ptr==mirror.ptr，len 相同，所有宿主输入未变。

源码检查列只有一次 toOwnedSlice，两个结果字段都从转移后 state.columns 读取，Frame 与 scratch 不转移。全分配失败覆盖正常结果对象构造；同 Arena retained calls 用不同 seed/count 重读前次 mirror。此夹具直接补齐现有草稿“只比较 JSON 值”的不足。

### 2. two_columns.zx：两个独立路径与嵌套结果

在共同基础增加 `other: u64[]`，从 `in.other` 初始化，每步 push `current.index + 100`；保留 scratch。Output 改为：

```zx
export type Output = { first: u64[], detail: [u64, u64[]], repeated: u64[] }
```

最终直接返回：

```zx
return { first: state.other, detail: [state.total, state.columns], repeated: state.other }
```

输出顺序有意与状态列声明顺序不同；other 重复一次，columns 位于 tuple。它同时检查路径选择、tuple 构造、表达式去重和两个独立 transfer。期待两个 toOwnedSlice，而非三个。

使用 columns `[8,3]` / other `[77]`，及两者借用同一个 `[5,5]` 输入的 case。正步结果分别追加不同 oracle，非空输出区间互不重叠，first 与 repeated 相同地址。OOM 包含第一列已转移后第二列处理的顺序；检查相应 errdefer，并准确记录可实际注入的 backing fault。资源预算允许两条输出增长。

### 3. zero_borrow.zx：非空列零步与 scalar/tuple 混合

共同基础的 loop 不变，Output 改为 `{ columns: u64[], summary: [u64, u64] }`，直接返回 `{columns: state.columns, summary: [state.index, state.total]}`。

重点输入 columns=`[31,0,31]`，count=0，frames 空/非空。期待 summary `[0,0]`，列值和地址均保留宿主 seed；没有 begun 的标量列不应被替换成 take 的临时空 slice。Frame 初始转换及输出包装允许分配，所以同时做零步 OOM，不设零分配断言。

count=1 对照期待 `[1,2]`，列变为 `[31,0,31,2]`，输入 seed 保留；新列不得通过原地修改输入获得。同 Arena 第二次调用用另一组 seed，前次借用结果仍依赖原种子存活，必须保留两个输入 owner 到检查结束。

### 4. after_transfer.zx：完成转移后执行越界投影

共同基础的 loop 不变，Output 和最终 return 改为：

```zx
export type Output = { columns: u64[], selected: u64, length: u64 }

return { columns: state.columns, selected: state.columns[in.selected], length: state.columns.length }
```

只从 state 的投影构造结果，避免插入 helper call 或其他绑定导致入口变化。先通过源码确认 finish、状态 slice 更新、index/length 读取的顺序。

列 seed `[9,4]`、count=2：输出列 `[9,4,2,7]`；selected 0/3 分别为 9/7，length=4。selected 4 和 maxInt(u64) 在无故障运行是 IndexOutOfBounds；count=0、空列 selected=0 也失败。非空增长 case 的非法索引用于直接验证已经 started 的列转移后失败，不能只测试零步未转移的错误。

宿主输入在所有结果前检查；失败后同 Arena 用合法 selected 再执行并验证恢复，同时检查此前 retained 结果。OOM 和终态 Arena 清理照既有 helper；源码 errdefer 是必要补充证据。

### 5. captured_loop.zx：捕获直接 loop，完整回退

使用相同初值和步体，将绑定改为 `const [err, res] = try loop(initial, {...})`。错误分支返回普通 `{ok:false,total:0,columns:[]}`；成功分支返回 `{ok:true,total:res.total,columns:res.columns}`，Output 为对应 object。普通语法可沿用 typed_try 的 error/res refinement；具体草稿仍需主代理确认 CLI 接受。

此处捕获 loop 的完整 State，不试图让内部 Frame[] 以值布局转移给公开调用者。它验证捕获状态的回退、成功结果列与错误处理，不声称仅凭该写法就精确命中了 mixed result.eligible 的 capture 拒绝分支；生成 IR/源码必须确认实际边界。

成功输入至少覆盖 0/1/3 步与非空 seed；错误/OOM 按实际有限错误集处理，捕获到 OOM 后的错误输出构造也可能再次 OOM，后者应正常传播。不要让测试吞掉未知错误。源码检查不得要求选定列内联，runtime 必须保留输入、列值、错误分支和清理。

### 6. helper_result.zx：普通模块边界与库消费
