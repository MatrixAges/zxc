# 准备修正记录

## Intent：最终目标

排除测试准备与观察自身的误判，真实验证产品 reader 及原始箭头断言。

## Data：可用证据

准备 Debug 进程真实终止为 1；63/104 构建步骤成功，114/114 已运行测试通过，全部为原有 60 与新增 54 箭头用例。八组产品程序尚未实际运行，不能登记通过。准备输入清单与修正前源码保存原字节。

## Edges：边界与限制

七组程序被自有结构检查误判：reduce 生成普通 for，检查却只接受 while。nested 自有夹具用了当前 ZX 不支持的 optional access 写法，应以普通 coalesce 后读取字段表达相同 null/非 null 值，仍保留独立期待。未确认生产缺陷，不向实现 chat 发送这些准备失败。

## Answer：修正与成功标准

限定 execute 中至少两个 for，分别来自 seed map 和 reduce；按输入 IR 的 read.zx 身份识别实际 reader 调用，不只数 helper 定义。普通函数至少定义加一次调用；value helper 阈值额外排除自身 ABI wrapper 的一处转调。未固定函数编号，不要求全部 ABI wrapping 零分配。

自我复核另外删除 mirror 与 values 的公共 ABI 指针相等要求，语言只承诺产品值；改为完整逐记录比较。caller 输入指针槽不变仍是合理观察。正式语义、字符串字节、旧结果留存与增长边界不放宽。修正后在最终冻结输入上重新运行两优化模式。
