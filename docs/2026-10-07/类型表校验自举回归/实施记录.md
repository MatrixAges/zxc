## 具体覆盖

| 分类       | 独立声明 | 观察                                                                                                                                           |
| ---------- | -------: | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| shape      |       36 | 四个行列长度、field 配对、未消费尾部、四种非连续/最大 range、未知 kind 9/255、非法 label 与无效 first/second                                   |

Fixture 通过公开 TypeStorage 真实追加完整 11 个 Scalars 和八种复合 tag，不假造最大 slice 长度或无效指针。普通 tuple/object/errors/enum 起点来自真实构造；enum 位于 error_set 后，具有非零 names offset。最大 u32 只写入真实短数组中的 first/second/child 字段。

每条语义负例先由独立 core validStructure 确认列形状合法；每条 shape 负例确认结构拒绝。所有条目随后通过公开 compiler.validateIr，使用仅含 void input/output、无表达式和函数的 type_only Program；native_ref 正例具有对应 NativeModule owner，而不是通过缺失 owner 取得假拒绝。拒绝断言常量 contract 诊断、准确零 span 和消息。

每次校验前在独立测试 arena 复制八列；校验后逐列比较整数与字符串。实际调用使用 fail_index=0 的 FailingAllocator，所有接受与拒绝都断言未诱发分配失败。正式生成校验器自身也由生产 wrapper 的零容量 arena 执行；任何意外分配/越界 panic 都不会被测试视为正确拒绝。

## 失败与修正

首轮 Debug 终止码 1：references/allowed 两个测试入口缺少 ir 别名，分别编译失败。其余 shape36 与 names20 实际通过，但首轮整个门禁不能记为通过。修正最小导入后先格式化、同步哈希，再执行双模式新缓存门禁，最终全部通过。首轮日志与当时输入哈希保留；这是测试夹具错误，没有向实现会话发送缺陷消息。

复用工作区前，已确认前轮循环草稿十个输入与其正式提交哈希完全一致，保存前轮 diff 后仅撤回自己拥有的修改，并切至本轮干净冻结提交。历史循环实时核验脚本需恢复旧 HEAD 与补丁；历史日志和草稿未改写。

## 自我批判与续接

范围检查使用 core 原生形状检查和具体契约双重观察，未复制 seed 算法作唯一 oracle，但不能当作形式证明。超过 u32 的实际列长度没有构造；以最大 u32 字段覆盖加减与索引安全，不能据此声称真实 4GiB 分配经过验证。

允许值依据 IR validator 当前公开契约；enum 的宽松标签/成员和 object 的非空字节排序不表示源码声明语法自动接受这些名字。类型表校验通过也不证明该表对应的任意可执行 Program 合法。

本轮未发现真实实现缺陷，未发送实现会话消息。目录矩阵仍为 80,625 个 JSON 用例与 50,869 个未审阅上游文件，目录审计不测执行结果。总体生产级语言和 Test262 对齐目标继续未完成。下一部分优先检查 bulk merge/artifact extraction 的独立重映射、原生名义类型与内存失败边界，不从这组校验器测试推断它们已经覆盖。
