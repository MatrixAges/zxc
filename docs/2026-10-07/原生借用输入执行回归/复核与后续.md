# 原生借用输入执行回归复核与后续

## IDEA

- Intent：将 native 借用值调用从分类推进到真实执行，并明确语义与优化证据的界限。
- Data：四类 payload、两条源码/统一编译库消费路径、每路径 8 项命名 Zig 检查；生成产物实际调用 callBuffered 和 callValue。
- Edges：运行次数、优化模式、参数矩阵和 allocator 故障点不另计 JSON 或 Test262 审阅。借用输出的调用者所有者保持合法存活；Arena 释放后不访问 Arena 自有分数列表。
- Answer：每优化模式 64 项执行检查、完整原始产物与命名测试输出，独立检出与输入 SHA，可恢复执行记录。

## 已覆盖的语义

- 字符串：空字符串、ASCII、嵌入 NUL、中文和四字节 UTF-8 字符。
- 数值列表：空列表、不同位置值、零、65535、重复值。
- 嵌套列表：空外层、空行、不同长度行、等值独立行所有者和共享行。
- 可选字符串：上列字符串及 null，记录 presence，区分空字符串与 null。
- 空 reduce 不调用 native；现有 seed、每个动态 step、1024/4096 步增长、同 Arena 后续不同输入均保留完整值。
- 每一步四个 native 调用的顺序、校验值、长度和存在状态。28 个原生失败点跨第一次与第二次执行，失败后不得调用后续 native。
- 第一条执行和后续执行的每个 backing allocator 失败点；输入快照与首次逃逸结果必须在传播错误前仍有效。
- 真正的 native OutOfMemory：host 使用 allocator 分配 64 个 u64 的临时缓冲，保持原数值结果；必须观察到实际失败，不能仅有生成代码中的分配失败。
- 库提供者、原始库和编码字节在消费前释放；解码库通过新的 consumer 编译并实际运行。

## 证据解释

callBuffered 和 callValue 是模块化输出中的名称。不能只检索单文件输出使用的 function_N_value，错误计数为零。生成清单核验二者的实际调用，并保留所执行代码；命名测试还验证该路径不消除、缓存或乱序执行 native 调用。

原始生成文件全部以 .txt 保存，保持真实编译字节，包括 JSON 元数据与日志；避免 pre-commit formatter 重写原始证据。SHA 同时核验实际缓存文件、保存文件和 Zig 命令引用的文件。

## 自我批判

1. 多次准备失败来自测试夹具：导入分组、公开 Input/Output 契约、push 返回元组、Zig 模块根限制。未把测试作者错误当作生产缺陷。
2. 最初 8 字节 native 分配总被 Arena 剩余容量吸收，无法证明 native OOM 分支执行。改为真实临时缓冲请求，保留必须观测到 native OOM 的断言，没有人工返回错误或按 case 编号造结果。
3. 校验和可能碰撞，因此输出 payload 要完整比较，输入所有存储及行指针/长度快照也分别检查。指针只用于证明调用者存储没有被修改，不要求公开输出与输入拥有相同物理地址。
4. 生成形态说明值调用和缓冲路径参与运行，不证明特定性能上界；本轮 native 本身有实际分配，不把总分配量误作 zxc 额外成本。
5. 实现会话在测试期间发布缓冲改动，必须保存旧证据并同步重跑，不外推结果。
