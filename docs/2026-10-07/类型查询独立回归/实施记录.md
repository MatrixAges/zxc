## 第一性契约

类型表要求完整 Scalar 前缀，子类型先于父类型，查询根 ID 有效。数据本身是有序 DAG：根之后的行不能改变该根的可达目标或触发本来不需要的分配。所有夹具先通过正式 validateTypes，不用循环、越界或伪造 Analysis 测试一个不存在的输入契约。

两个模式具有明确差异。NativeReference 从 optional/list 的子类型、tuple/object 的成员和 task.result 传播；List 从 optional 和 tuple/object 传播，list 根直接命中，却刻意不穿透 task。task.errors 是错误集合，名字或成员文本也不构成类型边。即使 root 前已有目标行，非祖先噪声也不能变成肯定结果。

直接目标根在分配前返回 true；根前没有该模式的目标行时在分配前返回 false。其他情况按前缀顺序生成 bool 标记，借助之前完成的子类型标记计算根结果。测试使用手写图关系及明确布尔预期，没有比较两份同源算法的输出，也没有添加生产 case-id 分支。

## 深宽图和状态独立

2048 层 optional 分别以 Node、list<u64> 和 u64 为底层。纯 u64 链在根之后再放两个目标，观察目标不能反向污染根或阻止早退出。宽 tuple 把唯一目标放在最后一个 pooled child，避免只覆盖首成员；普通宽 tuple 以及空 tuple 的前缀包含无关目标，仍必须返回 false。

共享正例在根和列表目标间多次复用子类型。自我复核发现正例可能首项就短路，不能充分观察重复路径展开，因此在首轮 61 项通过后补充共享负例：1024 层 tuple 每层重复引用前一层，全部祖先均无目标，而前缀含无关 Node/list。最终新增数为 62。负例通过证明该输入没有指数展开或递归栈问题，不把有限样例说成所有图的复杂度证明。

同一小图按反向根顺序交替查询 List/NativeReference，共三轮；根直接命中、正例和负例混合，八列及字符串字节始终不变。每次使用独立 caller Arena，结果是 bool，没有可逃逸的临时切片。

## 资源与失败契约

查询 owner 在稳定地址初始化 Arena，defer 统一回收。输入、预期和深快照在另一个输入 Arena 中准备，排除夹具构造分配；对输入八列逐项核对，字符串列同时核对长度和每项字节。

资源正例/负例在两个模式下均经过慢路径，FailingAllocator 确认发生过分配，查询返回后 allocated_bytes 等于 freed_bytes。故障扫描复用 tests/support/allocation_testing.zig：禁止 backing allocator resize/remap，再由 Zig 标准 checkAllAllocationFailures 按无故障基线的每个 owner 分配点注入失败。要求精确 OutOfMemory 向外传播、输入不变、失败时已分配字节全部释放。另对公开 Types.containsList 做同样扫描，验证包装器没有吞错。

故障场景为混合 DAG 两模式、负向宽 tuple 两模式、task 内深链两模式及公开 List 正例。扫描范围是 Arena 的 backing 分配点，不声称枚举每次 ArrayList append/resize 的内部 API 调用；Arena 可服务多个内部申请。没有固定分配次数或 malloc 编号，生成优化后扫描根据实际基线自动调整。底层 resize/remap 被禁用不代表所有平台分配器行为被穷尽。

## 自我批判和整体进度

- 合法 TypeTable 包含 task 的 NativeReference 结果，用来验证查询拒绝候选；不声称那些 task 已经通过完整可执行 IR 检查。相邻门禁验证既有任务规则，而不是把表校验当程序执行。
- 慢路径资源释放由查询 owner Arena 验证，不能推断每个内部缓冲在任意调用者 allocator 下都即时归还系统内存。快速路径只证明指定根/模式没有分配。
- 深宽测试只覆盖具体结构与规模，不穷举任意节点数、字段池或输入别名布局，也没有执行独立应用程序。没有以复制 seed 或手写 native 查询作为 oracle。
- core.ir.containsNativeReference 仍是手写 Zig；本轮直接 generated_type_query 的结果不能宣布所有 native 查询使用点均已迁移。最终自举还需规则定义的依赖闭包和 stage 1/2/3 检查。
