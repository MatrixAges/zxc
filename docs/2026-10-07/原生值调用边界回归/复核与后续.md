# 原生值调用边界回归复核与后续

## IDEA

- Intent：确保测试证明原生调用分类改动的正确边界，并将未证明的部分保留为后续任务。
- Data：32 项普通契约检查、3 项逐失败分配检查；每项包含源码分析与独立解码 IR；14 项旧实现断言失败；Debug 与 ReleaseSafe 的实际运行日志。
- Edges：测试不执行真实 native host，因此不证明值结果、错误顺序、IO 次数、地址别名或缓冲性能。不会把两条路径、两个优化模式、分配故障点重复计为新的独立语言用例。
- Answer：35 项命名 Zig 测试及可恢复证据；保持 Test262 矩阵计数不变。

## 覆盖复核

- 借用：string、string?、数值列表、字符串列表、可选列表、可选字符串列表、嵌套列表、原生引用与其可选/列表形式。
- 传值：u64、i64、f64、bool、展开标量参数、string 和可选 string 结果、嵌套数值列表结果。
- 保守边界：对象输入、对象列表、单参数元组、展开对象参数、对象/元组/可选对象/对象列表结果。
- 上下文：IO 与进程分别结合标量和借用输入；allocator 注入结合 string 输入与显式 OutOfMemory。
- 传播：原生函数到 leaf、middle 两层普通函数；库路径还核验导出入口。每个普通函数的 pure/local/value 都逐一检查，不固定函数 ID。
- 所有权：原分析、库链接结果和编码字节在解码后检查前销毁；编码字节先覆写，再释放。
- 失败分配：嵌套借用列表、展开借用参数和 IO 回退分别遍历所有失败分配点，生产分析/摘要/链接/编码/解码路径的清理均参与检查。

## 自我批判

1. 准备阶段夹具曾违反格式和纯类型模块规则，还遗漏 fmt 模板花括号转义；这些错误属于测试作者，已经修正并保留失败日志。未把它们误报为实现缺陷。
2. 新解析器发布后必须重跑，不应把旧提交的绿色门禁外推；最终输入清单固定了新提交。
3. summary.pure 的现有含义比自然语言的“纯函数”窄。测试保留 IO/进程标量的旧分类，同时要求 local/value 拒绝，不擅自重新定义生产契约。
4. 35 项检查能保护分类和跨普通函数传播，不能代表原生功能全部完成，更不能代表 Test262 已对齐。
5. 验证器本身也是代码，因此它核验真实日志的测试名称与计数、直接执行被构建运行的二进制，并用恢复旧实现的 14 项断言失败交叉验证；不以验证器输出代替实际测试。
