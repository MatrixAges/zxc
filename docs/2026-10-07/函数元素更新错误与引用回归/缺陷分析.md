# 普通元素赋值提前读取旧值缺陷

## Intent：最终目标

普通元素赋值只需要目标容器、索引和右侧值，不应额外读取被替换的旧元素。保持普通赋值与复合赋值的求值区别、native 调用次数及错误优先级。

## Data：可用证据

基线 `8b0a7060ef454d5eb0e5b3888fe454bf2a4c7f7e`，工作区没有生产改动。新增 effects_set/effects_add 均从真实 ZX 生成，另有销毁 provider 后的真实编译库消费者。

Debug 中纯 fixture 352/352 通过；effects_add 的两路线各 25/25 通过；effects_set 的两路线各 21 通过、4 失败。两个 effects_set 实际二进制独立复跑均返回 1。

失败包括 empty write bounds、invalid index bounds、invalid index and value failure、invalid index skips after。在普通 `=` 的越界场景，预期调用 source/index/value 后由 list_update 校验边界，但实际只执行 source/index；右侧 value 应抛 ValueFailure 时被错误替换为 IndexOutOfBounds。

`packages/compiler/src/zx/analysis/iteration/block.zig` 第 81 行对所有更新调用 prepare。`update.zig` 第 42 行无条件将最终 Place.value 加入临时绑定，即使 `update.operator == null` 也求值旧元素。生成物出现无用 `_ = block { ... source[index] ... }`，其越界失败位于 native value 调用之前。

`packages/genz/src/zx/list_update.zig` 本身依次 bind target/index/value 后才校验边界。问题来自前端多插入的旧元素读取，不是 native 导入名的接线，也不是缓冲模式才出现的错误。

## Edges：边界与限制

此缺陷在当前生产基线可复现，尚未证明由 c938 新优化引入。纯函数执行通过不能代替副作用顺序检查。测试中的 source 是前一条显式状态赋值，不声称它是同一元素赋值的任意调用表达式目标。

ZX 的严格索引范围与 JavaScript 动态数组不同；这里要求对齐的是普通赋值不读取旧值，以及先求值 RHS 再写回的语义，不把 JavaScript 数组自动增长冒充 ZX 能力。复合赋值必须先读取旧值，不能一概删除所有层的索引读取；嵌套更新仍可能需要读取父容器。
