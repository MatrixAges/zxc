# 函数元素更新错误与引用执行记录

## Intent：最终目标

为持久列表元素更新补齐容器保留引用、native 求值顺序和错误优先级回归。测试反向发现并推动修复普通赋值多余旧值读取；实现由指定会话维护，本部分提交测试和证据。

## Data：可用证据

测试最初基于 `8b0a7060ef454d5eb0e5b3888fe454bf2a4c7f7e`。沿用 `test-function-updates`，新增 6 种 fixture：escape_before、escape_after、effects_set、effects_add、effects_nested_set、effects_nested_add，均通过源码与真实编译库新消费者执行。

编译库编码字节清零，provider、编码存储和链接库销毁后才分析消费者；native 导入名从实际 IR 的 native_modules 元数据读取，源码和编译库身份分别接线。没有硬编码编译库 native 身份，没有对生成源码改名来绕过接口。

### 容器保留的版本

escape_before 先把当前列表保存到 boxes[0].values，再更新列表元素，然后读取保存的版本。escape_after 先更新元素，再保存当前版本。令 N=m×n，为全部元素写入次数；a 为选中元素初值，δ 为增量。

| 模式          | 最终值 | mirror                  | seen         |
| ------------- | ------ | ----------------------- | ------------ |
| escape_before | a+Nδ   | N>0 时 a+(N−1)δ，否则 a | Na+δN(N−1)/2 |
| escape_after  | a+Nδ   | a+Nδ                    | Na+δN(N+1)/2 |

两组沿用独立初值与闭式公式，完整输入和哨兵保持检查，覆盖零、一、二、多轮、257 内层循环、负增量、索引边界、OOM，以及同一 arena 中后续调用不能破坏先前输出。各 19 项，双路线新增 76 项检查。

### native 求值与错误

native 宿主只观察和原样返回 source/index/value/after/container，失败位置由测试显式配置；每轮记录调用顺序、参数和 source 看到的当前选中元素值。每次 execute 和 OOM 重试都会重置宿主。

| 模式               | 成功顺序                                                       | 最终选中值         |
| ------------------ | -------------------------------------------------------------- | ------------------ |
| effects_set        | source、index、value、after                                    | 有写入时 δ，否则 a |
| effects_add        | source、index、旧元素读取、value、after                        | a+Nδ               |
| effects_nested_set | source、container、父容器读取、index、value、after             | 有写入时 δ，否则 a |
| effects_nested_add | source、container、父容器读取、index、旧元素读取、value、after | a+Nδ               |

旧元素/父容器读取由 ZX 完成，不伪装成 native 日志事件。对实际事件逐项比较阶段、载荷和 source 当前值，既验证求值一次，也验证跨内部循环及外部调用的版本传递。

简单更新各 25 项，包括零外层、零内层、空列表、第一轮及第 4 轮的四种 native 失败、未达到的失败、空/越界写入、错误优先级、负值/末尾元素与分配失败。嵌套更新各额外 8 项父容器检查，共 33 项；无效父容器必须先失败，跳过 index/value，container 自身失败则先于父容器读取。

普通 = 的最终元素越界应在 value 求值之后被更新操作发现；若 value 抛错则保留 ValueFailure。复合 += 必须先读取旧元素，因此最终元素越界会跳过 value。父容器索引属于定位嵌套目标所必需的读取，仍须在后续 index/value 之前校验。

两种简单模式、两种嵌套模式、双路线共 232 项 native 检查。新增检查为 76+232=308 项/优化模式；保留前一部分的 276 项，总入口为 584 项/优化模式。Zig 构建汇总只显示纯 Zig 根的 352 项；另外 232 项由静态 Zig 二进制的 node 调用工具执行，不把构建步骤数当作测试数。

### 缺陷与修复因果证据

当前生产基线在普通 = 中额外临时绑定最终 Place.value；生成 Zig 在 RHS native 调用前出现无用旧元素读取。源码与编译库消费者均复现：简单 = 各 21/25 通过、嵌套 = 各 29/33 通过，同样的四项最终元素越界断言失败；两个 += 模式均通过。完整生成物、两份独立失败二进制 SHA 和日志见 `缺陷证据/`。

已向用户指定实现会话发送经过复现的缺陷与根因。实现候选只在普通赋值跳过最终值临时绑定，递归父路径仍读取，复合赋值保留旧值读取。候选两文件、SHA 和隔离 Debug 因果验证在 `修复候选/`；原断言不改，候选的 584 项全部通过。正式基线与最终门禁结果另在 `最终核验.md` 保存，候选证据不代替正式发布证据。

## Edges：边界与限制

source 是前一条显式状态赋值，后面才执行元素赋值；此测试没有宣称支持任意函数调用结果作为可修改左值。native 副作用路径不被当作已启用共享缓冲的证据，其目标是语义、轨迹和失败停止；纯函数的缓冲容量回归仍在原 276 项内运行。

ZX 严格范围校验与 JavaScript 动态数组不同，本部分不宣称实现 JavaScript 数组自动增长。Test262 的文件评审和 JSONL 案例数不因这些 Zig feature tests 增加；现有 83,490 条登记案例计数保持原有含义。

native 编译库使用实际生成身份。初版手工沿用 source 的 probe 导入名导致库路线接线错误，改为读取 IR 元数据；这是测试工具问题，没有作为生产缺陷发送。观测变量扩充时发生 Zig 遮蔽错误，已自行修正，其日志归入 `工具记录/`，不冒充运行失败证据。

## Answer：交付与成功标准

正式测试变更限于 `输入冻结.json` 的精确路径；代码副本在 `草稿/`。Debug/ReleaseSafe 必须在正式修复版本运行全部 584 项，再保存实际二进制、生成物、native 元数据和复跑日志的 SHA，核验原有修改后提交、push。提交信息使用英文 Conventional Commits。

```sh
cd packages/test

zig build test-function-updates -Doptimize=Debug --summary all --verbose

zig build test-function-updates -Doptimize=ReleaseSafe --summary all --verbose
```

## 自我批判与继续位置

plain 与 compound 分开核验比只检查最终结果更有区分度：越界与 RHS 失败同时发生，才能观察多余读取改变的错误优先级。嵌套父路径用例防止为了消除最终读取而误删必要的中间读取。source 采样避免普通赋值最终常量值掩盖错误的输入版本。

闭式值检查和声明式轨迹不模拟生成器的版本证明；OOM 枚举依赖实际 allocator 请求，不猜测分配次数。本部分仍只是有限 fixture 的证据，不能说明所有 nested transform、Task、Store 或尚未审阅的上游语义均完整。生产级目标与全部 Test262 对齐继续保留，后续需继续审阅及补齐对应范围。
