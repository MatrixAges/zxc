# 复合赋值空白原文对齐实施记录

## Intent：最终目标

逐项对照十一份锁定compound-assignment whitespace原文，在五种已支持复合算术中验证原始空白字节、实际状态写回、负零，以及词法和表达式语法的明确边界。

## Data：可用证据

最终验证基线为`69897bd718665f48e3ddca688fab83594b853a50`，起始基线为`93f4dd8dc7f75a21f5a0f60fc0f043b06ed82d26`。20个正式文件及其基线/最终SHA在`输入冻结.json`，完整实现和目录数据在`草稿/packages/test/`。

### 原文事实

十一份原文均完整读取并比对固定索引SHA。每份有10组实际空白、每组表达式值和写回值两次SameValue断言，总计220项显式断言。ASCII组为TAB、VT、FF、SP、LF、CR；非ASCII为NBSP、LS、PS及含它们的组合串。

原文U+000D确含0d字节，组合串依次为`09 0b 0c 20 c2 a0 0a 0d e2 80 a8 e2 80 a9`。提取器限制空白字符集合，左右原始字节必须一致；所有原文以.js.txt保存，避免提交格式化改变实际空白。

乘法与除法原值为1；余数为负零，期望f64位模式`8000000000000000`；加法和减法为-2。预期来自实际原断言，不从zxc输出反推。

Node v25.8.1与Bun1.3.10分别对每份原文执行严格、非严格模式，均22次原文执行、440次SameValue断言通过。每个新realm先加载锁定sta.js/assert.js，再在同一realm包装原sameValue以计数，严格指令放在原文脚本开头。委托原断言保留SameValue的负零规则，另将原最终x编码成f64位模式；没有改写原文。

### 实际ZX测试

五份runtime源码的Input.shape选择18种ASCII空白形态（6组×左/右/双侧）。真正的复合更新同时作用于普通字段、嵌套字段和列表元素，每个原子形态单独生成具名Zig测试。新增显式state_update_whitespace支持模块读取第三个shape参数，按位比较三个输出，并检查Input.left/right/shape保持不变；没有用整数0代替负零。

新增90项runtime目录数据；每项都真实编译和执行，不把三个输出字段的断言数另计为三个案例。

前端目录共有1,050项：

| 类型              | 用例数 | 具体观察                           |
| ----------------- | -----: | ---------------------------------- |
| 合法ASCII状态更新 |    270 | 分析成功，三类目标及单/双侧        |
| ASCII混合bool右值 |    270 | analyze/type_mismatch              |
| 非ASCII空白       |    420 | parse/lexical，首个非ASCII字节span |
| ASCII赋值表达式值 |     90 | parse/syntax                       |

普通更新矩阵为5种操作×10组字符×3个位置×3类目标×2种类型，共900项；表达式值位置另外150项，其中60项由Unicode词法错误先截断，90项ASCII进入语法拒绝。预期阶段不把词法拒绝算成类型拒绝。

### 原文审阅状态

五个已支持算术文件登记adapted，链接全部对应runtime和frontend案例，明确保留写回观察或记录拒绝边界。JS可返回值赋值表达式被ZX状态更新语句与后续观察替代；表达式值位置本身另有真实syntax拒绝测试。Unicode空白原本接受，而ZX按其ASCII契约拒绝，因此不声明源码或完整JS语义等价。

六个按位/位移文件登记excluded、cases为空：当前没有对应复合操作，原文还具有JS数值转换和表达式结果要求。没有以乘除、简单整数索引或其他已通过用例替代。

### 构建和实际证据

Debug与ReleaseSafe分别执行`zig build test-compound-whitespace test-frontend -Dfrontend-filter=compound_whitespace --summary all --verbose`并传入对应optimize与当前Zig archive。每种模式54/54构建步骤、1,140/1,140项Zig测试通过。

每种模式6个真实二进制：5个runtime各18项，1个前端包含1,050项。收集器再次直接运行全部二进制，保存实际输出、二进制SHA、生成测试与程序的原字节；两种模式共12个二进制、2,280项独立复跑通过。构建步骤数、测试数、三个字段断言数和两个参考引擎的原文断言数分别记录，不互相替代。

目录从127,044增至128,184，新增1,140个命名案例。上游审阅为788个adapted、2,029个excluded、103个equivalent，仍有50,677项未审阅；compound-assignment内从395项未审阅降至384项。

## Edges：边界与限制

适配语法与拒绝边界均不是原文全部通过的声明。赋值表达式值、Unicode代码空白、六种未支持复合操作和动态数值转换仍有明确差异；本轮没有实现这些语言特性。

本轮f64原子值属于原文Number语义，实际位模式检查保留负零。既有f32/f64全数值state-update、定宽整数和宿主求值顺序专项各有独立证据，本轮不冒充全部数值域、所有Store/RX生命周期或所有库消费路线完成。

实际主机为macOS x86_64，Zig0.17.0，Node/Bun版本如上；没有扩张为跨平台证明。未新增生产运行库、解释器、动态加载或共享状态持久化设施。

## Answer：交付与成功标准

交付20个正式文件、1,140个命名案例、11项上游审阅、两种构建和独立复跑证据、两引擎原文证据、原始字节清单、可复制草稿及IDEA计划中的架构图与数据流图。生成器加入默认test的--check一致性核验，新增runtime/前端目录均进入已有包总test。

成功标准为冻结SHA与实际交付一致，12个二进制及2,280项检查可核验，原文两引擎880次SameValue断言真实执行，原文CR/组合串/负零未改写，审计无重复或失联。发布按英文Conventional Commits提交并push，根目录原有11项修改保持原SHA。

### 自我批判

初始正则使用任意字符匹配，误吞了上一项side-effect断言；字节一致性断言立即阻止产物写入。改为仅允许实际空白字符，逐组核对左右字节、完整20项断言及CR/组合顺序，不能只信描述标签。

初版runtime使用case后独立花括号块，ZX当前语法不允许该普通块形式。前端直接更新测试已通过，但runtime编译拒绝。改为既有成熟的case语句序列，没有修改编译器来绕过语法约束，也没有把该草稿错误当生产缺陷通知实现会话。

runtime若使用普通数值比较会遗漏余数负零；此处使用f64原始位模式。Unicode或表达式值要求不能被ASCII成功掩盖，故分别保存拒绝测试和适配边界。没有按用例ID特判生成程序或降低断言。

本阶段没有发现经过验证的zxc生产实现缺陷，因此未向实现会话发送消息。所有特性与Test262对齐的总目标仍未完成。
