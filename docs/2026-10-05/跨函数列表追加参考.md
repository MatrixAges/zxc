# 跨函数列表追加参考

## Intent：最终目标

把对象归约的状态转移拆成普通 ZX 模块，列表仍能跨 helper 保留追加容量。无需添加特殊列表类型或优化标记。

## Data：支持范围

归约回调直接调用内部函数，函数返回完整下一状态；待优化列表的输出字段必须对应同一累加器输入字段。函数可以经过多层调用、局部绑定、对象重建及条件返回，保持列表或用 `push`/`concat` 追加。

现有词法扫描采用以下写法，状态继续传入 `advance`、`emit` 等独立模块：

```typescript
const state = in.reduce((state, byte) => tick({ byte: byte, state: state }), initial)
```

完整来源见 [词法扫描入口](完整词法扫描/lex.zx) 和 [状态转移](完整词法扫描/tick.zx)。编译器按输入/输出字段路径分析，不依赖函数名、字段名或词法器业务。

## Edges：边界与限制

内部函数必须消费 owned 输入，完整调用图不能依赖原生接口、Store 或 Parallel。当前优化拒绝包含契约或嵌套 transform 的候选函数；列表元素读取、重排、重置、隐藏别名、重复输出、未沿返回链使用的追加及已缓存整个追加操作的情形也不复用该列表容量。未满足条件时保留普通生成路径。

归约持有 ArrayList；第一次追加复制外来初值的元素槽位，此后以保留容量的方式增长。helper 只借用缓冲区，归约完成时一次交付切片。输入可能来自另一分配器，因此不对输入 slice 直接 realloc。此处减少的是重复列表构造，不能宣称所有数据操作均零复制。

公开 Input/Output、`call` 和 `execute` 的 slice/指针契约保持原状。新增的 `callBuffered` 是生成器内部入口，不作为宿主绑定接口；无需额外运行库。输出值、顺序和非分配错误语义保持一致，分配失败时点可能改变。归约以外的独立追加、嵌套对象及其他操作仍可能分配。
