# 同步子进程参考

## Intent：最终目标

从 ZX 或 RX 同步执行外部工具，取得完整的 stdout、stderr 和终止状态。功能参考 [Node.js 同步子进程接口](https://nodejs.org/api/child_process.html#child_processspawnsynccommand-args-options)，使用强类型记录和显式宿主 I/O。

## Data：接口

```typescript
export enum TerminationKind { Exited, Signal, Stopped, Unknown }

export type EnvironmentEntry = { name: string, value: string }

export type Options = { command: string, args: string[], cwd: string?, env: EnvironmentEntry[]?, max_stdout_bytes: u64, max_stderr_bytes: u64 }

export type Result = { stdout: u8[], stderr: u8[], kind: TerminationKind, code: u32 }

export declare function spawnSync(allocator, io, in: Options): Result throws
```

应用只传 Options，allocator/io 由编译器沿调用图传递：

```typescript
import type { Options, Result } from "std:child_process"
import process from "std:child_process"

export type Input = Options

export type Output = Result

export default function (in: Input): Output {
  return process.spawnSync(in)
}
```

| 字段                                | 含义                                                                                          |
| ----------------------------------- | --------------------------------------------------------------------------------------------- |
| command / args                      | 可执行文件与参数数组，不拼接 shell 命令；参数中的空格及 shell 符号保持字面值                  |
| cwd                                 | null 继承工作目录，否则使用给定路径；空字符串不等于继承                                       |
| env                                 | null 继承环境，空数组表示空环境；同名键按平台规则后项覆盖，Windows 不区分大小写               |
| max_stdout_bytes / max_stderr_bytes | 每个流允许返回的最大字节数，包含端点；0 允许空输出                                            |
| kind / code                         | Exited 表示正常退出，code 可非零；Signal/Stopped 的 code 为信号数值，Unknown 为底层未知状态值 |
| stdout / stderr                     | 独立字节列表，不要求 UTF-8；需要文本时显式 decodeUtf8                                         |

## Edges：边界与限制

创建进程、参数校验、管道读取和输出超限失败会抛错，超限为 StreamTooLong；非零退出本身仍返回 Result。错误路径终止并等待本次直接启动的子进程，清理资源，不返回截断输出伪装完整结果。

本轮固定 stdin 为忽略（无输入），不提供 stdin 输入、流式 handle、异步事件、IPC、进程树管理或超时。后代继续持有输出管道时，收集仍会等待管道关闭。

输出限额是接受上限，不是严格内存占用上限：底层收集可能先读取和扩容，再检查限额。stdout/stderr 同时收集，避免单流先读完造成另一管道填满而阻塞。

Zig 0.16 的命令查找使用宿主 PATH，显式 env 只替换子进程环境；与 Node 的 options.env.PATH 查找有差异。可移植配置应提供明确的可执行文件路径。command、args、cwd 和环境字符串必须是有效 UTF-8 且不含 NUL；环境名称还必须非空且不含 `=`。

Windows 正常退出码经 Zig 0.16 的 u8 Term.exited 归一化，不能保留系统原始 32 位退出码；外层 code 为 u32 不会恢复被截断的高位。POSIX 的信号数值不转成平台无关信号名。

此接口不会自动启动 shell，也不执行 Node/V8 代码。显式把 shell 可执行文件作为 command 时，其后参数遵循该 shell 自己的规则。纯 Parallel 当前不接受此原生副作用调用。

## Answer：运行与库消费

```sh
zxc build docs/2026-10-05/同步子进程/应用/main.zx --out /tmp/child_process
/tmp/child_process '{"command":"/usr/bin/printf","args":["%s","hello"],"cwd":null,"env":null,"max_stdout_bytes":1024,"max_stderr_bytes":1024}'

zxc build docs/2026-10-05/同步子进程/应用/main.rx --mode lib --out docs/2026-10-05/同步子进程/消费/library
zxc build docs/2026-10-05/同步子进程/消费/main.zx --out /tmp/child_consumer
```

示例按 macOS/POSIX 可执行路径演示，Windows 需换成实际程序路径。结果 kind 为 Exited、code 为 0、stdout 为 hello。CLI 既有字节 JSON 规则会把有效 UTF-8 字节显示成字符串，其他字节显示为整数数组；这不改变 ZX 的 u8[] 类型。

[RX 示例](同步子进程/应用/main.rx) 使用普通顺序 Call。发布后既可由 ZX 使用，也可由 [Zig 宿主](同步子进程/Zig消费/main.zig) 以 `execute(arena, input, init.io)` 显式注入 I/O；在 Zig消费 目录运行 zig build 后，将同一 JSON 传给生成程序。

真实调用、输出边界及双流大输出记录见 [运行结果](同步子进程/运行结果.json)，消费和跨目标构建证据见 [消费结果](同步子进程/消费结果.json)。内部资源流与自我复核见 [IDEA 实施计划](同步子进程实施计划.md)。
