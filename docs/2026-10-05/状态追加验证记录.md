# 状态追加验证记录

## Intent：最终目标

为对象归约状态列表追加优化建立独立运行回归，验证语义、所有权与实际分配增长。对应阶段 395。

## Data：执行证据

新增 `packages/test/build/object_append.zig` 和 `tests/collections/object_append/`，总 test 已接入 `test-object-append`。夹具按 fixtures 收口，编译、期望计算、分配检查与错误恢复分开。

- Debug：`zig build test-object-append --summary all`，退出 0，45/45 步，140/140 测试。
- ReleaseSafe：`zig build test-object-append -Doptimize=ReleaseSafe --summary all`，退出 0，45/45 步，140/140 测试。
- 两种模式重复执行同一组测试，不重复计数。
- 原始日志、首轮失败与版本/工作区状态见 [配套目录](状态追加验证/结果.json)。

六种模式为 push、concat、整状态条件跳过、列表字段条件跳过、旧列表索引读取、被覆盖追加。每种走直接源码和库 link→encode→decode→生成 Zig→执行两条路径。

计数为 6×2×8 基础测试 + 4×2×5 容量/空初值测试 + 1×2×2 错误恢复测试 = 140。

基础测试覆盖空归约、单步、两步、37 项混合分支、32 项全零、257 项长序列，以及混合/全零的全部分配失败。初始列表含 71、83、97，归约前通过 map 获得独立拥有的副本；宿主 seed 和 steps 在执行后及失败后均核对保持不变。

独立 Zig 循环计算 count、previous 和完整结果列表。concat 每步追加 item 与 item+10，条件模式跳过零，index_read 始终读取旧列表首项，overwritten 最终交付空列表。非空结果不能与宿主初值共用列表地址。

四个优化候选分别检查 128、2048、8192 项下 arena 容量和累计申请字节，上限为 `8192 + 128 × (输入长度 + 输出长度 + 初值长度)`；同样在禁止原地 resize 时执行。输入与期望列表分配不计入程序 arena。该线性上限足以排除大规模每步复制前缀的二次增长，允许缓冲区增长和中间列表的正常线性开销。

旧索引读取回退另检查空初值触发 IndexOutOfBounds 后，在同一个 arena 中再次执行有效输入恢复成功；完整错误/恢复链遍历分配失败。

## Edges：边界与自我批判

首轮 134/136 通过，concat 在 2048 项时超过最初仅按输入长度设置的容量上限（观测 276738，对照 270720）。旧上限漏计每步两个输出元素和中间列表，不能据此认定生产缺陷。修正为输入、输出总规模的线性上限后，两模式均通过；保留首轮日志供审查。

本轮未发现生产缺陷，因此没有向实现会话发送消息。工作区中该会话正在修改字段级所有权，本记录保存验证时状态，不宣称整个工作区干净或只包含已提交代码。

有限规模回归不证明任意长度的渐近复杂度；OOM 时点允许优化改变。回退模式不要求保留低效分配策略，只要求正确结果。尚未覆盖多列表字段、嵌套字段消费、任意元素类型、concat 可变长度输入和全部 match 表达式；下一阶段针对正在完成的字段级所有权实现补齐。库链路未覆盖 CLI 安装发布。该阶段不代表完整 Test262 或 zxc 全部特性已完成。
