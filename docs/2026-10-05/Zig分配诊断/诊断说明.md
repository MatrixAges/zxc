# Zig 0.17 分配次数诊断

## Intent：最终目标

定位测试会话反馈的字段所有权分配失败检查 NondeterministicMemoryUsage，保持 OOM 传播与内存释放检查，不为测试计数修改生产算法。

## Data：可用证据

observe.zig 直接调用现有 `packages/test/tests/ownership/fields/check.zig` 的 allocated，使用其 nested valid 输入。相同 SafeAllocator 上连续执行 20 次，alloc_index 为 117～119、resize_index 为 26～40，各次 allocated_bytes == freed_bytes。仅将 backing allocator 的 resize/remap 替换为标准 noResize/noRemap，保留同一 SafeAllocator 分配和释放实现，20 次均为 131 次分配、0 次原地调整，字节全部释放。最后调用原 `std.testing.checkAllAllocationFailures` 及原 allocated 函数，完整遍历成功。

命令：在本目录执行 `zig build --summary all`，随后 `zig-out/bin/observe`。结果见 [对照记录](对照记录.txt)。本文件不生成或替代正式测试。

## Edges：边界与限制

0.17 std.testing.allocator 改用 SafeAllocator。FailingAllocator 把成功的原地 resize/remap 记为 resize_index，只有 alloc 才增加 alloc_index。SafeAllocator 的 bucket 尾部空间、分配位置和底层页面扩容影响原地调整是否成功，因此同一算法的 alloc 次数不保证跨遍历一致。checkAllAllocationFailures 用首次 alloc 次数作为之后逐个失败的上界；后续某次分配更少，就会返回 NondeterministicMemoryUsage。

只验证了反馈中的 nested valid 案例，不能据此断言其他反馈已全部修复。测试侧可采用通用、只在故障注入期间禁用 resize/remap 的 backing 适配；继续由原 std.testing helper 检查泄漏、OOM 传播与意外吞错。正常运行仍使用真实分配器。未改生产源码，未删除或弱化现有测试，未执行全量回归。

## Answer：结论与自我复核

本次已获得真实运行的对照证据，确认该例违反的是故障注入 helper 的确定性前提。测试会话负责通用测试侧适配与其他案例复验。不能将“禁用原地调整后通过”表述成生产分配优化错误，也不能把诊断中的 131 次写进生产代码或断言。
