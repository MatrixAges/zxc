# 显式进程上下文参考

## Intent：最终目标

ZX 程序通过 `std:process` 读取宿主参数、指定环境变量和当前目录。参考 Node.js 的 [argv](https://nodejs.org/api/process.html#processargv)、[env](https://nodejs.org/api/process.html#processenv) 和 [cwd](https://nodejs.org/api/process.html#processcwd)；实现基于 Zig，不依赖 Node.js。

## Data：接口与使用

```zx
import process from "std:process"

export type Input = void

export type Output = string[]

export default function (in: Input): Output {
  return process.argv()
}
```

| API           | 返回值                              | 宿主能力                   |
| ------------- | ----------------------------------- | -------------------------- |
| `argv()`      | `string[]`，含第零项程序名称        | `std.process.Init.Minimal` |
| `getEnv(key)` | `string?`，缺失为 null，空值为 `""` | `std.process.Init.Minimal` |
| `cwd()`       | 当前工作目录 `string`               | `std.Io`                   |

所有 API 可以失败。环境键不得为空、含 NUL 或等号，字符串须为有效 UTF-8。参数、环境值和路径结果均存入调用者 allocator，参数迭代器释放不影响返回值。

## Edges：边界与限制

- `argv()` 返回真实宿主参数，不插入 Node.js 的解释器或脚本名称项。
- 生成应用只有在 `Input = void` 且调用图需要 process 时接受任意命令行参数。其他 void 应用仍不接受额外参数；非 void 应用仍接受一个 JSON 输入参数。
- 非 void 应用调用 argv 时会看到该 JSON 参数的原始文本。
- Zig 宿主向 execute 传入 `Init.Minimal`；调用图若也需要 I/O，则参数顺序为 arena、input、可选 State context、io、process。生成的 `requires_io` 与 `requires_process` 可供宿主编译期选择签名。
- State 用户通过 `Request.execute(input, io?, process?)` 转发能力，State 初始化契约保持不变。
- 宿主必须在同步调用期间保持 args/environ 底层存储有效。Minimal 按值传递不复制其底层视图；Windows 环境视图为显式 global/empty 选择，不保证跨平台冻结快照。
- 本模块不提供环境修改、进程退出或 PID API；标准输入输出见[标准输入输出参考](标准输入输出参考.md)。需要启动子进程时使用 `std:child_process`。
- 原生 `.d.zx` 注入顺序为 allocator、io、process、业务参数，各能力可省略；带类型的 `process: string` 是普通业务参数。

## Answer：交付与验收

声明、IR、生成器、缓存与入口共同传播能力，不引入全局进程对象或动态能力查找。实现及验证进度见[实施计划](显式进程上下文实施计划.md)。当前平台的四种能力组合、热缓存、发布库 ZX 消费、Zig 宿主和 State 请求已实际构建运行；跨平台运行未验证。
