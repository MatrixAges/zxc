# 标准输入输出参考

## Intent：最终目标

通过 `std:process` 使用同步标准输入输出，适用于命令行数据读取和诊断写出。功能参考 [Node.js process 标准流](https://nodejs.org/api/process.html#processstdout)，不提供 Node.js Stream 对象或事件循环。

## Data：接口

| 函数            | 输入           | 输出   |
| --------------- | -------------- | ------ |
| readStdin       | max_bytes: u64 | u8[]   |
| readStdinText   | max_bytes: u64 | string |
| writeStdout     | data: u8[]     | void   |
| writeStdoutText | text: string   | void   |
| writeStderr     | data: u8[]     | void   |
| writeStderrText | text: string   | void   |

函数均可失败，读取需要 allocator/io，写入需要 io。调用图不会因此要求进程参数视图。读取到 EOF 后返回独立内存，超过 max_bytes 报错；文本入口拒绝无效 UTF-8。

```zx
import process from "std:process"

export type Input = u64

export type Output = string

export default function (in: Input): Output {
  return process.readStdinText(in)
}
```

编译示例后，通过管道输入文本并以 JSON 数字参数传入最大字节数。

## Edges：边界与限制

写入不自动添加换行，每次调用刷新缓冲。不关闭标准句柄，不保存隐藏的全局 Reader/Writer。重定向到文件时沿当前流位置写入；不能保证并发多次写入原子性，也不能撤销失败前已写出的字节。

读取会等待 EOF；这不是交互式逐行读取。超过上限会失败而不是返回截断数据，此时部分输入可能已消费，不能假设可重试读取原文。无效 UTF-8 可通过字节接口保留。

生成的 CLI 仍会在业务调用后输出 JSON 返回值（void 为 null）。如果业务自行写 stdout，这两部分依次出现；stderr 与 JSON 输出分离。需要完全控制标准输出时，以 Zig 宿主消费发布库并自行选择返回值处理方式。
