# 显式输入消费参考（已废止）

> 2026-10-06：用户明确移除此语法。本文保留历史设计和验证记录，不再是当前语言契约；当前用法见 [不可变输入参考](../2026-10-06/不可变输入参考.md)。旧消费型编译库与缓存必须重建。

## Intent：最终目标

将独占列表或状态交给普通辅助模块更新，并将返回的独占结果继续传递，保持无环模块组织。

## Data：语法与用法

默认签名 `in: Input` 借用输入。辅助函数需要消费输入时显式标注：

```typescript
export type Input = { items: u64[], value: u64 }

export type Output = u64[]

export default function (in: owned Input): Output {
  const value = in.value

  return in.items.push(value)[0]
}
```

调用语法不变：`append({items, value})`。编译器检查实参的实际归属，调用后旧 owner 不可再次使用。返回归属仍由函数体分析，不能只凭 owned 参数把借用输出当作独占。

[完整应用](显式输入消费/应用/main.zx) 将 reduce 累加器交给 [append 模块](显式输入消费/应用/append.zx)，然后继续 reverse 最终列表。初值通过标量 map 建立独占存储，不复制整个输入对象。

## Edges：边界与限制

- 借用输入、Store getter、临时借用和已消费绑定不能交给 owned 参数；标量仍可复制。
- 聚合字段移动仍消费整个根 owner。本例先复制 value 标量，再消费 items；不支持分拆多个引用字段的部分移动。
- 消费式列表调用在参数求值期间预留接收者，因此 `items.push(items.length + value)[0]` 可读取标量；参数不能再次消费接收者或让其借用逃逸。
- 输入消费不保证 allocator 来源。不要据此对缩短或内部 slice 执行 free/realloc。
- 普通 RX 输入继续借用。RX 可以把本流程新建的 owned 值交给消费式 ZX 函数，见 [编排示例](显式输入消费/应用/main.rx)。
- Zig 公共入口导出 `pub const consumes_input`。为 true 时，宿主必须提供可写且无仍存活别名的可变数据，并停止使用被转移的输入；这个要求也包含输入内部不同字段之间的可变别名，字段独立消费遵循 [字段所有权参考](字段所有权参考.md)。底层存储须覆盖结果及 Store 引用的生命周期。常量存储不能冒充可变独占缓冲。
- 没有新增 runtime 所有权跟踪、引用计数或深拷贝。原生接口本轮保持借用输入。
- 跨 helper 的追加目前仍走普通列表生成，不属于局部只追加 reduce 容量优化。此功能解决模块表达能力，不声称通用状态构建性能已完成。

## Answer：构建与消费

```sh
zxc build docs/2026-10-05/显式输入消费/应用/main.zx --out /tmp/owned_input
/tmp/owned_input '{"seed":[1,2],"values":[3,4]}'

zxc build docs/2026-10-05/显式输入消费/应用/append.zx --mode lib --out docs/2026-10-05/显式输入消费/消费/library
zxc build docs/2026-10-05/显式输入消费/消费/main.zx --out /tmp/owned_consumer
/tmp/owned_consumer '{"seed":[1,2],"value":3}'
```

结果分别为 `[4,3,2,1]` 和 `[3,2,1]`。[Zig 消费源码](显式输入消费/Zig消费/main.zig) 从 JSON 创建输入，确认库的消费契约后调用 `execute`；在该目录运行 `zig build`，再给生成程序传入 `'{"items":[1,2],"value":3}'`，结果为 `[1,2,3]`。

二次发布消费示例先将 `消费/main.zx` 以 lib 模式导出到 `二次消费/library`，再构建 `二次消费/main.zx`。它验证内部消费签名经过编译库重发布后仍保留。
