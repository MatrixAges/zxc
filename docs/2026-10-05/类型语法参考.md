# 类型语法参考

## Intent：最终目标

以无递归的 ZX 状态机解析完整类型语法，为整个编译器自举提供可直接组合的前端模块。

## Data：当前实现

[parse.zx](../../packages/compiler/src/zx/frontend/parser/types/parse.zx) 接受 tokens、start 和调用方现有 depth，返回类型节点表、直接子边表、下一 token 索引、根节点索引与诊断。token 来自正式 [scan.zx](../../packages/compiler/src/zx/frontend/lexer/scan.zx)。

支持命名类型、对象、元组、单参数泛型、可选后缀和列表后缀。字段问号包装和类型后缀顺序与当前语言一致；名称引用原始字节位置，节点不包含原文副本。

Node 的有效载荷由 kind 决定：Named 使用 name，Optional/List 使用 child，Application 使用 name 与 child，Object/Tuple 使用 head 与 count；其余字段保留零值。

类型表使用 0 起始节点索引。对象字段边与元组元素边各有独立数组，节点的 head 为 1 起始边索引、0 为空链；沿 previous 取 count 个孩子再反转即可恢复源码顺序。字段 name 保留 span，value 指向类型节点。

## Edges：边界与限制

本模块已独立实现和核对，生产 parser 仍在 Zig 中。它不负责类型名称解析、别名循环检查、枚举声明或表达式语法；这些职责由相应阶段承担。

单次解析的有效输入须包含 EOF token，并提供有效的起点。只有 diagnostic.message 为空且 control.phase 为 Done 时，才能消费 control.result 指向的根类型；失败状态中的中间节点不是有效 AST。

整体 parser 应以 [step.zx](../../packages/compiler/src/zx/frontend/parser/types/step.zx) 接续 token 流并复用节点表。独立 parse 入口会遍历提供的整个列表，不适合在每个注解位置从源头重复调用。

## Answer：构建与证据

```sh
zig-out/bin/zxc build packages/compiler/src/zx/frontend/parser/types/parse.zx \
  --out /tmp/zxc_type_parser --no-cache
```

844 份既有源码中的 8677 个解析位置，与旧 typeNode 的类型树、停止索引和首个诊断一致，覆盖六种节点。核对范围、未覆盖边界、架构图、数据流图和自我复核见 [IDEA 执行记录](语法前端迁移/类型语法/执行记录.md)。完整自举仍以生产入口迁移与 compiler stage1/2/3 验收。
