# 字段所有权参考

## Intent：最终目标

分别消费独占对象的不同静态字段，用普通对象表达包含多个集合的状态，不需要人为拆成多个归约或额外复制列表。

## Data：使用方式

```typescript
export type Input = { first: u64[], second: u64[], count: u64 }

export type Output = Input

export default function (in: owned Input): Output {
  const first = in.first.reverse()[0]
  const second = in.second.sort()[0]

  return { first: first, second: second, count: in.count }
}
```

消费 first 后，second 和 count 仍可使用；整个 in 已不完整，不能再次返回、传给函数或展开。再次访问 in.first 也会被拒绝。嵌套对象和静态元组字段遵循同样的父子路径规则。

对象归约可以在一轮中构造多个新列表字段：

```typescript
return in.reduce((state, item) => item == 0 ? state : ({
  primary: state.primary.push(item)[0],
  secondary: state.secondary.concat([item, item + 1])[0]
}), initial)
```

完整示例见 [multiple.zx](字段所有权/示例/multiple.zx)。它与 [状态列表追加优化](状态列表追加参考.md)结合后，生成两个独立的容量缓冲区。

## Edges：边界与限制

- 动态索引仍按所在列表整体处理。消费 items[index] 后，不能假设另一个索引一定独立。
- 借用输入和原生返回仍不能直接消费。只借出某字段时，已证明独立的兄弟字段仍可消费；把整个父对象作为借用别名转交后，所有相关子字段都会被冻结。
- 分支汇合使用保守规则：只要某条继续执行的分支消费了字段，后续就不能使用该字段。已经返回的分支不会污染其他继续执行的分支。
- owned 是递归独占契约。Zig 宿主提供 owned Input 时，输入内部不同路径之间也不能共享仍可访问的可变子对象；不能仅保证没有输入之外的别名。编译器不在运行时检测宿主是否违反契约。
- 当前没有原地补回字段的赋值语法。部分移动后应构造新的完整对象，不能把旧父值重新视为完整。

## Answer：结果与验证

```sh
zxc build docs/2026-10-05/字段所有权/示例/multiple.zx --out multiple
./multiple '[2,0,3]'
```

输出为 `{"primary":[2,3],"secondary":[2,3,3,4]}`。正式 lib 发布后的独立 Zig 宿主也已执行同一模块。

实际运行包含空源、全部跳过、双字段追加、嵌套消费、兄弟借用与条件选择。重复消费、部分移动后使用整个父值、分支消费后重用、动态索引重用、消费借用字段及父借用别名后的消费均得到 ownership 诊断。见 [实施计划](字段所有权实施计划.md)、[运行证据](字段所有权/借用与分支运行结果.json)和[拒绝边界](字段所有权/拒绝边界观测.json)。

自我复核：这些是具体源码、编译与运行证据，不是全语言独占性的形式化证明。原有将“移动任意字段后连独立标量字段也不可读”作为预期的测试需要按此契约更新；本项未修改测试文件。

对象展开的内部临时值也遵循逐字段消费。归档 IR 不能通过重复引用同一个缓存列表字段获得两个独占所有者，相关校验已修复并经正式入口验证，见 [缓存所有权记录](缓存所有权实施计划.md)。
