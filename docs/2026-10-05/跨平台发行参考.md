# 跨平台发行参考

## Intent：最终目标

构建携带 Zig 工具链的 zxc 发行包，并通过 GitHub Actions 产出各平台的归档和校验和。

## Data：可用证据

[工作流定义](../../.github/tsflows/build.ts) 使用 @jlarky/gha-ts，由 Bun 生成 YAML；[目标清单](../../.github/tsflows/targets.ts) 包含 Linux musl、macOS、Windows GNU 的 x86_64 与 aarch64，共六个目标。[打包脚本](../../.github/scripts/package.ts) 调用 Zig 构建，执行 [独立发行验证](../../.github/scripts/verify_standalone.ts)，再归档。

## Edges：边界与限制

Bun 负责工作流生成和打包编排，编译器本体由 Zig 构建。维护者需要 Bun 与工作流指定的 Zig 版本；发行包用户不需要另装 Zig。Windows ARM64 工作流使用 x64 Zig 工具链。目标配置存在不等于本次六平台 CI 已通过，此页没有发起远端运行。

## Answer：维护与使用

在仓库根目录安装工作流依赖、生成并检查工作流：

```sh
bun install --cwd .github --frozen-lockfile
bun run --cwd .github build
bun run --cwd .github check
```

修改 TypeScript 定义后提交生成的 `.github/workflows/build.generated.yml`。工作流由 pull_request 或手动 workflow_dispatch 触发，成功后从相应 `zxc-<target>` artifact 下载 `.tar.gz` 和 `.sha256` 文件。当前工作流上传构建产物，不自动发布 GitHub Release。

本地在匹配的目标宿主上运行同一打包流程，例如 Apple Silicon macOS：

```sh
ZXC_TARGET=aarch64-macos bun .github/scripts/package.ts
```

输出位于 `.zxc/artifacts/`，中间发行目录为 `.zxc/distribution/zxc-<target>/`。脚本会重建该目标的中间目录，并验证许可文件及独立运行能力。不要用不匹配的宿主执行目标二进制；工作流已为各目标安排对应 runner。
