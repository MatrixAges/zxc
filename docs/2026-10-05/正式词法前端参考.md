# 正式词法前端参考

## Intent：最终目标

正常构建和使用 zxc 时，由正式 ZX 源码执行主词法扫描。应用继续使用原有 CLI 与 compiler API，无需安装额外的自举编译器。

## Data：实现与证据

正式扫描入口为 [lexer/scan.zx](../../packages/compiler/src/zx/frontend/lexer/scan.zx)，共 36 个 ZX 文件，涵盖 UTF-8、标识符、关键词、数字、字符串、注释、运算符和模板 token 边界。词法结果仍为 token、comment 与 diagnostic，位置使用源字节偏移。

构建先用宿主种子生成词法模块，再将该模块编译进目标平台 frontend。完整 ZX 源码目录和每个 helper 均进入构建依赖；词法源码、生成器和宿主种子也进入 CLI 语义缓存身份。生成文件位于构建缓存，不提交一份需要手工同步的巨大 Zig 产物。

初次迁移（f1a9e65e）的验证：CLI ReleaseSafe 构建 17/17 成功；837 份既有源码在宿主种子与正式适配入口之间零差异；31 份正式词法源码在种子、适配入口和独立生成应用之间也全部一致。使用新 CLI 再次生成词法模块，与种子生成结果逐字节相同，均为 334269 字节，且只导入 `std`。

## Edges：边界与限制

本项是主词法入口迁移，不是整个编译器自举。Parser、模板插值定位、类型与所有权分析、模块联结、后端和 CLI 仍有 Zig 实现。最终的完整 stage 1/2/3 对照及旧仓库归档尚未完成。

内部 token 现在以枚举保存类别、词与标点，携带字节 span、token 间换行和 `$` 起始标志，供后续 ZX parser 使用。[lexer/lex.zx](../../packages/compiler/src/zx/frontend/lexer/lex.zx) 保留原有字符串 kind 与 `{kind, span}` JSON 形状；生产宿主直接接入 scan，由 Zig 适配器转换类别，不经过 legacy 投影列表。当前阶段的核对见[语法 token 参考](语法词法元数据参考.md)。

旧 parser 接收连续的 Token/Span 数组，适配层因此复制词法输出，并将诊断文字保存到调用方 allocator。临时 arena 不向外暴露指针；调用方本身使用 arena 时，临时内存可能保留至整个解析结果销毁。不能以 `defer arena.deinit()` 推断完整 parse 的峰值内存已经下降。

主词法逻辑执行 ZX 生成结果，不调用旧主词法器。旧种子仅服务构建生成器；仍在 Zig parser 内的模板插值定位需随后续语法迁移处理。关键词表生成脚本是维护工具，普通构建不需要 Python。

## Answer：使用与复现

普通用户命令不变。维护者在仓库根目录执行：

```sh
zig build dist -Doptimize=ReleaseSafe
zig-out/bin/zxc packages/cli/examples/quote.zx --out /tmp/quote.zig
```

单独保存宿主种子生成的词法模块：

```sh
zig build --build-file packages/compiler/build.zig bootstrap-lexer \
  --prefix /tmp/zxc_formal_lexer_seed_artifact -Doptimize=ReleaseSafe
```

使用正式编译器再次生成：

```sh
zig-out/bin/zxc packages/compiler/src/zx/frontend/lexer/scan.zx \
  --out /tmp/zxc_formal_lexer_stage2.zig --no-cache
```

初次迁移的核对范围与散列见 [阶段记录](正式词法前端/阶段核对.json)，完整行为记录见 [既有源码](正式词法前端/已有源码核对.json) 和 [正式源码](正式词法前端/正式源码核对.json)。设计、边界和自我审查按 IDEA 记录于 [实施计划](正式词法前端/实施计划.md)。
