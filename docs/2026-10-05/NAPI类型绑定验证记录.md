### 工具链迁移

工作区升级到 Zig 0.17.0 期间，默认 `zig` 仍是 0.16.0。首轮失败涉及新构建 API，切换显式 0.17.0 后又发现 Ast.parse 参数与 std.meta.Int 的迁移问题。已反馈指定实现会话，未自行改动生产源码。日志为 `NAPI类型绑定验证/工具链迁移失败.log`。

等待修复期间，用先前成功构建的 CLI 预检了类型消费与首次加载，随后测试对语法失败的诊断文本假设不符：实际为 `syntax:`，已按真实分类修正。这个旧 CLI 预检不作为当前工作区完整通过的证据。

当前源码在显式 Zig 0.17.0 下已完整通过 Debug 与 ReleaseSafe 的各 43 个场景，两个进程退出码均为 0。日志中的优化标签分别为新枚举名称 debug 与 safe。范围内 TypeScript 严格检查及 Zig 格式检查也通过。

## Edges：边界与限制

- 21 个负向类型场景均使用 `@ts-expect-error`；若声明放宽导致错误调用被接受，TypeScript 会因未使用的指令失败。正向消费覆盖 readonly 数组/元组、两种字节 TypedArray、输入 optional 和输出 Buffer/必需 nullable 字段。
- 失败发布后逐字节比较三份既有产物。非生成 sidecar 的原字节必须保留，另一份声明/入口和插件也必须保持不变。
- 同一源码路径从记录改为 void 后重建，检查签名变化，并在两个新进程中实际调用无参入口。没有通过清除 require.cache 假装卸载已加载动态库。
- 不模拟系统崩溃、断电或任意写入失败，不能据本组宣称跨多文件发布具有完整事务原子性。
- 当前覆盖路径导入，不包含 npm 发布、包 exports 条件、watch 重建或 Windows 文件锁行为；这些属于后续范围。
