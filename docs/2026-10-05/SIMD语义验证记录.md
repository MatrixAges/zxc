# SIMD 语义验证记录

## Intent：最终目标

验证浮点向量块、标量尾部与未向量化的集合路径，落实《SIMD语义验证计划》。不将汇编存在等同于结果正确，也不由这一组结果宣称任意表达式均可向量化。

## Data：可用证据

实现基线为 `b1982c15`。新增 `packages/test/tests/targets/simd/`，通过测试包构建入口 `test-simd-semantics` 调用本次构建产生的 CLI，不使用已安装的旧 CLI。

| 路径                  | 场景数 | 说明                                 |
| --------------------- | -----: | ------------------------------------ |
| Node f32/f64          |    168 | 每种类型 42 长度 × 有限值/特殊值两组 |
| WASM baseline         |     84 | 两种类型 × 42 长度                   |
| WASM baseline+simd128 |     84 | 两种类型 × 42 长度                   |
| 整数与嵌套集合回退    |     42 | map、filter、reduce、嵌套 map        |
| 合计                  |    378 | 多字段和逐元素断言不额外累加场景数   |

长度包含 0 至 33，及 63、64、65、127、128、129、257、1025。每次浮点执行同时核对 identity、取负、常量广播、加减乘除、乘后加、括号分组、取消误差及条件表达式共 11 个输出字段。

Debug 与 ReleaseSafe 最终各 378 场景全部通过，两个进程均退出 0。正式日志为 `SIMD语义验证/Debug.log` 与 `SIMD语义验证/ReleaseSafe.log`。

### 汇编检查

四个 WASM 构建均请求 `--asm`。从 `.file` 识别生成的 `program.zig` 文件编号，跟踪 `.loc`，仅统计归属于生成源码的算术指令。simd128 产物必须出现对应的 `f32x4.mul` 或 `f64x2.mul`，baseline 对应源码不得出现浮点向量四则指令。汇编之外仍实际执行全部结果断言，不以静态模式匹配替代运行。

## Edges：边界与限制

- Node 对 NaN、Infinity、负零、次正规数和大数进行真实值调用；独立预期按表达式树计算，每个 f32 算术节点单独 `Math.fround`。
- WASM 的 JSON 输入仅使用有限且算术输出不会溢出的样例；输出 f32 的十进制最短表示由宿主解析后再舍入到 f32，避免将 JSON 文本表示差异误报为运算差异。
- 条件表达式覆盖不满足显式 SIMD 资格的浮点回调。整数回退同时覆盖预分配、filter、reduce、嵌套映射；整数零按整数语义比较，不期待浮点负零。
- 输入数组在 Node 调用前后保持一致。没有断言分配次数或旧版逐项扩容的 OOM 时机，因为这不属于保留契约。
- 本机 Node 和 WASM 可执行性不证明所有硬件目标都运行正确；本阶段不声称 ARM/AVX 等交叉产物已在对应机器执行，也不提供未经测量的速度结论。
- 汇编检查依赖 Debug/ReleaseSafe 的调试位置；源码位置缺失或没有归属于生成源码的算术指令均失败。未将该门禁扩展到移除调试信息的构建。

## Answer：交付与成功标准

测试总入口接入 `build/simd_semantics.zig`，复用已有 Node/WASM 宿主边界代码，独立维护本组标量预期。两种模式、范围内 TypeScript 严格检查和 Zig 格式检查均通过，本阶段独立提交推送。未发现生产缺陷。

## 自我批判

最初汇编搜索范围为整个文件，可能误纳入标准库指令；改为应用函数符号后，ReleaseSafe 实际把业务内联到 main.run，导致测试定位失败。现改为追踪生成源码的调试位置，既支持内联，又排除其他库的指令。这个失败属于测试证据定位问题，未归咎生产实现。

探索时直接调用仓库旧 `zig-out` CLI 曾得到不相关的旧 WASM 构建错误；正式测试始终使用构建依赖提供的当前 CLI，不能把旧二进制失败归为当前实现缺陷。

对长度与数值样本的覆盖是有限证据，不是浮点代数等价性的完整证明。NaN 比较仅要求类别相同，不保证 payload 保持；未加入 fast-math 或将容差放宽以掩盖结果差异。
