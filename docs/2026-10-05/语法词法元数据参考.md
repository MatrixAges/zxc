# 语法词法元数据参考

## Intent：最终目标

为纯 ZX 语法状态机提供可按值传入的 token。内部 token 无字符串或源文本借用，不需要在消费状态时带入 borrowed token，也不在语法每一步重新比较源字符串。

## Data：实现

[scan.zx](../../packages/compiler/src/zx/frontend/lexer/scan.zx) 接收 UTF-8 字节列表，返回 tokens、comments 与 diagnostic。它沿用已接入生产的词法扫描逻辑；构建生成器与正式 Zig 适配器直接使用这一入口。

| 字段       | 含义                                                              |
| ---------- | ----------------------------------------------------------------- |
| kind       | Identifier、Keyword、Number、String、Template、Punctuation 或 Eof |
| word       | 标识符 DFA 的最终状态；完整上下文词、完整关键字和普通前缀保持区分 |
| symbol     | 标点枚举；非标点固定为 None                                       |
| span       | 源 UTF-8 字节的半开区间                                           |
| line_break | 与前驱 token 之间是否存在 CR 或 LF；首个 token 固定为 false       |
| dollar     | 当前标识符是否以 `$` 开头                                         |

[lex.zx](../../packages/compiler/src/zx/frontend/lexer/lex.zx) 投影旧 `{kind: string, span}` 接口，独立词法工具的 JSON 格式不变。正式适配器直接以 enum switch 转换 kind，无需该投影分配。

上下文词仍然是 identifier，不扩大保留词集合。`Input` 与 `input` 大小写敏感；DFA 的 Upper 前缀区分大小写路径。`queryOne` 等名称仅提供识别能力，是否允许泛型仍由语法上下文决定。`Store` 和 `Array` 没有被新增为语言关键字。

## Edges：边界与限制

此项完成 token 表达与生产扫描入口接入，语法解析器仍由 Zig 实现。模板 token 内的插值解析、flat AST、显式 continuation 与完整自举固定点仍待完成。

内部 word 暴露 DFA 最终状态，普通标识符可能恰好是关键字的未完成前缀；parser 必须判断完整词对应的枚举成员，不能把非 Dead 当成关键字。关键字分类本身继续由原 25 项关键字表决定。

新字段增加每个内部 token 的固定存储大小，没有复制标识符原文。旧 Zig parser 适配仍会复制 Token/Span 列表；不能把本阶段宣称为整个编译管线零拷贝。

## Answer：使用与核对

```sh
zig-out/bin/zxc build packages/compiler/src/zx/frontend/lexer/scan.zx \
  --out /tmp/zxc_parser_scan --no-cache

zig-out/bin/zxc build packages/compiler/src/zx/frontend/lexer/lex.zx \
  --out /tmp/zxc_parser_lex --no-cache
```

两者输入均为字节列表的 JSON 命令行参数。前者返回语法元数据，后者保留原有结果。普通 zxc 应用无需调用这些编译器内部模块。
