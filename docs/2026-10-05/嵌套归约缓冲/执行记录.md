# 嵌套归约缓冲执行记录

## Intent

将已有跨函数追加分析接入嵌套列表路径，不扩大安全分析许可范围。

## Data

修改 genz 的 reduce lane 匹配和 object_reduce 初始化，增加 append/writeback.zig。完整字段路径必须同时对应调用输入和输出；归约结束时对每条已启动 lane 执行一次 toOwnedSlice，并沿路径重建只读祖先。相同祖先上的多条 lane 顺序写回，后一次保留前一次更新。

生成的模板准备模块第一遍已启用四个嵌套 buffer：graph.events、graph.parts、graph.templates、lexer.comments。第二遍仍只有最终 interpolations，active session 的保存与恢复没有被错误放行。

## Edges

模板边界观察仍读取新 token 的最后一个元素；现有 element_read 审计因此拒绝 token lane。token_templates helper 返回裸列表，也未进入聚合值函数的 buffer 摘要。此次通用路径修复没有消除这些额外瓶颈。

实测 16466 字节的 keyword_transition.zx，准备阶段 arena 容量仅从 166146524 降至 163770960 字节，仍明显不合适。两个较小的模板材料分别从 524644 降至 524346、815092 降至 767136。记录保留原始数据，不能据此宣称模板准备性能完成。下一步应先消除算法中不必要的 token 元素读取并恢复索引列表的可分析传递，再独立解决会话转移。

未新增测试用例、未执行全量测试。tuple 写回实现经过源码审查，本轮未单独构造 tuple 材料，不声称穷举其路径。

## Answer

- `zig build dist -Doptimize=ReleaseSafe` 成功。
- 新生成模块编译后重放 1963 份既有材料，297 模板、311 插值全部一致。
- 新 RX 类型产物重放 878 份源码的 9336 个解析位置，全部一致。
- 格式及 diff 空白检查通过。
- 只读审查确认输入/输出路径一致性、多个 sibling lane 的顺序写回、只读祖先重建和单次冻结；未发现可证实错误。此为代码审查结论，不是形式化证明。

## 自我复核

本轮提升只解决路径深度限制，不代表解决所有列表复制。首次从外部初值追加仍需复制元素槽位，容量增长也可能移动内存；这些属于明确列表存储行为，没有创建专用运行库。性能观测指出主要成本依然在 token 更新，后续应针对实际原因修复，不通过撤销审计来获得表面结果。

## 边界追加补齐

随后去掉 boundary.advance 对末尾 token 的元素读取：模板表长度在当前字节增加且 lexer 同时发出 token 时，该 token 即为关闭的根模板。嵌套模板关闭不会产生根 token，所以不误标。模板索引 helper 改为返回具名 ids 字段，使既有聚合值与 lane 分析可以追踪其所有权；没有放宽生成器审计。

第一遍现在启用 graph.events、graph.parts、graph.templates、graph.token_templates、lexer.comments、lexer.tokens 六条稳定 lane。无模板时无需插值路由，prepare 直接交付根结果和空插值表。第二遍 active 会话的保存、恢复及冻结仍待独立优化。

最终既有 keyword_transition.zx 的准备阶段 arena 容量从 166146524 降至 9440266 字节，减少约 94.3%。两个模板材料分别为 524124、514322 字节。这里只报告三个真实文件的观测，不把单点降幅等同于普遍线性或零开销证明。语义差分继续覆盖 1963 份材料、297 模板、311 插值；完整明细见边界追加差分.json。

最终源码定向执行 test-type-parser，29/29 构建步骤、16/16 测试通过；没有新增测试用例或执行全量测试。此前 RX 类型差分为 878 份源码、9341 个解析位置全部一致，记录见边界追加类型差分.json；该差分生成于无模板短路之前，短路后的最终源码由模板差分和定向回归核对。
