# 归约追加生成参考

## Intent：最终目标

对独占列表的只追加 reduce 保留循环内容量，避免反复复制整个累加结果。不需要新语法、额外包或运行时解释器。

## Data：支持的写法

```typescript
const initial: u64[] = []

return in.reduce((items, item) => items.push(item)[0], initial)
```

同时支持 concat，以及条件选择追加或保持原值：

```typescript
return in.steps.reduce((items, step) => step.enabled ? items.concat(step.values)[0] : items, initial)
```

示例分别见 [逐项追加](归约追加生成/示例/append.zx)、[条件追加](归约追加生成/示例/select.zx)。原有 [展平](归约累加器所有权/示例/flatten.zx) 无需改动即可优化。

## Edges：边界与限制

优化要求回调结果为累加器本身、push/concat 更新后的第零字段，或上述表达式的条件组合。条件和追加参数均不得依赖累加器；例如使用 `items.length` 决定分支仍走普通生成。pop、splice、reverse、sort、其他回调结果和跨函数传递均不在本轮范围。

首次真正追加才建立 builder 中的初值副本；空源或全部跳过时直接返回初值。初值可以是任意合法 owned 列表，无须假定它来自完整 allocation。优化不会对旧 slice 调用 realloc/free，不改变公开列表 ABI。分配次数和 OutOfMemory 时点可能变化。

对于命中的只追加归约，标准 ArrayList 保留容量，追加构造总成本随初值与追加元素总量摊销线性增长；回调本身的计算成本另计。普通消费式 push/concat 独立调用仍可能反复复制，不能将本优化理解为所有列表都已携带容量。

## Answer：运行与证据

```sh
zxc build docs/2026-10-05/归约追加生成/示例/append.zx --out /tmp/append
/tmp/append '[4,7,9]'

zxc build docs/2026-10-05/归约追加生成/示例/select.zx --out /tmp/select
/tmp/select '{"seed":[1],"steps":[{"enabled":false,"values":[2]},{"enabled":true,"values":[3,4]}]}'
```

结果分别为 `[4,7,9]` 和 `[1,3,4]`。实际记录见 [运行结果](归约追加生成/运行结果.json)、[性能观测](归约追加生成/性能记录.json)，内部设计和自我复核见 [IDEA 实施记录](归约追加生成实施计划.md)。
