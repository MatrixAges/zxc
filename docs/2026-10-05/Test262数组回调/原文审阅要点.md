# 数组回调原文审阅要点

## Intent：保留下一阶段可继续使用的语义证据

本批全文读取 reduce 260 份、map 216 份，正式新增六份适配；其他文件没有整批写入 excluded。完整路径、SHA、flags 与 includes 见 `原文清单.jsonl`。参考执行 946 个严格/非严格变体全部通过，不等于 ZX 执行这些原文。

## Data：主会话复核的观察转换

### 空数组不调用 reduce callback

`reduce/15.4.4.21-5-9.js` 除返回3外还要求外部 accessed=false。单独验证seed或采用返回原accumulator的callback不足。ZX无捕获副作用，因此用读row[0]的fallible callback；空输入返回原seed，非空空行必须报IndexOutOfBounds，非空有效行必须改变结果。该转换标adapted，明确改变了观察机制。

### 二形参 reduce callback

`reduce/15.4.4.21-9-c-ii-11.js` 的callback有且仅有prev/cur两参数，以输入[11]与seed1检验cur>10且prev===1，再把结果写外部布尔变量。适配保留原输入、初值、形参数与谓词，成功返回2，失败返回0。空列表返回1，不能通过成功码2断言；wrong_seed/wrong_item控制必须返回0。只关联原文单元素case，不把新增多元素控制说成原文行为。

### 不采用的近似替换

- map/8-c-ii-9：文件明确测试零形参callback。补一个unused形参后返回true不算该核心语义已经支持。
- map/9-13：原输入不变且called===4；结果长度4不能替代调用次数观察。
- map/8-c-ii-4：输入恰好0至5，但原文检查的是callback index参数，不能用item代替idx。
- reduce/9-c-ii-10：只声明prev一个形参是测试目标之一，补第二个形参会改变目标。
- reduce/7-11、9-5、10-2：省略initial是必要语义。添加显式seed或把单元素改成空数组不能作为适配。
- reduce/9-c-ii-7：异常停止场景的接收者是稀疏array-like对象，索引0抛错；普通稠密列表越界失败仅能作为ZX自有补充。

## Answer：复核发现的原文陷阱

- map/15.4.4.19-3-6.js 的description说string，实际length是number 2。
- map/15.4.4.19-8-8.js 与9-5.js实际是带数字属性而length为0的array-like对象，不是单纯[]。
- map/15.4.4.19-8-7.js callback的obj遮蔽外层obj，删除的是数组上不存在的srcArr；不能据description声称验证了释放原持有者。
- map/create-ctor-non-object.js的callCount += 0不能强力证明callback没执行。
- reduce/15.4.4.21-9-b-1.js是new Array(10)的十个洞，不是空数组。
- reduce/15.4.4.21-9-7.js删除o.arr后仍要求完整结果12345，不能按description称遍历停止。

自我复核：这些阅读结果支持精确选择新适配和保留缺口，不能证明上述未适配能力已经实现，也不能将476份参考执行计入ZX测试通过数。
