# 统一库发布参考

## Intent：使用目标

将源码包的公开模块一次发布，供 zxc 应用和 Zig 模块系统消费。RX 编排与 ZX 计算可以属于同一库。

## Data：接口与证据

```yaml
name: arithmetic
version: 1.0.0
exports:
    ./increment: increment.zx
    ./multiply: multiply.zx
```

```sh
zxc build pkg.yaml --mode lib --out dist/arithmetic
```

产物清单保留公开路径，目标变为 library.zxcir 中的模块名称。消费者声明正常包依赖，再使用 `import increment from "arithmetic/increment"`。不会发布私有源码路径为隐式导出。

Zig 项目将输出目录声明为路径依赖，调用 `dependency.module("./increment")`。模块名与 exports 键完全相同；默认模块名为 `.`。每个公共模块提供已声明类型与 execute，具体参数按生成的 Zig 签名使用，计算入口通常为 `execute(&arena, input)`。可在同一个 arena 中组合多个公开模块。

## Edges：边界与限制

- entry 与 exports 不能混用。entry 可指向包内 .zx 或 .rx 文件；单入口构建归一为默认公开模块 .，产物同样使用 library.zxcir。单入口的 Zig 模块名保留 library、文件保留 root.zig。
- 本入口接收源码包及 library 指向统一产物的编译包。编译包可直接 verify，也可 build --mode lib 到新目录；按清单公开映射选择模块，保留类型、Store 和原生身份。实现及真实消费见 [编译包重建记录](统一库/编译包重建实施记录.md)。
- 原生实现与包内资源随包复制。系统库、外部头文件目录等要求保留在 library.json 中，不承诺无条件跨操作系统可用。
- 发布库内所有公开模块必须通过已有契约证明要求；这不等同于证明任意业务目标。
- 现有发布检查会避免覆盖输入并检查构建期输入变化，不构成整个目录的原子替换承诺。
- library.json 的 managed_files 记录本次生成文件与 SHA-256。后续构建删除已登记且不再生成的文件；未登记文件保留，退役文件被手工修改时拒绝发布。旧清单只有 bundled_files 时只清理原生资源，不追溯猜测其他文件归属。
- `zxc build pkg.yaml --mode lib --out dist/arithmetic --watch` 支持库持续重建；已实际验证删除导出、编译失败保留旧产物及恢复，见 [发布清单实施记录](统一库/发布清单实施记录.md)。

## Answer：产物与成功标准

输出 library.zxcir、pkg.yaml、build.zig、library.json、共享 ABI、public 与 modules 目录，以及需要的原生实现。消费成功以真实编译和执行为准。

本轮实际验证：算术包被 zxc 与 Zig 分别消费，输入 3 得到 40；原生库先被源码包导入并再次发布，再搬迁消费，zxc 输出 First→Second、Second→First，Zig 输出 Second First。RX/ZX 混合包也完成发布；尚未用该新发布物验证所有混合执行路径。

实现及复核见 [统一发布实施记录](统一库/统一发布实施记录.md)。

Store初值现已随统一产物保存、实例重绑定并可再次发布；写入格式为zxc.library.v2，仍可读取没有初始化声明的v1库。普通ZX函数不会因此获得Store权限，RX 可通过 Call.module 显式调用已编译的公开 RX 流程，并从库初值生成应用共享内存状态；其内部 Store 授权保留，调用者不获得任意读写句柄。Input 为 void 时省略 in。实现与实际执行记录见 [RX公开模块实施记录](统一库/RX公开模块实施记录.md)。
