# 状态列表追加参考

## Intent：最终目标

在对象 reduce 中累积列表时复用容量，避免每次追加都复制此前全部元素。公开对象和列表接口保持普通指针与切片，生成代码使用 Zig 标准库 ArrayList，不需要专用运行库。

## Data：支持写法

```typescript
export type Input = u64[]

export type State = { count: u64, values: u64[] }

export type Output = State

export default function (in: Input): Output {
  const values: u64[] = []
  const initial: State = { count: 0, values: values }

  return in.reduce((state, item) => ({
    count: state.count + 1,
    values: state.values.push(item)[0]
  }), initial)
}
```

支持候选字段保持原列表，以及直接 push 或 concat 后选取第零项。可以按条件跳过追加，也可以读取旧列表的长度。第一次实际追加时复制初值，后续复用容量；归约结束后交付最终切片。空输入或所有分支都保持状态时，不启动列表缓冲区。

## Edges：边界与限制

资格按表达式结构静态判断，与示例中的变量名、字段名和输入长度无关。旧列表完整值传递、索引读取、放入其他结果字段，以及被最终字段覆盖的额外追加，均不能使用本优化。编译器保留普通生成，不为命中示例放宽所有权规则。

当前前端以整个对象跟踪消费，尚不支持一次归约分别消费两个列表字段。后端逐字段分析不代表此类源码已获支持。字段所有权和内部别名需要独立处理。

优化保留求值顺序、长度溢出检查与错误传播；分配次数和 OutOfMemory 出现时点可能变化。该优化没有消除所有嵌套对象、字符串与列表操作的分配。

## Answer：使用与成功标准

```sh
zxc build docs/2026-10-05/状态列表追加/示例/collect.zx --out collect
./collect '[3,0,9]'

zxc build docs/2026-10-05/状态列表追加/示例/collect.zx --mode lib --out library
```

应用结果为 `{"count":3,"values":[3,0,9]}`。发布库中的 `execute` 同样保留优化，独立 Zig 宿主已运行得到 `{"count":3,"values":[2,3,5]}`。

空输入、条件跳过、非空初值 concat、旧元素读取回退和被覆盖追加回退，均有实际运行结果。5000 项 collect 的 arena 容量由 120021366 字节降为 87566 字节，值和顺序一致。容量是该宿主的观测结果，不能解释为通用固定内存上限。
