# 发布清单格式修复

## Intent：最终目标

让生产发布的 pkg.yaml 直接通过自身 fmt/lint，避免归档语义检查及工作区检查被生成格式挡住。

## Data：可用证据

独立测试会话阶段 404 发现发布清单的 name/version/library 与 exports 之间缺少空行。现有 lint.configuration.yaml 规则在相邻顶层字段任一为多行时要求分隔，manifest/write.zig 却连续输出所有字段。相同问题还影响 dependencies、workspace 与 native 配置块，不能只针对 exports 补特例。

## Edges：边界与限制

在共享清单 writer 内修复所有多行块边界，保留字段顺序、值及序列化形状。不在消费端宽松绕过检查，不对测试发布目录补跑 fmt，不修改测试会话源码。URL 域名层的未完成代码继续保留，本次修复提交不夹带它。

## Answer：实现与成功标准

每个多行顶层块前输出分隔空行；exports 后紧跟 private 单行字段时同样分隔。保持 writer 原错误接口，不增加解析与再次格式化成本。执行反馈要求的 test-semantic-lint 定向回归，使用未经格式化的生产发布结果验证归档包和工作区检查。

```mermaid
flowchart LR
  Manifest[清单数据] --> Writer[共享writer]
  Writer --> Blocks[按单行与多行边界输出]
  Blocks --> Published[发布pkg.yaml]
  Published --> Lint[原样lint]
```

```mermaid
flowchart LR
  Scalars[name/version/library] --> Gap[空行]
  Gap --> Exports[exports块]
  Exports --> Next[下一字段边界]
  Next --> Config[依赖与原生配置]
```

## 验证与自我复核

反馈指定的 `zig build test-semantic-lint --summary all` 成功，14/14 步通过；五组 Node 检查为 5、13、15、18、16 项，总计 67 项全部通过。归档相关 16 项包含发布包自身 lint、消费工作区 lint、无原源码消费、损坏归档和公共接口错误拒绝。已检查 fixture 使用 build 的原始 published/pkg.yaml，没有自动 fmt。

[完整定向日志](发布清单格式修复/定向回归结果.txt)保存实际结果。没有运行全量测试，没有新增或修改正式测试文件。更广的清单块边界修复来自同一 writer 的共同缺陷，但本次归档回归不等于所有清单字段组合均已穷尽；保留现有格式器作为独立判断依据。
