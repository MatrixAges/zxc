### 已发现的生产缺陷

`zxc_alloc(0xffffffff)` 在 Debug 下进入 `ArenaAllocator.alloc` 后发生整数溢出，宿主得到 `WebAssembly.RuntimeError: unreachable`；约定的返回值 `0` 与错误结果 `OutOfMemory` 未得到满足。分配长度与 arena 元数据开销已超过 wasm32 地址范围，此场景不要求宿主实际提供 4 GiB 内存。

已将复现反馈至指定实现会话。实现会话已在工作区加入基于分配器块大小及开销的上界校验，并将输入存储独立分配和释放。测试保留该边界；没有在测试中跳过、吞掉 trap 或改写预期。日志保存在 `WASM协议验证/Debug.log` 与 `WASM协议验证/状态与WASIDebug.log`。

修复后日志：`WASM协议验证/修复后Debug.log`、`WASM协议验证/ReleaseSafe.log`。两次运行对应 runner 文件 Git blob 为 `884b682ac40e59d72ff06c78ed10e769964392c7`，与修复提交 `e2cebde7` 中的 runner 完全一致。

## Edges：边界与限制

- i32/i64 的宿主参数转换发生在模块调用之前；u32/u64 返回值按位宽还原无符号值，f32 预期使用 `Math.fround`，浮点比较保留负零与 NaN 语义。
- JSON 通道比较解析后的值，不要求浮点数字面文本完全相同；宽整数的精确边界通过 BigInt 标量通道验证。
- 每次分配后读取当前 `memory.buffer`，立即复制解码结果，避免使用内存增长前的视图。
- 20 次预热后重复 100 次无状态调用检查内存页数稳定，仅证明该工作负载，不能据此宣称任意 Store 更新具有有界内存。
- RX 验证成功提交、重复执行拒绝、错误不更新状态、reset 保留状态、deinit 重新初始化和实例隔离；未覆盖并发宿主调用。
- 捕获到 WASM trap 后弃置记录测试实例，不继续调用其 deinit。整个测试仍失败。
- WASI 使用 Node preview1 宿主运行，不涉及浏览器 UI 验证。
