# Gateway 请求验证记录

## Intent：最终目标

第 393 部分验证 Gateway 的定义分析、HTTP 请求宿主、独立服务类型、显式原生能力与应用级 Store 请求生命周期。

新增 `test-gateway` 并接入 packages/test 总 test。定义分析使用真实 XML 解析入口；运行时从独立临时项目构建应用并通过原始本地 TCP 请求观察响应；样例按 basic、native、state 分层分组，整理后的路径已重新通过双模式检查。

共享状态样例使用两个物理 Store，均名为 counter 且具有相同字段类型，初值不同；读取服务反转局部声明顺序，能暴露误用局部槽位编号的错误。第二个 Call 使用新的 Store getter，而不是前一个 Call 的返回值，验证提交后重新读取；先成功再失败的服务验证已提交状态不回滚。

replace 路径先复制输入列表形成 owned 值，再交给 owned Input helper 追加元素，最后与请求字符串组成 Store 新值。响应完成后通过多次无写入的临时请求，再读取 Store，对照数组和 Unicode 字符串；这验证请求 arena 生命周期，但不宣称长期回收有界。

测试先保留动态回环端口用于构建，释放后立即启动专用服务器；如果碰撞则测试失败，不用固定端口或静默重试掩盖错误。运行 cwd 与编译 cwd 分开，服务器 argv 和专用环境键由测试控制。请求超时由测试宿主设置；进程最终停止，临时目录清除。

## Edges：边界与限制

HTTP 宿主顺序处理、每连接一个请求。本文没有并发、请求超时、TLS 服务端或长期有界 Store 回收的完成证据。持有提交的请求 arena 保留到应用结束是当前实现边界。

分析 OOM 检查只证明定义分析阶段，不替代 Gateway 运行时、请求 JSON/响应序列化或 Store 提交注册的全部分配失败验证。没有测试 watch 产物更新、应用构建选项完整矩阵、跨平台运行或编译库 Gateway 服务；这些仍需后续补齐。

运行中的服务器默认顺序循环，通过 SIGTERM 停止；重启检查证明没有隐式磁盘 Store 持久化，不证明信号退出时执行了正常 deinit。每个检查可能发出多个实际请求，统计的是场景数，未把启动探测和辅助读取重复算作新测试。

## Answer：结果与交付

Debug 与 ReleaseSafe 均通过 48/48 定义分析检查和 86 项真实应用场景；各为 16/16 构建步骤成功，执行进程终态退出码均为 0。运行日志、JSON 复现材料、执行 JSON、源码草稿位于 Gateway请求验证目录，IDEA 计划包含架构图和数据流图。

## 缺陷闭环

实现会话在 `530b944d` 修复以下边界：

1. 原始请求头中的无冒号行、含空格头名和含 NUL 头值都会被底层 parser 容忍，Gateway 继续执行服务并返回 200。原始 TCP 复现已记录；新增分派前的头校验，非法请求返回 400。回归同时检查合法 HTAB、非 UTF-8 头值仍可接受，并用写入路由证明非法头不会修改 Store；空 Gateway 也必须执行校验。
2. listen='127.0.0.1' 和 listen='[::1]' 被底层 parseLiteral 接受为端口 0，与显式 IP:port 契约不符。已增加明确端口语法检查；显式 0 和 65535 仍可接受。
3. 513 字节请求头超过 512 限制时，服务器虽发出完整 431，但本机因未读数据而触发连接重置。实现侧调整关闭顺序，先 shutdown 再 close；测试继续要求完整响应和正常关闭，没有放宽为接受空响应或重置。

## 自我批判

- 初版状态夹具在 map callback 捕获 in.increment，违反 ZX 无捕获回调契约；已采用每次成功 Call 将 history 元素加 1 的独立规则，value 则按输入 increment 增加。没有将夹具错误报告为生产缺陷。
- 直接传 RX 借用输入给 owned 参数不合法；最终夹具先 map 复制再消费，遵守既有所有权契约，不借测试需求放宽语言规则。
- 头超限的连接重置经抓包证实包含完整 431，与“未发响应”不同；实现修复后重新运行严格收包断言。保留修复前材料用于解释差异。
- HEAD 测试同时检查副作用和无正文，不能仅凭空响应认定服务已执行；Store 读取提供独立证据。
- 本轮只提交测试和文档；生产修复由指定会话独立提交。共享工作区的记录时 HEAD/状态不代表整个测试过程完全静止。
