# 新增编译目标实施计划

## Intent：最终目标

将用户更新目标中的 SIMD 汇编优化（原文 SMID）、WASM 支持、对齐 napi-rs 使用方式的 N-API 插件支持纳入整体实现与自举前核对。保留全部原有需求。

## Data：可用证据

2026-10-05 用户先后更新目标，明确新增以上能力。实施前检查当前 genz、CLI target、原生接口及 app/lib 发布契约，再核对 WebAssembly、Node-API 与 napi-rs 官方实现依据；目前不把 Zig 可选 target 的存在视为这些功能已经完成。

## Edges：边界与限制

保持静态类型、zero runtime 与分包职责。SIMD 需区分自动向量化证据与显式向量操作；WASM 需明确宿主导入导出和可执行证据；N-API 插件需采用宿主规定的 ABI 与生命周期，不把动态语言宿主的必要适配误称为无成本，也不另建 zxc 解释器。详细范围按当前实现与官方契约进一步拆解。

## Answer：交付与成功标准

分别形成实施方案、对应编译与发布入口、实际宿主消费产物及 usage/reference。完成证据必须覆盖实际 SIMD 汇编、WASM 宿主执行和 Node 加载插件；不能只凭构建成功或模板存在认定交付。本轮仅记录目标，尚未开始这三项新增实施。

## 实施进展

WASM 已在提交 22e4bf90 接入：WASI 命令执行，以及 wasm32-freestanding 的 JSON/直接标量调用、RX 持久 Store 生命周期均取得实际宿主执行证据。见 [WASM 实施计划](WASM实施计划.md) 与 [WASM reference](WASM参考.md)。SIMD 与 N-API 仍待实施，不能以此次交付替代。

N-API 已接入 --host node 和独立 napi 包，完成本机加载、类型转换、Store/Worker、void、URL 标准库及 Linux/Windows 交叉构建证据。见 [N-API 实施计划](NAPI实施计划.md) 与 [N-API reference](NAPI参考.md)。宿主 I/O/process、异步接口及真实跨平台执行尚未覆盖。SIMD 仍待实施。

SIMD 已通过通用 map 预分配与浮点 Vector 生成接入，取得 SSE、AVX、ARM、WASM 指令证据及本机与 Node WASM 执行记录。见 [SIMD 实施计划](SIMD实施计划.md) 和 [SIMD reference](SIMD参考.md)。N-API 的 TypeScript 声明和普通模块入口已实现并完成 strict/NodeNext 与真实 Node 加载验证，见 [类型实施计划](NAPI类型实施计划.md)。用户明确对齐的是 napi-rs 使用方式，不要求引入 Promise 或 AsyncTask。原生插件、声明导出和模块入口已交付；其他宿主边界继续以 reference 为准。
