## Intent：最终目标

第 390 部分覆盖真实 ZX/RX/State 应用入口中的 Process 转发，以及返回值 json/discard 策略，避免只根据生成源码文本推断行为正确。

## Edges：边界与限制

每次运行创建新的 State，不证明同一 State 下多个 Request 的回收或跨请求 owned setter 生命周期。这里只覆盖标准输入输出中的写流与应用返回值组合，完整 stdio 读写边界另立部分。没有进行网络请求或浏览器检查。

编译和运行时用户环境的大部分键由子进程继承，但断言只依赖专用受控键；不枚举或输出用户环境。非零退出诊断依赖当前 CLI 可观察契约；非法参数由 usage 和非零退出验证，并断言未产生输出产物。

## 缺陷与修复闭环

首次 RX `Call.fn` 调用 Input=void 的 snapshot，`in="$in"` 报未知名称。Schema 要求 fn/service 必须带 in，而表达式编译阶段跳过了 void 输入绑定。实现会话已在 `c691b739` 按反馈修复：把无运行时数据的 `$in` 表达为编译期单位值并生成 unit IR，保留普通变量不能绑定 void 的限制。补充 Call.service 路径以验证该机制可贯穿服务调用。

初轮另外修正了测试夹具自身的问题：RX 编译不能在项目外 cwd 下推断项目根；CLI 的无效参数错误输出 usage 而非内部错误名称。两者未报告为生产缺陷。保存首轮日志不代表这些失败仍然存在。

## 自我批判

- discard 的空 stdout 不足以证明内部字段值正确，因此断言名称明确其只能证明接受参数和丢弃返回值；default/json 做值级别对照，错误分支验证执行未被整体跳过。
- 默认仍然是 json，本部分没有批量迁移旧测试，也不把 discard 当成默认行为。
- 共享工作区有实现会话并行修改；记录时 HEAD 和生产状态只是当时快照，不宣称整个执行期间对应完全静止且干净的提交。
- 这里只验证本部分入口行为，不宣称已完成所有 Process、HTTP、Store 生命周期或 Test262 对齐工作。
