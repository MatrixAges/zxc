# 子进程输入验证记录

## Intent：最终目标

验证新增 spawnSyncWithInput 的完整二进制输入、EOF、三管道并发与资源清理，同时保持已有 spawnSync 行为。对应阶段 401，生产依赖为 1cdb3ca9。

## Data：测试覆盖

新增 `test-child-input` 并接入标准库总 test。测试位于 `tests/standard/resources/child_input`，子进程、选项夹具、结果、限额、参数校验、分配、并发注入、编译工具和生成代码宿主分别组织。

新增 57 项：原生结果 11、限额/提前关闭 8、分配 4、参数与 IO 校验 11、并发注入 3，合计原生 37；源码直接生成与库 link→encode→decode 后生成各执行 10 项，合计 20。不同优化模式不重复计数。

### 字节和并发

空输入必须使子进程读到 EOF；验证 NUL、255、128、CR/LF、Unicode 原始字节以及 1/255/256/8191/8192/8193/65537 长度边界。非零退出在完整读取输入后仍作为正常 Result 返回，POSIX TERM 信号在完整读取后保留 kind/code。

大管道夹具先交替写出 262144 字节 stdout 和 262144 字节 stderr，再读取并回显 524288 字节 stdin。测试要求 stdout 总长 786432、stderr 长 262144，前缀逐字节核对且尾部完全等于输入；若先写完 stdin 才读输出，此交互会互锁。

每个专用子进程都有独立并发 watchdog，15 秒后以 124 退出，防止死锁无限挂起。正常结果必须 code=0，watchdog 退出不能冒充成功。输出超限和关闭 stdin 后继续存活的场景另要求 5 秒内返回错误，不能依赖 watchdog 或子进程自行退出。

显式参数保留空参数、空格和 shell 特殊字符；环境与空环境行为、显式 cwd 及父目录不变均核对。子进程不调用 shell。

### 失败与资源

检查两个输出流恰好上限、超过一字节、零上限空流、重复失败后恢复。2 MiB 输入下子进程先输出时，任一流超限必须取消阻塞写入并返回 StreamTooLong。子进程关闭 stdin 后继续睡眠 10 秒，调用须迅速报告 BrokenPipe，而不是等输出 EOF。

参数校验覆盖命令、每个 argv、cwd、环境名称和值的空值、NUL、非法 UTF-8；使用显式 IO 的 processSpawn 拒绝探针确认无效参数在启动前拒绝。另验证缺失可执行文件、空/不存在 cwd。

并发注入分别令 Io.Select 的第一次、第二次 groupConcurrent 返回 ConcurrencyUnavailable，验证错误传播、直接子进程 kill/reap、最终句柄清空与恢复调用。第二次派发失败时已启动写任务，通过 fileClose 包装和原子计数确认被转交的 stdin 写端恰好关闭一次。等待结果时模拟 childWait 返回 Canceled，确认仍 kill/reap。

原生成功和输出超限遍历所有分配失败；DebugAllocator 检查完整释放。生成宿主也遍历 OOM、验证显式 IO 拒绝、限额失败后恢复、结果跨后续调用保持，以及 requires_io 和 borrowed 输入契约。

### 编译与库路径

main.zx 真实导入 std:child_process.InputOptions 和 spawnSyncWithInput。编译工具分别从源码 IR 与库编解码后的 IR 生成 Zig/ABI，再以相应 ABI 实例化标准库模块并运行宿主。两条路径均验证二进制双流、空输入、262144 字节输入、错误传播、退出码与信号。

## Edges：边界与自我批判

最初 fixture 的 bytes 函数与参数同名，Zig 拒绝编译；改为 payload 后继续。并发注入首轮误覆盖独立 Future 的 concurrent 入口，未触达 Io.Select 的 groupConcurrent，导致两个测试得到真实输出超限而非预期派发错误。核对本地 Zig API 后修正注入点，保留失败日志；没有把未触发故障的运行算作通过，也没有修改生产实现。

本阶段未发现新的生产缺陷，没有向实现会话发送修复消息。等待取消是模拟指定 vtable 返回 Canceled，不等于覆盖所有真实宿主取消时序。allocator 检查覆盖传给库的分配，不能代表 IO 后端内部所有分配的峰值。

当前本机 POSIX 运行信号测试；Windows 分支明确跳过信号用例，未在 Windows 实机执行本套件。不覆盖继承管道的孙进程、生产超时、进程树管理、长期交互会话或严格瞬时内存上限。15 秒 watchdog 属于测试夹具，不是给生产 API 添加了超时。

## Answer：复现与交付

在 `packages/test` 执行：

```sh
zig build test-child-input test-child-process --summary all
zig build test-child-input test-child-process -Doptimize=ReleaseSafe --summary all
```

最终 Debug、ReleaseSafe 均为 98/98 测试、42/42 构建步骤，退出 0。新增 57 项与原有 41 项 child_process 回归分别计数；两个优化模式不重复累计。最终结果见 [结果 JSON](子进程输入验证/结果.json)，[配套目录](子进程输入验证/)保存日志和草稿。[计划](子进程输入验证计划.md)包含 IDEA、架构图和数据流图。完成后独立提交推送。
