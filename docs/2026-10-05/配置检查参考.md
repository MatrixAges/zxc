# lint 与配置格式化参考

## Intent：使用目标

在不构建应用、不安装依赖的情况下检查源码与包配置；按显式请求整理清单或包索引格式。

## Data：命令

```sh
zxc lint workflow.zx
zxc lint workflow.rx
zxc lint pkg.yaml
zxc lint pkg.lock.json
zxc lint registry.json --kind index

zxc fmt pkg.yaml
zxc fmt pkg.yaml --check
zxc fmt pkg.yaml --write
zxc fmt registry.json --kind index --write
```

--kind 可选 manifest、index、lock；可用它明确指定自定义文件名的配置类型。pkg.yaml 与 pkg.lock.json 自动识别；包索引必须显式指定 index，不依赖文件名猜测。lint 成功不输出文本，失败返回非零退出码及诊断。

fmt 默认输出标准输出，--check 比较格式并返回状态，--write 原子替换原文件。无效配置不输出格式化结果、不写回。

## Edges：检查范围

| 输入                 | 检查内容                                              | 不代表                                     |
| -------------------- | ----------------------------------------------------- | ------------------------------------------ |
| ZX                   | 语法、名称、现有 AST 空行规则                         | 完整项目类型、依赖和证明通过               |
| RX                   | XML、按文件种类的单文件 Schema、元素空行              | 所有依赖可达、项目无环、完整类型和执行正确 |
| pkg.yaml / manifest  | 现有清单 schema、重复与未知字段、字段类型和组合、格式 | 本地路径存在、依赖已安装、原生接口正文有效 |
| package index        | 现有索引 schema、包名、版本与摘要字段、格式           | 归档存在、下载成功或归档内容与摘要相符     |
| pkg.lock.json / lock | 严格锁定图校验                                        | 锁与当前工作区、安装映射或磁盘内容一致     |

pkg.yaml 的 YAML 格式化只整理顶层块映射字段间的空行，多行字段与相邻字段分开，同层单行字段紧凑排列。保留注释、原有缩进、引号、锚点／别名及标量正文；块标量尾部空白不调整，流式映射不展开。格式器处理 UTF-8，并保留既有 LF/CRLF 间隔。格式化前后使用同一清单 schema 核验语义。

包索引 JSON 使用 tab 缩进及末尾换行，保留数组顺序和数字原文。不会重排包或版本。

锁文件原始字节摘要参与安装映射标识，因此所有 fmt 锁文件操作均拒绝；使用 lint 只读检查。锁文件由 zxc pkg install 维护。receipt、library.json、IR 与缓存是生成协议数据，由所属加载器检查，不作为此命令的默认用户配置类型。

## Answer：实际示例

[配置示例](配置检查/示例) 包含清单与索引；工作区可以按以下顺序执行：

```sh
zxc pkg install docs/2026-10-05/配置检查/工作区示例/pkg.yaml --offline
zxc lint docs/2026-10-05/配置检查/工作区示例/pkg.lock.json
```

该流程已实际完成，锁文件只读检查前后字节不变。实现、IDEA 边界与自我复核见 [实施计划](配置检查实施计划.md)。

## 项目语义检查

```sh
zxc lint main.zx --semantic
zxc lint main.rx --semantic --project pkg.yaml
zxc lint main.gateway.rx --semantic
zxc lint state.store.rx --semantic
zxc lint pkg.yaml --semantic
```

`--semantic` 在源码格式检查之外，复用正式编译链路检查模块解析、依赖无环、类型、所有权及公共模块链接。ZX 或普通 RX 输入检查该入口的可达依赖；pkg.yaml 输入检查 entry，或 exports 中的全部公共模块。即使一个公共模块没有被另一个调用，也会独立接受分析。

`--project` 可显式选择清单，只在语义模式中接受；不指定时沿正常项目规则发现清单。`--kind` 与 `--semantic` 互斥。成功不输出内容，失败报告诊断并返回非零状态；不会写入构建产物或语义缓存，也不会下载或安装依赖。

本模式不调用证明求解器、不生成 Zig 或可执行文件、不执行业务代码，因此不能代替 `verify`、`build` 或运行时验证。它不扫描不可达文件或整个 monorepo；每个包可分别执行。Gateway 入口会检查路由配置及其可达服务，独立 Store 会检查初始化表达式与字段类型；也支持以 pkg.yaml 的 entry 指向这两种文件。普通 RX 和 Gateway 可达的 Store 定义同时接受语义与格式检查。Gateway 不会监听端口，Store 初始化程序不会执行。清单 exports 仍遵循既有库公共模块约束，不把 Gateway 或 Store 定义改成可发布的执行函数。

已编译库通过现有归档加载器与链接器校验 IR 和公共接口；没有原始源码时无法重新检查其源码格式。原生 Zig/C 实现正文仍需后端构建检验。`pkg.lock.json` 与索引继续使用上面的单文件配置检查，不接受语义模式。

[示例包](项目语义检查/示例/pkg.yaml)同时展示 ZX、RX 和多个公共模块；[运行记录](项目语义检查/运行结果.json)包含合法入口、跨文件类型错误、公共模块遗漏、依赖环及只读观测。职责划分和限制见[IDEA 实施计划](项目语义检查实施计划.md)。

Gateway 与 Store 的专用入口示例及观测见 [RX 专用入口实施记录](RX专用入口语义检查实施计划.md)。
