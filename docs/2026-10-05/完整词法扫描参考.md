# 完整词法扫描参考

## Intent：最终目标

提供用 ZX 实现的完整词法扫描，作为编译器核心迁移的第一部分。实现已接入[正式主词法入口](正式词法前端参考.md)，也可独立构建；整个编译器仍未完成自举。

## Data：输入与输出

入口为 [lex.zx](../../packages/compiler/src/zx/frontend/lexer/lex.zx)，输入 `u8[]`，表示原始源文件字节。输出包含 tokens、comments 和 diagnostic。token 的 kind 使用 identifier、keyword、number、string、template、punctuation、eof；span 为字节区间 `[start, end)`。注释只保留范围，不复制原文。

成功时 diagnostic.message 为空，最后一个 token 为源文件末尾的 eof。失败时 tokens/comments 为空，diagnostic 提供 code、message、start、end。先校验完整 UTF-8；非法编码使用覆盖全源的 lexical 诊断。

已有词法、模板与原始字节编码样本，加上草稿自身源码，共 837 份去重输入已与原 Zig 词法器实际比对，token、注释和诊断全部一致，见 [核对结果](完整词法扫描/已有源码核对.json)。这证明所核验输入的行为一致，不是全输入空间的等价证明。

## Edges：边界与限制

模板使用显式帧栈，在词法阶段定位嵌套结构；插值中的表达式合法性仍由后续解析决定。扫描保留原实现的深度规则和错误位置。关键字转换表来自当前语法的 25 个词，不来自验证样本；[关键词数据](完整词法扫描/keywords.json)已与 core/src/syntax.zig 核对一致。

源数据不会复制进扫描状态。状态只保留两个前瞻字节，配合输出范围处理最长运算符、注释和模板边界。关键字使用前缀状态转换，不为每个名字重新扫描完整源文件。UTF-8 校验与扫描各遍历一次输入。

初始草稿存在重复列表复制和状态根分配，历史内存记录见 [初版观测](完整词法扫描/内存观测.jsonl)。后续[跨函数列表追加](跨函数列表追加参考.md)已将同一 9750 字节、2283 token 样本的生成模块 arena 容量降至 518236 字节。正式旧 parser 适配层仍有数组转换成本，不能把独立扫描观测当作完整 parse 峰值。

## Answer：构建与使用

在仓库根目录执行：

```sh
zig-out/bin/zxc build packages/compiler/src/zx/frontend/lexer/lex.zx --out /tmp/zxc_bootstrap_lexer
```

应用入口接收一个 JSON 字节数组。可以把既有源文件编码为参数：

```python
import json
import subprocess
from pathlib import Path

source = Path("docs/2026-10-05/首页示例/shipping.zx").read_bytes()
subprocess.run(["/tmp/zxc_bootstrap_lexer", json.dumps(list(source))], check=True)
```

独立旧词法器宿主 [reference.zig](完整词法扫描/reference.zig) 仅用于核对，接收源文件路径；新 ZX 扫描执行路径不调用它。

```sh
zig build-exe --dep zx --dep lexer -Mroot=docs/2026-10-05/完整词法扫描/reference.zig --dep zx -Mlexer=packages/compiler/bootstrap/lexer/lex.zig -Mzx=packages/core/src/root.zig -O ReleaseSafe -femit-bin=/tmp/zxc_lexer_reference
/tmp/zxc_lexer_reference docs/2026-10-05/首页示例/shipping.zx
```

如修改关键词数据，用[正式生成脚本](../../packages/compiler/src/zx/frontend/lexer/generate_keywords.py)更新前缀枚举、转换和接受状态，再对三个输出调用 `zxc fmt --write`。生成后的 ZX 已保存，普通构建不依赖 Python。

完整实施与自我复核见 [实施记录](完整词法扫描实施.md)。
