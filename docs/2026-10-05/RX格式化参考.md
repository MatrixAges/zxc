# RX 格式化参考

## Intent：使用目标

使用 zxc fmt 整理 RX 元素之间的空行与四空格缩进，保持源码中的表达式、注释与属性原文。

## Data：命令与输入

```sh
zxc fmt workflow.rx
zxc fmt workflow.rx --check
zxc fmt workflow.rx --write
zxc fmt state.store.rx --write
zxc fmt http.gateway.rx --check
```

默认输出到标准输出；--check 只检查，格式不一致返回非零退出码；--write 写回原文件。格式化是单文件操作，不要求 pkg.yaml、业务依赖、原生模块或求解器。XML 语法错误报告位置，--write 不改写失败文件。

## Edges：格式规则与边界

同层多行元素、不同标签或不同结构的元素之间保留一个空行；标签、属性名列表及子元素结构相同的单行元素保持紧凑。元素内部首尾不保留多余空行。注释按原有行内或独立位置保留，正文不改写。

调整已有换行处的空行与结构缩进，默认每层四个空格；独立属性续行比标签多一层。不拆同行标签，不重排属性，不改变引号或行宽。保留 LF/CRLF。属性内的表达式、XML 实体和 CDATA 保持原文；含非空白文本的父元素不调整自身间隔。

格式化通过只表示 XML 可以解析且符合当前空行与缩进规则，不表示 RX Schema、命名、依赖、类型或执行正确。当前构建不会强制 RX 空行格式。非法属性、缺失业务目标等仍交给相应语义检查入口处理。

## Answer：结果与验证

成功后可再次运行 --check；重复格式化不会继续修改已经格式化的文本。此前的空行阶段示例位于 [原始示例](RX格式化/原始示例) 和 [格式化示例](RX格式化/格式化示例)。四空格与表达式风格规则的当前验证见 [实施计划](../2026-10-06/表达式风格与四空格/实施计划.md)。
