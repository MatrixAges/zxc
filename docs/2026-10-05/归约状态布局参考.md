# 归约状态布局参考

## Intent：最终目标

对可证明中间对象身份不逃逸的对象 reduce，消除每轮顶层对象分配，保留不可变状态语义与既有对象 ABI。

## Data：支持写法

```typescript
const initial: State = { count: 0, total: 0 }

return in.reduce((state, item) => ({
  count: state.count + 1,
  total: state.total + item
}), initial)
```

也支持根据条件保持 state，以及在结果对象中使用 `...state`。所有新字段先读取旧状态，构造完整下一状态后才替换；并非逐字段修改可见对象。字段可包含借用列表、字符串和子对象，顶层优化不会移动这些字段原有存储。

## Edges：边界与限制

完整 state 被传给函数或放入其他聚合值时通常回退普通生成。符合 [内部状态值返回条件](内部状态值返回参考.md) 的根调用现在可临时借用完整 state 并按值返回下一状态。match 或其他未匹配形状仍保留既有实现。优化不依赖变量名、字段名或输入长度，不向应用增加选项。

初值只求值一次；空源或所有分支都保持原值时直接返回初值。实际创建新状态时，循环结束再创建最终对象。对象公开接口仍为不可变对象指针，Zig 宿主与发布库调用方式不变。

满足静态条件的字段列表追加现已与此布局融合，见 [状态列表追加参考](状态列表追加参考.md)。嵌套对象、字符串和未通过分析的列表仍保留原分配。更少的分配可能改变 OutOfMemory 时点。

## Answer：使用与证据

```sh
zxc build docs/2026-10-05/归约状态布局/示例/scan.zx --out scan
./scan '[2,3,5]'
```

结果为 `{"count":3,"total":10}`。同一源码也可以通过 `--mode lib` 发布，生成库保留优化。

在直接执行生成模块的宿主中，10 万个元素的双整数状态扫描，arena 容量从 1906000 字节降为 72 字节，输出一致。空源、条件保持、借用列表与完整状态调用回退均有真实运行记录。详见 [实施计划](归约状态布局实施计划.md)与[内存观测](归约状态布局/优化后观测.json)。

自我复核：这是通用表达式结构上的静态优化，覆盖范围由逃逸检查决定；不能据此称全部状态机内存、自举效率或 Store 回收已完成。
