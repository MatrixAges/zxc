# 同步 HTTP 边界验证记录

## Intent：最终目标

第 392 部分从真实协议字节验证 std:http.request，覆盖请求校验与序列化、响应协议边界、独立内存、资源清理，以及 ZX/RX 真实网络调用。

## Data：可用证据

新增 `test-http` 并接入 test-standard-resources 与总 test。正式测试按用途位于 packages/test/tests/standard/resources/http 与 packages/test/tests/runtime/http。

| --------------- | ---: | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 输入校验        |   22 | URL UTF-8/控制字节、协议/凭据/host、头上限、方法与 body、六种管理头、非法头名称和控制字节                                                 |
| 请求发送        |   15 | 七种方法、POST/PUT/PATCH 空 body、短写与 16385 字节请求体、显式认证、重复头、非 UTF-8 头值、fragment、转义 query、scheme 大小写、独立连接 |

无网络传输替身基于 std.Io.failing，只替换解析回环地址、连接、读取、写入、关闭；其他 IO 不会回退到真实网络。提供精确原始响应字节，按 1/2/3 等短读写粒度驱动真实 Zig HTTP Client，并检查连接创建与关闭计数。回应缓冲覆写后，已返回的 headers/body 仍须正确。

真实服务使用 Node net 绑定 127.0.0.1 动态端口，记录收到的方法、目标、重复头、字节头值和 body，并发送受控 HTTP 字节后关闭连接。子进程异步执行，避免测试父进程阻塞服务事件循环；每个应用有 30 秒宿主超时。真实应用从临时项目构建，结束后关闭服务并删除自建目录。

## Edges：边界与限制

本部分仅实际执行明文 HTTP 回环服务；没有验证受信任 HTTPS 成功链、系统证书来源、TLS 主机名匹配或其他平台执行，也不把此前实现会话的外网记录算作本部分测试。后续需要独立补齐 TLS/证书与发布库路径的验证。

大小上限不是协议超时。本接口无内置超时，本部分仅测试宿主有总时间限制。没有断言操作可重试或并发连接可复用；契约规定一次请求不共享连接池、不自动重试。

HTTP body 为内容编码后的原始字节，chunked 的传输分帧会移除，gzip 不解压。合法 UTF-8 字节在 CLI JSON 中可能是字符串，其他字节是数组；测试将两者还原成 Buffer 后逐字节对照，不把 JSON 表示误认为 HTTP 数据转码。

## Answer：结果与交付

Debug 与 ReleaseSafe 均通过 87/87 直接检查和 70 项真实应用场景，各为 21/21 构建步骤成功；两个执行进程终态退出码均为 0。运行日志、执行 JSON、源码草稿位于同步 HTTP 边界验证目录。IDEA 计划含架构与数据流 Mermaid 图。

## 生产缺陷闭环

发现响应声明 Content-Length=10、仅发送 abc 后 EOF 时，原实现把这三个字节作为成功 Response 返回。不是单纯上限校验问题，而是底层 Reader 的 EOF 被 allocRemaining 正常结束语义接收，未检查 HTTP 报文是否完整。

已按授权通知指定实现会话，由其在 `a166b59a` 修复：非 HEAD/204/304 路径读完正文后检查 HTTP reader 完成状态，未完成返回 ReadFailed。合法的连接关闭定界仍允许返回。回归保留拒绝截断的要求，覆盖固定长度截断、分块数据截断、缺少终止块和终止块 CRLF 未完成；同时在真实 TCP 和 OOM 路径验证。

## 自我批判

- 首轮 expectError 收到意外成功 Response 后没有释放它，日志因此出现测试夹具泄漏。已让失败 helper 释放意外成功结果后报告错误；不把该日志解释为生产分配清理缺陷。修复后的 OOM 检查独立验证生产清理。
- 不完整响应头的实际错误是 HttpRequestTruncated，最初预期 HttpConnectionClosing 不符合现有接口，已修正；这不算生产缺陷。
- 上限、错误和序列化断言来自独立构造的协议字节及明确预期；非法输入的错误预期直接列在测试数据，不用被测实现计算答案。
- 直接接口为 87 个 test 声明，真实应用为 70 个场景；不同短读粒度、OOM 注入点和同一声明中的多个控制字节不重复计数。
- 本轮只改测试和文档，生产修复属于实现会话的独立提交；共享工作区记录时状态不能代表整个执行期间完全静止。
