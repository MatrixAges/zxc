# 对象归约布局验证记录

## Intent：最终目标

第 394 部分验证对象 reduce 顶层值存储优化保持不可变语义与对象 ABI，并在符合条件的表达式上限制分配增长。

## Data：可用证据

新增 test-object-reduce 并接入总 test。每个样例经过独立源码生成，以及库链接、编码、解码、取模块再生成两条路径，实际编译为 Zig 测试执行。

| 样例          | 核对范围                       | 常量分配界限 |
| ------------- | ------------------------------ | ------------ |
| plain         | 全字段构造、所有字段读取旧状态 | 是           |
| spread        | 展开与字段覆盖                 | 是           |
| select        | 更新或保持初值                 | 是           |
| nested        | 嵌套条件分支                   | 是           |
| field_call    | 字段值传给标量 helper          | 是           |
| checked       | 字段索引、失败与恢复           | 是           |
| initial_call  | helper 构造初值                | 是           |
| escape_call   | 完整状态传入 helper 后再构造   | 不要求       |
| root_call     | 根结果为 helper 调用           | 不要求       |
| nested_object | 每轮构造嵌套对象               | 不要求       |

10 个样例 × 2 条生成路径 × 8 项基础检查 = 160；7 个有界样例 × 2 路径 × 2 项容量检查 = 28；checked 的错误恢复与全部分配失败 × 2 路径 = 4，共 **192 项新检查**。两种优化模式不重复计数。

宿主从固定初值 count=3、total=10、last=2 出发，按独立 Zig 循环计算期望值。total 使用旧 count，last 保存旧 count，能识别错误的逐字段原地更新。每轮都校验原始 steps、seed、子对象未被修改；labels、text 与未更新的 child 保留原借用存储。

空源与 select/nested 的全零保持分支必须返回原 seed 指针；发生更新时返回新对象。initial_call 从新构造初值开始，因此不把宿主 seed 指针当成它的初值身份。源码与库路径采用相同独立断言。

容量检查使用宿主 FailingAllocator 包装程序 arena，在 128、2048、16384 元素时，实际 arena 容量和累计分配量均须 <=4096 字节、底层分配次数 <=4；另禁止原地 resize 后重复验证。输入样本由另一 allocator 创建，不计入程序归约分配。对所有路径进行分配失败清理检查，checked 额外覆盖 IndexOutOfBounds 后同一 arena 的恢复。

## Edges：边界与限制

这些有限长度上的实际分配上界不等于任意输入长度的机器证明。嵌套对象、逃逸和根调用的结果/清理有检查，但不要求它们故意产生更多分配，也不以某个内部变量名或生成文本片段作为通过依据。

library 路径为编译库 codec 往返后真实执行，不代表本部分重新验证 CLI 发布目录、包下载或跨进程安装。没有包含状态字段列表追加的新优化，也未覆盖所有标量类型、根 match 形状和所有跨 helper 逃逸组合。

初值 helper 样例和常量分配检查可发现随迭代重复构造初值的增长；没有通过有副作用的初始化器证明所有副作用调用次数。保持该证据边界，避免把容量上界解释成精确分配次数契约。

## Answer：结果与交付

Debug 与 ReleaseSafe 各通过 192/192 项检查、73/73 构建步骤，执行进程最终退出码均为 0。正式测试在 packages/test/tests/collections/object_reduce，构建入口为 packages/test/build/object_reduce.zig。配套目录保存草稿、执行日志与 JSON；计划遵循 IDEA 并含架构和数据流图。

## 自我批判

- 分配计数仅包含被测程序 arena；输入构造和 oracle 使用独立宿主分配，避免输入规模掩盖优化效果。
- 回退样例以正确性为成功标准，未来若出现更强且安全的优化，不应因为分配减少而被本测试拒绝。
- 错误时点可能因更少分配改变，检查所有失败点的清理和可恢复结果，不固定 OutOfMemory 出现于第几次分配。
- 只改测试与文档，本部分未发现生产缺陷，未向实现会话发送无问题消息。
- 实现会话同期提交了状态列表追加优化 10082875，本部分样例没有追加状态列表；该功能需要下一部分单独验证。
