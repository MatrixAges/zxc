# 自举执行细节

## Intent：最终目标

按完整职责推进 RX/ZX 自举；性能不因迁移而退化。第一阶段收口 YAML 字段间规则，每阶段验证后提交并推送。总体计划与架构、数据流图见 [自举执行计划](自举执行计划.md)。

## Data：可用证据

### 第一阶段：YAML 字段间规则

基线 `f570aa73`。原实现位于 `packages/lint/src/configuration/yaml.zig`：每个字段间隙先扫描并收集注释，再由空白规则重新寻找可编辑范围，临时注释列表与编辑列表分别管理。

迁移后的正式入口是 `packages/lint/src/configuration/yaml/gap/resolve.rx`：

- RX 对块标量尾部直接短路，再调用间隙扫描；无效内容或没有可编辑换行时短路，否则连接字段多行判断与已有 `spacing/boundary/check.zx`。
- `scan.zx` 负责有界扫描、行尾与独立注释归属、连续水平空白及首尾换行位置；状态来自 ZX，没有注释数组。
- `multiline.zx` 只判断借用的左右字段切片是否包含换行。
- `root.zig` 只借用三个切片、调用生成入口并将标量范围转成公开编辑结构。使用 `executeValue`，零容量固定分配器使任何意外分配直接暴露；没有专用运行库。
- `entries.zig` 与 lint 构建规则注册 `yaml_gap`。正式构建使用 RX/ZX 生成结果；`bootstrap/yaml_gap.zig` 只供 seed。

### 基线与根因

首版在普通间隙上从 290.17ms 变为 335.93ms，多行字段从 278.01ms 变为 309.18ms，未通过门禁。检查实际生成代码后发现两处可避免的记录物化：构造多行谓词输入记录，以及 `executeIn` 将按值输出再次分配成指针记录。

改为复用完整输入记录并调用已有 `executeValue` 后，移除了这些记录分配。随后长空白间隙仍从 171.29ms 变为 187.80ms；将水平空白作为连续区段扫描，避免每个空格都经过换行状态更新分支，最终消除了该退化。没有修改编译器所有权规则或按源码名称放行。

### 最终测量

工具链：macOS arm64，Zig 0.17.0、Node.js 26.12.1、ReleaseSafe。使用 `skills/compiler-performance/scripts/measure.mjs`，所有性能轮次顺序执行且无并发构建。每组分别编译同一个临时驱动中的旧、新 formatter；驱动与构建脚本保存在本机 `/tmp/zxc-yaml-bench/`，未添加仓库测试。

普通输入每轮执行 100,000 次格式化，每次 256 个字段；长输入每轮 2,000 次、每个间隙含 1,024 个空格或注释字符。不是单次调用耗时。每轮计算完整输出摘要及累计长度，前后均一致。

| 场景                          | 墙钟中位数：旧 → 新 | CPU 中位数：旧 → 新 | 峰值 RSS 中位数：旧 → 新 |
| ----------------------------- | ------------------- | ------------------- | ------------------------ |
| 普通间隙，5 轮                | 290.17 → 256.34ms   | 0.28 → 0.25s        | 2,408,448 → 2,408,448 B  |
| CRLF 与两类注释，5 轮         | 624.02 → 519.98ms   | 0.61 → 0.51s        | 2,441,216 → 2,441,216 B  |
| 多行字段，5 轮                | 278.01 → 274.24ms   | 0.27 → 0.27s        | 2,408,448 → 2,408,448 B  |
| 长水平空白，同一二进制各 7 轮 | 166.63 → 126.00ms   | 0.16 → 0.12s        | 7,307,264 → 7,307,264 B  |
| 长注释，同一二进制各 7 轮     | 179.00 → 149.85ms   | 0.17 → 0.14s        | 7,323,648 → 7,323,648 B  |

最初将长输入分别链接为两个可执行文件时，新版本 RSS 高 32KiB，但其 `__TEXT` 反而减少约 2KiB，调用方实际临时缓冲高水位也下降 144 B。为隔离映像与页面驻留影响，进一步把两种实现静态链接到同一驱动，分别预热一次后再选择待测实现；上述最后两行使用此对照，RSS 中位数一致。没有将 RSS 差异隐去或当作堆分配收益。

报告与原始日志位于本目录下被忽略的 `yaml-{plain,comments,multiline}-{before,run-scan}.json`、`yaml-shared-long-{space,comment}-{before,after}.json` 及对应 `.logs/`。临时驱动的 SHA-256、实际命令与二进制摘要均由报告记录。

CLI 使用既有 `manifest_test.ts`，同一用例集、同一执行方式：基线三轮 665.02ms，最终五轮 637.53ms，中位 CPU 及 RSS 见 `configuration-cli-{before,run-scan}.json`。这包含 Node 测试驱动和进程启动成本，不能当成规则自身收益。基线首轮完整 CLI 构建 138.20s，最终编辑后重建 77.15s；缓存状态不同，不据此声称构建提速。

### 正确性与接线核查

- 最终 `zig build -Doptimize=ReleaseSafe` 成功，主生成清单从 54 增至 55 个入口。
- 现有 `manifest_test.ts` 126 项、`index_test.ts` 15 项、`lock_test.ts` 4 项全部通过，覆盖 LF/CRLF、Unicode、行尾与独立注释、块标量保护、无效输入保持及只读边界。
- 新增 ZX 均通过既有 `zxc fmt --check` 与 `zxc lint`；RX 通过 `check-rx --entry`。ZX 最长 56 行。
- 本次 Zig diff 通过现有格式脚本检查及 `git diff --check`；未新增测试。
- 生成的规则调用闭包只借用输入，未发现 `dupe`、`renew`、数组复制或分配记录。适配器零容量分配器与上述实际调用共同验证无临时分配路径。

## Edges：边界与限制

- 此阶段迁移的是字段间规则。YAML 解析及字段收集、字段对遍历和文本编辑应用仍有手写 Zig 过渡依赖；没有宣称 YAML formatter 整体或编译器整体完成自举。
- 未运行全仓测试或完整 seed → stage1 → stage2 → stage3 验收。完整自举仍必须按 `rules/自举完成标准.md` 审计正式入口传递闭包。
- 旧 CLI 在 `fmt packages/lint/src/indentation/line/line.rx --check` 及已有 `spacing/boundary/boundary.rx` 上触发 `indentation/line/root.zig` 的 `IndexOutOfBounds`，新 RX 的格式化检查遇到相同基线问题。记录在 `/tmp/zxc-baseline-line-fmt.log` 和 `/tmp/zxc-baseline-rx-fmt.log`，不将失败说成通过；下一阶段独立检查 RX 边界桥的返回值生命周期。
- 微基准只能支持已测场景。多行字段的微小差异处于噪声量级，只报告未观察到退化；不推算整个编译器端到端收益。

## Answer：交付与自我批判

第一阶段交付正式构建中的 YAML 字段间 RX/ZX 规则、英文规范提交及推送。后续继续迁移字段集合与编辑状态，并检查其余 lint、genz、前端、项目与 CLI 的手写语义闭包。

自我批判：初版仅满足语义与架构，性能证据实际否定了它；按值调用及连续空白扫描是在测量后才收敛出的实现。零容量分配器比“栈上缓冲足够大”的假设更可检验，但不能替代一般所有权证明。保留字段遍历和文本应用的 Zig 实现意味着迁移范围有限，不能以入口数量增加计算整体自举完成率。
