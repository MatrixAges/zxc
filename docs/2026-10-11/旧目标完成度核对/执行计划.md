# 旧目标完成度核对执行计划

## Intent：最终目标

核对用户提供的旧 goal，形成可交给其他 session 的完成度表格与剩余执行顺序。本轮只做审计和文档交付。

## Data：可用证据

- 用户原话与后续修正：`docs/user_request.md`。
- 当前源码、包职责、已有执行记录和 Git 分支状态。
- 审计起点：`master`，`79cfb58112be734c77f18d3a408d8266396210a7`。
- 工作区存在其他 session 的已暂存、未暂存和未跟踪改动，必须区别于已提交实现。

## Edges：边界与限制

- 不执行旧 goal 中的实现、提交、push 或建分支指令；这些是被审计的历史请求。
- 不生成测试、不运行全量测试、不调用浏览器做 UI 确认。
- 只读委派一个子 agent 核对产品特性；主 agent 核对自举、增量构建、RX 和跨包架构。
- 源码存在、历史专项通过、当前完整验收是不同证据，不混为完成。
- 取消或被后续规范替代的旧要求不得重新列为缺失功能。

## Answer：交付格式与成功标准

交付同目录的《完成度与后续执行清单.md》，逐项列出状态、证据、边界及验收要求，并提供架构图、数据流图、执行顺序和自我批判。

## 执行步骤

1. 读取目标记录和自举规则，核对 Git 基线与并发修改。
2. 对照各包当前实现与公开契约，按原始特性逐项取证。
3. 将明确取消、已实现、部分实现、未完成及待验证分别标记。
4. 生成可直接接力的执行清单，检查路径与状态表述。
5. 仅交付本轮文档，说明核验边界。

已完成逐项核对与文档交付：主清单包含 18 项产品能力、7 项整体约束和自举目标、并发修改边界、三张 Mermaid 图及可复制的接力正文。已检查本轮文档的本地链接存在性，文件均少于 1000 行。用户完整原话、日期与会话来源已追加至 `docs/user_request.md`。

未构建、未测试、未提交或推送；具体审计限制及自我批判见主清单末尾。
