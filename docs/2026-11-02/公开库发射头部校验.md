# 公开库发射头部校验

## Intent：最终目标

修复公开库发射在优化构建中跳过公开头部校验的问题，复用 RX/ZX 中的现有规则。
不以恢复全量 IR 扫描的方式弥补一个常量时间门禁，也不把修复扩大为新的校验体系。

## Data：可用证据

现有 library/bundle_test.zig 的缺少公开导出表检查在 ReleaseSmall 失败。
backends/zig/library.create 仅在 checks_internal_ir 为真时调用完整校验；
该标记仅在 Debug 开启。编译库链接、装载和编解码边界已有全图校验。
既有 compiled/validation/header.zx 同时检查发布条件和列长度一致性。

## Edges：边界与限制

- 发布规则仍以 ZX 为正式来源；seed 只用于初始引导。
- 发射边界检查 type_only、无入口导出、无入口常量导出、无入口 Store、非空公开表。
- 宿主仅把五个标量投影到栈上，零字节分配器约束调用，不复制或遍历图。
- 原有全量校验继续检查公开行、类型、初始化函数及全图；不宣称任意篡改后仍可信。
- 不新增测试，用已有库链接、库发射与分配失败检查验收。

## 自我核对与剩余边界

本次没有恢复 Release 的全图重复校验；正式发布条件只由 publication.zx 定义，
Graph 头部复用它并继续校验全部列长度。seed 的相同判断仅用于初始引导。
原生桥仍负责从现有 Program 读取五个标量，是过渡表示适配，不能据此声称
Program 状态及所有库校验职责已自举。完整 RX 校验和统一结构化 AST 发射仍保留。

ReleaseSmall 的既有失败已修复并通过原测试。ReleaseSafe 的代表性工具链崩溃
已取得阶段前复现证据，但该优化模式的完整库检查仍未完成；保持此限制可见，
不重复构建碰运气，也不修改预期或扩大本次改动去绕过编译器崩溃。
