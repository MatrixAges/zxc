## 完整观察

Array.concat 依次涉及对象装箱、结果 Species 构造、Spreadable 读取、LengthOfArrayLike 转换、索引存在判断、getter、属性创建、长度与对象身份。ZX 的同类型 list 接口没有这些 JS 动态对象入口。69 项逐文件分析依据原文断言，未按文件名猜测行为。例如 number-wrapper 原文最后实际检查 primitive true，不能按名字改为 number；compareArray 对 sparse 输入的比较一般只是读取 undefined，不擅自加上原文不存在的 hasOwnProperty 检查；A3_T1/T2/T3 才明确观察 own property。

已有普通 concat_three 的五项值对应 A1_T1 的一部分，但缺少 getClass 反射，已有 excluded 不重复或改算适配。已有普通 concat 的 0/1 对应 A1_T3 的值及长度，却没有 arr !== x 和 class 反射。一个空列表也不能证明 Symbol.isConcatSpreadable 的 Get、ToBoolean 或 IsArray fallback 已经执行。

## 参考执行与宿主失败

完整原文 VM 参考实际退出 1：69 份共 137 次执行，135 次通过、2 次失败；失败仅 arg-length-near-integer-limit.js 的普通/strict 两种模式。该原文要求 length=Number.MAX_SAFE_INTEGER 时访问第 0 项 getter 并传播 Test262Error；当前 Node v25.8.1 没有抛异常，原文 assert.throws 因此失败。没有修改原文让它通过，也没有将此问题报告给 zxc 实现聊天。

两份 Realm 原文在普通与严格模式均通过，每次原文实际创建一个额外 Realm。运行器先独立核对两个 Context 的 Array/Object 不相同，并在真实 Context 中核对数组原型，再加载原始 sta.js、assert.js 与 metadata 指定 includes。Realm 构造器、原型和 Species getter 由真实 JS 引擎处理。

独立 Node 进程通过标准输入执行相同原文与完整上游 harness，普通/strict 子进程同样实际退出 1，并保留相同 assert.throws 失败；这排除了单个 VM Context 配置导致该参考现象的简单解释。只记录当前宿主的结果，不推断其他 JS 引擎或版本的行为。
