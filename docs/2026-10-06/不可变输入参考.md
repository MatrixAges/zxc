# 不可变输入

## Intent：统一函数契约

ZX 普通函数只接受 `in: Input`。输入保持不可变；不需要所有权标记，也不需要调用方在调用后放弃原值。旧 `owned Input` 语法已移除，使用它会得到语法错误。

## Data：源码行为

```typescript
export type Input = u64[]

export type Output = { original: u64[], reversed: u64[] }

export default function (in: Input): Output {
    const reversed = in.reverse()[0]

    return { original: in, reversed: reversed }
}
```

反转产生新列表，original 保持原顺序。push、concat、pop、splice、sort 和 reverse 保持已有返回形状，但不再要求独占接收者或使旧列表失效。可以将同一不可变值传给多个函数或并行分支。

## Edges：存储、资源与兼容性

新结果可以共享未改变的不可变元素，无需深复制整个对象。编译器证明旧版本不再被观察时，可以复用内部私有缓冲；未获证明时使用必要的新存储。此优化不改变公开函数契约，也不依赖引用计数或专用运行库。

Task 是一次性资源，await 与 cancel 的单次消费规则仍保留。Store 的显式授权、来源与生命周期仍受检查；输入不可变不等于允许悬空引用。

Zig、CLI、Wasm 与 NAPI 的普通函数入口同样不消费输入。Zig 入口不再发布 consumes_input。曾以旧消费契约发布的编译库必须重新构建，IR 22 会拒绝旧库和旧缓存，而不是将旧二进制重新解释为不可变实现。

## Answer：成功标准

调用前后输入值一致，旧值与新结果可同时使用，普通函数签名不出现 owned。详细实施、验证范围和自我复核见 [不可变输入修正](不可变输入修正/实施计划.md)。
