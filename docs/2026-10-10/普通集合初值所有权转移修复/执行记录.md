# 普通集合初值所有权转移修复执行记录

## Intent：最终目标

恢复普通集合结果作为循环初值时可证明安全的缓冲转移，同时保留共享、借用和重复区域来源的复制保护。

## Data：可用证据

修复前普通入口的动态 dupe 已复现，参见实施计划与修复前普通入口.txt。既有 Debug 专项现已通过：79/79 构建步骤成功，128/128 用例通过。safe 专项也已通过：79/79 构建步骤成功，128/128 用例通过。

### 实现与安全边界

生产变更只涉及 genz 的 iteration_buffer/ownership/root.zig：

- field 与 tuple_field 将字段索引前置到待追踪路径。
- iteration 复用既有 analyzeWithCalls，证明指定路径维持当前版本、更新未逃逸；空调用摘要使涉及候选缓冲的未知调用保守失败。
- 通过版本证明后沿 iteration.initial 继续追踪，仍要求 Graph 的独占、单引用和同执行区域成立。
- 直接 list 叶仅接受空列表，不把非空静态字面量当作可写存储。

既有 shape 检查改用 Zig AST 限定顶层 execute 的函数范围，并仅排除可证明零长度的数组 dupe；动态复制计数及必须出现转移的断言仍保留。没有增加用例，没有改变既有八种模式的预期。

在 packages/test 执行 `zig build test-loop-initial-ownership -Doptimize=debug --summary all`，最终退出 0，完整结果见 Debug构建验证.txt。

八种模式分别为 map/filter/local/nested/tuple，以及 shared/borrowed/repeated。每种模式覆盖 source/library 两种入口，各有八项既有行为、边界、分配及 OOM 检查，共 128 项。

从通过 Debug 的现有 compile-loop-initial-ownership 工具保存两种入口的源码及 ABI，共 32 个压缩产物；全部 32 个文件与通过构建的缓存输出逐一哈希一致。工具路径、哈希、缓存映射见生成产物.json，普通 execute 的复制与转移行见普通入口对照.txt。

五种独占模式的普通入口均只有空列表初始化的零元素 dupe，实际动态列表使用 constCast 转移。shared、borrowed、repeated 仍有动态 dupe，保持复制保护。

safe 配置的自举生成阶段已完成；其 92 个生成文件与 Debug 生成文件逐一 SHA-256 比对全部相同，覆盖提交 hook 格式化后的生成器源码。比对目录与文件清单已写入验证输入.json。命令为同一目标的 `-Doptimize=safe --summary all`，最终退出 0，完整结果见 Safe构建验证.txt。专项工具 LLVM 编译耗时 14 分钟；此性能问题单独处理，不以用例通过认定解决。

### 构建中发现并修正的问题

首次 Debug 构建在生成器中积累约 23 GB 物理内存。用户反馈“构建卡住了”后，产物时间与两次调用栈证明阶段仍有推进，但进程 arena 作为 genz 临时 arena 的父分配器使模块间内存无法及时回收。保存 89 个已生成文件哈希后，主动终止旧生成器；退出 1 是诊断后的主动中止，不是用例失败。原日志保留为 Debug内存诊断中止.log。

修复 build/generate_parser.zig 的资源生命周期后重跑，正式生成成功。生成器修复独立提交 ea5c91dac，合并远端测试记录后以 6943ecf5d 推送 master；详见相邻的自举生成器内存释放修复目录。提交 hook 只调整该文件空行，没有语义变化。

随后 shape 检查首次编译暴露 Zig 0.17 已将 dupeZ 改为 dupeSentinel；修正后利用生成缓存续跑通过 Debug。格式器也将 enumFromInt 更新为等价的 fromBackingInt。失败日志保留为 Debug检查工具API修正.log，验证输入记录修正前后哈希。

## 自我批判

“新分配”“独占”与“可写”是不同证据，不能用其中一项替代其他两项。本次组合来源资格、图上的独占与循环版本证明，并用实际生成代码和既有反例验证。shape 检查仅排除无元素复制的空列表初始化；不能用它掩盖动态列表复制，也不能仅凭有 constCast 宣称整个入口安全。

只读源码复核未发现新增路径的确定别名、重复区域或静态存储写入漏洞：候选相关调用会被空摘要拒绝；零长度列表的更新仍先执行越界检查；Storage.transfer 在首次实际写入时才接管缓冲。Graph、循环版本分析和来源追踪分别证明不同约束，不需重复增加 allocation Trace。复核前提是合法、已验证 IR，未重新证明既有 allocated_functions 和旧 transform 终点的全部生成路径，不构成一般形式化证明。
