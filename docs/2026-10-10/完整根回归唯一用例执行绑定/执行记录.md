# 84,786 个不同 case ID 的实际执行证据

## Intent：最终目标

按 IDEA 框架直接核验超过 30,000 个不同仓库测试 ID 已真实执行，区分目录规模、构建汇总与逐项运行证据。本部分核验既有测试，不新增重复用例或修改生产实现。

## Data：可用证据

证据来自固定 `bbd92b5c536139a6a36ce3ad4e0062768bf1337f` 的完整根 Debug。原始起点、完整日志与退出 1 终态已发布于 `9bb05da81`，详见 [根回归终态](../Indexed入口根回归Debug终态/执行记录.md)。完整根仍有 40 个直接失败步骤、10 项失败 Zig 测试；本批只核验其中成功执行的 runtime 子集。

固定 runtime 清单有 578 个不同 suite 名。根据同版 `build/runtime.zig`，本批选择由普通 runtime 循环直接注册的 526 项；另外 52 项由 application JSON、immutable list、RX floating、collection trace 等专用构建模块接线，不纳入这份绑定。52 项未被这份绑定覆盖，不等于它们执行失败。

### 逐项绑定

每个选定 suite 都满足以下实际证据链，没有缺失或重复节点：

1. JSONL、ZX 入口、附加源码、emitter 与 support 等固定输入的 SHA 与原始起点一致。
2. 本轮 CLI 生成命令的输出是该编译节点的 program 模块，emitter 输出是其 `-Mroot` 指向的本轮 cases.zig。
3. 生成测试根中的全部 test ID 与对应 JSONL 按顺序逐项相同，非空且无重复。
4. 整份日志中该 suite 的编译命令、实际二进制运行命令、最终运行节点各恰好一个，顺序正确。
5. 最终节点通过数量等于 JSONL 与生成测试数量，含真实耗时及 MaxRSS，不含 cached 或 reused 标记。
6. 编译和运行使用本轮 local-debug 缓存；归档的模块路径与编译命令中的全部 `-M` 参数一致。

526 个测试根路径及 SHA 均不同，526 个实际二进制路径及 SHA 也均不同。二进制合计 1,192,565,379 字节，保留在外部运行目录，只提交其 SHA。编译依赖可能复用缓存；这里证明的是测试节点各有一次真实运行，不能扩展为所有编译依赖都重新冷编译。

这 526 项共有 **84,786 个 case ID，全局去重后仍为 84,786**。这个结果来自逐项绑定，不取自原构建的 113,865 次测试汇总，也不取自重复可见日志的 47,387 次 OK。

### 输入、预期和断言的全文复算

仅比对 test 名称仍不能证明生成断言保留了 JSONL 的输入和预期。为此，使用固定 Node 及原 emitter，向独立外部目录重新发射这 526 份测试源，逐字节与本轮实际编译的 cases.zig 比较。

复算于 UTC `2026-10-10T01:12:58.648669+00:00` 开始，至 `01:13:36.956479+00:00` 完成，526 次 emitter 调用实际退出 0，全部源字节一致。完整命令、时间、退出码、标准输出摘要和生成 SHA 记录在《生成断言复算终态.json》。这是测试发射复核，不是新增 526 次程序测试执行。

源码阅读确认既有 control、collections 和 floating support 实际调用 `program.execute`，检查结果或准确错误；collections 还检查调用者输入未变。全文复算保留这些调用及输入、预期，不以空测试或预设成功替代执行。它不证明全部 oracle 都是独立且完备的，原文语义审查仍须逐项推进。

### 无损归档与恢复

共 1,545 条内容归档：526 份生成测试根、526 份固定 JSONL、474 份去重后的生成程序/ABI 模块、7 份固定接线源码、12 份固定执行源码。原始字节合计 59,676,614，gzip 合计 2,767,060；逐项核对压缩与解压 SHA、字节数和归档清单完整性。

链路索引还绑定 1,137 个固定源文件 SHA，覆盖本子集的 JSONL、ZX、附加源和相关接线。这是本子集证据，不是整个编译依赖闭包；完整闭包仍由原起点的源码、工具、Node 依赖及 SDK 身份提供。

恢复会话时，普通 Git fsmonitor 状态缓存没有报告磁盘中缺失的归档。关闭该缓存检查发现 1,977 个已跟踪文件缺失。本部分只从 Git 恢复其直接依赖的 7 个已提交文件；1,545 条未提交归档从仍保留的原始运行文件按旧清单重建，压缩 SHA 与此前记录逐项一致。没有恢复或暂存其他缺失文件，也没有把恢复操作记成重新执行测试。恢复清单另存《中断恢复记录.json》；此后加强版链路核验再次实际通过。

## Edges：边界与限制

- 84,786 是不同仓库 case ID，不是不同 Test262 原文数量，也不代表 84,786 种独立语义。
- 本证据覆盖固定旧版 Debug 的这 526 项；不代表当前 HEAD，也不代表 ReleaseSafe 或源码/统一库双路线均已通过。
- 完整根仍退出 1。Test262 目录中仍有大量原文未审查、部分语言特性尚未完整覆盖，生产级目标仍未完成。
- 52 个委托专项和其余根运行节点没有纳入本批 ID 去重，不用它们推高此处数量。
- 恢复过程中发现的工作区其他缺失归档保持原状，不能将其遗漏混入本批提交或宣称全仓库证据仍完整。

## Answer：交付格式与成功标准

交付全部链路索引、1,545 条无损内容归档、固定源码身份、完整断言复算终态、采集及独立核验脚本。核验已证明 526 个真实成功节点与 84,786 个不同仓库 case ID 对应，零链路异常。本部分以英文 Conventional Commits 单独提交推送；完整原文适配、特性覆盖和共同回归继续进行。

## 架构与数据流

同目录《执行计划.md》保存架构图和数据流图。固定 JSONL 经原 emitter 进入本轮测试根，连同实际生成程序编译为测试二进制，实际运行后由最终成功节点确认；链路索引将每条路径、命令、行号、数量及 SHA 连接，全文复算独立确认生成断言。

## 自我批判

目录数量和聚合测试数量容易产生过度完成的印象。此次逐项绑定使执行数量可复核，但没有自动解决测试语义、oracle 完备性或整体失败。第一轮采集器未把相对模块路径归一到固定工作树，采集因此中止；修正采集器后重建，未改实际测试输入或终态。恢复时又发现二进制归档缺失及 fsmonitor 缓存陈旧，说明发布保护不能只依赖常规 git status，本批改用磁盘存在性与精确字节核验，其他变化仍按范围隔离。
