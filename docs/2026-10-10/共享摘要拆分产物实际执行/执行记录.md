# 共享摘要拆分产物实际执行记录

## Intent：最终目标

采用 IDEA 框架，为共享函数摘要生成的拆分产物补齐实际编译和运行证据。单次与共享两条生成路线都必须静态连接入口、函数文件与统一 ABI，并通过独立的数学和借用身份预期。

标量五项检查：零及普通输入，恰好到达 u64 上界，后续调用不影响先前结果，禁止首次分配，直接调用最后一个函数与普通入口一致。预期是独立的 `input + count`，没有从调用后的数据构造答案。嵌套四项检查：空列表，1/17/257 长度的内容与输入保持，早先结果在后来输入执行后仍有效，以及禁止首次分配。内容参考在真实调用前保存；返回根对象、嵌套对象与列表指针都必须保持借用身份。

### 生成与静态连接

生成工具对同一个 Program 分别调用 modules.prepared 和 modules.analyzed。共享路线只创建一个拥有摘要，在独立输出 arena 保存文本，退出摘要作用域并 deinit 后才写入文件；后续独立 Zig 编译不依赖生成器进程的内存。

每种配置生成 types.zig、entry.zig 及 count 份函数文件。每函数静态绑定统一 ABI 和在前函数模块，入口静态绑定函数模块；运行测试通过 program.execute 和标量 last.call 调用。真实普通入口的生成源码使用 function_N.call，嵌套文件也声明 executeValue/executeBuffered，但本批没有执行这些额外入口，不将它们算入运行覆盖。

两模式共有 16 次配置生成、120 份应用 Zig 文件。相同配置的单次/共享路线逐文件 SHA 相同。核验从实际 Zig 编译 argv 还原模块图，绑定测试源、count 选项、入口、ABI 和每个函数文件，检查无环静态依赖。生成源码的导入仅限 std、zxc_abi 与 function_N，没有专用运行库、解释器或动态加载层。

## Edges：边界与限制

- 本批为 genz 拆分生成入口的真实运行检查，不证明完整前端、compiler batch 缓存调用链、整库发布或完整 root 已通过。
- 仅运行普通 execute 及标量最后函数 call；executeValue、executeBuffered 等其余生成入口仍需单独测试。
- 标量检查合法输入及恰到上界，不检查独立进程中的溢出陷阱；嵌套案例为借用身份，不包含新增、删除或更新列表。
- 数学、输入快照和身份预期独立于两条生成路线，但夹具仍有限，不能据此穷尽全部类型、目标或优化模式。
- 本批不作冷/热吞吐、驻留内存或整体生产编译性能结论。整体 Test262 参考对齐与 zxc 全部自身特性目标仍在进行。

## 自我批判

相同生成文本不等于正确运行，因此本批真正编译连接产物，并增加独立数学、借用身份与输入保持检查。仅看成功分配字节仍可能允许失败后兜底，最终补上诱发失败标记的断言再执行门禁。核验器自身也出现过变量命名错误，必须与生产及测试结果区分，保存原记录后修复，不能隐去失败或重写原始终态。新增运行范围仍局限普通入口；其他生成接口与完整编译器调用链的缺口必须继续保留。
