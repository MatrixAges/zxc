# 普通循环 SIMD 回归执行详情

## Intent：最终目标

确认普通集合循环是否保留已承诺的纯浮点 Map 显式 SIMD，提交可复核的实现缺陷证据。

## Data：可用证据

固定源码为 `bbd92b5c536139a6a36ce3ad4e0062768bf1337f`。复制实际根 Debug 生成的 CLI，并以 SHA-256 核对复制前后身份。用该版本既有 `f32.zx`，分别构建 `wasm32-freestanding`、Debug、`baseline` 与 `baseline+simd128`；两次真实编译退出码均为 0。

既有 WASM host、输入长度与数值检查均直接从固定工作树导入。baseline 与 simd128 各通过 42 项行为检查，共 84 次；没有新增或改写测试用例。独立运行现有严格汇编检查：baseline 退出 0，simd128 退出 1，失败点为缺少归属于 `program.zig` 的 `f32x4.mul`。

实际汇编的 target_features 包含 `simd128`，因此不是参数未生效。两个生成的 `program.zig` 都没有 `@Vector`。SIMD 汇编全文件没有 `f32x4` 指令；归属于生成程序的浮点四则指令中有 4 条 `f32.mul`，另有 4 条 `f32.add` 与 3 条 `f32.sub`。这排除了单纯调试位置归属检查遗漏向量指令的解释。

生产源码显示 `.iteration` 与 `.transform` 分别进入不同后端，现有显式 SIMD 入口只由 transform 调用，并接受 `ir.Transform`。普通集合降级已经产生 scope 与 iteration，因此符合纯算术契约的 Map 绕过了旧入口。相关后端与既有 SIMD 测试在 `bbd92b5c5` 到 `fe7bfd6b7` 之间静态未变；真实 CLI 执行仅属于前者。

## Edges：边界与限制

本次确认的是承诺的优化能力回归，84 项数值结果检查通过，不报告为数值语义错误。不把 f32 诊断扩展为 f64、Node、fallback 或 ReleaseSafe 的完整专项通过。原根门禁在 f32 SIMD 指令检查处失败，后续分支未执行。

不修改生产实现，不删除或放宽指令断言，不恢复已淘汰的 transform 模型。修复应让当前普通循环模型在保持求值顺序、浮点规则、标量尾部、zero runtime 与 zero copy 的前提下履行显式向量化契约。
