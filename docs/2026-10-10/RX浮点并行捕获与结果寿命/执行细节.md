# RX 浮点并行捕获与结果寿命执行细节

本文采用 IDEA 框架，与执行计划、正式输入、运行状态和证据清单共同交付。

## Intent：最终目标

验证浮点数据经过真实 Parallel Task 的捕获、复制与结果汇合，并确认旧聚合结果在父 arena 内跨调用保持。补齐分配失败清理与真实工作线程证据，继续推进 zxc 特性和 Test262 的完整目标。

## Data：可用证据

### 输入与编排

冻结编译器基础为 `84be0c937bf1e0336e5080d1cc96aab14eb60844`，隔离工作树为 `~/.codex/worktrees/rx-parallel-floating-conformance/zxc`。最终运行目录为 `~/.codex/conformance/rx-parallel-floating-84be0c937/r2`。

RX 先通过 marker 原子函数取得明确的 f32/f64 标量契约。direct 把左输入直接交给 Task；captured 先调用 copy_values 创建 owned 列表，再供左 Task 读取。两个兄弟 Task 调用 copy_local 复制各自列表，分别通过 Task.out 和 Return 返回 `{items, marker}`，父 RX 显式返回 left、right 和 captured。ZX 只有 marker 恒等传递和 concat-copy，没有阶段总控或原生观察器。

### 宿主检查

测试为左右输入分别建立含哨兵的整数位模式存储，转换为实际浮点切片后保存整个快照、marker、长度和实际传入指针。它不假设规范空切片指针等于非空数组起点。

每次正常检查先执行一次，再交换左右输入并翻转 marker 的符号位，在同一 arena 再执行；随后复核首次的 left、right、captured 列表和 marker。后次调用失败时同样复核首次输出，验证错误路径不会破坏已返回的数据。

左右复制结果不得别名任一输入或彼此。direct 的 captured 保持原输入借用；captured fixture 的 captured 必须独立于两个输入和 Task 复制结果。空列表不强求独立指针。

线程专项使用 fresh arena，并把 Tracking 放在其底层 allocator。direct 要求恰好观察到两个非父线程，captured 仅要求至少一个并保存实际值。读取发生在 execute 已 join 后；观察器仅存在于宿主测试端。

分配失败复用成熟 checkAllAllocationFailures，实际遍历受控底层 allocator 失败点，正常返回原始错误。它不注入线程创建失败或独立标准库内存，不把预期 OOM 当作实现缺陷。

### 首次诊断与修正

第一次 r1 两模式都在 fixture 分析阶段终止，尚无任何主矩阵测试程序完成。copy ZX 的空列表声明与解构赋值缺少语义空行，触发现有 spacing 规则。

单独纠正排版的预检进一步显示 marker 只由 RX 转发，无法从现有约束推导其输入类型。最终生成器增加带 f32/f64 契约的 marker 原子函数，并用 `$ctx.marker` 明确捕获标量结果；排版也从生成源头修正，没有只编辑生成产物。

f32 direct 与 f64 captured 各五条 Debug 控制用例已实际通过，包含空列表、NaN、负零、线程和分配失败检查。这十次控制执行仅用于诊断，不并入最终矩阵数量。另一个关于参数切片类型不兼容的猜测，经独立原生编译预检证伪，未作多余代码修改。

原始 25 个正式输入、命令、两模式失败状态、诊断、控制源码和日志已保存于前置诊断目录及失败诊断清单.json，共 99 条记录。所有初次进程到终态后才更新输入，最终 r2 重新准备并生成编译器模块。

## Edges：边界与限制

- Native 宿主 allocator 观察器不进入 ZX 或 Parallel 业务分支；没有增加生产运行库、动态调度层或原生外部调用。
- 线程观测不证明时间重叠；owned capture 的 arena 预留可能隐藏另一线程的底层申请，不能把 observed workers 当成线程总数。
- 不覆盖 signaling NaN 或全部 NaN payload 保持。
- 本批重跑既有用例只作为测试驱动回归，不计作新增语义或上游适配。
- 本批没有执行 Test262 原始文件，不声称完成所有特性或全仓库回归。
- 发布时主分支已由实现会话推进至 `2fd314197d5b5e06ba7bc10165f45479adcb30a1`，另有 `b635e6cbc` 的统一源码图迁移；580 个生产文件相对本批冻结基础改变（compiler 503、core 71、genz 6），没有 test 包改动。发布基线逐一保存并保护其 SHA。本轮执行结果只证明 `84be0c937` 冻结编译器下的行为，尚未证明这些后续实现通过本矩阵。

## 自我批判

首次分析失败说明仅有 AST、排版工具和只读复核还不足以证明 fixture 符合真实 ZX/RX 分析契约。应保留失败证据并从生成源头修正，不能把构建拒绝伪装成执行通过。

线程 ID 和 allocator 观测的证明强度也必须受限。使用 fresh arena 排除历史容量干扰，并把 direct 的两线程观察与 captured 的至少一线程观察分开解释。旧输出检查包含真实列表与捕获数据，避免把标量按值保存误当成聚合寿命证明。

用例数量来自有意义的数据边界组合，不能等同于同等数量的语言机制。新增、既有回归、预检控制和上游适配分别计数。最终运行与独立核验均已成功，未发现实现缺陷；这一结果仅适用于本批明确的输入、路径和检查边界。
