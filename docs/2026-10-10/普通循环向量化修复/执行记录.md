# 普通循环向量化修复执行记录

## Intent：最终目标

恢复普通迭代 IR 中同类型 f32/f64 逐元素纯算术映射的 SIMD 生成，并保持浮点语义、标量尾部及不支持循环的回退路径。

## Data：实现与证据

回归原因是集合已降级为普通 iteration，而 SIMD 入口仍只识别旧 Transform。新 iteration 识别器从长度条件推导源与索引字段，从最终列表投影推导结果字段，不依赖变量名、字段名或 fixture。

识别器证明 u64 零起点、严格长度边界、步长一、初始空结果、每轮单次追加，以及源和其他状态字段原样传递。每个被省略的绑定均通过纯度检查；对象 evaluation 必须与实际字段对应且不重复，避免遗漏隐藏求值。源码与尾部共用列式绑定视图和表达式解析，不复制 IR，也不留下已经省略的 callback 参数引用。

向量生成器继续使用目标编译期 suggestVectorLength、完整向量块及标量尾部，不启用 fast-math、不重排浮点运算树。常量回调使用匿名尾部元素捕获。

普通浮点列表在值入口和常规入口均为 slice，不能因 layout 标记排除合法候选。窄 SIMD 路径保留 iteration/result 缓存检查，并先于 general consumer 的限制尝试；allocator.alloc 经 self.call 继承原 capture 的 failure/label，事务仍由外层 statements 在结果求值后 commit。其他循环继续使用原消费器及其限制。

验证结果：

- 独立 CLI 构建退出 0，35/35 步成功。
- 现有完整 SIMD 专项 Debug：378/378 通过。
- 同一专项 safe：378/378 通过。
- 两种配置均覆盖 f32/f64 的 Node 特殊浮点值、42 种长度与尾部、WASM baseline 和 simd128，以及整数和嵌套集合回退。
- assembly.ts 未修改：simd128 的 program.zig 来源指令包含 f32x4.mul 与 f64x2.mul；baseline 不含对应向量四则。
- 五个 SIMD 源文件的哈希在构建及两次验证期间保持一致；验证后仓库格式化器仅调整语义块空行，提交版本哈希另行记录。

## Edges：边界与自我批判

只接受已证明的纯算术列表结果，不把任意 iteration 当作可向量化映射。函数调用、条件选择、整数计算、跨元素依赖等继续回退。捕获与事务的顺序已按实际源码核对，本轮未新增针对这些上下文的独立用例。验证没有测量应用整体提速，也不能据此推断所有所有权路径或整个 genz 已完成自举。

genz 当前仍是待迁移的 Zig 编译期实现；本次修复不引入运行库、动态分派或输入数据复制。未恢复旧集合 IR，未新增用例，未执行全量测试。

## Answer：交付

交付普通循环结构证明、纯算术别名解析及共享向量生成路径，保留既有失败回退。作为独立修复提交，不混入编译库迁移或后续缓存恢复计划。
