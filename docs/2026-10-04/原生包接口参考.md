# 原生包接口参考

## Intent：最终目标

让 ZX 包使用自己声明的 Zig/C 接口，并支持安装、同名多版本消费以及 library 发布后的 Zig/ZX 消费。

## Data：输入与使用方式

在包的 pkg.yaml 中声明接口与实现；路径相对于该包目录，而非消费者目录：

```yaml
name: native_math
version: 1.0.0
entry: main.zx
native_interfaces:
    - specifier: zig:math
      path: math.d.zx
      module: math
native_modules:
    - name: math
      path: math.zig
```

ZX 使用 `import math from "zig:math"`。消费者在自己的 dependencies 中声明 native_math，并使用 `import math from "native_math"`。依赖包内部的 zig:math 不会成为消费者可直接访问的接口。

```sh
zxc pkg install --index /path/to/index.json
zxc build main.zx --out application
zxc build main.zx --mode lib --out library
```

library 目录提供 pkg.yaml、ZX 源码、Zig 入口及 build.zig。Zig 项目可将该目录声明为依赖，并使用 dependency.module("library")。生成的 build.zig 会连接原生实现对应的 ABI 视图；无需修改原始 Zig 实现。

### native_modules 的补充字段

| 字段          | 含义                                                                    |
| ------------- | ----------------------------------------------------------------------- |
| dependencies  | 本包原生实现的依赖名称；支持 alias=target 保留 Zig 源码中的本地导入别名 |
| include_paths | 可选的本模块头文件搜索路径；省略时继承包级值，空列表表示不继承          |
| bundle_files  | 随库交付的相对文件或目录；Zig 模块相对入口目录，纯 header 模块相对包根  |
| abi_aliases   | 可选的 ABI 名称映射数组；省略时使用本包声明的原始名称                   |

ABI 映射示例：

```yaml
native_modules:
    - name: transport
      path: native.zig
      abi_aliases:
          - name: zig:transport
            specifier: zig:private_transport
```

这里 native.zig 仍可读取 `@import("zxc_abi").native.@"zig:transport"`，映射目标必须是同一包声明的 zig:private_transport。library 构建器会自动保存相应映射；再次安装时，目标绑定到新包实例中的声明身份。不要将缓存目录或旧机器上的包身份填入映射。

### 可搬迁 C 资源

```yaml
include_paths: [include]
native_modules:
    - name: bridge
      header: late.h
      bundle_files: [include]
```

纯 C 模块可使用 bundle_files 携带头文件及其配套资源。目录声明递归包含所有普通文件；文件符号链接须解析到模块根内部，目录符号链接不支持。保留路径层级与 include_paths 搜索顺序。搜索目录一旦包含打包资源，其全部文件都必须被清单覆盖，否则导出报告 IncompleteNativeIncludeBundle，避免部分搬迁改变同名头文件的选择。

未覆盖的搜索根仍保留为外部要求，记录在 library.json 的 external_build_requirements 中。绝对 header 配合资源搬迁会被拒绝；使用相对头文件名和 include_paths 表达位置。资源不能包含输出目录，也不能越过逻辑或物理模块根。

watch 会观察声明目录的新增、删除及文件内容。重建时只清理旧 library.json 拥有且摘要仍匹配的退休资源；用户改动的退休资源报告 LibraryResourceModified，未登记的文件保留。普通构建和 watch 都保护本轮输入文件。发布不是整个目录的原子事务，复制中途发生文件系统错误时应修复后重新构建。

## Edges：边界与限制

声明组身份与原生实现名不同。同一声明组可有多个实现；不同包实例的同名声明不会合并。生成的 ABI 视图引用共享类型定义，不能自行重新声明外观相同的 Zig struct/enum 来替代接口类型。

ABI 别名不能指向两个不同声明。系统库、外部头文件路径和 C 链接符号仍受目标平台约束；隔离 Zig 模块名不代表任意不兼容 C 库都能共存。库构建会保留这些外部构建要求，不宣称自动打包所有系统依赖。

NativeModule.identity 保存声明组身份；未指定时回退 specifier。旧版本原始 IR 和语义缓存需要重新生成。普通 ZX 源码的导入写法保持不变。

## Answer：成功标准与证据

真实安装回归覆盖同名模块的标量及不同对象布局、冷/热构建和发布库重新安装。迁移场景删除了原项目、原发布目录、原索引及旧共享包缓存后仍可运行。既有构建模式回归保留了直接 Zig 消费、搬迁后库消费、聚合引用语义及原生错误传播检查。

实施细节与未覆盖边界记录在 [原生包作用域实施计划](原生包作用域实施计划.md)。这些运行证据来自当前 macOS 工作环境，不替代其他目标平台的运行验证。
