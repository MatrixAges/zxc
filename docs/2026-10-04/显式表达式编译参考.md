# 显式表达式编译参考

## Intent：用途

从单个 ZX 表达式或 RX 属性生成有类型表达式和可执行函数，供应用编译器通过显式输入组合。

## Data：API 与输入

| 接口                                                                | 结果                          | 用途                                          |
| ------------------------------------------------------------------- | ----------------------------- | --------------------------------------------- |
| compiler.parseExpression(allocator, source, file_name)              | ExpressionParseResult         | 解析一个完整表达式，拒绝剩余 token            |
| compiler.expressions.analyze(allocator, parsed, options)            | expressions.Result            | 类型与绑定分析                                |
| compiler.expressions.compile(allocator, parsed, options)            | AnalysisResult                | 生成包含 Input、Output、主体和所有权摘要的 IR |
| rx_compiler.expression.compile(allocator, path, attribute, options) | rx_compiler.expression.Result | 从 XML 属性编译并映射诊断及表达式范围         |
| dsl.attributeLocation(attribute, offset)                            | ?Location                     | 解码 UTF-8 字节偏移到原始 XML 起点            |
| dsl.attributeEndLocation(attribute, offset)                         | ?Location                     | 解码范围终点到原始 XML 终点                   |

rx 同时导出两个属性位置接口。application 由 Zig 构建依赖的 module("rx_analysis") 获取，其独立入口为 expression。

options.types 是完整有序类型表，可以省略以使用内建标量。提供时必须有完整标量前缀、合法字段与引用；分析结果复制该表。options.bindings 按输入顺序提供 name 和 type_id；options.expected 可指定结果类型。

绑定允许普通名称与标识符路径，例如 value、$input、result.user。路径不能为空、不能包含关键字或非法字符，不能重复或互为祖先。result.user 和 result.total 可以并存；result 与 result.user 不能并存。每个 type_id 必须在共享表内，且不是 void。

## Edges：所有权与限制

所有 Result 均应调用 deinit。解析结果拥有源码和 AST；分析完成后可以释放解析结果，分析结果保留独立类型表、名称和字面量数据。application 返回的诊断含原始字节 span 及一基行/字节列，可在 XML 解析结果释放后使用。

手工 AST 未提供 raw_value 时，属性映射返回 null；application 将诊断退回属性起点。实际 XML 解析保留 raw_value，不使用字符串搜索定位。实体内部的非空范围覆盖整个实体，零宽范围保持相同起终点。

没有绑定时，生成 Program.Input 为 void；有绑定时为按声明顺序排列的元组。外部值被借用，不能作为可消费所有者使用；普通回调的禁止捕获规则仍生效。analyze 的成功不保证所有权合法，可执行用途使用 compile，并通过 compiler.zig.emit/emitBundle 的 IR 校验。

当前 Zig 工具链对动态匿名元组指针的隐式转换有已复现问题。宿主应使用公开 Input 布局构造局部值：

```zig
const input: std.meta.Child(program.Input) = .{ left, right };
const result = try program.execute(&arena, &input);
```

宿主值及其字符串、列表等引用数据必须活到所有借用输出使用结束。多个生成模块互传值时须共用同一类型表与 ABI，不能用字段相同推断两个匿名 Zig 类型可互换。

表达式入口尚未装载外部函数导入，也不会自动建立 Call.out 可见环境、分支合流或完整 RX 调度。普通 ZX 命名和风格检查不因表达式绑定路径而放宽。

## Answer：使用顺序与成功标准

1. 解析单表达式，或从真实 XML 解析结果取得属性。
2. 提供已有类型表、显式绑定与期望类型。
3. 检查返回 union：诊断立即交给调用者；IR 进入统一生成门禁。
4. 按绑定顺序构造运行输入，执行并管理借用数据生命周期。
5. 释放解析、分析与生成结果拥有的资源。

已有验证覆盖绑定冲突、非法类型、成功及拒绝路径分配失败、实际生成代码的绑定顺序、短路与借用指针，以及实体和换行的位置映射。具体结果见[交付计划](显式表达式编译交付计划.md)。
