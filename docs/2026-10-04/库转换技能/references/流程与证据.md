# 流程与证据

脚本以迁移清单为输入，状态写到清单旁的 `.translib/<清单文件名去扩展名>/`。一个迁移项目使用一份清单和一个集中构建负责人。写操作通过原子创建 execution.lock 目录互斥，正常结束释放。异常终止可能留下目录；先核对 owner.json 中的 PID 与实际进程状态，确认原执行已结束，再删除锁目录重试。工具不自动推断锁是否陈旧。

## 迁移清单

JSON 顶层字段固定，未知或缺少字段拒绝。路径相对于清单目录；source_root/target_root 必须已存在。单元 sources/targets 分别相对于对应根，必须留在根内；源文件必须存在，目标文件可以尚未生成。目标不可同时归属两个单元，也不能覆盖源文件。

```json
{
	"format_version": 1,
	"environment": ["PATH", "HOME", "TMPDIR", "SystemRoot", "TEMP", "TMP", "USERPROFILE", "LOCALAPPDATA"],
	"source_root": "../legacy",
	"target_root": "../zx",
	"rulebook": "RULEBOOK.md",
	"inputs": ["../legacy/adapter.ts"],
	"units": [
		{
			"id": "quote",
			"sources": ["quote.ts"],
			"targets": ["main.zx", "pkg.yaml"],
			"depends_on": []
		}
	],
	"artifacts": ["../zx/out/quote"],
	"build": {
		"argv": ["zxc", "build", "main.zx", "--out", "out/quote"],
		"cwd": "../zx",
		"timeout_seconds": 300
	},
	"smoke": {
		"argv": ["./out/quote", "{\"amount\":100,\"discount\":20,\"enabled\":true,\"factor\":1.5}"],
		"cwd": "../zx",
		"timeout_seconds": 30
	},
	"parity": {
		"cases": "既有输入.jsonl",
		"mode": "json",
		"oracle": {
			"argv": ["bun", "{source}/adapter.ts", "{input}"],
			"cwd": "../legacy",
			"timeout_seconds": 30
		},
		"candidate": {
			"argv": ["./out/quote", "{input}"],
			"cwd": "../zx",
			"timeout_seconds": 30
		}
	}
}
```

这是字段示例，需要换成实际库、既有输入和可运行命令，不会生成示例中的 TypeScript 原实现。Windows 应填写实际可执行文件名和路径。

`inputs` 包含单元之外会影响结果的文件，例如适配器、依赖锁、构建脚本和配置。允许文件或目录；目录递归哈希，不应包含输出、缓存、证据目录等变化产物。判定 cases、RULEBOOK、清单与辅助脚本自动跟踪，不必重复列入。命令的可执行文件也按解析后的路径和内容跟踪；构建产物单独跟踪。

`artifacts` 必须完整列出实际被消费的构建产物，可为文件或目录。辅助脚本不是产物，应列入 inputs。运行时会改变的日志、缓存不应放入 artifacts。由间接启动器执行的工具、运行时依赖与外部资源仍需列入 inputs；工具无法自动穷尽任意构建系统的隐式依赖。

命令必须提供 argv 字符串数组、cwd 和正整数 timeout_seconds（1–86400）。不调用 shell；管道、重定向和多条命令应放入受跟踪的适配脚本。`{source}`、`{target}` 展开为根目录；parity 的 `{input}` 展开为该条输入的 JSON 参数。stdin 关闭，需要其他协议时使用适配器。

`environment` 明确列出允许子进程继承的环境变量名称；未列出的变量不传入子进程。按工具需要声明 PATH、用户目录、临时目录、Windows SystemRoot，以及会影响行为的 locale、特性开关或凭据变量。缺少的变量保持未设置，不自动填值。实际传入环境的摘要参与证据，环境值不写入报告；命令查找使用同一套 PATH。调整声明或已声明变量的值，需要重新获取证据。`{input}` 不允许决定可执行文件或工作目录。

## 规则与迁移单元

RULEBOOK 记录实际决定和依据：API 映射、数据表示、所有权、错误、数值/文本语义、模块边界、资源、平台及许可。尚未决定的差异明确保留，不用默认规则掩盖。另列语义差异清单，逐项关联源位置、目标策略、证据和处置状态。

依赖图应来自源语言的真实解析证据。脚本按声明依赖拓扑排序，拒绝未知节点与循环；这不证明声明没有遗漏。代码审查必须核对实际导入与清单，目标编译器继续执行自己的无环限制。

先用 `status` 得到顺序和摘要。`written` 只表示声明的目标文件存在；它不是“翻译正确”的判定。清单必须覆盖约定的迁移范围，不能删除失败单元来使 check 变绿。

## 代表性试迁移

保留完整迁移清单，另建 `试迁移.json`，仅包含代表性单元及其传递依赖闭包。为这份清单配置独立的构建产物和实际消费入口，执行相同的 review/build/smoke/parity/check 命令。脚本要求当前清单所有目标文件存在，因此不能在完整清单中创建空文件绕过尚未迁移的单元。

试迁移通过后把得到的规则修订带回 RULEBOOK，再按完整清单推进。试迁移证据属于它自己的清单，不能充当完整迁移的完成证据；最终以完整清单运行 check。只有一个小单元的库可以直接用完整清单试迁移。

## 独立审查

审查者获得当前单元、它的依赖、规则、源码与目标，独立输出：

```json
{
	"fingerprint": "复制 status 中该单元的当前摘要",
	"findings": ["尚未解决的问题及源码/目标定位"]
}
```

通过审查时 findings 为 `[]`。报告通过 `review 单元ID 审查者ID 审查.json` 记录。不同审查者使用不同 ID；修复后由审查者重新检查并记录当前摘要。脚本要求两个不同 ID 的无问题报告，不推断两份文字是否由独立上下文产生，也不把 ID 当作身份认证。

不要给旧报告替换摘要。证据只在对应内容下成立；只有人工实际审查后才能提交清洁报告。不能因为 reviewer 给出建议就扩大迁移范围，先区分正确性缺陷、已约定差异和任务外建议。

## 集中构建与修复

`build` 在执行锁内执行唯一配置命令，保存原始 stdout/stderr、退出码及超时信息。常见 `文件:行:列: error:` 或 ZX 分类诊断转换到 repair_queue.json，并按单元依赖顺序排列。无法匹配的定位保持全局错误，原始日志始终保留。

任何非零退出、超时、构建产物缺失或受跟踪输入在执行中变化都会失败。命令启动失败也不会沿用上次通过状态。构建日志解析是定位辅助，不应代替退出码和真实编译结果。

修复者消费队列并更新代码；构建负责人重新执行。`smoke` 要求当前 build 通过，且运行前后产物一致。编译成功后产物被替换、删除，或源代码/规则/工具变化，都使已有结果过期。

## 行为对照

cases 为既有输入整理的 JSONL，每行有唯一字符串 id 和 input，可带 expected、exit_code。不要增删困难输入来改变约定覆盖范围；转换格式时保留原始用例与映射证据。

```json
{
	"id": "既有用例ID",
	"input": { "amount": 100, "discount": 20, "enabled": true, "factor": 1.5 },
	"expected": { "amount": 80, "factor": 0.75 }
}
```

默认 exit_code 为 0。显式错误用例可声明 1–255 的预期码，不接受信号终止作为普通错误返回。parity 对每条输入分别启动两个实现，比较退出码、stderr 和 stdout，并保存原始输出。oracle 与 candidate 都必须满足预期退出码，不能用“两边都崩溃”当作正常用例通过。空用例集合失败。

`json` 模式在成功返回时按 JSON 值比较 stdout：对象键顺序不影响结果，列表顺序保留，布尔值不同于数字，任意精度整数和十进制数不转为二进制 float，负零区别保留；重复键、NaN/Infinity 和非 JSON 输出失败。有 expected 时，两边都要匹配它。此模式不接受“近似相等”阈值，浮点容差需要在双方共同认可的判定协议中显式表示。

`bytes` 模式及预期非零返回的错误用例按 stdout 原始字节比较。此时 expected 如存在，必须是对应 UTF-8 字符串。stderr 始终按字节比较；若旧新实现正常包含不同路径或时间戳，应在受跟踪的适配器中按事先约定的协议归一化，不能在工具中静默忽略。

原实现必须可执行，适配器不能代算业务结果。运行前用既有输入确认判定能够拒绝已知错误的候选。该演练验证判定器，不作为新增业务测试集。副作用、平台、性能、内存行为等若不在此协议中，需要独立证据。

## 完成与恢复

`status` 只读输出状态，未完成时仍返回 0，适合查看队列；`check` 在未完成时返回 1。完成需全部声明单元存在且有当前双审查，并具有当前 build、smoke、parity 成功证据。

再次运行失败阶段即可恢复。正常完成或已处理的失败会释放执行锁；异常终止后的锁按开头的恢复步骤处理。运行期间不要并行改写同一迁移单元；执行前后摘要用于检测变化，不是文件系统快照隔离。

最终仍需人工检查声明范围、审查独立性、原始测试继承、未覆盖语义和许可。check 证明的是本地证据链及约定命令的结果，不是形式化等价证明，也不能抵御人为伪造证据文件。
