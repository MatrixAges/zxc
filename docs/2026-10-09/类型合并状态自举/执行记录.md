## 原型证据

草稿已实现显式 Request/State、普通 ZX 引用重映射、Candidate、名义/结构查找、增量列追加。RX 明确前缀检查、映射前缀初始化与集合合并。当前合并原型可以由正式 CLI 无缓存生成。

初版 references 使用 splice 删除整个列表再取剩余部分，无法获得缓冲通道。改为取长度为零的前缀，即 `references.splice(0, 0, [])[1]`，复用既有前缀借用契约后，14 个输出数组全部获得通道：mapping、delta 八列、origins 四列、references。

仍观察到每新增类型行生成两个描述符分配：类型 Table 和来源 Bindings。原因是 state_value 将仅出现在输入或临时聚合里的同类型重复也视作必须保留的共享身份；Tables{base,delta} 因此让 Table 全局装箱。

## 通用值表示调整

重复聚合身份保护收窄到程序及函数的输出类型；比较（含 contracts）、native、list、task、Store 的既有递归保护不变，调用边界的 containsDescendant/sharesAggregate 与 borrow/value/pointer 选择不变。

依据：外部输入带原始 zx_origin；fresh 对象重复返回由输出重复扫描保护；内部比较及外部可观察边界由原有 mark 保护。内部参数包装本身不是身份观察点。只读复核未发现反例，但这仍需现有身份、逃逸和容器专项验证，不能仅以静态分析结论宣布安全。

该调整已写入 genz 正式源码，构建运行中。其余类型合并实现仍在草稿，尚未接替正式 Writer。

## 传递调用复核修正

入口和合并循环无 create 还不够。继续追踪实际 executeBuffered 调用闭包，发现 nominal 的 encode(find(in)) 在纯标量返回函数参数上装箱 Search 一次。lower 的只读临时参数借用条件原来只接受 object 字面量，遗漏 fresh call 和 tuple。移除该表达式形状限制，仍要求纯函数、标量输出、未缓存实参；复用既有 argument.borrow 的 fresh 判定和缓存恢复，非 fresh 调用仍走原路径。未改写用例或业务源码以绕过问题。

首批身份、无效输入、资源及批量四组均通过；压缩专项首次编译因执行器未声明已有 type_merge_fixture 模块失败，属于验证命令缺依赖，已补齐。生成器通用规则再改后会重建并复跑相关专项。

最新正式生成文件的 executeBuffered 传递闭包共 26 个函数，create 调用为 0，14 个列通道保留；证据在缓冲调用闭包.json。该检查覆盖描述符分配，不把 ArrayList 扩容和必要字符串生命周期复制说成零分配。首次正式构建 36/36，参数借用修正后的构建与专项仍在运行。

## 最终验收与自我批判

- 正式 merge.rx 编排前缀校验、映射初始化、集合合并及结果汇合；ZX 合并循环是一个内聚的集合算法，最长文件 50 行。
- 映射、引用重映射、候选构造、结构/名义查找、增量追加状态来自 RX/ZX；旧 Writer、merge_columns 以及仅服务这些桥的辅助文件已删除。packages 非文档源码中无 merge_writer 或 merge_columns 引用。
- executeBuffered 的实际传递闭包有 26 个生成函数，无描述符 create，14 个数组通道全部静态关联输入/输出列。仍有标准 ArrayList 必要扩容和新增字符串独立生命周期复制；该结论不等于整个操作零分配。
- 新增 delta 在读完 source 后才提交，避免压缩别名覆盖；长期 mapping 原缓冲区保留，不做全表复制。104 项现有类型合并专项覆盖身份、错误顺序、输入生命周期、批量、压缩及 owner/temporary 分配失败。26 项引用身份专项覆盖 source/library 两条路径。
