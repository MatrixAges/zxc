## 首轮失败与自我批判

1. 首次生成器命令误在主工作区执行，而新生成器仅位于固定工作树，因路径不存在失败；切换到正确工作树后成功。这是执行路径错误。
2. 首轮校验器将 input 和 visits 元素声明成按值对象，但共享 Zig 字面量发射器将对象表达为指针。两种模式都在编译阶段失败，没有运行任何目录测试。
3. 等同批两种模式确认终止后，仅将校验器 input 对齐为 `program.Input`，visits 对齐为静态对象指针切片；没有删除或减弱任何断言。修正后全部组合通过。

首轮声明、输入身份、发射源码、失败日志和退出状态全部保留；不把这些测试设施错误报告为 zxc 实现缺陷。本次没有确认的新实现缺陷，未向实现会话发送消息。

当前 oracle 使用 JavaScript 自身的 reduce，生产执行用 zxc 生成 Zig，两者实现路径独立。native 宿主只记录参数和注入失败。错误类名称映射、undefined 返回替换都已记为适配；没有宣称 JavaScript 全部动态集合语义已支持。未开展所有分配失败点穷举，也不声明该项完成。

`运行门禁.py` 复用首轮成功编译的工具，并要求新建最终模式目录。若要额外复现，应使用新的输出目录，并按照已归档命令与工具身份更新路径；不覆盖既有执行证据。新环境需要从记录的编译器生成与工具编译命令恢复外部输入和工具，不宣称脱离这些固定输入的一键复现。

发布前运行 `核验执行证据.py`；`准备发布.py` 复制已执行草稿并保存保护基线；暂存与提交后分别运行 `核验发布范围.py staged`、`committed`。正常 hooks 使用既有任务级 Corepack 路径，不修改项目锁文件或 hooks 配置。提交后核验终止成功，再 push 并核对远端 HEAD。
