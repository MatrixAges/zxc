# 列表替换与根导出参考

## Intent：目标

普通 ZX 函数可表达单元素替换；原生宿主可复用生成入口的已有列表容量。语言规则与缓冲审计仍由编译器负责，不增加运行库。

## Data：接口

```typescript
const updated = values.with(index, replacement)
```

`values: T[]`、`index: u64`、`replacement: T`，结果为 `T[]`，长度不变。这是 ZX 的检查式下标更新原语：先求目标列表和索引，检查边界后再求替换值。越界返回 `IndexOutOfBounds`；不支持负索引或越界扩展。原列表若仍可观察，其值保持不变；元素中的引用不会被深复制。

编译器把它降低为已有 ListUpdate IR。独占消费满足静态审计时可复用存储，否则按普通不可变更新生成代码。不要把使用 `with` 本身理解为分配次数保证。

满足静态准入条件的生成模块可以提供以下额外入口；应以实际生成声明为准。

| 声明              | 用途                                                         |
| ----------------- | ------------------------------------------------------------ |
| `execute`         | 保留既有 ArenaAllocator 接口                                 |
| `executeValue`    | 使用普通 allocator；对合格聚合按值返回，其他类型保留原值表示 |
| `executeBuffered` | 为合法列表通道接收标准 ArrayList 与 started 标志             |
| `buffer_lanes`    | 每个合法通道的 slot 名、Input 字段路径与 Output 字段路径     |

只有具备合法缓冲通道时才生成后两项。值表示仍保留真实重复聚合、引用身份、列表元素、原生接口、Store 与任务等边界，不能假定每个嵌套对象都会展开为值。

## Edges：宿主责任

宿主必须独占提供的可变缓冲，并按元数据对应输入与输出路径；不得凭通道编号猜测对应字段。通道允许截短有效前缀，但不能保留随后还要观察的旧别名。

- `started = false`：缓冲初始为空，生成代码在首次需要写入时接纳输入前缀。
- `started = true`：输入切片必须就是该缓冲的有效前缀，长度不能超过容量；不能把另一块内容相同的内存冒充为当前缓冲。
- 空 slot 使用普通不可变路径，可能分配；其 allocator 生命周期必须覆盖返回数据。
- 若选择直接 GPA 管理各列，宿主需证明所有需要复用的通道都已绑定；不能遗漏通道后丢失普通分配路径的所有者。

这些条件不是动态检测，也不是专用运行时协议。生成入口使用普通 Zig 参数和标准库容器；宿主在编译期依据元数据完成绑定。

## Answer：使用与验证范围

RX 继续负责真实阶段编排，ZX 负责集合算法与原子规则；根导出能力同时适用于两者的最终 IR。流程状态消费者展示了显式状态、标准容量资源和静态路径绑定的组合，规则见[执行计划](执行计划.md)，实际构建与既有专项结果见[执行记录](执行记录.md)。
