## 固定源码与准备反馈

最初管理检出固定 c83c2a80e。首次真实编译工具在 formatter 返回 diagnostic 时缺少详细输出；补充路径及消息后，确认测试生产者没有按既有 ZX 语法公开 Input/Output 别名。修正测试声明，并让虚拟源码路径 factories/create.zx、steps/patch.zx 与相对模型引用一致。没有把这些准备问题当作语言缺陷发送给实现聊天。

旧草稿按相对最终草稿的差异保存，避免在多个阶段复制相同文件。复现时复制最终草稿，再覆盖该阶段的草稿目录，按阶段执行输入里的 SHA 核对；草稿差异.json 列出覆盖文件。原始生成代码及失败日志独立保留字节。

格式和真实项目推导通过后，旧源码的 object 场景得到零转移槽。产物入口调用 function_1，而非缓冲调用；生成代码归档保留在顺序调用修复前。两个独立 map 容器及固定写入需求未改动，也没有降低预期转移槽。

执行期间实现已提交 1cd5896ffe74b43cbbc2b4c7ef7a0408bed043a1，完善顺序调用的所有权传递。另建管理检出 product-transfer-sequential-conformance 固定该提交，旧检出不移动。当前编译器、genz 与真实 parser generator 重新编译执行，生成 81 个模块文件，避免沿用旧版本生成语义。

两个宿主模式分别编译并实际执行测试生成器。RX 使用与正式构建一致的 generated_paths、generated_graph、generated_rules=true；项目来自真实 XML 和 ZX 文件，经 project.infer、validateIr 与 emitBundle。九组场景的生成源码及 ABI 在 Debug/ReleaseSafe 逐字节一致。

## 运行结果

最后一轮冻结 5818 个包文件。每种模式实际执行九个值与资源测试根、两个容量测试根，各 47 个检查、11 个二进制；合计 94 个检查、22 个二进制。两种模式全部通过。生成工具的九次成功调用不计为运行测试数量；参数矩阵和分配失败轮次也不重复计数。

| 场景            |               转移槽 | Debug 检查 | ReleaseSafe 检查 |
| --------------- | -------------------: | ---------: | ---------------: |
| object          |                    2 |          6 |                6 |
| nested          |                    2 |          6 |                6 |
| shared          |                    0 |          5 |                5 |
| retained_target |                    1 |          5 |                5 |
| retained_parent |                    0 |          5 |                5 |

| 合计            | 6 个槽分布于四个场景 |         47 |               47 |

所有输入的 canary、数组值及标量字段保持不变。保留目标或祖先的输出保持原值；共享来源、跨分支相交来源及重复消费路径均没有转移槽。growth 仅转移固定写入的右列表，没有给增长的左列表建立 fromOwnedSlice 所有者。

九组场景均覆盖空与非对称列表、实际执行的索引边界、同 arena 连续调用后早期结果不变，以及每个分配失败的释放和输入不变性。每个失败或成功返回后，跟踪分配字节与释放字节相等。

容量检查保留左 65537、右 32771 的规模。最初 payload 表达式被 Zig @min 的常量范围收窄为 u16，乘法在测试编译时溢出；明确提升操作数至 usize 后再执行两模式。仅改动测试数值计算，生成程序与生产源码未变，所有此前执行都先进入终态，旧失败保留在容量常量复验。

Debug 的两个正向场景均得到 initial/first/long=1966374 个跟踪分配字节，对应零次、一次与 64 次写入。较小列表载荷为 262168 字节；测试约束是激活写入及增加轮次均不增加一整列复制，不强加任意固定分配次数。输入长度与这些字节计数仅用于此测试，不声称普遍分配量或性能基准。

实际运行墙钟 Debug 约 19.6 秒，ReleaseSafe 约 86.9 秒，存在其他并行工作，不作为隔离性能比较。

## 边界与自我批判

生成槽结构、实际值和资源检查同时成立，不能只凭存在 buffered 函数证明入口用了缓冲；旧版本普通入口是这一风险的具体反例。独立两个分配与保留观察者的测试没有改写为更容易通过的单列表场景。

转移槽计数匹配生成代码里的 .fromOwnedSlice 字段访问，兼容调用表达式的括号排版；旧零槽产物全文确实没有该调用，调整识别文本未改变旧结论。Code 文件与 raw 日志保留字节，生成源码采用 .zig.txt，避免提交 hook 重排归档。

本批执行的是固定 1cd5896ff 上的编译 API 和生成程序，未运行完整 zig build、CLI 或统一库编码门禁。后续主分支提交的原生模块规划尚不在本批执行范围，发布基线单独保存差异并保护最新实现。原生启动使用已核验的签名 SDK 副本及空 entitlements，不修改系统策略。

矩阵仍有 128614 个 catalog 用例。本批原生具名检查单独计数，没有伪增 Test262 的适配或 catalog 数量。没有确认新的当前实现缺陷，因此没有向实现聊天发送消息。整体语言生产就绪与 Test262 完整对齐仍未完成。
