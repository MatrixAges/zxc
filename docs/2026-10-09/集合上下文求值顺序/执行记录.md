# 集合上下文求值顺序执行记录

## IDEA

- Intent：验证显式集合上下文作为表达式参数时的求值次数、顺序、错误优先级与未使用参数行为，补齐之前只读静态字段的覆盖。
- Data：源码固定为 `39d4bf10000fad24023478b59bd727942a317887`；冻结 5844 个包输入。与此前实际生成编译器模块的 `6b0cbb6b8befe5fde492e77d69c46dbc66001a5b` 比较，1928 个非测试包输入逐字节相同，Git 范围比较也没有生产包差异，因此明确复用此前实际生成的 81 个模块。两种模式的编译工具实际运行并产生八个 ZX 程序的普通 Zig 与 ABI。
- Edges：这是普通集合表达式的原子语义测试。原生 host 仅提供显式测试观察，不引入专用语言运行库、解释器或动态调度。上下文类型为 i64，不能推出对象/list/Task 上下文已完成验证。本批执行直接公共编译器 API 与实际生成程序；全仓库回归不在本批结果范围内。
- Answer：Debug 与 ReleaseSafe 各 8 个真实测试二进制、64 项具名检查，合计 16 个二进制、128 项检查全部通过；两模式生成程序及 ABI 完全相同；正常提交钩子及提交后范围核验通过后，以英文 Conventional Commit 提交并 push。

## 被观察的语义

IR 契约规定 target 与 initial 依次在外层求值一次。ZX 测试保留这一完整表达式，分别调用静态原生 source、context 与 visit，host 记录真实 S/C/V 事件、上下文原始 tag、每次元素和收到的上下文。四个方法各有使用和忽略上下文的程序，共八个。

context 返回 tag+7，使传入参数和最终上下文值可以区分；使用上下文时 visit 必须收到该结果，忽略上下文时 visit 使用 0，但 context 仍必须求值一次、其错误仍需传播。map 比较完整 item+context 输出，filter 比较完整筛选结果，every/some 比较 bool 与首次决定位置。

独立 oracle 从输入列表和上下文计算完整结果及应访问的元素前缀。它不调用生成程序，也不从生成源码读取期望。测试同时检查 source/context 次数、S→C→V 顺序、每次元素与上下文、错误、输入内容与 tag 不变性及两端 canary；单独计数不足以通过本批。

## 具名检查

每个程序实际运行以下八项，而参数矩阵内部的循环不额外计算测试数量。

1. 空列表仍求值上下文一次。
2. source 先于 context，回调按输入顺序接收正确上下文；覆盖多个列表和五个 tag。
3. source 失败阻止 context 和回调，空列表亦如此。
4. context 失败先于任何回调传播，空列表亦如此。
5. 遍历每个可能的 callback 失败位置，对照独立 oracle 判断可达性。
6. 回调错误按实际决定位置传播；every/some 不执行短路位置之后的失败。
7. 连续 17 次独立调用重新求值上下文，tag 持续变化。
8. 4096 元素遍历保持一次 context 求值并保留完整输入。

## 准备失败与修正

第一轮两模式均被测试 ZX 的 spacing 规则拒绝。读取 spacing 实现后确认 Input 与 Output 声明之间需要空行。待所有首轮门禁终态后，保存 `格式首轮/` 的冻结输入、草稿和日志，再仅补上这八个声明边界；没有改动回调、预期或语义。

第二轮两模式成功生成全部八个程序。Debug 的首个运行测试编译失败，原因是本批测试假定对象输入为值；实际当前 ABI 是 `*const` 对象和只读 slice。生成的 ABI 是权威证据，因此测试构造真实 child 对象并传入地址，host.source 按只读 slice 签名接收与返回。`宿主ABI首轮/` 保留修正前的输入、草稿、终态和日志。ReleaseSafe 第二轮完成了生成，没有将未开始的运行测试写成通过。

第三轮只改上述两个测试宿主文件，保留第二轮八个普通 Zig/ABI 的原 SHA，实际重新编译并运行两模式全部测试二进制。`semantic_generation_reused_from` 标注生成证据来自第二轮，`parser_generation_reused_from` 标注 81 个编译器模块的来源；没有宣称第三轮重新生成这些产物。

两次失败都属于测试准备问题，未确认新的 zxc 实现缺陷，因此按用户约定没有向实现会话发送消息。

## 文件边界与发布

正式范围共 15 个路径：根测试构建注册、独立 context_effects 构建器、compile/host/oracle/check/root 五个 Zig 文件，以及按方法和上下文使用状态组织的八个 ZX 文件。测试位于 test 包 src 同级的 tests/collections/context_effects，ZX 每个 11 个物理行，均低于 120 行。

本批新增原生语义检查，不新增 JSONL catalog 和 Test262 review，因此 catalog=128614、adapted=823、excluded=2081、equivalent=103、linked_cases=6953、unreviewed=50590 保持不变。矩阵审计与实际运行是独立证据。

发布脚本保护其他包、根配置及并行工作，精确暂存本批文件，并在正常钩子后重新核验源码字节、原始归档字节和提交范围。正式编译器实现没有修改。

## 自我批判与后续

准备时没有先核对 declaration 空行规则和不可变 ABI，造成两次本可避免的测试工具失败。失败已保留，修正由真实源码及 ABI 支持；不能把它们误报为实现缺陷，也不能删去使用未被回调读取的上下文来绕过语义检查。

验证 S/C/V 计数、收到的参数和完整结果，可以证明本批执行中的求值行为；它不能证明所有上下文类型、库编码路径或所有 zxc 特性已完成。下一步应覆盖借用对象/list 上下文和静态边界、必要的库消费者路径，并继续审查上游原文。完整生产级目标保持进行中。
