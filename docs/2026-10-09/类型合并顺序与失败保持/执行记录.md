## 前期诊断

1. r1 的生成命令把外部 options 路径映射到了尚未复制的新目录，词法器编译失败。已补齐独立 options 快照；不是实现缺陷。
2. r2 在用户更新规则时被中断，执行句柄消失，进程查找也没有发现对应生成器。保留旧状态与日志，另建 r3；没有把陈旧 running 状态当作执行成功。
3. 首轮新测试编译发现 Snapshot.origins 使用 owner 类型，实际列快照为 owner.Table。修正测试类型后重新运行，两种模式的失败日志均已保留；没有向实现会话发送此测试自身问题。

4. 直接 CLI 以单个测试文件为模块根时，imports/resources 引用同级目录之外的 fixture 被 Zig 拒绝。仅改为相对路径或添加 --build-root 仍会失败；最终使用测试公共目录下的薄入口载入原文件，不改原断言。
5. 独立 Debug 门禁完成 31 组、192 次命名测试。ReleaseSafe 多个入口重复优化编译器闭包；核对具体 Python/编译器父子 PID 后，仅向冗余编译器子进程发送 SIGTERM，等待包装脚本终态，再转为静态汇总门禁。这是有记录的执行策略调整，不是因观察超时而重启。
6. 按仓库 staged formatter 落实两个新增文件的空行要求，随后用最终字节重新执行汇总门禁。主门禁含 29 组；两个 compaction 根单独汇总，以保持既有 type_merge_fixture 模块身份，避免与主门禁内直接 fixture 导入重叠。
