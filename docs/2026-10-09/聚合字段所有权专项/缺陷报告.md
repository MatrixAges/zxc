## 确认的行为

1. 拥有字段 untouched 在循环中从未被赋值，但其它字段转移及 index 更新使其输出摘要从 owned 降为 borrowed。
2. do 循环每次 body 都将 `fresh` 替换为新 scalar map 输出，随后更新 index，最后投影 fresh 仍得到 borrowed；该路径不存在零次 body。
3. 控制一：untouched 改为独立 `[1]` literal，仍失败，排除共享同一 fresh 初值的解释。
4. 控制二：无产品包裹的 do 循环直接将列表 state 替换为 map，得到 owned，通过。
5. 控制三：mixed 产品 do 循环只执行 `state.fresh = []`，没有后续 index 字段更新，得到 owned，通过。

## 源码归因与进一步增强

只读审查发现 `analysis/iteration/update.zig` 的 field prepare 以 read_value=true 暂存整个 parent；`block.temporary` 使用普通 borrow binding，`ownership/runtime/execute/scope.zx` 随后 permanent borrow 与 Freeze 整状态，未更新的拥有字段也被降为 borrowed。postcondition 入口和出口调度本身按 body→condition→capture 运行，当前证据不应错误归因为遗漏 do 的顺序。

原多字段链测试的 borrowed 结果可能受同一 Freeze 影响而提前成立，不能单独证明多轮反馈。后续正式传播链将使用一次完整 root replacement，单独保留字段更新回归测试，并补充同语义更新顺序和整状态替换对照。

## 强化控制的实际结果

传播链改为完整 root replacement 后，2、5、17 个字段的借用反馈和 untouched owned 断言均实际通过。独立 scalar index 字段更新仍使 fresh sibling 降为 borrowed；do 中把 scalar 更新移到 fresh map 前则通过，整状态替换也通过。Debug 第三轮共 27 项（含 root）25 通过、2 失败；两处失败正是 scalar 更新污染 sibling 与 fresh-first/scalar-last 的 do 顺序。结果与源码归因一致，不能再用原字段链的 borrowed 通过宣称多轮传播正确。
