# 函数导入编号规划

## Intent：最终目标

在现有产物规划之后延续函数首次纳入编号与顺序，保留函数导入对原生模块和类型规划的依赖，为正式宿主替代提供状态。

## Data：可用证据

artifact/build.zig 的 extract 逐条校验 function_imports 的源编号及输入输出类型；importFunction 对首次函数先纳入 external.module，再纳入输入输出类型，最后写 function_mapping。重复导入仍校验签名，已有编号不重新纳入函数。external 的其他字段不增加类型引用。

## Edges：边界与限制

固定列元数据按源函数数量分配，不复制函数体。失败不提交当前函数编号，但此前完成的模块与类型规划状态保留。函数导入后仍须处理导出、函数体和 Store。当前入口尚未正式宿主集成；新增函数签名及导入列已校验等长，前置类型表、模块表和初始化规划状态仍沿用内部契约。不得把入口编译当成运行对照测试，不新增测试、不执行全量。

## Answer：交付与成功标准

FunctionPlan、函数元数据初始化、单函数纳入、函数导入集合算法与 RX 阶段连接，逐字源码草稿和真实生成入口编译证据。检查既有五列及新增两列缓冲在实际调用中的传递。

```mermaid
flowchart LR
    imports[类型及原生依赖导入] --> ready{Ready}
    ready -->|是| functions[函数导入集合]
    ready -->|否| failed[返回已有状态]
    functions --> output[类型 模块 函数规划结果]
```

```mermaid
flowchart LR
    binding[函数导入签名] --> check[与源函数签名核对]
    check --> native[纳入原生模块]
    native --> input[纳入输入类型]
    input --> output[纳入输出类型]
    output --> commit[提交函数编号和首次顺序]
```

## 本次实施边界

函数源签名使用 inputs、outputs、native_modules 三列，导入使用 ids、inputs、outputs 三列；规划持有 mapping、order、count，1-based mapping 保留 0 表示未纳入。函数导入集合逐项校验签名，对首次函数计算依赖闭包并在 Ready 时提交编号，重复导入仍校验。依赖闭包按原生模块、输入类型、输出类型顺序推进，不把源函数体复制进新状态。RX 显式连接前置导入、函数列初始化及 Ready 分支后的函数导入阶段。

上一节点 e2ab4035f 已修复循环引用身份和原生捕获逐轮分配；本次以该编译器源码重建真实 RX 生成工具，不依赖旧的生成产物证明新入口可编译。
