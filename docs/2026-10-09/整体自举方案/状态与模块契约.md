# 状态与模块契约

- **Intent：** 先固定完整分析器与后端的数据所有权和阶段边界，避免逐文件迁移产生新桥。
- **Data：** parser/syntax/model.zx、canonical/body_model.zx、Analyzer 状态、contracts 子分析器、genz Lower 与递归目标节点。
- **Edges：** 本文是实现契约；概念字段不冒充已经编译的源码。优先复用现有模型，不创建全包共享的万能 State。
- **Answer：** 模型归属、入口输出、状态分区、无环遍历和发布不变量，供 A/B/D 大块一次性实施。

## 1. 模型归属

| 所有者        | 模型及职责                                                  |
| ------------- | ----------------------------------------------------------- |
| compiler 前端 | 既有索引语法树、源码范围、声明与解析结果                    |
| core          | 跨分析与生成共享的 canonical IR、ID、公共能力及诊断数据契约 |
| compiler 分析 | 分析上下文、作用域、捕获、类型增量、工作栈及诊断状态        |
| compiler 项目 | 统一模块身份、导出、依赖图、链接与缓存事实                  |
| genz          | 优化事实、函数生成计划、目标节点与输出上下文                |
| 平台资源层    | 分配器、文件内容持有、标准容器缓冲区、字节写出              |

现有 canonical 模型位于 compiler 下的部分，在需要跨包共享时收口到 core 的单一模型来源；保留验证算法的包归属。不得建立两套同名 IR 或逐包复制类型定义。

## 2. 主分析器入口

输入契约：索引 syntax、source、module identity、导入类型/函数、共享类型基表、名义来源、授权 Store。输入表只读借用。

输出契约：新增类型与名义来源、Body、contracts、exports、Input/Output 类型、输出所有权及诊断。输出只包含新增数据和结果，不复制已有共享表。

复用 `frontend/parser/syntax/model.zx.Program` 与 `ir/canonical/body_model.zx.Body`。旧 Zig View 的递归指针与 anytype 是适配现有 Analyzer 的实现方式，不带入新接口，也不新增 Reader 桥。

## 3. 分析状态一次设计完整

| 状态区 | 内容与不变量                                                            |
| ------ | ----------------------------------------------------------------------- |
| 类型   | 只读 base、可追加 delta、名义来源及解析缓存；已有 ID 稳定               |
| 绑定   | symbols、active、scope_floor、作用域帧；离开作用域恢复可见性而不误删 IR |
| IR     | expressions、control、边表与 root；按行追加保持列长一致                 |
| 细化   | 复用 facts/marks；分支进入与恢复遵守已有规则                            |
| 上下文 | lambda depth、捕获上下文与父索引、授权 Store、注入绑定                  |
| 遍历   | continuation 帧、子结果与控制状态；仅服务编译算法                       |
| 诊断   | 首个失败的类别、位置与参数；不在叶子分散发布结果                        |

一个功能状态只保留一个写入 owner；上下文只读列与新增列分开。跨阶段传递结果沿用既有 buffer lane 机制，不用“重新构造同值数组”传递 owner。

## 4. 遍历与 RX 编排

RX 主阶段为：声明类型解析 → Input/Output 与 Store 资格 → 上下文初始化 → 主体分析 → 返回路径检查 → 导出解析 → 契约分析 → 所有权 → 结果发布。每阶段的失败分支与数据依赖必须可见。

表达式、语句、回调和循环在现有 Zig 中互递归。新实现采用普通 ZX 显式 continuation 栈，帧记录节点 ID、进入/归并状态、期望类型、作用域标记和结果引用。帧不是业务阶段调度器，不容纳“解析项目/运行 ownership/生成代码”等跨职责阶段。

算法分派层只调用单向叶子规则；叶子不能反向 import 遍历入口。嵌套语法通过压栈与归并处理，模块依赖保持无环。ZX 文件按节点族和状态职责分目录，最多 120 行。

契约分析复用同一语义引擎，但拥有独立的局部符号/表达式区和契约模式，共享同一类型 delta。不得另造简化表达式引擎，也不能把契约阶段塞回主体 walker。

## 5. 后端状态与目标表示

输入是同一 canonical IR，不接收前端私有 AST。准备变换之后产生统一事实：IO/process、pure/local/value、state 表示、allocation、buffer lanes、freshness、transfer、task 需求。

生成与缓存 fingerprint 使用同一事实结果，不分别运行两套旧规则。RX 依次组织准备/预算、事实分析、函数版本计划、节点生成、打印和产物组装。

目标节点采用稳定 ID 和表式关系：表达式、语句、声明分别存储；字段、参数、分支和子项使用连续边表的起点/长度。类型表达式与其他表达式按实际可复用结构组织，不为了统一制造万能属性字典。

生成上下文包含类型/布局映射、符号名称、表达式缓存、作用域、错误捕获、辅助声明和 buffer/state 计划。全部以普通数据显式传递，不保留 opaque Lower/Builder。

打印算法使用节点 ID 与显式遍历栈，生成可追加 UTF-8 字节。缩进、转义、括号、关键字等是自有规则；最终文件写出才是平台适配。

## 6. 生命周期与失败

- 同次编译内部借用 source 和输入列；读取方的生命周期不能超过所有者。
- 公共 API 若要求结果脱离解析输入仍有效，保留必要的边界所有权复制，或采用已有可证明的拥有关系。不得以 zero copy 为名返回悬垂引用。
- 本模块 delta 在成功发布前不修改共享 base。发布失败时不得暴露半行或部分提交的状态。
- 临时构建失败的缓冲区由已有标准资源生命周期回收；语言诊断通过普通结果返回，OOM 保持资源错误。
- 分支和内联失败回退只能在定义的事务边界恢复，不能将 ExpansionLimit 混成 OOM 或返回半个 IR。
- 不引入动态语言运行时、专用引用计数或解释执行层。

## 7. 已知约束与设计验证项

已知：ZX/RX 源模块均要求无环；当前 Analyzer 有互递归和捕获父指针；现有 IR 构造还通过 Zig Storage；这些必须改为显式状态与遍历，不是新增指针语言特性的理由。

已有：executeBuffered、值调用和统一库的静态函数消费。不能把跨入口 owner 或 ZX 消费 RX 模块笼统列为完全缺失。

A 块需关闭的检查项：统一库对完整状态的名义身份和静态调用；输入 owner 与输出 buffer 路径；主体/契约共享 delta 的别名与回退；源码字符串的拥有边界；热点查找的复杂度；目标节点及字节输出能否完整表达。

只在这些完整契约出现具体不可表达或错误生成时，才补通用语言能力。禁止先增加编译器专用接口，也不把线性扫描自动视为最佳性能方案。

## 8. 自我批判

表式模型减少递归类型依赖，但并不会自动保证性能或零复制。集中验收必须看真实生成闭包，尤其是否逐节点复制整表、是否丢失输入身份、是否有跨阶段悬垂引用。模型设计通过不等于实现或自举通过。
