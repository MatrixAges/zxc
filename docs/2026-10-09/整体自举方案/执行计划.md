# 大块执行计划

- **Intent：** 按完整职责持续实现，减少重复构建、重复测试和碎片化提交。
- **Data：** 整体方案与状态契约；当前已完成节点保留，正式自举主链仍未闭合。
- **Edges：** 不跑全量测试，不新增测试用例；使用既有相关专项。实现不因上下文切换而重启，不为小 helper 单独建验证节点。
- **Answer：** 每块具有明确开始条件、实现范围、集中验收与提交条件；只有块闭合才标记完成。

## 1. 固定执行节奏

1. 先确定本块输入/输出、状态、RX 阶段图、正式调用与迁移清单。
2. 批量实现完整范围；期间做源码查阅、格式化、类型/调用关系和 diff 静态复核。
3. 本块源码与正式入口闭合后，集中运行一次集成构建和选定专项组。
4. 有失败时归因、成批修复；仅重复失败或受修复影响的检查。
5. 核对传递依赖、零成本约束和源文件职责，记录结果，英文提交并推送。

不再按“改一个规则 → 整仓构建 → 数组专项 → 提交”的节奏推进。也不在实现中持续重跑同一套已经通过且未受影响的检查。

若出现真正阻止设计继续的通用能力缺口，将它纳入当前块的前置工作一起收口；必须提前验证时，仅做关闭该阻塞所需的一次限定检查，并记录原因，不扩展为每次修改都验证。

## 2. 块 A：统一数据与静态模块契约

交付：现有模型的单一归属；主分析 Input/Output/State、目标节点与生成上下文；类型、owner、跨模块调用、诊断和发布协议；普通统一库的构建依赖分层。

实现范围：共用模型、必要标准资源适配、统一接口接线。若现有统一库足够，直接使用；不因源码相对导入限制自动新增语法。

结束条件：B/C/D 能依赖同一契约独立实现，未引入 opaque 自有状态或语言分类库。集中核对模型和 ABI 兼容、统一库消费、buffer/引用身份与 IR 表不变量。范围从既有 library/runtime、compiled_packages、collections/value_return、loop_columns、IR 专项选择，不运行全量集合。

## 3. 块 B：完整单模块语义分析器（首要实现块）

范围：indexed syntax 入口、类型准备、绑定/作用域、全部现有表达式和语句、调用/集合回调/循环/任务/Store、契约、所有权连接与结果发布。包括 append/bind/finish 等状态修改，不保留专用 Writer。

内部顺序：状态与帧 → 绑定/表达式节点族 → 语句与控制流 → 调用/回调/能力 → 契约与公开结果 → 正式入口切换。内部步骤不单独构建提交。

结束条件：正式 indexed 入口整块调用 RX 分析流程；传递闭包不回调旧 Analyzer。旧 Analyzer 仅供 seed，不存在按节点回退。

集中验收：compiler/tests/language、ownership、IR 中相关用例；test/tests 的 expressions、collections、contracts、stores 代表组；借用与分配失败。按语义覆盖选组，不按“本轮新增文件”选几条容易通过的例子。

## 4. 块 C：项目、RX 推导与链接流程

范围：模块身份和加载顺序、导出与导入绑定、共享类型/函数映射、缓存恢复/失效规则、RX 类型约束与降低、Store 注册、链接与完整 IR 门禁。

RX 输入与 ZX 主分析共享模块契约和 canonical IR。文件读取与通用哈希留在平台层，依赖规则、编译顺序与哈希内容不能留在 host 总控。

结束条件：ZX 项目入口和 RX 项目入口均走新流程；缓存命中与未命中不使用不同自有规则。

集中验收：compiler/tests/rx、test/tests/rx/inference/modules、incremental/module_records/type_merge/artifact/semantic_cache/module_generation 与 compiled_packages 的相关组，包含循环拒绝、别名、失效和所有权。

## 5. 块 D：完整 genz 后端

范围：内联及预算、能力传播、value/state/buffer/fresh/transfer 事实、函数版本计划、全部表达式/语句 lowering、Store/Task/native、ABI/分模块输出、目标节点与打印。

同时切换 compiler/backends/zig/fingerprint.zig 的事实消费者，避免缓存和生成不同源。现有 seed 后端可编译新后端，但正式路径切换后不能回调旧 lowering 或 printer。

结束条件：规范 IR 到 Zig/ABI 的自有规则闭合；普通、值和 buffer 入口及模块产物全部覆盖，不把 printer 当作免迁平台层。

集中验收：test/tests/collections 中引用身份、buffer/transfer/嵌套状态代表组；library/runtime、native、stores、incremental/backend_runtime/module_generation/generation_runtime、targets 的相关组。生成闭包检查与运行行为同时进行。

## 6. 块 E：产品闭合

范围：lint 遍历/格式规则、包解析与工作区规则、CLI/构建/缓存/目标产品规则；保留通用 I/O、分配器和外部工具调用。固定完整源码清单 S 与平台模块 P，更新 seed 引导接线。

结束条件：产品正式入口的自有规则全部有 RX/ZX 所有者；原生白名单逐项解释，不能仅检索 Writer 名称判完成。核对最新目标清单中的功能边界与现有实现，未完成项继续纳入本块，不凭旧文档跳过。

集中验收：formatting、semantic_lint、package_manifest/lock/install/store、build_modes、toolchain、incremental/watch 和相关目标/标准库的限定组。全量测试继续留给负责该工作的会话。

## 7. 块 F：三阶段自编译

输入：冻结 seed、相同完整源码 S、相同平台 P、固定工具链/配置。

输出：G1/C1、G2/C2、G3/C3 的来源、实际命令、摘要、生成源码/ABI/模块比较与代表行为证据。stage2 不得调用 seed 生成器，stage3 不得偷偷链接手写 genz。

结束条件：传递依赖闭合和阶段一致同时成立。普通 zig build、parser 生成成功或某个二进制可运行均不能替代此验收。

此处仍不擅自执行用户禁止的全量测试；运行专门的自编译与代表行为检查，并接收其他测试会话的全量结果。没有现有覆盖的要求记为缺失证据，不能伪称已验收。

## 8. 记录与沟通

每个大块只维护一组计划/执行记录与必要证据，超过 1000 行按职责拆分。保留失败原因及最终边界，不为每个小修正新建一批文档。

进度按“设计完成 / 实现中 / 集中验证 / 已提交”报告。实现中报告完成了哪个完整子范围和剩余依赖，不用代码行数估计整体百分比。

## 9. 本次设计执行记录

已查阅当前 Analyzer、RX 项目流程、genz render/lower/target AST、seed 构建接线及统一库 RX 消费实现，并由两个只读分析分别复核主分析器与后端路线。

关键修正：最初怀疑 ZX 不能直接 import RX 就需要新增语言机制；进一步核对 replay_import 后，确认已有统一库静态消费可作为基线。因此未将 Fold 或混合源码导入预设为必做功能。

本轮只形成设计和大块策略，没有修改正式源码，没有运行构建或测试。下一执行动作是块 A 的契约收口，再进入块 B 整体实现。

## 10. 自我批判

大块计划仍可能暴露未知的表示或别名问题。允许在块内修正设计，但不把完整职责悄悄缩成更容易通过的片段。集中验证失败不代表需要恢复逐文件测试；先根据共享状态和调用链定位根因，再批量修复。
