# 产物模块编号与导入规划执行记录

## Intent：最终目标

把产物提取中原生模块的编号、首次纳入顺序及类型导入和显式原生依赖推进规则迁入 RX/ZX，为移除专用产物状态实现准备完整阶段。

## Data：可用证据

正式源码位于 `packages/compiler/src/zx/modules/artifact/planning/`；逐字草稿位于本目录 `草稿/`。`plan.rx` 先初始化模块元数据及类型元数据，再依次连接初始根、原生发现、类型导入和显式原生依赖。`imports.rx` 与 `declared_native.rx` 在阶段边界按 Ready 状态短路。

- NativePlan 用 mapping、order、count 保存编号和首次纳入顺序；native_include 在全部成员类型纳入成功后才提交模块编号，空模块同样经过提交步骤。
- native_types 保持前向扫描，只根据扫描当时已纳入的类型决定是否纳入模块，不回扫之前的模块。
- native_dependencies 按依赖顺序扫描全部原生模块，使用现有 canonical key；同 key 的多个模块均纳入，重复模块保持原编号，未匹配的原生依赖返回 Invalid。
- semantic planning 的 visit 对已有映射直接返回原状态，避免为重复类型重新创建遍历栈。

已检查生成单文件实际 `execute` 调用链，非仅检查备用 helper 声明：

| 阶段     | 生成调用                     | 实际传入缓冲                                      |
| -------- | ---------------------------- | ------------------------------------------------- |
| 初始根   | function_15_buffered_pointer | 类型 mapping、order、origins                      |
| 原生发现 | function_26_buffered_pointer | 模块 mapping、order；类型 mapping、order、origins |
| 后续导入 | function_48_buffered_pointer | 模块 mapping、order；类型 mapping、order、origins |

上述调用均由 fromOwnedSlice 接管当前切片，并将 started=true 的缓冲地址传入。入口没有为这些列复制完整数组。普通产品包装仍可能分配，不能由列缓冲复用推导整个执行无分配。

单文件生成与分模块生成均成功；两种真实入口的 Zig 编译退出码均为 0。精确参数见 `入口编译参数.json`，结果见 `入口编译结果.json`。本次没有新增测试，没有执行全量测试，也没有把之前其他功能的专项结果当成本功能运行证据。

## Edges：边界与限制

此阶段仍未接入正式 artifact 宿主。输入表、模块列、依赖列及 roots 的形状要求由后续宿主集成的入口校验保证，当前内部规划入口不能用作任意外部输入的公开校验器。

固定元数据保留类型规划额外空间，以及每源原生模块 4 字节的 order；复用缓冲不等于消除这些空间。字符串物化仍借用源数据，源 arena 释放前后的所有权尚待正式集成解决。

函数导入、导出、函数体、Store 与其他依赖阶段仍待迁移；旧 Types.include 与专用 Workspace 尚未撤除。生成成功与入口编译成功不代表完整职责已自举，也不替代首次纳入顺序的运行对照验证。

## Answer：交付与验收

交付 NativePlan 及其原子操作、真实 RX 阶段编排、源码草稿、生成产物和两种入口编译证据。当前达到这一内部规划阶段的源码及编译验收，整体自举目标仍在进行。

```mermaid
flowchart LR
    native[模块元数据初始化] --> types[类型元数据初始化]

```

## 自我批判

已通过静态对照覆盖空模块、重复模块、同 key 多模块以及失败后不提交编号的分支，但没有执行这些情形的新增运行测试。先前布尔选择掩码无法保留迟到模块顺序，现已由显式编号与 order 替代；后续函数规划仍必须延续这一顺序，不能在物化时按源模块顺序重新排列。最终验收需检查正式入口依赖闭包和源内存生命周期，不能停留在新增模块本身。
