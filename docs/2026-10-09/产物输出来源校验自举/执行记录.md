# 产物输出来源校验自举记录

- **Intent：** 将正式 artifact 输出 body 的来源合法性移入 RX/ZX。
- **Data：** 原宿主谓词、Roots 调用关系、FunctionTable 的 external 重建方式与本轮源码差异。
- **Edges：** 仅约束被选为输出 body 的来源，不禁止外部函数导入；types 记录保持原有行为。dependencies compiled 目标规则仍待后续处理。
- **Answer：** RX 显式校验与短路，ZX 原子谓词，宿主只借用/组装已验证函数并材料化；构建与既有专项提供验证证据。

## 实施

Request 增加 program.file_name/type_only，Functions 借用 files 列，Record 借用 path。没有为新增元数据复制字符串或数组。形状校验增加 files 长度；原有索引检查仍在 select 之前执行。

entry/function 两条 RX 分支分别调用来源谓词；成功后才选择 body 并计算根闭包，失败返回 null。宿主 contents.function 删除 type_only/path/external/越界规则，保留已验证记录到 IR Function 的数据投影与所有权处理。

## 规则与边界复核

入口条件为非 type-only 且路径相同。函数条件为 native_modules[id] 为空且路径相同；core/function_table/root.zig 从该可空列重建 external，二者等价。types 分支不执行来源校验。

内部 Roots 更早拒绝错误来源；最终错误仍为 InvalidModule。没有发现直接依赖旧宽松 Roots 行为的测试或调用。更早拒绝可能改变 OOM 的发生顺序。

## 自我批判

本轮不是整个 artifact 或整个 contents 的自举完成。dependencies 的 compiled 目标拒绝仍在 Zig，是下一独立规则；宿主仍有资源材料化。不得用当前专项结果推导所有无效输入已经穷尽验证。既有五组专项共 27 项通过，正式构建 exit 0，36/36 步通过。

## 初次构建反馈

RX 直接用 body_function 索引数组时，索引约束为 u64，与记录中 u32 的函数 id 冲突。函数来源谓词改为接收 Functions 与 u32 id，在 ZX 中沿用现有 function_body 的 integers.widen，再读取文件与 native_module。RX 不执行类型转换，仍显式编排判定和短路；未改变编译器索引规则。

只读复核确认原有 valid 先于 select，覆盖索引与列长度；types 分支和外部函数导入边界保持。新增元数据均同步借用原 Program/Record，没有持久引用或复制。
