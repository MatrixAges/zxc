# 公开成员导出生成自举

## Intent：最终目标

将实际使用的公开成员导出生成迁入 RX/ZX：按成员顺序从目标函数模块导入 call，
生成公开同名常量，与既有入口声明前缀连续组装，不改变产物及调用成本。

## Data：可用证据

modules.publicEntry 由 Batch.generate 的公开成员入口消费。初查 signatures 发现其
仅为旧分区模式生成签名，当前 compiler 配置固定开启 partition_groups，正式路径
不消费它；因此本阶段优先处理实际启用的 publicEntry 成员导出。
最新完整冷构建为墙钟 130.33 秒、CPU 197.44 秒、2140667904 B 单体峰、
2150121472 B 采样树峰。固定基线仍为 129.74 秒、216.03 秒、2075033600 B
单体峰及 2247294976 B 树峰。

## Edges：边界与限制

保留 lower.declarations 的既有前缀及调用顺序。Source 使用绝对 expression_base
与 declaration_base，只在末尾添加窄 AST 列，不创建新的完整 Context。
成员名、模块路径借用输入；Native 投影成员索引和名称描述符，仍是过渡适配。
Source AST 列直接在 AST owner 中构造，提交时借用嵌套参数；scratch 仅保存
名称及索引投影，文本借自输入或静态常量，不把临时字段列或 builtin 参数悬空。
不新增测试用例，使用现有成员调用、库批次及发布回归；按受影响路径测量。

## Answer：交付与成功标准

```mermaid
flowchart LR
    Prefix[既有入口前缀] --> RX[RX导出编排]
    RX --> Init[初始化绝对基址]
    Init --> Members[ZX逐成员构造AST]
    Members --> Publish[提交窄列]
    Publish --> Printer[统一printer]
```

```mermaid
flowchart LR
    Members[公开成员名称和函数ID] --> Projection[借用名称及索引投影]
    Paths[已有函数模块路径] --> Source[RX与ZX]
    Projection --> Source
    Source --> Columns[导入与公开常量AST列]
    Columns --> Owner[复制非文本载荷到AST owner]
    Owner --> Suffix[连续后缀声明]
```

成功标准：同输入全部生成文件一致、工具自生成一致、正式构建及相关既有行为
检查通过，记录局部和固定基线累计性能差额，统一提交推送全部未提交内容。

## 实现与覆盖纠偏

RX 连接 initialize、members、publish。ZX 单项构造模块路径字符串、import、call
字段及公开常量，保留成员顺序和既有前缀；循环只携带窄列，未重新组装完整 Context。
新增表达式 builder/publish 按公开列契约投影，不增加运行时层或源码片段节点。

首次编译补齐函数索引 u32→u64 的显式宽化。executeValue 返回内部借用视图，
包含来源元数据；直接交给 AST 导入会触发未知列检查。适配先按 generated.Output
的公开列描述投影，未放松导入检查，也未把 private
视图元数据伪装成 AST 列。该投影只复制列头；最终版本在 AST owner 中构造非文本载荷，
用 appendBorrowed 提交，文本借用输入及静态常量。

只读审查确认 default 入口回归不证明成员非空。为此复用仓库已有
`zx/frontend/parser/imports/index.zx`，在忽略目录的诊断 manifest 增加公开入口，
而不新增源码测试。它重导出 advance/resume，真实生成两条 import.call 常量，
且 resume 需要由统一 printer 打印成 Zig 关键字转义标识符。

该同输入的 8093 份文件（仅排除 .zxc-inputs）在前后工具之间逐路径哈希一致；
每次都断言存在 advance 和 @"resume" 导出，避免分支零命中却宣称验收通过。
使用现有 initial.zx 创建真实状态、取消分区生成后编译独立 Zig 消费者，实际调用
advance 与 @"resume"，分别验证 Done、Start 及索引保持零，消费者执行成功。
诊断 manifest、生成文件、编译探针和日志仅留在忽略缓存目录。

## 生命周期优化与初次冷构建

初次同配置完整冷构建 43/43：time 墙钟 131.07 秒、CPU 199.50 秒、单体峰
2146729984 B；采样树峰 2158198784 B。现有发布入口 5/5、运行 2/2 均通过。
该版本的工具、隔离指标保留于带 -copying 后缀的目录，完整冷构建为
`partition-reference/cold-public-exports`，不覆盖初次证据。

相对上阶段 CPU +2.06 秒、墙钟 +0.74 秒的正差保留。分阶段摘要显示 host 均为
33 秒，但无关 cache-identity 的编译墙钟从 5 秒变为 19 秒，不能把全量差额
直接归因于成员导出。另一方面，适配层的额外 AST 深复制可以从所有权独立证明：
Source 先在 scratch 构造参数数组，再由 appendBorrowingText 复制到 AST owner。

保持迁移，令 Source 直接使用 lower.allocator 构造 AST 列与嵌套参数，改用
appendBorrowed 提交；名称/索引投影仍在 scratch。所有被引用的 AST 数据归同一
外层 arena，完整 printer 执行后统一释放。这样消除参数复制及其泛型清理路径，
不延长输入借用或改变持久输出的 owner。需补生成一致、执行、构建及成本证据；
不能仅凭“减少复制”就认定完整冷构建一定更快。

## 自我复核与未完成范围

本阶段迁移公开成员的导出 AST 规则。入口前缀、Lower 自有状态、ABI 适配及其他
Native 编译器职责仍需迁移；旧 signatures 模式也未在本阶段迁移。
Source 生成器和普通静态 Zig 保持零运行库，语法打印仍由统一 printer 完成。
既有函数文件一一生成、名字及变体次序未变，没有为探针名称添加生产特例。
执行记录采用 IDEA 并保留架构图及数据流图，不把局部迁移或工具同值宣布为整体自举完成。
下一步应优先核对完整构建 CPU 正差及固定基线累计单体增长，避免继续叠加未解释成本。

## 归因结论及后续决策

固定产物host与实际旧/新Source两分区的三对实验都未复现完整CPU+2.24秒，
因此该值尚不能认定为由公开成员迁移导致的稳定退化，也不能宣布已经消除。
新Native静态库+3992 B和分区对象+2328 B是已证实的编译产物增长，配对小幅
CPU正差继续保留；不同场景的中位数不能相加后从完整构建中直接扣除。

本轮没有修改生成算法，没有撤回迁移，也没有在缺乏机制证据时改分区、线程数
或放松校验。完整固定基线依然129.74秒/216.03 CPU秒；最新完整结果仍是
130.37秒/199.68 CPU秒，累计墙钟+0.63秒、单体+72384512 B仍未恢复。

当前决策是停止重复全冷构建与没有新假设的追测。后续新增实际编译工作时继续
核对固定基线及阶段趋势；如果完整CPU增幅持续或在受影响路径稳定复现，再对
对应进程采集CPU/IR证据。seed、DSL与其他工具尚未单独计量，不能声称完整
2.24秒已被逐阶段解释。本轮完成归因边界核查，不是整个自举或性能目标完成。
