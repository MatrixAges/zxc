# 函数源码批次规划自举

## Intent：最终目标

迁移源码批次的缓存复用分类、拷贝布局和待生成位置规划，保持任务顺序、缓存
替换顺序和已有并发。先实现完整规划，再依据同输入证据优化，不回退迁移。

## Data：可用证据

function_sources.createJobs 原先在 Native 中识别 held/stored、汇总缓存源码长度、
分配复制区间及划分待生成任务。最新完整冷构建为墙钟 129.92 秒、CPU 197.46 秒、
time 单体峰 2150187008 B、采样树峰 2164178944 B。
固定基线仍为 129.74 秒、CPU 216.03 秒、2075033600 B 单体峰、2247294976 B 树峰。

## Edges：边界与限制

RX 连接缓存分类和字节布局两个阶段，ZX 执行稳定遍历。Native 只投影缓存标签及长度，
执行分配、实际复制、缓存 I/O 和线程调度；这些仍是过渡依赖，不宣称整个批次已自举。
所有借用缓存字节必须在 record 可能替换缓存之前完成复制；保留原有结果拥有权。
使用既有回归，不新增测试用例。先比较完整生成文件和受影响生成路径，再核对累计成本。

## 实现复核

Source classify 仅将 held/stored 列为复用，absent/invalid/failed 均保留为待生成；
layout 按复用顺序记录累加前的字节偏移，空命中自然得到空列表与总长度零。
Native 适配输入只包含缓存标签及长度，不传递 Cache、Job 或 Batch 指针。

createJobs 在并行复制完成后才逐原任务调用 cache.record，避免旧 held 引用因
缓存记录替换而失效；缺失任务与 remember 仍按原始 position 顺序回填。
错误缓存仍由既有 record 更新统计，不在 Source 中吞掉 failed/invalid。
规划分配失败可能比旧实现更早发生，但同样整体返回 OOM，不发布部分结果。

一次只读独立审查核对了标签分类、偏移、位置映射、复制前后生命周期及分配边界，
未发现语义阻断。新增开销是 O(N) 标签/长度及位置元数据，不能称零元数据成本。
实际生成循环复核显示 reused/pending/offsets 均回写 items 和 storage，未在每轮
重建宽表或丢失增长前沿；三列均由普通静态 Zig 列表增长实现。

初次 Source 编译要求为空列表显式声明 u64 元素类型；Native 适配随后修正了
运行时 tagName 用作字段名的问题（改为编译期穷举投影），并删除不属于该入口
错误集合的 IntegerOverflow 分支。没有放宽校验或添加编译器特定兜底。
