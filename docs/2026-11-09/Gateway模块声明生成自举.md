# Gateway 模块声明生成自举

## Intent：最终目标

把 Gateway 模块前导与服务 imports 的完整声明生成职责迁入 RX/ZX，保持声明
顺序、导出性、整数类型和借用生命周期。整体 render 装配及 arena 生命周期仍在
原生层，完整自举尚未完成。

阶段前为 75afb78d。上游 backend/gateway 已有连续的服务模块名数组
imports[1..]，现直接传入 Source；没有重新投影名称数组或复制模块名字节。

保留正常引导用途，正式路径不调用它。

## Edges：边界与限制

不重排声明，不改变max_body_bytes显式usize，不取消安全校验或回退迁移。
Source名称和参数数组由Builder allocator或稳定输入持有，覆盖整个打印期。
Constant[]只复制ID/标记/切片描述符进入目标；不复制名字节，不保存临时行地址。
行发布边界继续检查u32上限；旧列接口的重排及重复offset语义保持。

局部host峰值增长必须与实际构建条件共同核对。字段数量减少或
生成代码更短不构成收益证据。后续不能继续同配置盲目计时，也不能把优化IR
差异小直接当作前端内存无问题。原始IR已排除“大量新增LLVM指令”的假设；下一步应按编译阶段对齐RSS，
区分前端/Sema与LLVM后端工作集，而非再尝试减少几个输出字段。

### 末端峰值进一步归因

使用同一冻结控制和最终行版rsp，phase-rss记录0.2s内存曲线，并保存原始IR
及一次短栈。IR文件首次写入发生于0.42s，不是阶段完成边界；必须使用达到
最终文件大小的采样点。原始IR完整约2.745/2.751s，RSS883621888/886620160 B。
25s约1503/1501 MB，30s约1862/1865 MB；峰值位于约32s的机器码生成末尾，
分别2386837504/2396061696 B，差9224192 B。短栈明确位于LLVM的旧式函数
PassManager、MachineFunctionPass、SelectionDAGISel，不能据短窗口断言整轮占比。

vmmap-pair另在RSS达到2.1 GB附近抓取映射分类，两侧物理footprint均约1.8G，
主要为Malloc Small，另有Malloc Large及共享LINKEDIT/TEXT驻留页。两侧捕获
时刻不完全相同，汇总以M/G舍入，无法精确解释MB级增量；vmmap介入后峰值
2381922304/2440937472 B不能用作普通性能验收。保留原记录，不把它当收益或
退化证据，也不据字段少就继续改Source。

最大未优化IR函数crypto.tls.Client.init前后均4835399 B，位置接近模块末尾。
