# 列表增长声明生成自举

## Intent：最终目标

将 growth 的六项完整声明生成职责迁入 RX/ZX：ZxHeader、zxReserve、
zxReserveBounded、zxAllocate、zxRetract、zxRenew。保持原增长算法、静态 Zig
泛型、所有权与错误行为；Native 只负责借用、通用 AST 发布及兼容 seed。

## Data：可用证据

正式 types.lower 在 has_lists 时调用 growth.declarations；类型 bundle 与普通
模块均消费。现有 Source 的 Context、Fields、StatementsBuilder 与声明列可表达
这些 AST。生成的 @typeInfo/comptime 属于目标 Zig，不要求 ZX 新增泛型。

原算法只有 Lower.call 更新 uses_allocator，完整生成六声明成功后该值必为 true。
call(true) 必须沿用当前 capture；math.mul/add 使用普通调用及显式 OOM catch，
不能换为 try。已有 list.permission/tag 可直接复用 Exclusive 构造。

## Edges：边界与限制

- 保持 Header→Reserve→Bounded→Allocate→Retract→Renew 顺序与公开属性。
- 保持对齐、offset、最小容量 8、frontier/committed 及 prefix memcpy。
- Renew 保持 optional→pointer→wrapped/field 顺序，record 先复制再递归并替换。
- 参数 comptime、inline、错误集合、capture、shared_types 引用及 serial 均保留。
- 仅补通用 AST 构造原语，不增加解释器、运行库、Zig 源码片段或专用回调桥。
- 不撤回自举以掩盖退化；必要时保留迁移并优化成本。

## Answer：交付与成功标准

```mermaid
flowchart LR
    Bases[已有 AST bases 与配置] --> Header[容量头]
    Header --> Reserve[前沿复用]
    Reserve --> Bounded[有界 reserve]
    Bounded --> Allocate[对齐分配与前缀复制]
    Allocate --> Retract[回退 committed]
    Retract --> Renew[递归更新独占存储]
    Renew --> Publish[拥有型发布与统一打印]
```

```mermaid
flowchart LR
    Source[Context 与局部列] --> Nodes[结构化表达式]
    Nodes --> Bodies[语句范围与参数字段]
    Bodies --> Declarations[声明表]
    Declarations --> Native[通用 AST 导入]
    Native --> Output[普通静态 Zig]
```

复用既有增长、嵌套缓冲及不可变集合回归；核对两阶段完整产物、memo 和固定
累计性能基线。全部验收后收口所有变更提交推送，不把此职责完成视为完整自举。

## 执行记录

### 实现及成本收口

declarations/build.rx 显式连接六声明的生成顺序。ZX 按布局计算、失败范围、
物理分配、头部初始化与前缀复制，以及 Renew 的四类子体组织；各函数负责一项
AST 构造职责，没有通过 Source 入口回调旧 Emitter。旧实现仅保留为 seed 分支。

通用 StatementsBuilder 增加已存范围的 selection、独立 scope，以及按引用捕获；
Context 增加 import_path，以结构化节点保留原 @import("std").x 表达。少量不常用
表达式列保留在本职责 Extra 中，没有扩大所有 Context 实例。复用现有 Exclusive
permission/tag、参数字段及声明构造器，不增加目标运行时机制。

初版 Source 完整生成已通过；第一阶段工具构建 21/21 步成功。新旧工具在同一
新清单上核对 main / collections / growth / ordered 的全部 3586 / 65 / 361 / 24
个文件，除 .zxc-inputs 的路径外逐字节一致。这证明所测生成形态，不代替行为
回归与最终版本的阶段自编译。

只读审查随后发现两个固定额外成本，已在保持迁移的前提下收口：

- 参数类型改为按实际参数名构造，避免为 Retract/Renew 生成未引用的 allocator、
  const slice 或 anytype 节点。参数列表仍按原顺序组装，comptime 属性不变。
- 通用 import_module 增加已有 BorrowingText 契约的整模块入口。默认 owning
  入口保持原行为；此声明模块使用文本借用，仍拥有非文本 slice、参数外层列和
  嵌套 arguments。所有固定名称来自 const 字符串，std.bytes.fromText 直接返回
  输入 slice；已生成体出现 @as([]const u8, "ZxHeader") 等静态字面量。capture
  名称来自现存 Lower，寿命覆盖本次生成与打印，不能将此证明推广给动态名称。

适配器在 scratch 释放前发布非文本数据。保留旧 [6]Declaration 返回契约，故五个
Function 的参数还需 materialize，随后由原 declarations 消费方存入字段列；这份
描述符中转仍存在，不能声称通用 AST 存储已经自举，也不将其当作 payload 拷贝。

目前 35 个 Source 文件 fmt/lint 通过，最终工具正在重建。前述初版证据不冒充
成本收口后的最终验收；原始日志位于忽略目录
.zig-cache/cold-build-analysis/ownership-research/growth-declarations。

### 统一复制与清理的编译期资格

实际 CLI 的未优化 LLVM IR 为 220,050,271 B。沿 growth adapter 调用链确认，
其三个 importer 实例合计 24,740 行；最大表达式实例有 19,394 行、3,274 个块。
这说明展开后的实际代码值得检查，不把“三处调用”未经核对地当作新增实例。

原 copy loop 已在 comptime 判断 copy_payloads、containsSlice 以及 BorrowingText
的精确 []const u8 例外，但 defer/errdefer 对部分不具备复制资格的列仍生成清理
分支。copied 位只在满足同一资格且完整复制成功后置 true；其他列永远为 false。

修正为三处复用 copiesPayload 谓词，仅在编译期剪去不可能执行的清理。实际
已复制列的释放顺序、嵌套清理、提交与失败行为不变；copy_payloads=false 不会
设置任何 copied 位，去掉其 payload cleanup 不影响目标预留失败。可空与嵌套
slice 仍按原规则复制；没有把文本借用扩大成任意 payload 借用。

隔离完整编译及 IR 对照如下，均为同一 CLI 输入：

| ---------------------------- | ----------: | ----------: |

| 75 个 importer 定义合计字节  |  18,578,261 |  10,156,766 |
| importer 合计行数            |     561,156 |     327,037 |

这些是静态定义统计，不是运行次数、真实复制量或峰值收益。它与此前失败的
ResourceGroup 清理聚合不同：没有新增运行时分组或改变任何实际清理控制流。
正在以普通冷编译配对确认能否覆盖本阶段增加的构建成本。

### memo 核对的顺序边界

完整键与事实内容相同：main 12982/3439/2916/0，collections 67/45/27/27，
growth 1154/315/270/0，ordered 27/14/14/14，冻结输入 8248/2419/1945/0。

原始序列化比较在 main 的一个 demanded 记录发现三条 normalized 事实的顺序
不同。已逐条核对为相同 ExprId→Level 映射；memo.putDemanded 明确来自 HashMap
迭代，不具有序列顺序契约。验证器只对 normalized/renewed 的键值集合规范比较，
并检查键唯一；marks、贡献、计划及其他顺序字段仍严格比较。报告保留这一处
raw_order_only_differences，不把语义映射一致写成所有 memo 字节完全一致。

### 保留迁移，继续收口所有权与容量准备

资格守卫的普通三对冷编译并未单独达标：原 Native 控制 CPU 中位数 87.72 s，
候选 88.29 s；墙钟 85.92→86.48 s，RSS 4,328,308,736→4,305,240,064 B。
因此没有把较小 IR 或约 23 MB RSS 下降当作阶段验收通过。

后续保留同一复制资格，将其在 comptime 一次过滤为 copiedFields，复制、defer
和 errdefer 都按原字段顺序遍历该列表。copied 标记仅为这些字段保留；Borrowed
模式直接得到空列表，不新增运行时策略、分组清理或跳过实际复制。

实际表达式 importer 中，容量准备占 1,253 行、36,046 B、249 个块，只依赖
Target、Counts 和新增行数。将它提为按 Target 共享的 reserveCounts，Counts
传 const 指针，保留 tags→offsets→各 payload 的容量准备及 OOM 顺序。Source/View
对应的复制与提交没有混入这个 helper。调用边界的实际执行成本仍需最终计时。

所有权继续按原 Native 成本模型对齐：本模块现在直接在 Lower allocator 生成，
通过通用 appendBorrowed 发布。动态 arguments、错误名外层数组等与 Lower 同寿命，
不再先在 scratch 生成再深复制。默认 owning 与 BorrowingText 两条接口继续保留，
其他调用没有切换。平面列值仍写入 Native Rows，不能宣称整个 AST 发布零复制。

这个取舍会让 Source 临时列、旧增长块和记录存活至 Lower 结束。隔离分配代理
只包住 Source executeValue，在固定 readability-final 输入中观察到一次声明生成：
1,689 次成功申请，累计请求 460,668 B，没有释放；逻辑当前量与高水位均为
460,668 B。这个数字包含最终嵌套 payload，不全是额外临时列；也不含父 arena
页容量、对齐浪费，不能写成精确物理峰值。模块输入没有可变长度集合，各循环
上限固定，因此每次开销有界；整体峰值还取决于并发活跃 Lower 数，继续看 RSS。
探针只留在忽略目录，正式代码没有日志或计数器。

三项组合后的单次隔离 CLI 编译为 CPU 85.83 s、墙钟 84.07 s、RSS
4,288,364,544 B。这是进入最终配对的信号，不是稳定收益证明。

最终所有权版本的两阶段工具各 21/21 步成功，SHA-256 均为
e6306a1fd9924ba7ff92faa27820571116c6fb72ab6962bc0ebe833b8990a9b5。
四组完整产物再次对照，与旧工具仍只有清单路径差异，两个新阶段完全相同。

### 自我复核与剩余职责

交付范围是六声明的完整生成职责及其必要成本修正，不是全部列表实现或整个
编译器自举。35 个 Source 文件均不超过 190 行，RX 表达真实阶段依赖，ZX
保留原子构造；没有用 Native facade 执行旧 Emitter，也没有加入专用运行库。

通用 AST 数据结构与发布、参数 materialize 中转、其他 Native 编译器语义仍未
迁移；最终整体自举仍需传递依赖审计及 stage 1→2→3。两阶段工具哈希和输出
一致不能替代这一整体标准。本阶段的原型失败、memo 顺序边界、临时列驻留与
性能波动均保留，不把局部绿色结果或一次较低峰值报告为所有权问题全面解决。
