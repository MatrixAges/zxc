# 集合显式上下文参考

> 此文记录的显式 context 回调接口已撤销。当前接口使用常规索引参数与词法捕获，见[数组回调使用参考](../../2026-10-09/数组回调语法恢复/使用参考.md)。

## Intent

在集合表达式回调中显式传递所需数据，无须隐式捕获或运行时闭包。

## Data

map、filter、every、some 都支持两种形式：

```typescript
values.map(item => item + 1)
values.map((item, context) => item + context, offset)

values.filter((item, context) => item > context, threshold)
values.every((item, context) => item >= context, minimum)
values.some((item, context) => item == context, expected)
```

第二个实参提供上下文，第二个回调参数接收它。参数类型从列表元素和上下文推导；提供上下文时必须声明两个回调参数，不提供时必须声明一个。多个所需值可以放进同一个普通对象。

表达式先求值源列表，再求值上下文，各一次，然后分配结果并执行回调。空列表、回调没有读取上下文或 every/some 提前结束，都不会跳过上下文实参的求值。回调体仍必须是表达式，只能使用自身参数与允许的导入，不能隐式捕获外层值。

## Edges

- 上下文在各次回调间共享借用，列表更新遵循不可变输入规则，不取得上下文的独占消费权。
- Task 句柄不能作为这些操作的共享上下文。Task 仍遵守一次消费契约。
- map 返回上下文中的引用时，结果保留来源借用。仅用上下文计算标量，不会因此把新标量结果列表标成借用。
- map 的引用结果目前保守保留源列表与上下文两侧借用；尚未按回调实际返回的来源进一步区分。
- filter 返回源元素，不因使用上下文而永久借用上下文；every/some 返回 bool。
- reduce 仍是 `values.reduce((accumulator, item) => expression, initial)`，第二实参是初始累加器，不是共享上下文。
- 带上下文的 map 当前生成普通循环；无上下文的 SIMD 优化条件不变。

## Answer

上下文编译为普通 Zig 局部绑定，回调编译为循环体；没有动态闭包环境或专用运行库。列表与对象数据沿已有借用表示传递，不为上下文复制底层数据。

编译器自身的类型引用映射使用此能力：

```typescript
const values = in.values.splice(in.offset, in.count, [])[1]

return values.map((id, context) => integers.narrow(workspace.getMapping(context, integers.widen(id))), in.workspace)
```

结果列表按范围长度分配一次、映射一次；无需先生成全零结果再遍历填值。这不代表整个类型提取流程没有其他分配或原生过渡依赖。
