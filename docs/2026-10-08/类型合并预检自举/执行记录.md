# 类型合并预检执行记录

## Intent

来源位置索引与前缀校验以 RX/ZX 表达，撤除专用 merge_workspace 桥并保留原分配与失败顺序。

## Data

- 索引使用 u64 加一编码，零表示缺失；source.kinds.map 初始化定长数组，直接按类型 ID 检查重复并写位置。
- preflight.rx 连接 shape、来源 binding、bounds，返回可空索引；shape 失败无需任何分配。
- Result 持有临时 arena，origins 直接借用生成结果；mapping 独立分配，Pool.appendFrom 在合并结束后释放 scratch，错误时释放未交付 mapping。
- merge.rx 在 mapping 分配后验证前缀内容，再写 identity 和执行 append；prefix 不符返回 InvalidModule。
- seed 同步索引编码与 scratch 生命周期；旧校验与 identity 顺序保留。
- 删除 Workspace 数据文件、原生实现、声明及构建注册。当前 merge_writer/reference 仍为既有过渡依赖。
- 已检查定长索引生成：一次 alloc(u64, source_length)，之后复用拥有的数组原地写入；没有整列复制或扩容。

## Edges

- 不把固定宽度 ZX 索引重解释为平台 usize；消费边界显式转换经验证的索引。
- 预检 scratch 与返回 mapping 生命周期分离，不能一起释放。
- 不把本次去 Workspace 宣称为完整通用类型合并自举。
- 正常预检仍有生成器产生的参数与结果描述符分配；索引定长分配、零复制不等于整个预检零分配。
- 最终生成的 merge 入口使用栈参数连接 table、prefix 和 identity，继续通过零字节临时 arena 执行。

## Answer

首轮错误集合声明不匹配已修正。随后资源专项发现 shape/allocator 与 mapping/prefix 顺序变化，已按现有契约修正，未修改测试。最终主构建通过 36/36 步骤；类型合并、名义来源、模块产物专项通过 66/66 步骤、149/149 测试。

生成产物复核了 shape 失败直接返回 null、索引定长分配及原地更新、merge 栈参数连接。15 份草稿与正式源码逐字节一致；修改的 ZX 文件最长 32 行。

未新增测试、未运行全量测试、未使用浏览器。

## 自我批判

首版仅关注数据索引与生命周期，未预先核对已有资源失败顺序，导致验证失败。最终方案必须以真实顺序和实际生成代码验收；原生 Writer 与其数据状态仍需要后续迁移，不能因一个状态桥消失就宣布整体完成。
