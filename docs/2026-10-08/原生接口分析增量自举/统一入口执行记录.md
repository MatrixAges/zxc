# 原生统一入口执行记录

## Intent

以 native/load.rx 作为从源码到接口结果的真实编排入口，移除解析与分析之间的手写视图、Context 组装与双生成模块。

## Data

- load.rx 调 parse.rx；只有空诊断才组装 indexed Source/Context 并调用 analyze.rx。
- types、type_order、declarations、members、functions、parameters、errors 直接来自 parse 输出；源码 u8[] 来自入口借用。
- native/interface.zig 只接收 base、origins、namespace 与源码，负责单次调用及终端拥有化；不再使用 Source/Snapshot/layout 适配。
- native.zig 仅保留类型存储所有权转交和 generated/seed 静态选择；seed 旧流程移入 native/seed.zig，view.zig 删除 Indexed，仅保留旧 Native。
- 构建撤除 generated_native 及 native_abi 输出与注册；generated_native_interface 的入口改为 load.rx，输出索引前移到 66/67 + entries.len。
- 生成 execute 已检查：先调用解析，依据 diagnostic.message 分支；成功时逐字段引用输入与解析列，Source/Context 仅包装描述符，没有阶段边界数组克隆。

## Edges

- 入口契约是全新的 native 接口分析：宿主每次创建 Types，resolved/aliases/visiting 本来为空。不能将本入口直接用于携带旧缓存的任意 Types。
- 解析与分析共用临时 arena；诊断、类型增量与成员输出在 arena 销毁前拥有化。
- seed 解析失败时虽已转交类型存储，但 defer 会原样归还，阶段顺序及输出字段保持。
- 终端 TypeStorage/cache/origin 存储拥有化仍为手写 Zig；对象描述符分配仍存在。本阶段不宣称完整自举或全模块零分配。

## Answer

主构建 36/36 步骤通过；原生声明、模块产物、原生运行专项 70/70 步骤、149/149 测试通过。独立只读审查未发现借用、诊断顺序、seed 保留或生成槽错配问题。未新增测试、未执行全量测试、未使用浏览器。

## 自我批判

本次迁移的是实际阶段切换和解析结果组装；此前已迁移的解析、类型与签名算法不重复计为新成果。宿主仍需要 terminal commit 与输出生命周期管理，后续必须继续核对完整传递依赖，不能因顶层 RX 已连通就宣布完成自举。
