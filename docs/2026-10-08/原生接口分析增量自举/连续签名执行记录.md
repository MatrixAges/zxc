# 连续原生签名分析

## Intent：最终目标

将原生接口的全部函数签名语义迁入 RX/ZX，并使参数、返回值和后续函数持续使用同一解析状态及类型增量。该阶段服务于完整接口增量自举，不替代尚未完成的共享名义所有者迁移。

## Data：可用证据

正式 native.analyzeView 在声明初始化和共享身份合并之后调用 signatures.rx 生成入口。RX 创建一次 resolving.State，然后 ZX 按函数顺序完成参数、void 输入限制、tuple 构造、返回类型、引用能力及所有权检查，最后生成 ABI 名称。首次错误结束循环。没有加入原生解析专用运行时或宿主语义 getter。

导出名称已在 initialize 中全部解析，直接读取 resolved 编号。宿主在成功后只提交一次 delta/cache，并将签名和 ABI 名称转成结果所有者持有的 IR；seed 原实现隔离到 seed_signatures.zig。借用 parser 的函数、参数、语法列，通过现有 layout.borrow 校验布局后接入。

首轮签名实现通过主构建 36/36 步，以及原生声明、别名、引用、名义来源、语义缓存专项 58/58 步、70/70 Zig 测试和 10/10 Node 集成测试。此证据早于后续 genz 修复，不能代替最终验证。

### 生成代码揭示的缺口

首轮生成结果中，parameters 内部已复用容量，但每个函数的 parameters 批次、返回值解析和 tuple 构造仍重新建立容量。functions 循环仅保持 signatures 容量，没有保留 resolution 各列。每参数还存在 State 等中间记录分配。

临时容量分析诊断显示：parameters 有 36 条可追踪且唯一的路径，其中 25 条被 duplicate 拒绝。对 delta.children（u32[]），fail 的输入被误计为 26 个别名，包含不可能持有 u32[] 的 string[]、u8[] 和语法对象列。诊断筛选只用于调查，必须从正式源码移除。

### 通用分析修复

may 分析先排除类型结构中不可能容纳目标列表的路径，复用现有 containsDescendant；optional、嵌套列表、对象与元组中真实存在目标列表时继续分析。精确输出 lane 匹配且输出与 origin 为同一种 list TypeId 时，使用其 backing 来源证明，避免回退将其他列误算为同一来源。lane 的来源证明与 audit 是否允许原位更新分开：不因后者拒绝而丢弃已证实的类型与来源事实。

参数循环返回的新 types 列仍会被旧的整状态独立性证明误判：状态中的 resolution 含 origin，不代表 types 也含 origin。independent.projection 以 (iteration, path, origin) 为归纳单位，分别检查该投影的初值和循环体；兄弟路径不能借用彼此的假设。只有没有外层临时假设的成功证明才进入缓存。已选择循环的快捷分析也仅作用于匹配的路径，不将单列证明扩展为整个状态证明。

修复后的调查产物已显示 parameters/functions 的 25 条可用路径通过，其中包括类型 delta 的全部八列。最终产物的真实调用链已核实如下；最终专项结果另行记录。

### 最终生成路径核对

指定产物为 `.zig-cache/o/02213e2fda60c562079ec2fb0ca829db/native_signatures.zig`，mtime 1791408620.8305542，哈希与行号见连续签名生成证据.json。

真实 execute 调用 function_65_value，循环外持有 delta 的八个 owner。参数 function_64_buffered、tuple 输入 function_44_buffered、输出节点 function_63_buffered 传递同一组 buffer/started 地址。tuple 继续经过 43/42/37_buffered，重映射到 delta 专用 lane。底层第一次 appendSlice 接收初始空 delta，之后持续追加；旧的 null-lane 完整复制分支在此调用链不可达。

八列均在全部函数循环结束后才 toOwnedSlice；不再逐函数重新复制已累积列。参数类型列表是每个函数的新阶段结果，不属于复制旧 delta。

同时保留边界：每参数的 State82、每节点的 Name60/Reference61/FrameInput85/Frame80、tuple 候选等仍有中间记录分配；最终逐列收口仍重建部分外层记录。结果列表增长和 toOwnedSlice 也不能表述为整个函数零分配或任何情况下零字节搬迁。

## Edges：边界与限制

- 语言 IR 禁止递归类型，类型关系来自已校验的 IR；新分析不是基于函数名、用例名或常量输入特判。
- 类型后代辅助目前针对同步普通容器；现有 audit 仍拒绝 task、await、capture、parallel 等能力，不据此扩大异步优化权限。
- 不跳过 stale-version、重复来源、旧值读取或容器逃逸检查。
- 即使容量传递接通，中间 State/Frame 等记录的分配也需另行处理，不能声称整个签名分析零分配。
- native 初始化前复制 existing 类型列、shared_types 合并 origins 和原始前缀的复制仍存在。Project、缓存恢复和编译库的完整单表所有权交接尚未迁移。
- 最终 ABI 名称必须在 parser scratch 释放后继续有效，因此宿主负责一次拥有化。
