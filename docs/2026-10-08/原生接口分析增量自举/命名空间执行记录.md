# 原生命名空间规则迁移执行记录

## Intent

在正式生成路径中由 ZX 执行命名空间规则，由 RX 表达通过后才分析签名的顺序与失败短路。

## Data

- `native/interface.rx` 显式连接签名初始状态、命名空间检查与函数签名集合分析。
- `native/interface/namespace.zx` 只负责 namespace 布尔谓词，不依赖类型解析 State；遍历在首个无效段停止，UTF-8 算法复用 lexer 的原子校验函数。
- 适配器对原始字节列使用布局校验后的借用，没有编码转换或输入副本。
- 原 host 规则仅在 seed 编译路径保留；生成模块和构建字段已按 interface 重命名。
- seed 签名依赖的结构类型导入随适配器同步更名，首次构建发现漏改后已修正。

## Edges

- namespace 空列表合法；单段空、NUL、非法 UTF-8 返回既有 module 诊断与零位置。
- 类型声明初始化仍发生在 namespace 校验之前，维持诊断优先级。
- 导出哈希查找、IR 描述符构造、宿主状态适配仍未迁完，本阶段不能作为原生接口完整自举验收。
- 现有 UTF-8 校验实现有完整逐字节遍历；它没有输入复制，但不会在首个非法字节立即退出。
- 没有新增测试用例，没有全量回归和浏览器检查。

## Answer

- 八份生产源码草稿位于 `命名空间草稿/`，相对路径与 compiler 包一致；旧 signatures.rx 与 signatures.zig 对应迁移为 interface 名称。
- 最终布尔谓词版原生声明专项：`zig build test-native-declarations -j2 --summary all`，30/30 步、17/17 测试通过。
- 最终布尔谓词版主构建：`zig build -j2 --summary all`，36/36 步通过。
- 生成产物入口已复核：直接调用 `function_5(allocator, in.namespace)` 取得 bool，namespace 列借用；RX 校验失败分支不会进入 functions 调用。
- 新 ZX 文件 19 行，八份草稿逐字节一致，diff 空白检查通过。

## 自我批判

这次迁移改善了规则实现归属和 RX 短路的可见性，但仍保留宿主类型初始化与数据拥有化。必须继续追踪其传递依赖，不能依据一次生成入口更名判断整个模块自举完成。原生导出迁移也不能以线性扫描代替现有哈希表；那会在大型接口中造成算法复杂度退化。

谓词版删去 namespace 对类型解析 State 的依赖和状态包装，RX 在失败分支静态组装原诊断。这进一步按职责减少了状态传递。
