# 原生解析与校验编排执行记录

## Intent

由普通 RX 模块表达原生语法解析、错误短路和声明规则校验，撤除相应宿主调度与独立校验生成模块。

## Data

- native/parse.rx 调用 frontend/parser/native，只有语法诊断为空才调用 native/validate；合并输出复用原解析列。
- native.zig 只调用统一 generated_native 并处理诊断，再进入现有类型初始化边界。
- 删除 native/validate.zig 与 native_validation 构建字段、生成输出、模块注册；相关静态依赖由统一模块接收。
- 首轮合并触发 NativeRequiresBundle。合并模块现采用已有源码加共享 ABI 构建契约，并从独立源码 entries 移到 bundle 生成区，配套调整输出顺序和索引，没有保留双份生成。

## Edges

- 语法错误优先；失败不得被后续校验的空诊断覆盖。
- 声明、函数、参数、错误及类型列只在 RX 中引用组装，源码保持借用，解析与校验同属一个 scratch 生命周期。
- 诊断由宿主统一复制到结果生命周期；seed 不变。
- 类型初始化、共享 nominal 合并及后续 IR 拥有化仍有宿主协调，不能以本次桥删除数量判定完整自举。
- 不新增测试用例、不执行全量测试、不调用浏览器。

## Answer

五份代码草稿位于解析编排草稿，计划含 IDEA 与架构、数据流图。删除的适配器由本提交历史保留。

- 主构建：通过，36/36 构建步骤。
- 原生声明与模块产物专项：通过，41/41 构建步骤、44/44 测试。
- native_validation 与 native/validate.zig 的生产引用搜索为零，diff 空白检查通过。
- 生成 execute 入口已核对：只在语法诊断为空时调用规则校验；返回对象直接引用原 types/type_order/声明/函数/参数/错误列，没有在阶段边界克隆数组。现有生成器仍有元数据对象包装分配，本阶段不宣称全模块零分配。

## 自我批判

真实迁移的内容是解析与规则校验之间的顺序、错误分支和结果汇合。规则本身此前已为 RX/ZX，本次不能将它们重新计为新迁移算法。共享 ABI 是既有静态构建契约，不是运行库；仍要核对生成结果的列借用与错误顺序，避免用入口合并掩盖复制或诊断优先级变化。
