# 名义增量接入执行记录

## Intent

原生声明初始化、共享名义身份规范化、导出与签名分析由 RX 显式连接，并通过同一 resolution State 传递类型增量与声明缓存。

## Data

- declarations.rx 连接初始化状态、声明名规则、完整声明解析。
- prepare.rx 连接诊断短路、shared 分支及 normalize.rx。
- normalize.rx 连接增量规范化、冲突短路、cache 与 result ID 重映射；七个 ZX 文件承担行比较、身份查找、引用映射、行追加及集合遍历。
- analyze.rx 在准备成功后进入 interface.rx；导出从 State.cache 读取，签名从同一 State.delta 继续构造。
- native.zig 只在 seed 路径调用宿主 resolution.initialize。生成路径不再调用 shared_types.resolve、Pool.compact、merge_writer 或 origin_writer。
- 当前生成 native_interface.zig 的全部 imports 为 std、integers、zxc_standard、zxc_abi，没有编译器专用合并或来源 Writer。
- native/commit.zig 预留来源容量并准备当前接口来源字符串，再提交类型/cache，最后无失败追加来源；来源字符串在同一接口的新增名义条目之间共享。

## Edges

- 规范化输入限于编译器产生的有效拓扑增量；外部类型表验证职责不变。
- 旧表与旧来源表借用，旧 TypeId 不变；mapping 只覆盖新增类型。
- 相同名义身份仍比较完整内容；不同来源不按结构合并。
- 初始化成功后 frames/active/scratch 已收束；签名只增加结构类型，不产生未登记的匿名名义类型。
- 所有语义诊断在提交前返回。拥有化期间 OOM 仍会消耗部分 arena 分配，不能称为分配事务。
- TypeStorage、宿主 cache 与 origin storage 的拥有化仍为手写 Zig；本次不宣称完整自举。
- 生成器仍分配部分对象描述符；不能用列借用推断整个模块零分配。

## 自我批判

主要成果是撤除原生路径中初始化与共享名义合并的宿主阶段协调，且没有用新 Writer 替代旧 Writer。新增的增量规范化算法也需要接受现有真实模块与名义冲突专项验证；仅生成入口成功不能证明行为保持。终端拥有化仍是清晰的过渡边界，应继续迁移，不能因专用桥引用消失就宣布最终完成。
