# Project 类型存储统一所有权

## Intent：最终目标

在 Project 的整个模块分析期间复用同一套可增长类型列，消除 source、native、external、compiled 与缓存恢复接入时对已有前缀的完整复制，并确保类型列扩容后不消费失效视图。

## Data：实现依据与改动

### 存储交接

Project.types 由只读 TypeTable 改为 TypeStorage。源码分析将 storage 元数据交给 Analyzer 并清空原位置，defer 在成功或失败时归还；Analyzer 完成时发布 view，保留容量。契约子分析同样逐条交接，不再为每条契约复制已有表。

原生接口和外部签名接受明确的 TypeStorage 指针，在局部 Types 中完成分析并归还。native artifact 在自己的 arena 上建立空 owner，仍与 Project 生命周期独立。

compiled.load 的只读入口保留；它拥有化外部类型和名称后复用 loadInto。Project 直接调用 loadInto，交接类型与 nominal origins 两套存储，避免复制已拥有的前缀。compiled_units 只缓存 exports，Store initializer 仍在第一次加载时追加。

### 缓存恢复

source 与 native 恢复先记住原类型行数和 origin 行数，再转交存储。Pool 追加缓存类型后继续验证函数和完整 IR。出错先 retainPrefix 回到原长度，再归还当前存储；外层可以重新分析或重新构建 native artifact。已有前缀只查找复用，不会被合并过程改写。

八个类型列与五个 origin 列的 append 均先准备所有容量，再修改使用长度。因此分配失败可能改变 backing pointer 和 capacity，但不会留下结构不完整的已用前缀；回退保留当前有效容量。

### 视图与生命周期

Unit 保存 Program 时清空 types；再次读取已完成模块时从当前 owner 取得 view。依赖导入只消费稳定类型编号和导出数据，最终对外 Program 绑定整个 Project 当前类型表。函数表快照保持原契约。

type_table.storage 从新分配且明确拥有的列构造 ArrayList，保留名称字符串深拥有化；不从任意 const slice 猜测容量。standalone 分析直接接管该 storage，消除原来 copy 后又 appendDelta 的第二次整列复制。

## Edges：边界与限制

- 公共只读 Context、compiled.load 输入以及 cache artifact 与结果之间有独立生命周期，仍保留所需拥有化。动态列扩容仍可能搬移已用元素；本次消除的是模块之间无必要的整前缀复制，不能声称所有分配和 memcpy 已消失。
- 缓存回退撤销逻辑追加，不立即回收 arena 中新分配的字符串、映射和节点；这些内存在本次分析 arena 释放时回收。
- loadInto 对编译库加载不提供事务回滚：错误时交回 owner，但可能包含部分追加。当前 Project 在此错误上终止整次分析，不捕获后继续使用。
- source/native/external 也在错误后终止本次分析；它们的 defer 保证所有权交回，不承诺恢复到错误前内容。
- 本次 Zig 宿主改动仍属于自举迁移的过渡实现。完整 RX/ZX 状态模型、正式入口传递依赖及阶段自编译尚未因此完成。

## Answer：交付、验证与自我批判

生产改动覆盖十三个文件，配套草稿与正式源码逐字节一致。本次涉及入口的 appendDelta 调用由八处降为零；这项源码检查只证明这些明确入口不再重复接入整表，不替代生命周期验证。未新增测试用例、未运行全量测试。

- 主构建：36/36 步通过。
- 原生 ABI 执行专项：44/44 步、78/78 测试通过，覆盖 original、linked、cached 三条生成执行路径。
- 原生声明、模块 artifact、语义缓存、名义来源、库联结及契约六项专项：76/76 步、111/111 测试通过。

自审没有把 Arena 的释放策略当成视图稳定性保证，也没有用强制类型转换恢复所有权。只读复核检查了模块缓存、公开 compiled.load 调用者、Analyzer.run/runView 的调用面、生成与 seed 两条合并路径及错误处理顺序。

关键风险是把“归还存储”和“事务回滚”混为一谈；实现仅在需要缓存失配后继续分析的两处恢复入口撤销尾段，其余失败路径继续终止整次分析。这个边界必须随未来调用者一起维护。
