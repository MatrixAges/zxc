# 原生成员描述符执行记录

## Intent

把声明与签名的配对、参数展开判定、错误集合提取迁入 ZX，由 RX 显式控制签名成功后生成成员；减少同一模块的共享前缀字节复制。

## Data

- interface.rx 在 functions 诊断为空的分支调用 members，失败返回空成员，避免部分签名与全部函数按索引错配。
- interface/members.zx 根据 Function.count 判定 expand_tuple，转发声明的注入、fallible 和 concurrent 标志，并连接签名。
- interface/member_errors.zx 按错误 Span 顺序提取名称列表；members.zx 根据 errors_present 选择 null 或调用提取，保留显式空列表。
- native/members.zig 负责 IR 表示拥有化。同一 owner 只复制一次 entry.path 和 namespace 字节，各函数路径保存共享前缀指针和自身名称。
- generated adapter 在 scratch 释放前拥有化名称、错误和 ABI 类型名；seed 已拥有的 NativeType 直接传给 owner，避免重复复制 ABI 名称。
- 正式生成路径不再回到 view.functionAt 决定函数描述符；对应旧规则仅在 seed 分支保留。

## Edges

- 单个 tuple 参数不能因类型是 tuple 就展开，规则仍为声明参数数目大于一。
- 错误集合 null 与空列表不合并。
- 路径段列表仍按成员分配，字节前缀与 file_name 在结果 arena 共享；结果统一释放 arena，不逐函数释放共享字符串。
- IR 结构拥有化及路径表示组装仍为过渡宿主代码；类型初始化与整体原生分析宿主协调尚未迁完，不宣称完整自举。
- 不新增测试用例，不执行全量回归，不调用浏览器。

## 自我批判

首版生成代码中，成员列表和错误名循环出现逐次追加复制。尝试将只读输入放入闭包时，编译器明确拒绝外部捕获，已恢复显式循环输入。根因是普通对象列表投影复用了只接受基础元素的内联布局门禁，genz 现将两条能力边界分开：保持原内联资格，普通直接列表投影走现有 consume 与容量缓冲区检查，保留对象指针身份。最新生成代码已确认两处列表均使用 ArrayList 容量缓冲区，正常增长之外不再逐次复制完整前缀。

首版功能检查为主构建 36/36、三组专项 64/64 步与 122/122 测试，但不能代替修正后的检查。新增复用 test-loop-call-origins，关注共享别名、调用结果身份和原生循环效应。共享前缀也只覆盖本次原生接口结果，不自动证明后续序列化、缓存还原和链接的所有路径都实现零复制。

独立只读审查未发现普通对象列表 consume 的身份、借用或原生调用效应阻断问题；建议保留原结果 ExprId 的 cache 门禁，已补回。原门禁并非完整投影链缓存检查，不扩大其含义。候选检查继续阻止普通对象列表误入 inline element 结果转换。
