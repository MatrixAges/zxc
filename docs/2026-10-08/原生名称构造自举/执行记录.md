# 原生名称构造自举执行记录

## Intent：最终目标

完成原生输入名称列构造的 RX/ZX 自举，保持既有名称、字段顺序及数组可寻址约束。

## Data：实现证据

- `native_names.rx` 编排初始化与遍历。`native_names/` 内七个 ZX 文件负责输入状态、参数栈、前序遍历、别名继承、集合约束、子项展开和字段排序。
- 正式 `native_types.zig` 只借用 Source/参数表、调用生成入口、映射诊断并在输出 owner 中保存名称字节。原算法移至 `seed_native_types.zig`，仅引导编译使用。
- 复用现有语义 Source 模型、AST 访问器和字段字节比较函数。没有新增原生语义 getter 或 AST 投影树。
- 原生装载沿现有两处调用边界传递结果 arena；缓存产物仍由自身 arena 持有结果。
- 编译时布局证明增加可选类型递归检查；分支配额仅容纳嵌套 Source 的证明规模，没有跳过字段、大小、对齐或指针形状检查。
- 实际生成文件及哈希见 [生成证据](生成证据.json)。入口向 step、children 传递非空容量通道，名称和工作栈按容量追加；全文中的普通调用后备复制分支不能用于推断入口每步都复制。

## Edges：自我审查与限制

别名栈保留最外名称；零/多参数保留空根；对象字段使用堆排序后逆序入栈，前序输出维持字节升序；元组保持声明顺序。集合元素可寻址检查从旧递归后的阶段移至展开前，诊断种类与消息保持一致，内部部分结果不会发布。

AST、源码和参数全列只借用。名称字符串借用源码时，输出前必须复制其字节到结果 arena；名称整列直接转交，不另作整列复制。没有据此宣称全链路零复制或零分配。

旧错误尝试曾遇到标准库模块重复注册、ABI const 指针形状及编译期证明配额不足；当前实现复用现有标准模块、显式声明 const 借用并提高证明配额。修复没有放宽布局证明。

这只完成名称构造职责。原生声明语义校验、模块加载总编排、导出与成员组装仍有手写 Zig。seed 仍是构建引导依赖，不能据此宣称整个编译器完全自举。
