# 压缩分配错误修复复核

## Intent：最终目标

优先处理测试会话反馈的压缩输出扩容失败问题，确认内存耗尽正确传播为 OutOfMemory，并明确 CLI 字节列表的现有 JSON 传输约定。此项验收完成后继续其他功能。

## Data：可用证据

- 当前 compress.zig 的 stored.write、flate.Compress.init、compressor.writer.writeAll、compressor.finish 已有四处最小映射；不重复覆盖同一修复。
- Zig 0.16 flate/Compress.zig 文件头明确 WriteFailed 来自 backing writer；此处 backing writer 固定为 std.Io.Writer.Allocating。stored.write 同样只向该内存 writer 写入。
- 原始失败与修复后测试见《压缩接口独立对照与资源测试》。当前具名压缩资源测试直接使用 testing allocator 和 checkAllAllocationFailures，成功路径释放结果；6000 字节固定种子伪随机输入覆盖扩容，未用 arena 掩盖释放问题。
- CLI runner 使用 std.json.Stringify 默认选项；Zig Stringify.zig 对 u8 slice 检查 UTF-8，再决定输出字符串或整数数组。

## Edges：边界与限制

- 错误映射仅因固定内存 writer 成立；将来换文件、网络或可插拔 writer 时必须保留其实际错误，不能沿用统一 OutOfMemory。
- 参数级别校验仍在任何分配之前，保持 InvalidCompressionLevel；显式 allocator 分配与 toOwnedSlice 原样传播分配失败。
- 不调整压缩算法，不修改测试输入或预期规避失败，不新增测试用例。
- 本次只文档化既有 JSON 约定；统一数值数组输出需要区分 ZX string 与 u8[] 的类型驱动序列化，不能直接开启全局 emit_strings_as_arrays 影响字符串输出。

## Answer：交付与成功标准

保留现有四处正确修复，补充 compiler README 的输出约定，复跑标准库资源及应用构建互操作。未通过前不把历史日志当成本轮结果。

```mermaid
flowchart LR
  Input[字节输入] --> Compress[压缩与 stored 写入]
  Compress --> Writer[固定内存 Allocating writer]
  Writer --> Failure[分配失败产生 WriteFailed]
  Failure --> Map[压缩接口映射为 OutOfMemory]
  Map --> Cleanup[defer 释放已有输出与窗口]
```

## 自我复核

当前四处改动依据错误来源成立，无需扩大生产补丁。压缩算法正确性由独立解码证据支持，分配失败由逐分配注入支持，两种证据不能互相替代。CLI JSON 形状随字节内容变化是现存宿主契约，不代表压缩数据发生变化。
