# 查询字符串标准库实施

## Intent：最终目标

实现 std:querystring 的解析、格式化和百分号编码能力。结果使用有序 Entry 列表，保留重复键，全部基于 Zig 纯计算，不依赖 JavaScript 或 zxc runtime。

## Data：可用证据

参考 https://nodejs.org/api/querystring.html 的 parse、stringify、escape、unescape。Node 默认使用 & 和 =，支持重复键、可配置分隔符及解析数量上限；解码对格式不完整的百分号序列采取宽容处理。ZX 已有共享原生声明类型与列表返回能力。

## Edges：边界与限制

ZX 不复制 JavaScript 动态对象及隐式类型转换，用字符串键值列表表达同等查询数据。默认解析上限为 1000 个分隔项，0 表示不限制；自定义入口显式接收参数。百分号解码保留无效转义的字面内容，非法 UTF-8 字节以替换字符表示。自定义 JavaScript 编解码回调不引入 ZX 接口。此模块不等于完整 URL 解析器。

## Answer：实施与成功标准

交付 escape/unescape、parse/parseWith、stringify/stringifyWith 的声明、实现和正式导入路径。解析维护原顺序，格式化按列表顺序输出；只读结果不授予消费权限。新结果分配失败须释放已完成部分。执行实际 ZX 应用并与 Node 查询字符串功能交叉核对，不新增 tests 用例。

```mermaid
flowchart LR
  Query[查询字符串] --> Split[分隔与数量限制]
  Split --> Decode[百分号与 UTF8 解码]
  Decode --> Entries[有序重复键值列表]
  Entries --> Encode[百分号编码]
  Encode --> Output[查询字符串]
```

## 自我复核

Entry 列表与 JavaScript 对象的形状不同，必须明确而不能宣称直接 API 兼容。特别检查空分隔项、重复键、加号、截断编码和错误清理，不能只验证正常英文输入。

## 实施与实际验证

接口和正式清单已接入，Zig 实现按百分号编解码、无效 UTF-8 替换、解析、格式化分别组织。解析失败会释放此前创建的 Entry 及其字符串；每次迭代的未发布结果也有独立错误清理。

仓库 zig build 通过。真实 ZX 示例在“查询字符串示例/main.zx”，已构建执行并与本机 Node querystring 比较：覆盖重复键、空键值、无等号项、连续分隔符、多字符分隔符、加号、中文、非法百分号、非法或截断 UTF-8。比较解析时将 Entry 列表按键归组；格式化仍保留列表顺序，不能假称 JavaScript 对象枚举顺序完全相同。

另外实际核对了 1100 个分隔项：显式 max_keys=0 返回 1100 项，默认入口返回 1000 项。没有新增 tests 文件。新模块逐分配失败遍历尚未补充，因此资源清理目前有实现审阅证据，不能借既有标准库资源测试宣称已经覆盖本模块全部失败路径。
