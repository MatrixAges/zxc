# 标准库功能对齐清单

## Intent：最终目标

以 Zig 原生能力实现与 Node.js 功能对应的 ZX 标准库，使用 std: 导入。保留 ZX 静态类型、显式副作用与 RX 调度模型，不以 JavaScript 引擎作为实现依赖。用户已授权由实现者自行完成具体取舍，无需逐项请求确认。

## Data：可用证据

- Node.js 官方功能索引：https://nodejs.org/api/index.html （本轮读取版本 26.10.0）。
- 路径语义：https://nodejs.org/api/path.html 。
- 原生扩展参考：https://nodejs.org/api/addons.html 。
- 本地 Zig 为 0.16.0，标准库具有 Io、fs、process、http、crypto、compress、Uri、unicode、json、base64 和 dynamic_library 等实现。
- ZX 已有标量、对象、列表、元组、枚举、模块成员接口注册和共享原生类型；资源类型与受控 effect 宿主联结仍未接通。

## Edges：边界与限制

对齐功能不等于复制 JavaScript API。事件循环、Promise、Buffer 可变别名与 V8 内部结构不能直接搬入 ZX；需要提供对应功能并明确类型、所有权和执行语义。不得将“Zig 存在某个模块”记为“ZX 已实现”。

## Answer：覆盖清单与验收

以下为完整实施目标，不代表各组已经完整交付。逐项完成须有标准库类型接口、底层实现、正式导入路径、诊断和真实调用证据。

| 功能组         | 对应 Node.js 能力                                        | Zig 基础与 zxc 适配职责                                       |
| -------------- | -------------------------------------------------------- | ------------------------------------------------------------- |
| 路径           | path、POSIX/Windows 路径、解析与格式化                   | fs.path；明确平台行为，保持纯计算                             |

| 数据表示       | JSON、检查与格式化工具                                   | json、fmt；静态目标类型与明确解析错误                         |
| 密码与压缩     | crypto、Web Crypto 的密码操作、zlib                      | crypto、compress；随机数属于 effect，哈希为纯计算             |
| 文件系统       | fs、目录、文件流、元数据、变更观察                       | Io.Dir/File 与平台观察适配；句柄由宿主持有                    |
| 系统与进程     | os、process、环境、child_process                         | process、Io、操作系统接口；显式权限与退出生命周期             |

V8 引擎内部 API、废弃 domain、旧 CommonJS 包装器等引擎专属机制不照搬。涉及通用能力时提供 ZX 的对应方式；涉及 JavaScript 引擎本身时记录不适用原因，不能用空实现凑覆盖率。

### 实施顺序与自我复核

已接通的部分：std:encoding 的 UTF-8/Base64/十六进制编码与解码，std:crypto 的 SHA-256/SHA-512；路径的 std:path、std:path/posix、std:path/win32 各有 isAbsolute、basename、dirname、extname、parse、format、normalize、join、resolve、relative。路径 resolve/relative 使用显式 cwd，Windows Unicode 比较等差异见《路径标准库实施》。这些成员不等于对应功能组的完整实现。

先接通模块命名空间、函数签名注册和纯计算功能；随后通过生成代码和显式宿主接口承接文件、进程、网络及流；不引入 zxc 专用 runtime，不恢复动态插件或懒加载。

自我批判：这份清单覆盖面很大，不能以先做几个纯函数为整体成功标准。不同平台的网络、动态库和终端能力必须分别核验，单机 macOS 构建不能证明跨平台完成。

### 最新核对

标准库清单当前包含 encoding、crypto、path、querystring、zlib 五个功能族。querystring 已接通有序重复键解析、格式化、百分号编解码及参数配置；完整 URL、数据表示、文件与网络等条目不能记为完成。crypto 已增加 HMAC、密钥派生与认证加解密，UTF-8 转换现为验证后的只读视图。查询字符串参考 [Node.js 官方文档](https://nodejs.org/api/querystring.html)，采用 ZX 静态 Entry 列表，差异与验证见《查询字符串标准库实施》。

`std:zlib` 提供 gzip、zlib、raw DEFLATE 的内存压缩与有界解压，并通过三个 With 接口控制默认和 0–9 压缩级别，完成真实 ZX 应用与 Node.js 双向互操作。校验、连续 gzip、级别与边界结果见《压缩标准库实施》。压缩组的流式接口、Brotli、Zstd、字典及其余参数控制仍未完成，不能将该组整体标记为完成。
