# 库构建配置生成自举

## Intent：最终目标

将已发布统一库build.zig生成的完整职责迁到RX/ZX：模块注册、依赖及别名解析、
C翻译/ABI view/include与链接参数、最终函数声明；仍由结构化AST统一printer输出。

## Data：可用证据

正式CLI library/publish→library_config→genz.host.library.render，现无Source分支。
原root+modules约165行：先native注册/立即配置，再generated注册，再generated依赖、
native依赖，最后public及链接选项。名称后写覆盖，native别名仅分割首个等号。
Source Context/Fields/Declarations和bytes.Index、std:path已覆盖所需通用能力。

## Edges：边界与限制

不生成Zig源码模板或RawCode；不提前验证依赖改变错误顺序。仅Native拆借Options、
AST接入及printer保留为过渡，seed保留旧实现。借用行布局需静态校验，保持对外
library.json字段序列化协议。先保持算法/顺序，再按生成体及测量优化表示。

固定完整基线129.74秒/216.03 CPU秒/2075033600 B单体/2247294976 B树峰不重置；
上阶段130.16秒/198.62 CPU秒，仍有0.42秒完整时间缺口。未新增持久测试。

## Answer：交付与成功标准

```mermaid
flowchart LR
    Init[初始化AST及名字表] --> Prelude[目标优化及ABI]
    Prelude --> Native[native注册与配置]
    Native --> Generated[generated注册]
    Generated --> GD[generated依赖]
    GD --> ND[native别名依赖]
    ND --> Public[公开模块及链接]
    Public --> Finish[build声明与发布AST]
```

```mermaid
flowchart LR
    Input[借用Options行] --> Source[Source AST列及名字索引]
    Source --> Status[有序错误状态]
    Source --> Native[薄AST适配]
    Status --> Native
    Native --> Printer[统一printer]
    Printer --> Output[调用方拥有build.zig文本]
```

成功要求原配置组合与错误顺序一致、生成文本全量对照、真实发布后zig build消费
通过、受影响路径及累计性能记录，完整实现后提交推送所有变更并确认工作区干净。

## 实现与验收记录

正式入口新增 `library_build`，由 RX 明确连接初始化、构建目标选项、原生模块、
生成模块、两类依赖绑定、公开模块、最终声明和 AST 发布。ZX 只处理各阶段的
集合算法或 AST 构造；原有 `root_seed.zig` 只在 seed 分支使用。

宿主保留公开 Options/Module/Native 类型及 JSON 序列化顺序，转换为 Source 行时
仅复制字段描述符并创建指针表，不复制路径、依赖或 include 内容。Source 执行和
AST 借用共用 builder arena，直到统一 printer 完成后一起释放。此适配器、底层 AST
存储和 printer 的原生实现仍是过渡依赖，本阶段不代表整个编译器完成自举。

新增源码已通过格式和 lint；首轮 bootstrap-stage 通过。后续自编译、正式 CLI、
文本对照、现有发布回归和性能验收仍待完成，不将前端通过当作功能交付。

### 分配证据及优化

262 组累计申请：旧 seed 25,342,538 B/1042 次；初版 Source 68,411,166 B/1388 次。
这里是累计 allocator 申请，不是进程峰值，也不能当作底层数组复制量。

检查生成依赖闭包发现 74 个模块中没有 `zxRenew` 调用，有 58 个对象 box 构造点；
增长包含不可变中间状态的列描述符分配。没有证据可把它等同于底层字符串复制。

移除 Source AST→Native AST存储→printer 输入的往返：新增通用的 printer 列适配，
借用已生成列、用空列补齐未使用的语法形式，直接调用同一统一 Source printer。
库调用的 workspace 生命周期仍覆盖输出打印；只将最终文本复制给调用方 allocator。

同一 262 组：Source 累计降至 63,937,540 B，减少 4,473,626 B（约 6.54%），
与 seed 摘要一致。仍高于 seed，不能宣称实现了分配等价；后续成本分析继续保留此项。

初版完整冷构建 `/usr/bin/time`：133.60 实际秒/199.65 CPU秒/2,129,510,400 B 单体
峰值；进程树采样峰值 2,149,253,120 B。相对固定基线仍有实际时间缺口。采样中
宿主 LLVM编译32.16秒，对比上阶段32.00秒；生成器启动前已增加约2.65秒。
这只能定位时间分布，不能单凭一次采样宣称全是环境噪声。

### 精确触发入口与第一版通用修正

二分缩小 350 个其他入口，最终只保留 `store_state` 就能使库 Context 的 managed
表示消失。其 `Parts = [Storage, Lifecycle, Regions, Request]` 包含多个同型 Context；
`state/traverse` 原规则把重复的子类型及其传递字段全部标为 boxed，影响同一生成
单元内所有无关用途，而非仅保护这个返回值的别名。

第一版通用修正（仍在验收）：重复子类型时保守地冻结返回容器，容器内部继续使用
canonical 只读引用，但不再将被重复引用的子类型全局降级。可选/列表外层先定位
实际聚合容器；不同输出根单独检查，用 checked 集合去重，不能复用“子类型先前已
出现”来假定其根检查完成。Source 分析与 Native seed 同步修改。

新工具 21/21 自举构建通过；由它重新生成完整 351 入口后，临时 renderer 得到：

|      0 |                         41,289 |
|      1 |                         41,477 |
|     16 |                        215,576 |
|    128 |                      2,128,120 |
|    512 |                     19,656,952 |

512 模块从484,603,590 B降至19,656,952 B（约95.94%），文本摘要仍与seed完全相同。
这仍高于 seed 8,733,186 B，且128→512增长约9.24倍，尚不能视为线性或验收完成。

进一步比较新主单元与单独生成的类型表示，Context、Ast、Fields、State 的 managed
表示已一致；隔离单元仍 managed、主单元却 boxed 的剩余类型是语句 header：
`{ offsets: u32[], tags: StatementsKind[] }`。下一步查清这个局部表的降级来源，

### 第二版尝试失败及回收

进一步尝试将列表元素、任务、Native 等边界的 boxed 标记也仅保留在直接容器，
不再递归到其字段。该工具自身21/21编译通过，但执行正式CLI生成任务时5个分组
发生 BUS/SEGV，构建22/33（5失败）。这是功能错误，不是可接受的性能差异。

同时发现两处 Native ABI 适配直接依赖 executeValue 的私有参数表示；尝试转为公开
Input + columns.invoke 后能编译，但不能解决上述运行崩溃。不能把“编译通过”作为
这种所有权布局变化的验收依据。

已将这两版分析优化及仅服务于尝试的ABI适配恢复至HEAD，删除新增root_boxes与
aggregate_root辅助文件；保留库RX/ZX迁移及直接printer列借用。失败只撤回优化试验，
没有撤回自举实现。之前第一版19.7MB结果也不构成正确性证明，不能用于交付。

后续路线：保留 canonical 容器的别名保护，检查跨引用边界时借用/所有权元数据如何
丢失及其作用域；不能通过全局解除子类型保护获得性能。对任何新的表示优化，先用
现有重复别名、混合字段、借用和快照回归验证，再扩大到工具执行与规模成本。

当前库迁移仍有512模块484,603,590 B累计申请的未消除回归；阶段仍在进行，尚未提交。

回收后使用最后已验证的 `final/bin/zxc-bootstrap` 对单入口重新生成成功：1入口、
81模块、74函数文件。LLDB诊断停在启动握手、目标进程处于停止态，未取得调用栈；
已清理该诊断的调试器和子进程，不据此编造崩溃位置。没有正在运行的构建等待续接。
所有权试验失败的精确崩溃原因仍未证实；不能仅由BUS/SEGV反推是哪条别名约束被破坏。

### 消除函数体表的反复复制

进一步对照相同源函数产物：完整入口的 statements/binding 将各输入列从 boxed
对象重建为 plain，再调用 reserve(false)；单独入口保留 managed 描述符。原因是
旧接口中内部 Context 与其语句表经常作为多个结果并列返回，重复类型保护在整个
生成单元生效。只修 header 溢出分支不能恢复此前已丢失的容量信息。

本阶段不展开重构全部旧接口，也不改变所有权规则。库生成复用现成的
ast/statements/builder，分别构建表达式 Context 和函数体；在函数声明生成时关闭
函数体，再发布只读打印列。这与原生实现中独立构建语句列表、最终形成函数声明的
成本模型一致；不新增专用语义桥、数据结构或语言特性。

### 后端成本定位：公开版本重复生成函数体

本轮从文件增长排序定位到 `genz/analysis/store/request/build.rx`：对应生成文件
293570 B，其中canonical `call`约289KB，`callValue`不足5KB。canonical版本重新
lower整段RX流程，在每次调用前后重复展开Context及各列的表示转换。内部实现并未
同幅度膨胀，不能仅归因于Context字段数量或笼统的LLVM慢。

为已有Value版本的无Task/IO/Process/Store/契约、且原本允许OOM的函数生成薄ABI
适配：复用现有pointerInvocation转换和调用规则，入口转换一次，执行callValue，
出口恢复公开表示。适用条件与valueMode一致：输出represented或输入inlineRows。
