# 构建配置模块表与冷构建优化

## Intent：最终目标

保留所有RX/ZX迁移及生成配置，通过消除build driver中的重复展开缩短冷构建。
固定完整基线129.74秒/216.03 CPU秒/2075033600 B单体/2247294976 B树峰不重置。

## Data：可用证据

当前完整131.77秒/199.71 CPU秒，单体2147844096 B、树峰2155773952 B。
关键路径为驱动约28秒、seed约19秒、P2约35秒、宿主约33秒。宿主等待分区
是既有防叠峰策略，不能移除后让两个大工作集重叠。

全新local/global缓存的相同root --help隔离：实际34.31秒、CPU32.27秒，峰621314048 B；
不运行编译步骤。约384字段的ParserModules使400项entry表在生产和接线位置重复
inline展开，每增加Source入口都会增大驱动本体。候选改为固定字段和ModuleBinding
切片，预计算文件名/import名，三处普通循环，模块集合及配置顺序保持一致。

## Edges：边界与限制

不改分区、优化模式、并发、LLVM后端或内存调度依赖；不改变产物中的执行代码。
构建配置绑定由b.allocator拥有，仅存在build driver，不引入zxc运行层。元数据
字符串在编译期生成，不在配置循环中拼接。不新增持久测试，复用现有检查。

先测隔离驱动；若有效再核全命令、产物及完整冷构建，记录固定累计变化。另一个
候选是AST行头泛型校验共享，本轮仅取得其before IR，未改实现，保留供后续归因；
不将该IR观测算作本轮收益，不同时更改宿主泛型以免混淆因果。

## Answer：交付与成功标准

```mermaid
flowchart LR
    Entries[既有入口列表] --> Metadata[编译期元数据表]
    Metadata --> Modules[普通循环创建模块]
    Modules --> Bindings[模块绑定切片]
    Bindings --> Frontend[前端接线]
    Bindings --> Backend[编译器及genz接线]
```

```mermaid
flowchart LR
    Table[静态路径及导入名] --> Driver[build driver]
    Driver --> Graph[同一构建依赖图]
    Graph --> Seed[既有Source生成]
    Seed --> Parts[分区对象]
    Parts --> Host[串行宿主]
    Host --> Output[原链接与产物]
```

成功要求入口、导入名、模块根、标志及依赖不变，隔离驱动及完整冷构建有可核查
收益，产物和现有行为检查通过；统一提交推送所有变更并确认工作区干净。

## 实现与验证

Entry列表仍是唯一事实来源。编译期module_entries保存set、原Entry、文件名和
import_name，过滤条件和main/ordered/collections/growth次序不变。ParserModules
改为type_views、nominal_data和bindings切片；保留前两者原创建顺序。配置循环
只调用原createModule及addImport，原类型宽度与重复inline展开不再随入口数扩大。
get只用于内部已知的partition_groups，其他接线直接遍历绑定，无新增应用运行成本。

首次元数据构造超过Zig默认1000次comptime回边预算，已局部提高为10000；只作用
于生成静态表，不是运行时阈值。失败日志保留，不计入测量。源码仅改3个构建文件。

同工具链、相同参数、全新local/global缓存的root --help成功对照：

| 指标            |    原实现 |    模块表 |      差值 |
| --------------- | --------: | --------: | --------: |
| 实际秒          |     34.31 |     34.21 |     −0.10 |
| CPU秒           |     32.27 |     32.18 |     −0.09 |
| 最大单进程RSS B | 621314048 | 583991296 | −37322752 |

单对时间收益较小，不以此宣称全部驱动开销已解决；约35.6 MiB下降仅是驱动单体，
不能加减到完整构建约2 GiB峰值。首次失败29.62 CPU秒的观测不纳入此表。

完整冷构建43/43步骤通过，四组main/ordered/collections/growth的生成文件分别
7545/23/64/360，共7992个文件字节一致（排除输入指纹.zxc-inputs）。这里是P2完整
构建，不能与P16工具对照文件数混用。前后宿主响应文件各451个模块根，去除缓存
目录身份后逐项一致，无模块漏接、改名或路径映射变化。

新冷构建CLI完成既有发布入口5/5及独立消费运行2/2；覆盖RX/ZX入口、显式默认
导出、包迁移和独立ZX/Zig消费者，以及type-only发布。3个Native构建文件格式
检查通过，无新增测试用例。

## 自我复核

这项改动只减少构建配置本体的展开，不代表新增自举职责，也不改变Source编译
行为。预计算表仍有与入口数成正比的静态数据，配置期增加一个绑定切片；没有
新增哈希缓存、调度器或运行库。get的线性查找只在构建配置选择已知模块时执行。
完整冷构建及固定单体峰的累计差值仍为正，不能以本轮改善宣称全部性能门禁完成。
后续继续针对关键路径优化，不能通过取消防叠峰依赖或回撤迁移来达标。
