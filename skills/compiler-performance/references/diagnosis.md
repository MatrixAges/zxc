# 诊断：把现象变成可证伪的成本模型

## 冻结可重放的命令

- 从真实构建输出或清单取编译命令，固定 cwd、argv、工具链、target、CPU/backend、根模块及依赖模块模式、输入与输出身份。清单里的相对路径依赖 cwd；FileNotFound 不是性能样本。
- 先用已有生成器只测生成阶段，再固定它的产物单测后端，最后测端到端。不要把生成器自身编译、安装时检查、链接与测试时间混在一个结论里。
- `measure.mjs` 记录 argv、可执行文件 SHA-256、显式 `--input` 文件摘要、wall/user/system/RSS 和原日志。它不证明缓存冷暖、不冻结整个工作树，也不采集完整环境；额外记录影响结果的配置和源码版本。
- 每轮只改变一个性能假设。按场景独立测；连续重复会自然升温，不能将三个连续运行都标成冷运行。冷测每次使用明确的新局部输出/缓存目录，不清理用户共享缓存。

## 层层缩小归因

1. 用粗阶段计时定位 infer、emit、write、backend 或 link，记录绝对时间及分母。
2. 在热点阶段采短栈，按调用者展开，不只看 top-of-stack。对短增量路径可在常驻进程接受重复请求时采样；不要把等待请求时间混入工作占比。
3. 对候选操作计数：调用次数、总处理行数、复制字节、失效原因、命中/回退次数。建 `总成本 ≈ 次数 × 每次规模 × 单位成本` 模型，核对实际阶段耗时。
4. 内存问题同时看 RSS 时间线、分配容量和 backing allocator 调用栈。单入口结束后 RSS 回落与跨入口持续增长是不同问题。

例：最终只有数百个函数，不代表成本只有数百行；每次 append 都校验增长中的全表，累计扫描可达数十万行。逐 origin 查询、逐函数遍历全调用图、每个模块复制全类型表同理。

## 符号与进程身份

`profile.mjs` 只接受明确 PID，保存 ps 的 PID/PPID/启动时间/命令及原采样。先确认采到真实 compiler/generator，不能把 shell 的 `__sigsuspend` 当编译器阻塞。

只看到 `main` 或 `<deduplicated_symbol>` 时，先查 strip、符号表和构建配置。历史会话先误以为 ReleaseFast 内联，再换 ReleaseSafe，仍无符号；最终发现 root ReleaseSmall 默认 strip。不要因缺符号而反复换优化级别。

可以临时保留符号再采样，但改模式后的时间不能与原版直接比较。若使用同次构建 `.o` 恢复已裁剪二进制地址，需核对 text 布局、装载基址、relocation 与链接松弛；不能拿另一轮构建的地址套用。归因不足时用局部阶段计时，移除探针后再报收益。

## 指标不可互换

| 指标                  | 可以说明                  | 不能说明                              |
| --------------------- | ------------------------- | ------------------------------------- |
| 某个短窗口的样本占比  | 该 PID 在该窗口的热点候选 | 整个构建准确占比                      |
| 累计 dupe/memcpy 字节 | 内存带宽工作量            | 同时占用的 RSS、内存泄漏              |
| arena capacity        | 特定 allocator 的保留容量 | 整进程峰值与所有子进程之和            |
| 每几秒采样 RSS        | 采样点内存走势            | 捕获了真正峰值                        |
| 静态 renew/defer 次数 | 生成代码检查入口          | 执行次数、实际复制量或性能收益        |
| 输出字节一致          | 所测输入在该路径产物相同  | OOM、非法输入、全平台与完整自举正确性 |

## 宿主工具链也是变量

根模块 ReleaseSmall、依赖 ReleaseFast、generated Debug、compiler-rt 模式可能不同。先看实际参数、工具链源码和反汇编，再解释热点。观察到慢 `memcpy` 时可能是大描述符复制、列表重建，也可能是体积优化选择逐字节实现，必须区分。

若标准工具链配置能解决，先做隔离变体，保持 target/CPU/backend/PIC/libc 一致，核对最终符号只链接一份；不要直接发明专用 runtime 或机械改所有 IR API。比较 `工具重建时间 + 每次运行成本 × 运行频率`，保留调试体验及安全模式的代价说明。

工具、后端与平台限制只对具体版本有效。历史 macOS Zig 增量链接失败不代表现在仍失败；有相关任务时核实当前安装版本，不把失败编译当快速样本。
