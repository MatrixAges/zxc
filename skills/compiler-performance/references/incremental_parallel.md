# 增量、不动点与并行

## 命中率高为何仍慢

把缓存路径拆成：准备事实、构造键、查找、读取、解码/复制、命中后剩余工作。历史生成器 1457 个单元全部复用，emit 仍约 9 秒，因为查缓存前先做了全程序唯一性分析。

优先使昂贵分析结果可复用，或者让便宜的局部身份先决定是否需要分析。不得为了提前查询省略影响结果的依赖。

缓存键/有效条件按算法实际读集合建立，可能包含本体、类型形状、callee I/O 与效应、input/output summary、导出、调用方需求、normalized/renewed 集合、编译器及格式版本。历史遗漏 callee 错误集与身份比较事实都导致调用者命中旧产物。

摘要计算也有成本：少量字段逐次哈希、每轮全程序哈希可能比命中读取更贵。只在字节流/算法兼容被确认时批量提交哈希数据；键语义或编码变化要改变版本并使旧记录失效。

## 完整增量链路

源变化 → 模块接口/正文变化 → 依赖事实失效 → 函数分析/生成 → 文件内容变化 → 独立目标对象 → 链接。对每段给出实际重算数量，不能只报告“缓存命中”。

- 稳定生成路径与名字，内容不变不重写；记录受本生成器管理的文件清单，处理陈旧文件只限这个清单。
- 按接口/结构摘要截断传播，但 RX 约束可能影响更早模块或全局签名，不能直接套纯 ZX 的依赖判定。
- 按绝对编号复用 IR 时，需保证模块顺序、共享表前缀和重映射规则成立。
- 全源码摘要若进入 configure，任意源码修改可能使整个构建配置失效；应检查它属于配置身份还是独立构建步骤。
- 64 个分区即使全部命中，也可能起 64 个编译进程；测 no-op 与进程时间线，识别固定开销。
- 分区/原生链接等方案同时核对 ABI、错误码、内联闭包、panic 和调试栈。历史平台方案不得复制为跨平台默认。

验证至少选择与本次改动相关的场景：函数体语义编辑、被调方效应/接口变化、恢复；涉及 RX 就增加 RX 语义编辑，涉及文件身份就覆盖同 inode 原地改写。每个编辑后的增量结果与该时刻同输入的冷结果比较；恢复后的结果再对比原基线。首次编辑与后续编辑单独报告。

## 不动点不能假定与顺序无关

先确认传递函数单调、合并运算和迭代顺序。历史 FIFO 改最小/最大序号会改变输出；Jacobi 式并行虽保持安全，却丢失增长/回收前沿，让生成程序反复复制甚至退化为平方复杂度。

有顺序依赖时，可复用纯函数分析结果并按原序回放 meet/join。键必须描述分析实际读取的状态，不能只缓存最终 output。状态不匹配就重算，不以高命中率取代正确性。

有证据证明必要时才做推测并行：在不可变快照或无数据竞争的读取协议下预分析，记录读取值/版本，顺序提交前验证仍成立；失效重算。自递归会在分析中观察自己的写入，不能直接纳入。记录命中、过期、回退与等待时间；没有收益就去掉推测层。

## 并行的收益由关键路径决定

先测依赖层宽度、最长链、单任务时长、分配与文件系统争用。历史 1416 模块需 560 轮，344 轮只有一个模块；完整并行实现输出一致，infer 却 260→420 ms，应撤回。

- 稳定的线程池只在频繁建线程确为热点时引入；低延迟路径要测空转争用。
- 限制工作窗口与线程数，避免任务先算完但很快失效；历史 31 个推测线程比 8 个更慢，不能据此将 8 固化为全平台参数。
- 并行输出目录写入曾被内核锁串行化；独立缓存记录写入在另一个场景又有收益。区分操作、负载和生命周期。
- 异步写盘需要对读取、替换、释放建立明确等待边界；回复之后释放可缩短延迟，但后台内存和错误仍必须被 owner 管理。

## 常驻与 SIMD 的适用条件

常驻本身只省启动；仍每轮重算语义时收益很小。应缓存不变模块/解析结果，明确版本身份、工作目录、失效、内存预算、退出和错误返回。检查继承的进度管道是否阻止父构建退出。不要为几毫秒无条件新增常驻服务。

SIMD 适合已确认的密集列过滤、字节相等/搜索。先用 kind/first/second 过滤候选，再做完整比较，保持首个匹配与尾部边界。先看真实优化级别和汇编，标准库在 ReleaseSmall 下可能退化，但专用实现并非默认答案。验证 CPU、平台与编译期路径；小输入不一定值得向量化。
