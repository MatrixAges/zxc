# 文档分工

## 面向使用者的指导

`packages/skills/` 面向任何使用 zxc 编写应用的 AI，也供应用开发者阅读。内容必须能在独立的业务项目中理解和使用，不要求读者拥有 zxc 源码仓库。

适合放入 skills 的内容：

- 应用的 RX/ZX 编写方式与公开语言约束。
- 按文件路径引用模块、组织业务职责和消除循环依赖。
- 输入输出、状态一致性、错误处理及应用验证。
- 基于使用者所用版本和环境判断功能是否可用。

不要放入 skills：

- zxc 内部目录、标签实现位置和源码阅读要求。
- Zig 包构建、仓库回归命令、内部 AST 接口及内存管理。
- zxc 内部测试布局、图算法实现和测试数量。
- 要求应用使用者修改编译器或新增语言实现才能完成普通业务。

skills 只保存 Markdown，不配置 build.zig、build.zig.zon，不构建或打包。采用 GitHub README 风格，不使用 IDEA 结构，也不依赖特定 AI 工具的自动加载机制。

## 面向维护者的规则

`rules/*.md` 指导修改 zxc 本身的开发者和 AI。内部代码组织、实现约束、测试入口和验证边界放在这里，并在根 AGENTS.md 中保留索引。

[RX 开发约定](RX开发约定.md)记录 RX 实现与回归要求。已有通用编码约束仍以根 AGENTS.md 为准，避免重复复制后出现多个版本。

## 执行记录

`docs/<日期>/` 保存设计决策、实施与验证记录。记录可以引用内部代码，但不应成为应用使用者阅读 skills 的前置条件。

维护文档时检查读者身份：如果一句话要求了解 zxc 源码、内部 API 或构建系统，应放到 rules 或执行记录，而不是 skills。
